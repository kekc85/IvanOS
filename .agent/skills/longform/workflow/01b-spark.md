# 01b - Mode B (Spark)

> Ситуативная генерация. Два sub-mode: B1 (расширение конкретной темы X в 5-7 углов) / B2 (генерация 5-7 longform-идей под JTBD).

## Sub-mode B1 - расширение темы X

### Когда

User input типа:
- `/longform про вайбкодинг`
- «напиши статью про контент-завод»
- «эссе про то как автор берёт клиентов»

### Шаги

#### Шаг 1 - извлечь X

Тема X = первое существительное-фраза после «про» / «о» / «about» / «on».

#### Шаг 2 - собрать 5-7 углов

Для темы X сгенерировать 5-7 longform-углов. Каждый угол = (1) framing + (2) main_thesis + (3) audience-pain-angle. Углы должны быть MECE (не пересекаются, покрывают разные грани X, один axis = «как раскрыть X»):

| # | Угол | Framing | Main thesis (1 строка) |
|---|---|---|---|
| 1 | Teaching | механизм | «X работает так-то, и вот почему» |
| 2 | Story | personal | «как я столкнулся с X и что понял» |
| 3 | Framework | mental model | «X - это не Y, а Z. Новый каркас» |
| 4 | Contrarian | myth-busting | «все думают X. на самом деле наоборот» |
| 5 | Case study | конкретный кейс | «ученик/клиент применил X - что получилось» |
| 6 | Listicle | N принципов | «N принципов которые я понял за <time>» |
| 7 | Deep-dive | research | «X с трёх уровней: теория / практика / экономика» |

В v1.0 - angles 1, 2, 3 (соответствуют templates v1.0). Если все три не подходят - добавить из 4-7 (но template для них = v1.1, выполнение будет в режиме fallback на ближайший доступный).

#### Шаг 3 - показать выбор пользователю

Plain text список (Telegram-friendly):

```
5 углов по теме «X»:

1. Teaching - <main_thesis 1 строкой>
2. Story - <main_thesis 1 строкой>
3. Framework - <main_thesis 1 строкой>
4. Contrarian - <main_thesis 1 строкой>
5. Case study - <main_thesis 1 строкой>

Какой раскрыть? (1-5 / другой / уточни)
```

Пользователь выбирает 1-5. Если «другой» - повторить с другим pivot. Если «уточни» - задать 1 уточнение про audience / outcome shift.

#### Шаг 4 - собрать brief

```yaml
mode_b1_brief:
  topic: "X"
  angle_chosen: "<1-5>"
  type: "<teaching | story | framework | ...>"
  main_thesis: "<выбранный thesis>"
  audience_pain: "<pain из аватара>"
  outcome_shift: "<shift>"
  personal_anchor: "<подобран из story bank>"
  language: "<from router>"
  platform: "<from router>"
```

## Sub-mode B2 - генерация под JTBD

### Когда

User input типа:
- «дай идеи для newsletter на эту неделю»
- «что писать в LinkedIn»
- «темы для блога»

### Шаги

#### Шаг 1 - load context

Read:
- `paths.avatar` - целевой читатель
- `paths.jtbd` - главные jobs-to-be-done
- `paths.objections` - топ возражения
- `paths.recent_articles_*` - что уже писал (no-repeat)

#### Шаг 2 - генерация 5-7 идей

Каждая идея = (topic + angle + main_thesis + рекомендованный type). MECE по jobs-to-be-done (не повторять job).

#### Шаг 3 - фильтр no-repeat

Удалить идеи которые покрывают тему из последних N статей (`config.paths.recent_articles_count`).

#### Шаг 4 - показать список

Plain text, тот же формат что B1.

#### Шаг 5 - выбор + brief

Та же структура brief что в B1.

## Edge cases

- **Тема X слишком узкая** (например «как ставить рекламу в Кит») → углы получатся бедные, в этом случае попросить пользователя расширить тему до уровня job/категории
- **Тема X слишком широкая** («про маркетинг») → в углах будет расплывчато, попросить сузить до конкретного job или audience segment
- **No recent_articles доступны** → пропустить фильтр no-repeat, warn пользователя

## Что НЕ делать

- НЕ генерить generic AI-идеи типа «10 way to do X» - каждая идея должна быть конкретной
- НЕ задавать выбор когда уже всё понятно из контекста - если тема + audience + type очевидны, генерить brief сразу
- НЕ дублировать темы между B1 углами - углы должны быть MECE

## Memory cross-refs

- - MECE для углов / идей
- - нет generic «10 хуков»
- - синтез из контекста + альтернативы + рекомендация
- - не задавать выбор когда не нужно
