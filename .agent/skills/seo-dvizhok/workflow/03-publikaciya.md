# Фаза 3. Публикация и индексация: 5 шагов, порядок жёсткий

Статья опубликованная, но не проиндексированная = статьи нет. Эта фаза доводит страницу до поиска за 1-3 дня.

## Шаг 1. Публикация

Публикует производственный конвейер движка - инструмент `ftp_publish.py` / `stateinik_publish.py` из модуля движка (адреса файлов - workflow/02, раздел «Производственный модуль»; скилл lead-magnit не вызывается) - на хостинг ученика из config. Адрес - чистый URL по шаблону `guides_path` из config, без `.html` на конце

## Шаг 2. Проверка живой страницы

🔴 Конвейер может отчитаться об успехе, а страницы на сервере не быть - тогда поиску сообщат о пустоте. Всегда проверяй сам:
```
curl -s -o /dev/null -w "%{http_code}" https://<домен>/<адрес-статьи>/
```
Не 200 - публикация не состоялась, вернись к шагу 1. Улику (вывод команды) - в журнал

## Шаг 3. Пинг IndexNow

Сообщи Яндексу о новой странице (ключ - из config, файл ключа положен в Фазе 0):
```
curl -s -X POST "https://yandex.com/indexnow" \
  -H "Content-Type: application/json; charset=utf-8" \
  -d '{"host":"<домен>","key":"<ключ>","urlList":["https://<домен>/<адрес-статьи>/"]}' \
  -w "\nHTTP %{http_code}\n"
```
Успех = 200 или 202. Другой код - проверь, что файл ключа отдаётся с сайта (`curl https://<домен>/<ключ>.txt`), и повтори. Дополнительно можно пингануть общий сервис `api.indexnow.org` тем же телом запроса

## Шаг 4. Пересборка sitemap

Добавь новый URL в `sitemap.xml`, перезалей, проверь: `curl -s https://<домен>/sitemap.xml | grep <slug>` находит статью. Страница вне карты выпадает из всех проверок корпуса

## Шаг 5. Запись в журнал

В `~/IvanOS/.business/marketing/seo/zhurnal.md` строка: дата · тема · URL · код ответа IndexNow · код-слово. В очереди статус темы → «опубликована». Незаписанная статья ломает учёт и план недели

## Ловушки публикации, снятые волной в даты запуска.2026

- **RSS: флаг даты не передавать.** Инструмент заливки ждёт дату в RFC-822; ISO-дата (2026-09-01) молча не парсится, item получает минимальную дату, встаёт «самым старым» и срезается лимитом ленты - при зелёном отчёте заливки. Правильно: `--update-rss` БЕЗ флага даты (инструмент сам читает дату первой публикации из JSON-LD живой страницы), а после - контроль цепочкой `publish_chain`: отчёту заливки на слово не верить
- **Маршрут артефактного гейта судится по datePublished в реестре публикаций.** Новая страница, чью запись реестр получил без datePublished (например, запись создала пересборка карты, а не публикатор), уезжает в маршрут legacy и требует не те артефакты. После публикации проставь датe записи реестра - и маршрут станет new
- **Кадр приёмки хаба и статьи свежее сборки.** Любая пересборка index.html (даже правка одной фразы) старит кадр - пересъём обязателен до заливки, страж сверяет mtime

## Контроль попадания в поиск

Через 3-7 дней проверь в Вебмастере, что страница в поиске (или оператором `site:<домен>/<slug>` в Яндексе). Попала - отметь в журнале. Через 7 дней нет - ручной переобход в Вебмастере (раздел переобхода страниц, веди по живому экрану). Ещё через 7 дней нет - разбор: что не так со страницей (дубль? тонкая? закрыта в robots?)

## Перелинковка (раз в неделю, не в день публикации)

Одним недельным прогоном: каждая новая статья получает минимум 3 входящие ссылки из старых статей той же темы + блок «Читайте также» на 4-6 соседних. Статья без входящих ссылок - сирота, живой замер чужих исследований: страницы с 40+ входящими получают в разы больше трафика, чем с нулём. После массовой правки - проверить каждый правленный URL живьём (файлы недоезжают молча)
