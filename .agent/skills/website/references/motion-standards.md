## 1. НАДО ЛИ ЭТО АНИМИРОВАТЬ - таблица частоты (Kowalski)

| Частота | Решение |
|---|---|
| 100+ раз в день (клавиатурные шорткаты, командная палитра) | **Анимации нет. Никогда** |
| Десятки раз в день (hover, навигация по списку) | Убрать или радикально уменьшить |
| Иногда (модалки, шторки, тосты) | Стандартная анимация |
| Редко / впервые (онбординг, фидбэк, поздравления) | Здесь живёт бюджет на восторг |

🔴 **Клавиатурные действия - дисквалификатор, а не суждение.** Raycast не имеет анимации открытия/закрытия - это ПРАВИЛЬНО для вещи, которую открывают сотни раз в день.

**Допустимые цели движения:** пространственная связь · индикация состояния · объяснение · фидбэк · снятие резкости перехода. «Красиво смотрится» на часто видимом элементе - не цель.

## 2. EASING - порядок решения и точные кривые

- Вход или выход → **`ease-out`** (стартует быстро, ощущается отзывчиво)
- Движение/морфинг по экрану → **`ease-in-out`**
- Hover, смена цвета → **`ease`**
- Постоянное движение (лента, прогресс) → **`linear`**
- По умолчанию → **`ease-out`**

🔴 **`ease-in` на UI - никогда.** Он стартует медленно и оттягивает ровно тот момент, на который пользователь смотрит. `ease-out` на 200ms ОЩУЩАЕТСЯ быстрее, чем `ease-in` на 200ms.

**Встроенные CSS-easing слишком слабые. Точные кривые (класть токенами):**

```css
--ease-out:    cubic-bezier(0.23, 1, 0.32, 1);      /* сильный ease-out для UI */
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);     /* сильный ease-in-out для движения по экрану */
--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);      /* iOS-подобная кривая шторки (Ionic) */
```

Bakaus добавляет для «уверенного прибытия»: `cubic-bezier(0.16, 1, 0.3, 1)`. Кривые искать на [easing.dev](https://easing.dev/) или [easings.co](https://easings.co/), не крутить с нуля.

## 3. ДЛИТЕЛЬНОСТЬ - бюджет по элементам

| Элемент | Длительность |
|---|---|
| Фидбэк нажатия кнопки | 100-160ms |
| Тултипы, мелкие поповеры | 125-200ms |
| Дропдауны, селекты | 150-250ms |
| Модалки, шторки | 200-500ms |
| Маркетинг / объясняющее | Может быть дольше |

🔴 **Правило: UI-анимации держатся под 300ms.** Дропдаун на 180ms ощущается отзывчивее, чем на 400. Более быстрые спиннеры делают загрузку ощутимо быстрее при том же реальном времени. Мгновенные тултипы после первого (без задержки и анимации) делают тулбар быстрее.

Bakaus по авторскому моменту (Persuade-поверхность может себе позволить дольше): 100-150ms немедленный фидбэк · 150-300ms рядовая смена состояния · 300-500ms лейаут/оверлей/смена вида · 500-800ms **сознательно авторский фокусный вход**. **Выход быстрее входа.** Долгий фидбэк ощущается как задержка.

## 4. ФИЗИЧНОСТЬ

- 🔴 **Никогда `scale(0)`.** Стартовать с `scale(0.9-0.97)` + `opacity: 0`. В реальном мире ничто не появляется из ничего
- 🔴 **Поповеры, дропдауны, тултипы масштабируются ОТ ТРИГГЕРА, не от центра:**
  ```css
  .popover { transform-origin: var(--transform-origin); } /* Base UI */
  ```
  **Модалки - исключение:** они появляются по центру вьюпорта, `transform-origin: center` там верен, это не дефект
- **Фидбэк нажатия:** `transform: scale(0.97)` на `:active`, `transition: transform 160ms ease-out`. Тонко (0.95-0.98). На любом нажимаемом элементе

## 5. ПРУЖИНЫ (springs)

Ощущаются естественно, потому что симулируют физику; фиксированной длительности нет - они оседают на параметрах. Для чего: драг с инерцией, «живые» элементы, прерываемые жесты, декоративный трекинг мыши.

```js
// Apple-стиль (проще рассуждать) - рекомендуемый
{ type: "spring", duration: 0.5, bounce: 0.2 }

// Классическая физика (больше контроля)
{ type: "spring", mass: 1, stiffness: 100, damping: 10 }
```

Bounce держать мягким (0.1-0.3); в большинстве UI отскока избегать - он для драг-to-dismiss и игривых взаимодействий. Пружины сохраняют скорость при прерывании (keyframes рестартуют с нуля), поэтому идеальны для жестов, которые пользователь может развернуть на полпути.

Для мышиных интеракций интерполировать через `useSpring`, а не привязывать значение напрямую к позиции курсора (прямая привязка = искусственно, без инерции). Только когда движение декоративно.

## 6. ПРЕРЫВАЕМОСТЬ - главное для динамичного UI

CSS **transitions** прерываются и перенацеливаются на лету; **keyframes** рестартуют с нуля. Для всего, что триггерится часто (тосты, тумблеры), transitions заметно плавнее.

```css
/* Прерываемо - годится для динамического UI */
.toast { transition: transform 400ms ease; }

/* Непрерываемо - для динамического UI нельзя */
@keyframes slideIn { from { transform: translateY(100%); } to { transform: translateY(0); } }
```

Вход без JS - через `@starting-style`:

```css
.toast {
  opacity: 1; transform: translateY(0);
  transition: opacity 400ms ease, transform 400ms ease;
  @starting-style { opacity: 0; transform: translateY(100%); }
}
```

Legacy-запасной путь: `useEffect(() => setMounted(true), [])` + атрибут `data-mounted`.

**Асимметричный тайминг:** медленно там, где пользователь решает, быстро там, где отвечает система.

```css
.overlay { transition: clip-path 200ms ease-out; }            /* отпустил: быстро */
.button:active .overlay { transition: clip-path 2s linear; }  /* держит: медленно, осознанно */
```

## 7. ПРОИЗВОДИТЕЛЬНОСТЬ

- **Анимировать только `transform` и `opacity`** - они минуют layout/paint и идут на GPU. `padding`/`margin`/`height`/`width`/`top`/`left` запускают все три стадии рендера
- 🔴 **`transition: all` - всегда находка** (анимирует непреднамеренные свойства мимо GPU)
- 🔴 **Не гнать трансформы детей через CSS-переменную на родителе** - это пересчёт стилей у всех детей:
  ```js
  element.style.setProperty('--swipe-amount', `${d}px`); // плохо: recalc на всех детях
  element.style.transform = `translateY(${d}px)`;        // хорошо: только этот элемент
  ```
- 🔴 **Шорткаты Framer Motion НЕ аппаратно-ускорены.** `x`/`y`/`scale` идут по главному потоку через rAF и роняют кадры под нагрузкой. Полная строка трансформа:
  ```jsx
  <motion.div animate={{ x: 100 }} />                          // роняет кадры под нагрузкой
  <motion.div animate={{ transform: "translateX(100px)" }} />  // аппаратное ускорение
  ```
- **CSS-анимации выигрывают у JS под нагрузкой** - они идут вне главного потока. CSS для предопределённого движения, JS для динамического и прерываемого
- **WAAPI** даёт JS-контроль с производительностью CSS:
  ```js
  element.animate([{ clipPath: 'inset(0 0 100% 0)' }, { clipPath: 'inset(0 0 0 0)' }],
    { duration: 1000, fill: 'forwards', easing: 'cubic-bezier(0.77, 0, 0.175, 1)' });
  ```
- `filter: blur()` на переходе держать **под 20px** - тяжёлый блюр дорог, особенно в Safari
- `will-change` - только на время известной анимации, не базово и не «на всякий случай»

## 8. ТРАНСФОРМЫ И CLIP-PATH

- **Проценты в `translate` считаются от собственного размера элемента**: `translateY(100%)` двигает на высоту элемента независимо от габаритов (так позиционируют тосты и шторки Sonner/Vaul). Предпочитать хардкоду в px
- **`scale()` масштабирует и детей** (шрифт, иконки, контент) - для фидбэка нажатия это фича
- **3D:** `rotateX/Y` + `transform-style: preserve-3d` для глубины, орбиты и флипа без JS
- **`clip-path: inset(t r b l)`** - мощный инструмент: каждое значение «съедает» со своей стороны. Применения: reveal на скролле (`inset(0 0 100% 0)` → `inset(0 0 0 0)`), оверлей «удерживай для удаления», бесшовный переход цвета таба (дубль + клип активной копии), слайдеры сравнения

## 9. ЖЕСТЫ И ДРАГ

- **Инерционное закрытие:** не требовать преодоления порога расстояния - считать скорость (`Math.abs(distance)/elapsedMs`), закрывать при `> ~0.11`. Флика должно хватать
- **Демпфирование на границах:** драг за естественный край двигает тем меньше, чем дальше (реальные вещи замедляются перед остановкой)
- **Pointer capture** сразу после начала драга, чтобы он продолжался, когда указатель вышел за границы
- **Защита от мультитача:** игнорировать лишние точки касания после начала драга (`if (isDragging) return`)
- **Трение вместо жёсткого стопа:** разрешать перетяг с растущим сопротивлением, а не невидимую стену

## 10. МАСКИРОВКА НЕИДЕАЛЬНОГО КРОССФЕЙДА

Когда кроссфейд показывает два наложенных состояния несмотря на подкрутку easing и длительности - добавить лёгкий `filter: blur(2px)` на время перехода, чтобы они слились в одну воспринимаемую трансформацию. Блюр держать <20px.

## 11. СТАГГЕР

Стаггерить групповые появления, **30-80ms между элементами**. Более длинные задержки ощущаются медленно. **Стаггер декоративен - он никогда не блокирует взаимодействие.**

Bakaus добавляет: стаггер уместен, когда список появляется КАК СПИСОК. Общую задержку капить и никогда не переинтерпретировать каждую проскролленную секцию как стаггер-список.

## 12. ДОСТУПНОСТЬ

```css
@media (prefers-reduced-motion: reduce) {
  .element { animation: fade 0.2s ease; } /* оставить opacity/цвет, убрать движение */
}
@media (hover: hover) and (pointer: fine) {
  .element:hover { transform: scale(1.05); } /* тач даёт ложные hover при тапе */
}
```

🔴 **Reduced motion означает меньше и мягче, а НЕ ноль.** Оставить переходы, помогающие понять; убрать перемещения. Глобальный `0.01ms`-килл, уничтожающий полезный фидбэк, - это дефект (Bakaus, `audit.md`).

Apple добавляет ещё два независимых сигнала:
- **`prefers-reduced-transparency: reduce`** - полупрозрачные поверхности делать плотнее/сплошными: поднять непрозрачность фона, убрать блюр
- **`prefers-contrast: more`** - почти сплошные фоны с явной контрастной рамкой

Плюс: избегать полноэкранных движущихся фонов, медленных зацикленных колебаний (около 0.2 Гц, один цикл на 5 секунд) и резких скачков яркости (переход тёмной/светлой темы плавить).

## 13. ДЕСЯТЬ НЕПРЕЛОЖНЫХ СТАНДАРТОВ (Kowalski, `review-animations`)

Каждая анимация меряется по ним. Нарушение = находка.

1. **Оправданное движение** - каждая анимация отвечает «зачем это анимируется»: пространственная связь, индикация состояния, фидбэк, объяснение, снятие резкости. «Красиво» на часто видимом = блок
2. **Соответствие частоте** - см. таблицу §1. Клавиатурные и 100+/день = НЕТ анимации
3. **Отзывчивый easing** - вход/выход через `ease-out` или сильную кастомную кривую. `ease-in` на UI = блок
4. **Под 300ms на UI** - медленнее требует обоснования, иначе находка
5. **Origin и физическая корректность** - поповер от триггера, не от центра; никогда из `scale(0)`. Модалки - исключение
6. **Прерываемость** - часто триггеримое и жестовое = transitions или springs, не keyframes с нуля
7. **Только GPU-свойства** - `transform` и `opacity`. `width`/`height`/`margin`/`padding`/`top`/`left` (и шорткаты Framer Motion под нагрузкой) = перф-находка
8. **Доступность** - `prefers-reduced-motion` соблюдён (мягче, не ноль); hover-анимации за `@media (hover: hover) and (pointer: fine)`
9. **Асимметричный вход/выход** - осознанные действия (нажатие, удержание, деструктивное подтверждение) медленнее; ответ системы щёлкает. Симметричный тайминг на press-and-release = находка
10. **Когезия** - моушен совпадает с характером компонента и продукта: игривое может быть отскокистее, дашборд остаётся чётким. **Когда сомневаешься, правильно ли ощущается движение, сильнейший ход - удалить его**

### Триггеры немедленной эскалации (флагать на месте)

`transition: all` · `scale(0)` или чистый фейд без начального трансформа · `ease-in` на любой UI-интеракции · анимация на клавиатурном шорткате / командной палитре / 100+/день действии · длительность UI >300ms без причины · `transform-origin: center` на привязанном к триггеру поповере · keyframes на тостах, тумблерах и всём часто триггеримом · анимация лейаут-свойств · шорткаты Framer Motion на занятой странице · обновление CSS-переменной на родителе ради трансформа ребёнка · отсутствие `prefers-reduced-motion` на движении · негейченный `:hover` · симметричный тайминг на press-and-release · появление всей группой там, где нужен стаггер 30-80ms

### Иерархия лечения (предпочитать ранние ходы поздним)

1. **Удалить анимацию** (высокая частота / нет цели / клавиатурный триггер)
2. **Уменьшить** - короче, меньше трансформ, меньше свойств
3. **Починить easing** - `ease-in` → `ease-out` / сильная кривая
4. **Починить origin и физичность** - правильный `transform-origin`; `scale(0)` → `scale(0.95)` + opacity
5. **Сделать прерываемой** - keyframes → transitions, springs для жестового
6. **Увести на GPU** - лейаут-свойства → transform/opacity; шорткат → полная строка трансформа; WAAPI для программного CSS
7. **Асимметричный тайминг** - замедлить осознанную фазу, ускорить ответ
8. **Полировка** - блюр для маскировки кроссфейда, стаггер для групп, `@starting-style` для входа, spring для «живых»
9. **Доступность и когезия** - reduced-motion, hover-гейт, подгонка под характер компонента

## 14. ФИЗИКА APPLE (перевод WWDC на веб, Kowalski)

Сквозная мысль: **интерфейс живой, когда движение стартует от ТЕКУЩЕГО экранного значения, наследует скорость пользователя, проецирует инерцию вперёд и может быть схвачено и развёрнуто в любой момент**

### 14.1 Отклик - убить задержку
- **Отвечать на pointer-down, а не на отпускание.** Подсвечивать кнопку в момент нажатия
- **Бдительность к каждой задержке:** дебаунсы, искусственные таймеры, ожидание переходов, ~300ms tap delay
- **Фидбэк непрерывен ВО ВРЕМЯ интеракции, а не только в конце.** Драг, слайдер, шторка обновляются 1:1 с указателем всю дорогу

### 14.2 Прямое манипулирование - трекинг 1:1
Схваченное держится за палец И уважает смещение от точки захвата. Прыжок к центру элемента ломает иллюзию мгновенно. `setPointerCapture` + короткая история позиции/времени (последние несколько `pointermove`) - скорость понадобится при отпускании.

### 14.3 Прерываемость - самый важный принцип
> «Мысль и жест происходят параллельно»

- **Никогда не блокировать ввод на время перехода**
- **Всегда анимировать от ПРЕЗЕНТАЦИОННОГО (текущего) значения, не от целевого.** На прерывании читать живой трансформ с экрана. Старт с логического значения даёт видимый прыжок
- **Избегать CSS-transitions и `@keyframes` для жестового** - их нельзя плавно схватить и развернуть
- **При развороте жеста скорость СМЕШИВАТЬ, а не резать.** Замена одной анимации другой на развороте создаёт разрыв скорости - «кирпичную стену»
- **Раскладывать 2D-движение на независимые пружины X и Y**

### 14.4 Параметры пружин, которые шлёт Apple

Apple заменил триплет (масса/жёсткость/демпфирование) на два дизайнерских параметра:
- **Damping ratio** - управляет перелётом. `1.0` = критическое демпфирование, без отскока. `<1.0` = перелетает и колеблется
- **Response** - как быстро значение доходит до цели, в секундах. Это НЕ «длительность»: у пружины нет фиксированной длительности

| Интеракция | Damping | Response |
|---|---|---|
| Перемещение / репозиция (например PiP) | `1.0` | `0.4` |
| Вращение | `0.8` | `0.4` |
| Шторка / sheet | `0.8` | `0.3` |

Дефолт: **damping `1.0`** на большинстве UI. Отскок (**damping ~`0.8`**) - только когда сам жест нёс инерцию (флик, бросок, отпускание драга).

### 14.5 Передача скорости - шов между драгом и анимацией
Анимация обязана продолжиться с ТОЧНОЙ скоростью пальца. Некоторые API хотят относительную скорость:
```
relativeVelocity = gestureVelocity / (targetValue − currentValue)
```
Motion/Framer Motion принимают абсолютную px/s напрямую (опция `velocity`).

### 14.6 Проекция инерции - анимировать туда, КУДА идёт жест
Не защёлкивать к ближайшей границе от точки отпускания. Спроецировать точку покоя по скорости, потом защёлкнуть к ближайшей от проекции. Точная функция Apple:

```js
// decelerationRate ≈ 0.998 для обычного скролл-ощущения; 0.99 - резче
function project(initialVelocity /* px/s */, decelerationRate = 0.998) {
  return (initialVelocity / 1000) * decelerationRate / (1 - decelerationRate);
}
const projectedEndpoint = currentPosition + project(releaseVelocity);
const target = nearestSnapPoint(projectedEndpoint);
animateSpringTo(target, { velocity: releaseVelocity });
```
Учебная формула `v²/(2·decel)` - НЕ то, что шлёт Apple. Так работают хорошие bottom-sheet и карусели (Vaul, Embla).

### 14.7 Пространственная консистентность
> «Если что-то исчезло одним путём, мы ждём, что оно появится оттуда же»

Вход и выход по ОДНОМУ пути. Панель, въехавшая справа, обязана уехать вправо. Меню/поповер/шторка исходят из вызвавшего элемента. Easing на обратимых переходах зеркалить (инверсные контрольные точки кривой).

### 14.8 Резиновая граница
```js
function rubberband(overshoot, dimension, constant = 0.55) {
  return (overshoot * dimension * constant) / (dimension + constant * Math.abs(overshoot));
}
```

### 14.9 Материалы и глубина (прямо применимо к hero и липким шапкам)
- Навигацию, тулбары, шторки строить полупрозрачными слоями (`backdrop-filter: blur()` + полупрозрачный фон), контент скроллится ПОД ними
- **Вес материала кодирует иерархию:** темнее/тяжелее разделяет структурные регионы; легче привлекает к интерактивным. **Никогда не класть светлую полупрозрачную поверхность на другую такую же** - читаемость рушится
- **Крупные поверхности читаются толще:** сильнее блюр + глубже тень, чем у мелких чипов
- **Затемнять для фокуса, разделять для потока.** Модальная задача = поверхность + затемняющий скрим + фон отодвинут. Параллельная неблокирующая панель = прозрачность и смещение БЕЗ скрима
- **Vibrancy держит текст читаемым:** над блюром не плоский серый, а выше контраст, чуть тяжелее вес и небольшая прибавка трекинга. Цвет класть на сплошной слой, не на полупрозрачный передний план
- **Краевые эффекты скролла вместо жёстких разделителей:** вместо 1px-бордера под липкой шапкой - небольшая градиент-маска там, где контент встречает плавающий хром
- **Материализовать, а не просто фейдить:** для стекла анимировать радиус блюра и масштаб ВМЕСТЕ на входе/выходе

```css
.toolbar {
  background: rgba(255, 255, 255, 0.6);
  backdrop-filter: blur(20px) saturate(180%);
  border-top: 1px solid rgba(255, 255, 255, 0.4); /* яркий верхний край = свет, пойманный материалом */
}
```

### 14.10 Мультимодальный фидбэк (звук, вибрация)
1. **Причинность** - очевидно, что вызвало фидбэк
2. **Гармония** - визуал, звук и вибрация срабатывают в ОДНОМ кадре
3. **Полезность** - только там, где заслужено. Пере-фидбэк учит игнорировать весь фидбэк

### 14.11 Типографика Apple (переносится в Фазу 05)
- 🔴 **Трекинг зависит от кегля - никогда одно значение на все размеры.** Крупный дисплей хочет ОТРИЦАТЕЛЬНЫЙ трекинг; мелкий текст - слегка положительный. Фиксированный `letter-spacing` где-то обязательно неверен
- **Leading идёт обратно кеглю:** тесно на крупных заголовках, свободнее на body
- **Иерархию строить из веса + кегля + leading КАК НАБОРА**, не из одного кегля. Акцент весом добавляет присутствия, не занимая места
- **Уважать пользовательскую настройку размера текста:** отступы в `rem`/`em`, не в фиксированных px

```css
:root { font: 100%/1.5 system-ui, sans-serif; }
.display {
  font-size: clamp(2rem, 5vw, 4rem);
  line-height: 1.05;        /* тесный leading для крупного */
  letter-spacing: -0.02em;  /* отрицательный трекинг с ростом кегля */
  font-optical-sizing: auto;
}
```

### 14.12 Восемь принципов дизайна Apple (имена, которыми удобно рассуждать)
1. **Purpose** - делать намеренно; решать, чего НЕ строить
2. **Agency** - держать человека в контроле: выбор, лёгкая отмена, диалог подтверждения только для действительно необратимого
3. **Responsibility** - действовать в интересах пользователя: приватность, безопасность, предвидение вреда
4. **Familiarity** - строить на том, что люди уже знают; одинаковое выглядит одинаково и живёт в одном месте
5. **Flexibility** - разные контексты, устройства и весь диапазон способностей
6. **Simplicity, не минимализм** - убрать лишнее, чтобы засияла суть. Спрятать всё в одно место выглядит минималистично, но простым не является. Иногда ДОБАВЛЕНИЕ контекста упрощает
7. **Craft** - бескомпромиссное внимание к детали строит доверие. Ничего не случайно: каждый отступ, тайминг и выравнивание - решение, которое можно защитить
8. **Delight** - результат правильных семи, а не конфетти сверху

Плюс тактические правила: фидбэк бывает четырёх видов (статус, завершение, предупреждение, ошибка) · **wayfinding** - каждый экран отвечает: где я, куда могу пойти, что там, как выйти · **группировка и маппинг** - близость подразумевает связь; контрол рядом с тем, на что влияет; если нужен лейбл, чтобы объяснить контрол, маппинг слабый · **прямые конкретные лейблы бьют безопасные общие** («Прогресс», «Библиотека», не «Главная»)

## 15. ПОИСК ВОЗМОЖНОСТЕЙ ДЛЯ ДВИЖЕНИЯ (когда «оживить, но не переборщить»)

Скилл `find-animation-opportunities` - это ФИЛЬТР не меньше, чем искалка. Kowalski: «Ожидай отклонить большинство кандидатов. Короткий список высокоуверенных возможностей бьёт длинный список хотелок»

**Гейт - четыре вопроса подряд:** частота (§1) → цель (одна из шести названных) → скорость (влезает в бюджет §3) → функция (декор на информационно-плотном UI мешает; данные, которые пользователь ЧИТАЕТ или по которым ДЕЙСТВУЕТ, не должны двигаться ради стиля).

**Где искать швы:** нажимаемые элементы без `:active` · деструктивные действия без hold-to-confirm · контент, который телепортируется (условный рендер, аккордеон, смена роута) · панели и меню без связи с триггером · закрываемые поверхности, уходящие не тем путём, каким пришли · группы, появляющиеся все разом · драг без физики · редкие эмоциональные моменты, отрисованные плоско (первый запуск, пустое состояние, успех).

🔴 **Обязательная часть отчёта - «Отклонённые кандидаты»** (2-5 штук с указанием, какой вопрос гейта их убил). Именно она отличает работу от списка хотелок. Кап вывода: 5-7 предложений на весь сайт.

**Скролл:** Scroll reveal · **Scroll-driven animation** · Parallax · Page transition · **View transition**

- **Покадрово:** панель Animations показывает расхождение таймингов между свойствами
- **Реальные устройства** для жестов: подключить телефон, зайти на дев-сервер по IP, Safari remote devtools
- **Свежий взгляд на следующий день** - несовершенства, невидимые во время разработки, всплывают потом
