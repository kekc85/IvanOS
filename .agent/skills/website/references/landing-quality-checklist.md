# Мастер-чеклист качества лендинга (HARD GATE перед показом автору)

> Собран из ~50 кругов правок автора по лендингу воркшопа по решению автора. Задача: скилл выдаёт продукт СРАЗУ, без ручных правок. **Прогнать ВСЕ пункты перед каждым показом автору.** Любое НЕТ → чинить до показа, не выносить «на ревью».

## A. Позиционирование и копи
- [ ] **Правильное слово-позиционирование** (воркшоп / интенсив / марафон — что реально). Не подменять, не называть тем, чем не является.
- [ ] **Формулировки СОГЛАСОВАНЫ, а не схвачены** из разговорной речи автора. H1/нейминг/слоганы крафтить и предъявлять на согласование, не брать дословно сказанное в потоке как финал.
- [ ] **Ноль дублей** — одна мысль один раз. Подзаголовок ≠ чипы с тем же текстом; hero ≠ финал (два одинаковых таймера); надзаголовок ≠ H1.
- [ ] **Конкретика, не вода.** «Аппарат продаж»/«система» разворачивать в реальные части с цифрами/действиями.
- [ ] **Методология ЯСНАЯ** — пошагово, человеческим языком (как у Миллера, но понятно). НЕ абстрактные кубики без объяснения отличия.
- [ ] **Все ключевые смыслы запуска покрыты** — сверить по карте смыслов. Не потерять разделы (забыли контент-завод — автор поймал).
- [ ] **Боль обоснована данными** — лид-боль = #1 боль ЦА из опроса (цифры/цитаты), не догадка. Уметь аргументировать каждый смысловой блок.
- [ ] Публичная копи через **humaniser** (без AI-клише/рубки, em-dash только дефис).
- [] 🔴 **Запрещено выносить отдельное слово на отдельную строку** (правило humaniser, прецедент в даты запуска) — ни в заголовках, ни в плашках, ни в копи. Машинно ловит орфан-гейт (раздел F + `09-self-review.md`), но держать как смысловое правило копи тоже.

## B. Факты под именем автора (фабрикация = провал)
- [ ] **Реальные числа автора**, сверенные с ним. НЕ выдумывать учеников/подписчиков/кейсы. Нет реального кейса → не ставить.
- [ ] Доход/суммы публиковать ТОЛЬКО по явному решению автора (может менять решение; уважать последнее).
- [ ] Счётчики: если **дёргаются** при count-up — статика или tabular-nums. Лучше статика, чем jitter.

## B2. Оффер, тарифы, обещания 
- [ ] 🔴 **Один продаваемый тариф, остальные — якоря.** Decoy + якорь + целевой тариф = осознанная конструкция (как 79/89/99/199 у воркшопа: 99 = «выбор большинства», 79/89 = decoy, 199 = якорь). НЕ плодить тарифы ради числа.
- [ ] 🔴 **НЕ выдумывать тарифы, бонусы и «Fast-action»**, которых нет в оффер-каноне. Состав/цена — ТОЛЬКО из подтверждённого источника (`00b-blueprint.md` Блок E `offer-canon.md` / от автора). Нет в каноне → не ставим на страницу.
- [ ] 🔴 **НЕ обещать сроки продаж** («через 6 недель будут продажи», «окупишь первым запуском»). Контент-завод И ЕСТЬ трафик — это механика, не обещание результата к дате.
- [ ] 🔴 **НЕТ гарантий результата и возврата денег** («доведём до результата», «вернём вложенное», «гарантия 14 дней»). Канон формулировки: «достижимо при внедрении всех шагов, результат зависит от тебя (трафик/навыки/подписчики/отношения с аудиторией)». Рассрочка 0% и «налоговый вычет» (не «вычет 13%») — ок.

## B3. Запрещённые концепты и термины (канон контент-завод 2.0, прецедент в даты запуска)
- [ ] 🔴 **Запрещены в любом тексте сайта:** «1 смысл на 6 площадок / перелив на N площадок / переливается на площадки», «авто-сторис», «авто-карусели», нераскрытые аббревиатуры («OSM», «OSMK» и подобные служебные коды). Писать понятным человеческим языком.
- [ ] 🔴 **Канон названия машины контента = «контент-завод 2.0»**, не самодельные синонимы. `grep` страницы на `перелив|на 6 площад|авто-стори|авто-карусел|OSM` → пусто.

## C. Дизайн: анти-AI-slop (см. `effects-arsenal.md`)

- [ ] **Сломана «стопка секций»**: крупные editorial-номера (01/02/03), асимметрия, наложения за край, один доминант на секцию.
- [ ] **Нет чекбоксов ☐** как буллитов → сплошные галочки/иконки/номера.
- [ ] **Нет текстовых стрелок `→`/пунктира** как «процесса» → сплошные градиентные SVG-коннекторы.
- [ ] **VIP-тариф доминирует** (золотая рамка/подложка/scale).
- [ ] Не тёмная неонка, не агит-клон. Light-premium.

## D. Реализм визуалов (движок реализма)
- [ ] **Картинки генерим через БЕСПЛАТНЫЙ ChatGPT** (image_generation). **Higgsfield ЗАПРЕЩЁН** (платный). Автор сам может дропнуть картинку — вставить.
- [ ] Иллюстрации (мозг) — реальная картинка, НЕ сток-«AI brain» силуэт, НЕ плоский SVG-блоб.
- [ ] **Device-мокапы** с перспективой (`rotateY/X`), глубокой тенью, реальным контентом, мини-навбаром. Не flat-плейсхолдер.
- [ ] **Оплата** — реалистичный банковский/CloudPayments пуш, привязан к устройству, не парящий toast.
- [ ] Мокапы помечены как **«твоё»** (сайт/воронка участника), но БЕЗ дублей-ярлыков на каждом объекте.
- [ ] Мультяшные графики (нарисованные «−80%») → реалистично или убрать.
- [ ] 🔴 **НЕТ требований к железу на сайте** : запрещено писать «нужен Mac M2/M3», «N ГБ RAM», любые требования к компьютеру/ОС. Стек учится на чём есть, барьер входа не поднимаем. `grep` страницы на `M2|M3|RAM|оперативн|железо` → пусто.

## D2. Подвал, оферта, политика (юр-обязательно, прецедент в даты запуска)
- [ ] 🔴 **Подвал (footer) есть на КАЖДОМ лендинге** со ссылками на **оферту** и **политику конфиденциальности** (рабочие, не `#`). Без подвала с этими двумя документами лендинг не показываем и не деплоим — это юр-минимум сбора заявок (152-ФЗ/ЗоЗПП). Документы — через `Skill('yurist')`, не из головы.
- [ ] 🔴 **Без дублей ниш** в подвале/на странице: одно направление = один блок, не повторять ту же нишу разными словами в разных секциях.

## F. Мобилка + перформанс (MANDATORY — mobile-first, принуждается машинно)
> 🔴 автор: «самое важное — на мобилке грузиться максимально быстро, лучше чем на компе». Архитектура с фундамента (`workflow/00-brief.md` шаг 7), не «оптимизация в конце». Машинный пол `layout-audit.mjs` на 390 **блокирует показ** на перф-дефектах (как орфаны/контраст) — это не галочки на совесть.
- [ ] Рендер на **360/390/768/1280**. Absolute-композиции (hero) — чистый mobile-fallback (стек, перспектива off).
- [ ] **Render-blocking JS = НЕТ** — некритичный `<script>` с `defer`/`async`/`module`, не синхронный в `<head>` (машпол `render_blocking`).
- [ ] **Шрифты `font-display:swap`** на каждом `@font-face` И `&display=swap` в Google-Fonts (нет FOIT; машпол `font_display`). Веса/начертания урезаны, `preconnect`.
- [ ] **Картинки:** ниже сгиба `loading=lazy` (машпол `img_offscreen_eager`); LCP-герой `preload`+`fetchpriority=high` (НЕ lazy); `width`/`height`/`aspect-ratio` (CLS=0); `srcset`/`sizes`; webp/avif.
- [ ] **Вес/LCP в бюджете** — advisory `_perf{weight_kb,requests}`/`lcp_ms` разумны; тяжёлый ассет оправдан или заменён; один GSAP-тикер на Lenis.
- [ ] **Машпол чист на 390:** `node layout-audit.mjs <index.html> 390` → exit 0. Live-URL — Lighthouse mobile Performance ≥90.

## H. Процесс (как не плодить 50 кругов) — ГЛАВНОЕ
- [ ] **Self-review-ГЕЙТ ПЕРЕД КАЖДЫМ показом — обязателен и блокирующий** (`workflow/09-self-review.md`): свежий независимый критик-агент скринит живой рендер (390+1280, динамику — серией кадров) → балл по каждому экрану → **порог показа: каждый экран ≥8/10 И ноль FAIL** → чинить до порога → ТОЛЬКО потом показ. Это и есть механизм против 50 кругов.
- [ ] **НЕ спрашивать автора «это тот уровень / всё ли идеально?»** — на это отвечает гейт, не автор. Не идеально по гейту → чинить, не выносить.
- [ ] **Реестр открытых правок сверен** (`tasks/projects/<site>.md`): каждая инструкция автора закрыта (`[x]` + проверена в свежем рендере) или явно вынесена как развилка. Ноль потерянных правок («я же говорил эти правки, почему не внедрил»).
- [ ] **Показывать АКТУАЛЬНЫЙ рендер** (`open` свежего) — не старую версию.
- [ ] 🔴 **После ЛЮБОЙ правки HTML — визуальное скрин-ревью рендера на ≥2 ширинах (390 моб + 1280 десктоп) ДО показа автору** . Смотреть глазами на свежие скрины, не «отредактировал = готово». Это вход в гейт 09, без скринов гейт не стартует.
   - Деплой на свой хостинг (Netlify / Vercel / GitHub Pages / FTP). Если сайт уже в проде - правку публикуй на прод сразу, не отдавай localhost-ссылку: бэкап живого, заливка, проверка https (curl 200). Localhost - только пока сайта нет в проде
- [ ] 🔴 **Выполнять ВСЮ пачку правок за раз, не десятую часть.** В конце сверить чек-листом КАЖДУЮ правку из запроса автора (реестр правок 9.4) — закрыта/вынесена развилкой. Частичная отработка пачки = брак.
- [ ] **Удалять то, что велено удалить, СРАЗУ** (велено «удали и не делай, пока новую не сделаешь» → так и делать).
- [ ] **Не приходить с лишними вопросами** — «доведи до высочайшего уровня» = сам выведи, что нужно (картинки/скиллы/ассеты), и сделай; развилку из контекста решать самому. Согласовывать только реальные авторские развилки (нейминг, состав тарифов, фактура).
- [ ] **Каждый блок аргументирован данными ЦА** — на «почему этот экран?» ответ есть ДО показа.
- [ ] **Конец сессии → внести правки в скилл**.

## I. Деки / слайды-презентации (когда website собирает HTML-деку запуска/программы, прецедент в даты запуска)
> Применяется, когда страница = слайдовая дека (эфир/программа/продающая презентация), не классический лендинг. Прогнать ПОСЛЕ разделов A-H, по каждому слайду.
- [ ] 🔴 **Каждый слайд = ультра-реалистичная визуализация** (терминал, чат-бот, воронка, лендинг, экран оплаты, реальный UI), НЕ текстовый слайд без картинки и НЕ абстрактная плашка. Текстовый слайд = брак. Реализм по разделу D.
- [ ] 🔴 **На каждом слайде — законченная мысль + вывод «к чему это приведёт»** (что человек получит/что изменится), не голый факт без следствия.
- [ ] 🔴 **НИКАКОЙ технички/служебных меток в финальной деке:** «режим свёртки», «слот», «обложка дня», номера фаз, внутренние коды — вычистить полностью. `grep` деки на `свёртк|слот|обложка дня` → пусто.
- [ ] 🔴 **Модули продукта раскрывать в строгом порядке: модуль → уроки → дополнение → результат.** Каждую микрофишку — супердетально, не «модуль 1, модуль 2» абстракцией.
- [ ] **Эфиры/лайвы — по субботам** (не по пятницам), нигде не писать «пятница».
