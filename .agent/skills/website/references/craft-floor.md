## ЧАСТЬ 1. ПОЛ РЕМЕСЛА (проверять на СОБРАННОМ, не на намерении)

Bakaus: «Каждый пункт - проверка результата, а не намерения. Гнать их одним батчем в общем прогоне инспекции, а не отдельными походами за скриншотами: у них один рендер»

### 1.1 VERIFY - восемь замеров

| Ось | Порог |
|---|---|
| **Контраст** | body и placeholder ≥4.5:1, крупный текст ≥3:1. На цветной поверхности вторичный текст тонируется ИЗ её тона или из foreground - никогда серым |
| **Глубина** | у тени есть смещение и мягкое размытие. Цветное гало с нулевым смещением - это декор, не глубина |
| **Пространство** | тесные группы, щедрое разделение, НАД заголовком больше воздуха, чем ПОД ним. Читать вычисленные значения, не «на глаз» |
| **Тип** | мера строки 65-75ch, дисплей максимум 6rem, трекинг не туже -0.04em, заголовки сбалансированы, шаги шкалы и веса очевидны. Прогнать РЕАЛЬНУЮ копи на каждом брейкпоинте и починить, что вылезло |
| **Моушен** | ОДИН авторский момент, а не россыпь эффектов и не одинаковый вход на каждой секции. Экспоненциальный ease-out из УЖЕ ВИДИМОГО состояния. Палитра шире transform/opacity: blur, backdrop-filter, clip-path, mask, shadow - если держат плавность |
| **Состояния** | hover, disabled, loading, error, empty. Плюс реальный контент, рабочие контролы, адаптивная композиция, keyboard focus |
| **Копи** | язык самого продукта. Контрол называет своё действие; ошибка называет проблему И восстановление |
| **Покрытие** | каждое требование брифа присутствует и находится за секунды |

### 1.2 REFUSE - что не берём по умолчанию

Bakaus: «Это дефолты категории, а не запреты: слова самого брифа могут заработать любой из них. Потянуться к одному, когда ось свободна, значит ты не решал»

**Каркасы страницы:**
- Одинаковые карточки «иконка + заголовок + текст» как СТРУКТУРА страницы. Карточка - ленивый контейнер; вложенная карточка в карточку - всегда брак
- Шаблон «hero-метрика»: большое число, мелкая подпись, вспомогательная статистика, акцент
- **Кикер/eyebrow над заголовком. Это ЗАПРЕТ, а не дефолт: ни один бриф его не отыгрывает.** Заголовок несёт свой вес сам; удалить лейбл и дать заголовку говорить
- Номера секций (01 / 02 / 03), если сама последовательность не несёт нужную читателю информацию
- Модалка для задачи, которой не нужно ни прерывание, ни защищённый фокус

**Поверхностные привычки:**
- Градиентный текст. Акцент даётся весом или размером
- Стекло и блюр как декор, а не как конкретный эффект
- Цветной `border-left`/`border-right` толще 1px на карточках, элементах списка, callout, alert
- Жёсткая офсет-тень (`box-shadow: 4px 4px 0`) вне мира, который реально необрутализм
- Спарклайны, кольца прогресса, скруглённые прямоугольники с мягкой тенью вместо контента
- Моноширинный как костюм «технологичности», а не для кода, данных, измерений
- Системный дисплейный шрифт (Impact, Arial Black, платформенный sans) как голос страницы со своим миром. «Ближайший установленный» - провал, не запасной вариант
- Юникод-глифы и эмодзи вместо системы иконок. Иконки - нарисованные, из реальной библиотеки или авторский SVG, в одном штрихе и весе
- Светлая или тёмная тема, выбранная по категории. Выбирать из сцены использования: кто, где, при каком свете

## ЧАСТЬ 3. БАН-ЛИСТ И ЗАМКИ (Leonxlnx, taste-skill v2)

### 3.1 Дополнительные баны сверх 59

- Ярлыки версий в hero (`V0.6`, `INVITE-ONLY PREVIEW`, `BETA`) - только если бриф буквально про запуск продукта
- Подписи-фотокредиты как декор («Field study no. 12 · Ines Caetano») - только при реальной атрибуции
- Декоративные текст-полоски внизу hero («BRAND. MOTION. SPATIAL.»)
- Пилюли и лейблы, наложенные на картинки
- Футер с версией сборки (`v1.4.2`, `Build 0048`) на маркетинговой странице
- Полоски локали / города / времени / погоды («Lisbon, working with founders») - не нужны в 99% брифов
- Скролл-подсказки (`Scroll`, `↓ scroll`, `Scroll to explore`)
- Декоративные статус-точки - ноль по умолчанию
- `border-t` + `border-b` на КАЖДОЙ строке длинного списка - взять другой компонент
- Полосы прогресса с залитым треком как визуал сравнения
- Фейковый продуктовый UI из div-ов (поддельные таск-листы, дашборды, терминалы, собранные из стилизованных блоков)
- Плавающий подтекст в правом верхнем углу заголовка секции
- Самодельные SVG-иконки - брать Phosphor / HugeIcons / Radix / Tabler

### 3.2 Замки консистентности

- **Color Consistency Lock** - один акцент на всю страницу; никаких смен цвета в седьмой секции
- **Shape Consistency Lock** - одна система скруглений на страницу
- **Button Contrast Check** - каждый CTA проходит WCAG AA (никакого белого по белому)
- **Hero Discipline** - H1 ≤2 строк, подзаголовок ≤20 слов и ≤4 строк, CTA видны без скролла, шкала шрифта спланирована вместе с размером картинки
- **Navigation** - одна строка на десктопе, высота ≤80px
- **«Используют / Нам доверяют»** - логотипная стена ПОД hero, реальные SVG-логотипы (Simple Icons / devicon), не текстовые начертания
- **Section-Layout-Repetition Ban** - на 8 секций минимум 4 РАЗНЫХ семейства лейаута

## ЧАСТЬ 4. ПОРЯДОК ПРИМЕНЕНИЯ (важнее самих списков)

**Закон двух изолированных оценок (Bakaus, из `critique.md` и `layout.md`):**
> Дизайн-оценка ВСЕГДА завершается ДО того, как находки детектора попадают в контекст. Вывод детектора детерминирован, но он всё равно якорит суждение

Практически в нашем процессе:
1. Сначала зрительный проход по эталону жанра (Фаза 09 слой B) - без списка правил перед глазами
2. Потом механический прогон: `layout-audit.mjs` + сверка по 59 + бан-листу
3. Только потом синтез: где оба совпали, где детектор поймал упущенное зрением, где детектор дал ложное срабатывание (явно назвать ложные)

**Потолок полировки (Bakaus, `SKILL.md`):**
> Проверять ограниченными проходами, а не циклом. Собрать полностью, осмотреть одним батчем (десктоп и мобилка вместе), починить всё найденное одним батчем, подтвердить максимум одним повторным проходом - и прекратить полировку

Это совпадает с нашим «капом здравого смысла» в Шаге 9.3: два круга по одной причине = менять подход к экрану, а не крутить дальше.
