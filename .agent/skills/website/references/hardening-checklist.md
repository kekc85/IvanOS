# Hardening checklist — слой принуждения скилла website

> Источник: сквозной аудит 3 субагентами по решению автора (смысловые фазы / форма+ревью / хуки).
> Принцип-идеал: **каждое проверяемое правило машинно принуждается на чокпоинте и
> неподделываемо; непроверяемое (вкус/смысл) — судит независимый второй агент.**
> Эталонный паттерн принуждения: «хук САМ выполняет машинную проверку артефакта, а не
> читает агентский флаг `approved/score`» (введён орфан-фиксом v1.9, обобщён в v2.0).
>
> Регресс-гарантия: `python3 ~/.claude/skills/website/scripts/selftest.py` (28/28 на момент этой редакции).

## ⚠️ ACCEPTED RESIDUAL — намеренный обход своего же гейта (вне порога защиты)

Гейты защищают от СЛУЧАЙНОГО пропуска/самообмана под нагрузкой (реальная боль), но
агент, НАМЕРЕННО обходящий собственный контроль качества, может:

- **string-split** литералов (`'.web'+'site-state.json'`) → префильтр не матчит. Принято: обфускация ради обхода своего же QA — вне модели угроз.
- **ручной `http.server` + печать localhost-URL** вместо `show-screen.py` → show-гейт не на пути. Митигация: доки предписывают показ ТОЛЬКО через `show-screen.py`; ручной сервер для дизайн-стопа — discouraged (см. _phases-state). Полное закрытие — DEFERRED (гейт на `http.server` в папке проекта).
- **`touch dummy.png`** удовлетворяет freshness edit-гейта. Реальную проверку даёт орфан-скан (содержимое html), freshness — вторичный нудж.
- **показ через MCP `playwright browser_navigate`** — matcher хуков только Bash/Stop. DEFERRED (добавить matcher).
- **прямая правка `.website-state.json` через Edit/Write-tool** — обходит Bash-триггеры. DEFERRED.

Принцип: при «доведи до результата» НЕ обходить собственные гейты ручными путями —
это и есть «обман», против которого они стоят. Закрытие адверсариальных путей —
по мере появления реального прецедента, не упреждающе (иначе паранойя ломает рабочий поток).

## 🧱 ПОТОЛОК (почему «идеал = неулучшаемо» имеет точную границу)

Система принуждения может гарантировать ровно то, что **РАЗРЕШИМО машиной**. Это не отговорка — это определение потолка. Осталось ДВА класса, которые принципиально не закрываются ещё одним хуком:

1. **СУБЪЕКТИВНАЯ КОРРЕКТНОСТЬ (вкус/правда/премиальность).** Никакой гейт не докажет, что текст «хороший», дизайн «премиум», а число «истинно» (только что оно ТРАССИРУЕТСЯ к источнику — это уже сделано). Теоретический максимум механизма = «проверить всё проверяемое + ПРИНУДИТЬ независимого второго судью с уликами». Реализовано: машинный Слой 1 (перепрогон), балл из осей `criteria` (recompute min), копи-линт, обязательный независимый критик в `09-self-review.md`. Дальше — суждение, не вычисление. Утверждать, что машина гарантирует субъективную правоту, было бы ложью.

2. **НАМЕРЕННЫЙ САМО-ОБХОД своего же контроля** (string-split литералов, ручной http.server, touch png, показ через MCP-браузер, прямая правка state редактором). Агент исполняет команды — он всегда может скрафтить обход. Это лечится не гонкой хуков (бесконечной), а поведенческим законом: **при «доведи до результата» НЕ обходить собственные гейты ручными путями — это и есть обман, против которого они стоят**. Реалистичные обходы закрыты (триггеры по семантике, jq-fail-open, ручной сервер дискуражен); адверсариальные — по прецеденту, не упреждающей паранойей (иначе ломается рабочий поток — это было бы хуже, а не «идеальнее»).

**Итог:** всё машинно-разрешимое — закрыто и под selftest (40/40). «Опциональных» машинных пунктов НЕ осталось. Оставшееся — за границей вычислимости, и там стоит максимально возможный механизм (структурный артефакт + независимый судья). Это и есть идеал ДЛЯ СИСТЕМЫ ПРИНУЖДЕНИЯ.
