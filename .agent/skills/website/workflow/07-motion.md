# Фаза 7 — Анимации

**Вход:** собранный фронт из Фазы 6.
**Цель:** оживить интерфейс, не перегружая.

## Шаги
0. **Реализовать ЭФФЕКТ-СИГНАТУРУ концепта из Фазы 4 (Шаг 5b)** — те 2-3 фирменных эффекта, что выведены из метафоры. Не импровизировать заново и не копировать конкурента.
0.5 🔴 **ВКУС-ГЕЙТ `Skill('emil-design-eng')` ДО вызова движка (реальный вызов, улика в Evidence) + точные значения из `references/motion-standards.md`.** Каждую анимацию (сигнатуру И микроинтеракции) прогнать через рамку: **частота** (клавиатурные и 100+/день действия → анимации нет НИКОГДА, это дисквалификатор а не суждение; десятки раз в день → убрать или радикально уменьшить; иногда → стандарт; редко/впервые → бюджет на восторг) → **цель** (пространственная связь / индикация состояния / фидбэк / объяснение / убрать резкость — нет цели = декор = не анимируем) → **easing** (вход/выход `ease-out`, движение по экрану `ease-in-out`, hover `ease`, постоянное `linear`; 🔴 `ease-in` на UI — никогда, он оттягивает ровно тот момент, на который смотрят) → **длительность** (кнопка 100-160ms · тултип 125-200 · дропдаун 150-250 · модалка/шторка 200-500; UI держится под 300ms). Анимировать `transform`/`opacity`; blur/backdrop-filter/clip-path/mask только если плавность держится. Не прошло рамку → выбросить, а не «оставлю красиво».

0.6 🔴 **ДЕСЯТЬ НЕПРЕЛОЖНЫХ + ТРИГГЕРЫ ЭСКАЛАЦИИ (`references/motion-standards.md` §13).** Полный слой Kowalski, которого у нас не было. Флагать на месте: `transition: all` · `scale(0)` или чистый фейд без начального трансформа (🔴 стартовать с `scale(0.9-0.97)` + `opacity: 0` — в реальном мире ничто не появляется из ничего) · `ease-in` на UI · анимация на клавиатурном шорткате или командной палитре · длительность UI >300ms без причины · 🔴 `transform-origin: center` на поповере/дропдауне/тултипе, привязанном к триггеру (**модалки — исключение, они центрированы, это НЕ дефект**) · keyframes на тостах, тумблерах и всём часто триггеримом (**они рестартуют с нуля; transitions перенацеливаются на лету**) · анимация лейаут-свойств · шорткаты Framer Motion `x`/`y`/`scale` на занятой странице (**не аппаратно-ускорены, идут по главному потоку**) · обновление CSS-переменной на родителе ради трансформа ребёнка (recalc на всех детях) · отсутствие `prefers-reduced-motion` · негейченный `:hover` (тач даёт ложные hover при тапе — гейтить `@media (hover: hover) and (pointer: fine)`) · симметричный тайминг на press-and-release · появление всей группой там, где нужен стаггер **30-80ms**.

0.7 **Иерархия лечения — предпочитать ранние ходы поздним:** удалить → уменьшить → починить easing → починить origin и физичность → сделать прерываемой (`@starting-style` для входа без JS, springs для жестового) → увести на GPU (WAAPI для программного CSS) → асимметричный тайминг → полировка (блюр 2px для маскировки кроссфейда, стаггер, spring для «живых») → доступность и когезия. 🔴 **Когда сомневаешься, правильно ли ощущается движение, сильнейший ход — удалить его.**
1. Движки по типу эффекта (не только Framer): `motion` (Framer) — scroll-reveals/stagger/hover spring; `gsap` ScrollTrigger — parallax/scroll-linked/pin; `three`/Spline — canvas/WebGL-герой; `css-animations` — лёгкие keyframes/marquee; `lottie` — векторные сцены. Стек уже заложен в Фазе 6.
2. ОБЯЗАТЕЛЬНО `prefers-reduced-motion`. 🔴 **Уточнение (`motion-standards.md` §12): это меньше и мягче, а НЕ ноль.** Оставить переходы, помогающие понять (opacity, цвет), убрать перемещения. Глобальный `0.01ms`-килл, уничтожающий полезный фидбэк, — это дефект. Плюс два независимых сигнала, которых у нас не было: `prefers-reduced-transparency: reduce` (полупрозрачные поверхности делать плотнее, убирать блюр) и `prefers-contrast: more` (почти сплошные фоны с явной контрастной рамкой). Избегать полноэкранных движущихся фонов, медленных зацикленных колебаний около 0.2 Гц и резких скачков яркости при смене темы.
2b. **Если в концепте есть жест, драг или липкая полупрозрачная шапка — читать `motion-standards.md` §14 (физика Apple).** Там точные вещи, которые иначе выйдут «почти правильно»: отвечать на pointer-down а не на отпускание · трекинг 1:1 с уважением точки захвата (`setPointerCapture`) · анимировать от ПРЕЗЕНТАЦИОННОГО значения, не от целевого (иначе видимый прыжок на прерывании) · параметры пружин Apple (перемещение `damping 1.0 / response 0.4`, вращение `0.8/0.4`, шторка `0.8/0.3`; отскок только когда жест нёс инерцию) · передача скорости при отпускании · проекция инерции `current + (v/1000)·d/(1−d)` при `d ≈ 0.998` · резиновая граница вместо жёсткого стопа · вход и выход по ОДНОМУ пути · материалы (`backdrop-filter`, вес материала кодирует иерархию, никогда светлое полупрозрачное на светлом полупрозрачном, краевая градиент-маска вместо 1px-бордера под липкой шапкой).
3. Анимации лёгкие, перф-бюджет соблюдён, эффект служит концепту (а не декор).

## 🔴 ОБЯЗАТЕЛЬНО: анимации через скилл-движок, не «на глаз» (без улики фаза не закрыта)
Эффект-сигнатуру реализовать РЕАЛЬНЫМ вызовом движка-скилла (`Skill('motion')` / `gsap` / `three` / `css-animations` / `lottie`), а не накидать transition руками и выдать за результат. Нет улики вызова = фаза не пройдена (хук `skill-usage-honesty-check.sh`).
