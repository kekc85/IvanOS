# Конвейер фаз website — состояние, улики, чекпоинты (ЧИТАТЬ ПЕРВЫМ при запуске)

## ⚡ КАК РАБОТАЕТ ЭТОТ СКИЛЛ (прочитай ПЕРВЫМ, держи в голове всю дорогу)

Сайт = **фундамент (1 раз)** + **цикл по экранам (каждый экран — ПОЛНЫЙ прогон подфаз)** + **сборка**.

```
ЭТАП 1 — ФУНДАМЕНТ (ОДИН раз на весь сайт):
   Blueprint(00b: бренд-ДНК lock + факты-канон с source-tag) → бриф → интервью → референс-доска → структура (= СПИСОК ЭКРАНОВ) → общий визуальный язык

ЭТАП 2 — ЦИКЛ ПО ЭКРАНАМ ◀── ГЛАВНОЕ. Берёшь ОДИН экран и прогоняешь ВСЕ подфазы по порядку:
   ┌─────────────────────────────────────────────────────────────────────────┐
   │ РЕСЁРЧ(10 эталонов блока, сам) → концепция ✋ → копи ✋ → дизайн ✋ →       │
   │ → сборка(сам) → 3 слоя проверки(сам) → готовый экран ✋                   │
   └─────────────────────────────────────────────────────────────────────────┘
   🔴 РЕСЁРЧ — ПЕРВАЯ подфаза КАЖДОГО экрана, не пропускать. 10 эталонов ИМЕННО
   этого блока (скрины+манифест в `refs/<экран>/`) ДО концепции. Трекер показывает
   его отдельной строкой ⬜/⏳/✅; «эталоны нет» при статусе ≥concept = проскок.
   ✋ = СТОП: показать автору, ждать «ок». Без «ок» к следующей подфазе НЕ идёшь.
   Закрыл экран №1 → берёшь №2 → ТОТ ЖЕ полный набор подфаз → №3 → … → №N.

ЭТАП 3 — СБОРКА: все готовые экраны → один сайт → Фаза 10 макро-ревью (сайт как СИСТЕМА, 7 осей) → деплой
```

🔴 **ВСЕ подфазы для КАЖДОГО экрана. Не часть. Не все экраны разом. По одному экрану, целиком.**

**Частые вопросы (на них агент путался — вот прямые ответы):**
- «С чего начинается экран?» → **с РЕСЁРЧА: 10 эталонов именно этого блока (скрины+манифест), ПОТОМ концепция.** Не наоборот. Трекер держит это первой строкой экрана.
- «Прогонять для каждого экрана ВСЕ подфазы или только некоторые?» → **ВСЕ, по порядку, для каждого экрана.**
- «Это цикл по каждому экрану?» → **ДА. Каждый экран = отдельный полный прогон подфаз. 1, 2, 3, … N.**
- «Можно собрать сразу весь сайт?» → **НЕТ. Экран за экраном, каждый со СТОПами-согласованиями.**
- «Что согласовывать, а что делать самому?» → ✋ **согласуешь**: концепцию, копи, дизайн, готовый экран. **Сам, молча**: сборку кода + 3 слоя проверки (это качество, не вкус).
- «`/website screen <имя>` — что будет?» → проведёт ОДИН этот экран по полному циклу подфаз (фундамент ЭТАПА 1 должен быть готов).

Ниже — тот же процесс детально. Схема выше = краткая карта, детали её не отменяют.

## 🔴🔴 КОНТРАКТ ВЫВОДА: КАЖДЫЙ ответ по сайту = ДВА ЛАГЕРЯ (автор, 3-й раз)

> Зачем. Все улики живут на диске (`.website-state.json`), а **автор диска не видит — работает с телефона**. Поэтому в чате агент схлопывал фазы, мутил «готово/собрал», и поймать его в реальном времени было нечем. Лечение автора: каждый ответ показывает, на какой мы фазе, сколько сделано/нет — и эта сводка **генерится ИЗ ДИСКА, а не из слов агента** (цифры подделать нельзя). Это и есть инструмент проверки «не врёшь ли ты».

**Любой ответ, пока активен скилл website, состоит из ДВУХ лагерей по порядку:**

1. **СЛОЙ 1 — РАБОТА.** То, что мы сейчас обсуждаем/делаем по текущей подфазе (концепция / копи / дизайн / вопрос автору / показ экрана). Обычное содержание ответа.
2. **СЛОЙ 2 — ТРЕКЕР ФАЗ.** В самом конце ответа — блок-чек-лист под ЭТОТ сайт/экран: где мы по фазам, что ✅ / ⏳ / ⬜, какой экран текущий, чего ✋ жду от автора. **НЕ печатать руками — генерить машиной:**

```bash
# <DIR> = папка проекта (где .website-state.json). Сначала запиши улику текущей
# подфазы helper'ом, ПОТОМ рендери трекер — иначе он покажет старое состояние.
python3 ~/.claude/skills/website/scripts/phase-tracker.py "<DIR>"
```
Вывод скрипта (начинается с `━━━ ТРЕКЕР ФАЗ (website) ━━━`) вставить в конец ответа **дословно**.

**Почему именно машиной:** трекер читает `status`/`approvals`/`score` из блокнота. Если я не записал улику подфазы — трекер честно покажет, что её нет. Соврать «мы на дизайне», стоя на концепции, физически нельзя — диск скажет правду. <твой-продукт> 2 = детектор схлопывания фаз.

**Гарантия (хук `website-tracker-gate.sh`, Stop):** если website-проект активен (рядом свежий `.website-state.json`), а в ответе нет маркера `ТРЕКЕР ФАЗ` → завершение ответа блокируется (exit 2) с напоминанием прогнать скрипт. Тест 5/5 (happy/negative/edge). Safe-fail: нет активного проекта → не трогает.

**Порядок каждого хода:** сделал работу подфазы → записал улику helper'ом → прогнал `phase-tracker.py` → ответ = <твой-продукт> 1 (работа) + <твой-продукт> 2 (вывод трекера). Так на каждом шаге видно, где мы и сколько прошли — без этого ход не завершён.

Прецедент по решению автора: скилл — длинный документ, который агент читал разом и сворачивал в один прыжок к финалу, проскакивая ресёрч/структуру (флагман собрал из головы → не та эстетика, «удивился» реальному эталону). Лечение: скилл идёт **по подфазам, по очереди**, каждая подфаза = маленький чанк + **улика на диске** + (для смысловых) **показ автору и согласование**. Машина (хук) проверяет улики — не верит на слово.

## 🔴 ДВЕ СТАДИИ + блокнот экранов (автор — главная модель скилла)

Скилл — **один**, но работает на ДВУХ уровнях, и сам понимает, на каком он, из блокнота `.website-state.json` (не из своей памяти — это и лечит «прыжок к финалу»). Аналогия: одна бригада, один проект — сначала фундамент на весь дом, потом отделка по одной комнате.

- **СТАДИЯ A — САЙТ (один раз):** фазы **00b→3** (🔴 **Blueprint** = lock бренд-ДНК + факты-канон с source-tag · бриф · интервью · reference · структура=карта экранов) + единый визуальный язык 4→5 (визуал-направление · токены → `Design.md`). Фундамент, общий для всех экранов. **Стадия A начинается с 00b, НЕ с брифа** — бренд-ДНК (палитра/шрифт/мотивы из РЕАЛЬНОГО билда `grep :root`) и факты-канон (доход/ученики/кейсы/статус с source-tag) лочатся первыми, чтобы дальше визуал и копи их не выдумывали заново. Выход = `Design.md` (с запертой ДНК) + факты-канон + **массив `screens[]`** в блокноте (карта экранов из 3a). Сюда же — site-level review единого языка.
- **СТАДИЯ B — ЭКРАН (цикл, по одному; КАЖДЫЙ экран = отдельный мини-проход с согласованием подфаз):** для каждого экрана из `screens[]` микроцикл **concept → copy → design → build → review** со СТОП-показами автору на смысловых подфазах (концепция · копи · дизайн ✋), а сборка + 3 слоя проверки — сам. 🔴 НЕЛЬЗЯ собрать и показать финал экрана, не согласовав концепцию/копи/дизайн — хук блокирует показ экрана без них в `approvals`. Формализация Закона 0.
- **СТАДИЯ C — СБОРКА САЙТА (финал):** все экраны `done` → собрать в `index.html` → **Фаза 10 — МАКРО-РЕВЬЮ САЙТА КАК СИСТЕМЫ** (`workflow/10-site-review.md`): сайт = воронка, а не сумма экранов. Customer Journey Map → машинный пол (journey-map-audit + check-deploy) → 4 адверсариальных судьи по 7 осям (one_big_idea/awareness_ladder/information_scent/persuasion_sequencing/conversion_physics/editorial_cut/canvas_continuity — `references/macro-rubric.md`) pairwise против сайта-эталона того же типа → таксономия REMOVE/ADD/REORDER/CONNECT до сходимости (7 осей ≥9 + регрессия экранов 09 цела) → 08 деплой. 🔴 Это МЕЖэкранная согласованность (горизонтальная ось) — НЕ дублирует 09 (вертикальная, per-screen). Гейт показа/деплоя сайта требует `.site-review.json` и сам перегоняет машинный пол.

**Два входа (скилл выбирает сам по блокноту, автор не выбирает «какой скилл»):**
- `/website` (без аргумента): блокнот пуст или СТАДИЯ A не завершена → иду СТАДИЮ A. СТАДИЯ A готова, есть `pending`-экраны → продолжаю СТАДИЮ B со следующего `pending`. Все экраны `done` → СТАДИЯ C.
- `/website screen <имя>` / «доработай экран X»: заходит ТОЛЬКО в микроцикл одного экрана. **Требует, что СТАДИЯ A завершена** (есть `Design.md` + `screens[]`) — иначе нет фундамента, отправляю на СТАДИЮ A. Это и есть «прогнать скилл на один экран отдельно».

**Структура блокнота `.website-state.json` (расширение, обратносовместимо):**
```json
{
  "stage": "site|screens|assembly|done",
  "phases": { "0_brief": {...}, "2b_reference": {...}, "3a_structure": {...}, "5_tokens": {...} },
  "screens": [
    {"name": "hero", "role": "захват+оффер", "status": "pending|concept|copy|design|build|review|done", "score": null, "approvals": []}
  ],
  "site_review": { "score_min": 0, "layout_audit": false, "cross_screen": false }
}
```
- `screens[]` пишется в конце фазы 3a (карта экранов из согласованной структуры), статусы крутит СТАДИЯ B.
- 🔴 **Микроцикл экрана = СТОП-показ автору на КАЖДОЙ смысловой подфазе (автор — исправление: скилл прыгал сразу к финалу, ничего не согласовав).** По порядку, НЕ двигаясь дальше без апрува текущей: `pending` → **РЕСЁРЧ** (10 эталонов блока, скрины+манифест `refs/<экран>/` — сам, ПЕРВЫМ, ДО концепции) → **`concept`** (раскладка экрана элемент→функция→пруф — ✋ СТОП, согласовать) → **`copy`** (копи + humaniser — ✋ СТОП) → **`design`** (визуал на языке СТАДИИ A — ✋ СТОП) → `build` (сборка — сам) → `review` (3 слоя ≥9 — сам, молча) → `done` (✋ показ готового экрана). Каждый ✋-СТОП пишет согласование в `approvals` (helper ниже). Слоями проверки автора НЕ дёргать.
- 🔴 **Что согласую vs делаю сам (исправление дефолта по решению автора):** ✋ согласую — концепция · копи · дизайн КАЖДОГО экрана + готовый экран. Сам, молча — сборка кода + 3 слоя (layout-audit + регрессия + критик до ≥9).
- 🔴 **Референсы — ПОД КАЖДЫЙ ЭКРАН свои (автор):** общая доска жанра 2b даёт стартовую планку (ЭТАП 1, один раз), НО на подфазе `concept` каждого экрана я отдельно собираю эталоны ИМЕННО этого типа блока (hero / тарифы / кейсы / FAQ-финал / value-stack…) — живые скрины, как этот блок решают у топов — и согласую их В СОСТАВЕ показа концепции (отдельного показа не добавляют, остаётся 4 показа). Улика — `refs/<screen>/*.png`.

## Закон конвейера (перекрывает «сделать сайт за один проход»)

Не верстать экран N+1, пока N не прошёл бенчмарк+доводку и не показан. ⚠️ **ДО сборки идут ✋-стопы концепция→копи→дизайн с апрувом автора (см. микроцикл экрана выше, строки 29-30). Луп крутится до СХОДИМОСТИ (0 красных машины И 100% рубрики И линзы ≥9), человек апрувит ЭКРАН, не микроправки.

## Модель показа (что показываю автору, что гоняю молча)
Источник — согласовано с автором. Машина проверяет проверяемое (молча), человек судит вкус/смысл (показ).
- **Молчаливый стоп + хук (НЕ показываю автору):** 2a семена · 2c синтез-черновик · 5 токены · 6 сборка · 7 анимации · 09 балл критика. Гарантия — улика на диске, не моё слово.
- **✋ ПОКАЗ автору + согласование (~6 касаний на сайт):** 0 бриф · **2b референс-скрины** (`open`, гляну глазами) · 3a структура · 3b копи · 4 визуал-направление · финал (после критика 09). Это места, где судья — только автор (вкус/позиционирование/голос), и где агент исторически дрейфовал.
- 🔴 **СТАДИЯ B добавляет НА КАЖДЫЙ экран 4 показа (✋): concept (раскладка) · copy · design · готовый экран.** Это НЕ «один hero + дальше сам» — каждый экран ведётся по подфазам с согласованием. Слои review (машина+критик) в показы НЕ входят — молча.
- Между показами НЕ дёргать автора «продолжать?» (Правило №1). Стоп = либо хук-улика молча, либо один из 6 смысловых показов.
- 🔴 **Любой показ ЖИВОГО РЕНДЕРА автору (превью Фазы 4 ИЛИ финал Фазы 09) проходит БЕНЧМАРК ПРОТИВ ЭТАЛОНА** (`references/benchmark-standard.md` + Шаг 9.2b): независимый судья мерит ДЕЛЬТУ до именованных best-practice образцов, не «улучшения на вкус агента». Без бенчмарка рендер не показывать .

## Helper — карта экранов (конец 3a) и статус экрана (СТАДИЯ B)
```bash
# Записать карту экранов из согласованной структуры 3a (один раз):
python3 - "<DIR>" '<SCREENS_JSON>' <<'PY'
import json,sys,os
d,arr=sys.argv[1],json.loads(sys.argv[2])
p=os.path.join(os.path.expanduser(d),'.website-state.json')
st=json.load(open(p)) if os.path.exists(p) else {"phases":{}}
st["screens"]=[{"name":s["name"],"role":s.get("role",""),"status":"pending","score":None} for s in arr]

json.dump(st,open(p,'w'),ensure_ascii=False,indent=2); print("OK screens",len(st["screens"]))
PY
# пример: '<DIR>' '[{"name":"hero","role":"захват+оффер"},{"name":"pricing","role":"тарифы"}]'

# Обновить статус/балл/согласование одного экрана (микроцикл СТАДИИ B).
# 5-й арг (опц.) = подфаза-согласование concept|copy|design -> пишется в approvals
# (ставить ТОЛЬКО после реального показа этой подфазы автору и его «ок»).
python3 - "<DIR>" '<NAME>' '<STATUS>' '<SCORE_or_null>' '<APPROVE_or_empty>' <<'PY'
import json,sys,os
a=sys.argv
d,name,status,score=a[1],a[2],a[3],a[4]
approve=a[5] if len(a)>5 else ""
p=os.path.join(os.path.expanduser(d),'.website-state.json')
st=json.load(open(p))
for s in st.get("screens",[]):
    if s["name"]==name:
        s["status"]=status
        if score!="null": s["score"]=int(score)
        if approve:
            s.setdefault("approvals",[])
            if approve not in s["approvals"]: s["approvals"].append(approve)
json.dump(st,open(p,'w'),ensure_ascii=False,indent=2); print("OK",name,status,score,approve)
PY
# примеры: '<DIR>' 'hero' 'concept' 'null' 'concept'   (согласовал концепцию)
#          '<DIR>' 'hero' 'done' '9'                   (закрыл экран)
```
🔴 **Хук `website-research-gate.sh` гейтит САМ этот helper:** перевод экрана в любой статус выше `pending` (concept/copy/design/build/review/done) без валидного `refs/<name>/_manifest.json` → BLOCK. Ресёрч принуждается ПЕРЕД концепцией, а не только перед показом (тест 7/7 по решению автора, safe-fail на неоднозначном парсинге).

Каждый экран в СТАДИИ B рендерится как `screen-<name>.png` (или `.html`) рядом с `.website-state.json`. Хук пускает показ экрана ТОЛЬКО если `status∈{review,done}`, `score≥9`, в `approvals` есть concept+copy+design (смысл согласован с автором ДО сборки) **И есть валидный per-screen манифест референсов** `refs/<name>/_manifest.json` (10 понятых эталонов этого блока ИЛИ честный shortfall — `scripts/validate-refs.py --block <name>` → PASS; см. `04b-screen-strategy.md`).

> 🔴 **PER-SCREEN РЕСЁРЧ (ПЕРВАЯ подфаза экрана, ДО `concept`; автор).** На КАЖДЫЙ экран — 10 эталонов ИМЕННО этого блока (hero/тарифы/кейсы/FAQ-финал…), живые скрины в `refs/<name>/*.png` + `refs/<name>/_manifest.json` {block, target:10, exemplars[{url,screenshot,why_works,niche_relevant}]}. Засчитываются ТОЛЬКО понятые релевантные (валидатор); недобор → честный `shortfall {found,reason,searched≥4}`, не мусор. 🔴 **ДВА хука принуждают ресёрч:** (1) `website-research-gate.sh` (PreToolUse) — блокирует САМ helper статуса экрана: продвинуть экран в `concept`/`copy`/…/`done` без валидного `refs/<экран>/_manifest.json` НЕЛЬЗЯ (ресёрч обязан быть ДО концепции); (2) `website-review-gate.sh` — блокирует показ готового экрана без него. 🔴 **Трекер выводит ресёрч ОТДЕЛЬНОЙ ВИДИМОЙ ФАЗОЙ экрана** (⬜/⏳/✅ «refs N/10 / SHORTFALL / нет»), первой строкой подфаз — НЕ хвостом-индикатором. Статус экрана ≥`concept`, а ресёрч ⬜ → трекер в строке «СЕЙЧАС» кричит «⚠️ РЕСЁРЧ НЕ СОБРАН … ДО концепции; не пропускать» (автор: «ты часто пропускаешь экран с ресёрчем и обманываешь»).

## 🔴 Носитель показа автору = localhost-URL (через `show-screen.py`), НЕ file-ссылка/`open`/PNG

File-ссылки (`[текст](путь)`), PNG-ссылки и `open` — НЕ кликаются / не то. (Прежняя запись «кликается только файл-ссылка, localhost не срабатывает» оказалась НЕВЕРНОЙ — отменена. Это совпадает с памятью `feedback_website_show_in_browser_not_preview`: живой localhost, сервер из папки проекта на чистом порту.) Показ идёт командой:

Скрипт сам гейтит (status/score/approvals для экрана; все-done + self-review для сайта), **сам поднимает `http.server` из папки проекта на чистом детерминированном порту (8900-8979) и печатает кликабельный `http://localhost:PORT/...` URL** — вставить его ДОСЛОВНО в чат, автор тыкает и видит живой рендер. `open`/file-ссылка — легаси, не использовать. 🔴 **Показ ЖИВОГО РЕНДЕРА — ТОЛЬКО через `show-screen.py`** (он гейтит и его перепроверяет `website-review-gate.sh`, который сам прогоняет layout-audit). ## Что блокирует хук (показ автору = `show-screen.py` ИЛИ legacy `open`)
Хук `website-review-gate.sh` гейтит ОБА носителя показа одинаково и различает ДВА показа:
- **Показ ОДНОГО экрана** (`open screen-<name>.png|html` рядом с блокнотом): BLOCK, если экрана нет в `screens[]` · `status∉{review,done}` · `score<9` · в `approvals` нет всех из {concept,copy,design} (концепцию/копи/дизайн не согласовал с автором ДО сборки) · **нет `refs/<name>/_manifest.json` ИЛИ per-screen референсы не дотягивают (валидатор `validate-refs.py --block <name>` → <10 квалифицированных эталонов и нет честного `shortfall`)**. Всё ДА → показ проходит. (СТАДИЯ B.)
- **Показ САЙТА-финала** (`open index.html` / preview рядом; на Windows `start ""` / на Linux `xdg-open` / универсально `~/.claude/skills/_shared/bin/open-file`): BLOCK, если нет `.website-state.json` · `2b_reference.approved≠true` · board-папка пуста/нет · `3a_structure.approved≠true` · нет `.self-review.json` · маркер старше `index.html` · `score_min<9` · нет `layout_audit`. Если есть `screens[]` — дополнительно требует, что ВСЕ экраны `done` (СТАДИЯ C не показывается с недоделанными экранами). Всё ДА → показ проходит.
Гарантия: «не проскочил ресёрч/структуру, не показываю непроверенный экран и не показываю сайт с недоделанными экранами». Safe-fail: не смог определить тип показа → exit 0.

**Второй хук — `website-edit-review-gate.sh` (Stop, Закон 5).** Ловит дыру первого: агент правит `*.html` и отчитывается словами/координатами БЕЗ `open` → первый хук (на `open`) не срабатывает. Этот на завершении ответа проверяет по transcript: правил ли html сайта в ЭТОЙ сессии, и есть ли в той папке свежий скрин (mtime > mtime html). Нет → BLOCK (exit 2): «сделай визуальное ревью глазами перед показом». Scope — только html этой сессии (чужие/параллельные билды не трогает). Safe-fail: нет transcript → exit 0.
