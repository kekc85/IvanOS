# Фаза 9 — SELF-REVIEW ГЕЙТ (обязателен ПЕРЕД КАЖДЫМ показом автору)

> 🔴 ГЛАВНЫЙ механизм против 50 кругов правок. Источник: лендинг воркшопа по решению автора — агент показывал сырьё и спрашивал «это тот уровень?», автор ловил очевидное (реплики «ноль из десяти», «сам посмотри и пойми в чём проблема», «я спросил все ли идеально — иди улучшай, хватит с вопросами»). Корень: правила в скилле были, но их никто не ПРИНУЖДАЛ применить до показа.

**Этот гейт работает НЕ один раз в конце. Он прогоняется ПЕРЕД ЛЮБЫМ показом автору** — первый показ, каждая итерация после правок, финал. Нет «вынесу на ревью полусырое». Сначала сам довёл до порога — потом показал.

## 🔴 ПО КАЖДОМУ ЭКРАНУ, и ПОРЯДОК: бенчмарк → доводка → показ (автор)
Сайт собирается экран за экраном (`06-build.md` закон поэкранной сборки). Гейт 09 — часть микро-цикла КАЖДОГО экрана, не только финала. Жёсткий порядок для каждого экрана:
1. **Сначала БЕНЧМАРК (Шаг 9.2b) — ДО review-доводки и ДО показа автору.** Мерим дельту экрана до ДВУХ слоёв эталона (`benchmark-standard.md`): Слой 1 (вкус/ремесло — флагман/Linear/Stripe/Awwwards) И Слой 2 (нишево-рыночный — реальные работающие образцы нашего типа лендинга: конкуренты-курсы для флагмана / марафонные образцы для марафона). Цель — мочь ДОКАЗАТЬ цитатой+баллом, что экран не хуже того, что уже конвертит в нише.
2. **Потом доводка до идеала** — закрыть ВСЕ разрывы из бенчмарка сам (Шаг 9.3), пересъёмка, пока каждый критерий **≥9** (порог ужесточён по решению автора, см. `benchmark-standard.md` шкала+порог; «до 9 не пропускать»). Asset-blocked критерий → довести контролируемое до ≥9 + вынести ассет-зависимость автору, не финализировать.
3. **Только потом показ экрана автору** — с уликой: балл по обоим слоям + против каких образцов мерил + что закрыл.
Показ экрана без пройденного бенчмарка обоих слоёв = брак (то же, что показ финала без гейта).

## 🔴🔴 ФИЛОСОФИЯ REVIEW: ПОЛНОТА через зрение+эталон, а НЕ конечный список классов
Прецедент по решению автора (автор): «review должен ловить ВСЕ классы дефектов, а не конкретный. Я не должен пополнять библиотеку классов правками — это ручная херня. У тебя есть эталон, бестпрактис и компьютерное зрение — отсматривай всё сам». Корень прошлого провала: review опирался на КОНЕЧНЫЙ список («наложение/прилипание/…») и ловил только перечисленное; всё вне списка проскакивало, и автор был вынужден дописывать классы вручную. **Эта модель ЗАПРЕЩЕНА.** Правильная модель — ДВА слоя, оба про ПОЛНОТУ:

- **Слой A — ДЕТЕРМИНИРОВАННЫЙ ПОЛ (машина, Шаг 9.0).** Меряемое (геометрия) НИКОГДА не должно проскочить, даже если глаз промигал: наложения, прилипания секций, вылет за вьюпорт, обрезка. Скрипт `scripts/layout-audit.mjs`, ноль терпимости. Это ПОЛ, не потолок и не главное.
- **Слой B — ПОЛНЫЙ ЗРИТЕЛЬНЫЙ REVIEW (главное).** У свежего критика-агента ЕСТЬ зрение и эталон → он обязан поймать ЛЮБОЕ отклонение от премиум-планки, а не пункты из списка. Установка: «эталон рядом, билд рядом — пройди КАЖДЫЙ экран, КАЖДЫЙ стык между экранами и КАЖДУЮ ширину (390/1024/1280) по полной таксономии-линзам И СВЕРХ неё: если ХОТЬ ЧТО-ТО смотрится не так, как в эталоне / как сделала бы топ-студия — это дефект, флагай, даже если он не назван». Таксономия — карта систематического охвата (чтобы не пропустить по невнимательности), а НЕ ограничитель: премиум-стандарт = «ничего не криво», а не «N галочек».

🔴 **Появился дефект, которого review не поймал → это НЕ повод дописать класс. Это провал ПОЛНОТЫ слоя B** (критик не дожал зрительный проход / не сверился с эталоном попиксельно / пропустил ширину или стык). Чинится строгостью прохода, а не расширением списка. Автор НИКОГДА не должен быть «пополнятелем библиотеки».

## Шаг 9.0 — ДЕТЕРМИНИРОВАННЫЙ ПОЛ (машинный аудит макета, ДО критика)
Запустить ПЕРВЫМ, на моб+промежуточной+десктоп:
```bash
node ~/.claude/skills/website/scripts/layout-audit.mjs <index.html> 360,768,1024,1280
```
Детерминированно ловит (ширины МЕЖДУ брейкпоинтами 360/768/1024/1280, не 3 точки): `section_sticking` (отступ между секциями < порога = прилипли), `text_overlaps` (стикер/абсолют перекрывает текст), `viewport_overflow` (вылет за край / обрезка на узком), `content_clipped` (контент шире контейнера), **`container_overflow`** (ГЕНЕРИК: контент вылез за СВОЙ стилизованный бокс — буква за плашку/чип/кнопку/карточку, при ЛЮБОМ overflow-режиме), **`axe_violations`** (контраст ≥4.5:1 + a11y), **`touch_targets`** (кликабельное < 24×24px, WCAG 2.2 SC 2.5.8), **`image_dims`** (картинка без width/height/aspect-ratio → reflow/CLS), **`cls`** (layout-shift ВО ВРЕМЕНИ за окно загрузки, порог ≤0.1 — закрывает ВРЕМЕННУ́Ю ось: шрифт/картинка/контент догрузились → прыжок). 🔴 **ПЕРФ-ПОЛ (mobile-first скорость загрузки, автор; мерится ТОЛЬКО на мобильной ширине ≤480):** `render_blocking` (синхронный `<script src>` в `<head>` без defer/async — тормозит первый рендер), `font_display` (веб-шрифт / Google-Fonts без `font-display:swap` → FOIT, текст-невидимка на медленной сети), `img_offscreen_eager` (картинка заведомо ниже сгиба без `loading=lazy` — качает впустую), `weight_over_budget` (вес моб-страницы сверх `--weight-budget`, если задан) + advisory-метрики `_perf{weight_kb,requests,dom_nodes}` и `lcp_ms`. «На мобилке грузиться максимально быстро» — машинный гейт, не пожелание. **exit 1 при любом дефекте → показ заблокирован, чинить до нуля.**

> 🔴 **Урок по решению автора (почему добавлен `container_overflow`):** на лендинге марафона буква «О» слова «наставничество» торчала за `float-badge` — самый базовый, частый класс дефекта. Старый аудит ПРОПУСКАЛ: `content_clipped` смотрел только заголовки И только при `overflow≠visible`, а «текст торчит наружу» — это ИМЕННО `overflow:visible`+`scrollWidth>clientWidth`. Логика была вывернута. Новый детектор generic ПО ПРИНЦИПУ (любой визуально-замкнутый компонент, `scrollW/H>clientW/H`), а не по списку частных случаев — закрывает класс целиком. Завтра текст вылезет за кнопку/чип/тариф → поймает та же проверка, без правки автором.

🔴 **ЗАКОН ДВУХ ИЗОЛИРОВАННЫХ ОЦЕНОК (Bakaus, `references/ux-critique-rubric.md` §0) — уточняет порядок Шага 9.0 против Шага 9.2.** Обе оценки обязательны, обе идут ИЗОЛИРОВАННЫМИ субагентами, и **дизайн-оценка обязана ЗАВЕРШИТЬСЯ до того, как находки детектора попадут в контекст синтеза**: вывод машины детерминирован, но он всё равно якорит суждение. Практически: критик слоя B получает вывод Шага 9.0 **после** того, как сдал свой независимый зрительный проход, а не вместо него. Если субагентов нет и пришлось гнать в одном контексте — **первая строка отчёта обязана нести баннер `⚠️ DEGRADED: single-context (<причина>)`. Молчаливо деградировавшая критика = проваленная критика.** Пропущенный машинный прогон = проваленный гейт (кроме случая, когда скрипт реально отсутствует или падает после настоящей попытки). Синтез — это НЕ конкатенация: явно отметить, где зрение и машина совпали, где машина поймала упущенное зрением, и **где машина дала ложное срабатывание** (ложные называть вслух).

Не заменяет слой B — гарантирует, что меряемое не проскочит. Вывод аудита передаётся критику слоя B на вход (чтобы он не тратил зрение на померенное и шёл глубже). Аудит — живой инструмент: новые ДЕТЕРМИНИРОВАННЫЕ проверки добавляются в скрипт по мере находок, но недетерминированное (вкус/смысл/«дёшево смотрится») остаётся за слоем B, не за скриптом.

## 🔴🔴 МОДЕЛЬ ПО ИНДУСТРИИ (2024-2026): 3-слойная пирамида + луп сходимости
Не изобретаем — берём проверенный промышленный паттерн авто visual-QA (ресёрч по решению автора, источники внизу). Ни один слой «всё» не ловит поодиночке; полнота = сборка слоёв + ДВЕ ОРТОГОНАЛЬНЫЕ ОСИ ОХВАТА.

- **Слой 1 — МАШИНА ловит ВСЁ ИЗМЕРИМОЕ** (детерминированно, без человека, без зрения): overflow/обрезка КОНТЕНТА (вылет за вьюпорт — декор с `pointer-events:none`, напр. aurora, НЕ флагать), overlap/коллизии (пересечение `getBoundingClientRect`, стикер закрывает текст), прилипание секций (gap<порога, дедуп обёрток по DOM-containment), **контраст+a11y через `@axe-core/playwright`** (≥4.5:1 — ~57% a11y, ноль false-positive), **токены через design-lint**. Скрипт `scripts/layout-audit.mjs` (Шаг 9.0). 🔴 **Текст-орфаны = БЛОКИРУЮЩИЙ (автор, ~50 нарушений за 2 дня → абсолютное правило, машинно).** `orphan_candidates` теперь hard-гейт: одно слово на отдельной строке заголовка/плашки запрещено. Редкий намеренный случай (имя, акцент-композиция) выводится из-под детектора ЯВНО — связкой `&nbsp;` последних слов ИЛИ классом `allow-orphan`/`data-br-ok`, не «машина догадается». **`website-review-gate.sh` на показе САМ перепрогоняет `layout-audit.mjs` — самоотчёт `layout_audit:true` не принимается** (раньше гейт верил маркеру → орфаны лезли десятками; теперь машина проверяет рендер). Фикс: `text-wrap:balance` заголовку / `text-wrap:pretty` абзацу / `&nbsp;` последних слов / `max-width` / переразбить `<br>`. См.. 🔴 **Чип/тег-орфан = БЛОКИРУЮЩИЙ** (`flexitem_orphan`): flex-wrap/grid, где последний ряд = 1 элемент при остальных ≥2. Намерения нет — одинокий чип всегда брак, поэтому hard-гейт (в отличие от текст-орфана). Скоуп: ≥4 однотипных чипа <60% ширины контейнера → ноль false-positive на сбалансированной сетке. **Исчерпывающе по детерминированным классам — зрение тут НЕ нужно и менее надёжно** (модели слабы в spatial 50-60%). Гейт «нельзя пройти с красным».
- **Слой 2 — ВИЗУАЛЬНАЯ РЕГРЕССИЯ против reference-эталона** (полнота по построению): сравнить экран с эталоном жанра в режиме **Layout/Strict match-level** (структура+иерархия, игнор плейсхолдер-контента и динамики). Ловит ЛЮБОЕ отклонение от эталона, не завися от перечня классов. Технически — pixelmatch с порогом+ignore-регионы (или match-level-дифф). Прямо усиливает.
- **Слой 3 — VISION-LLM по ЗАКРЫТОЙ РУБРИКЕ, pairwise, с грундингом** (вкусовое, что машина не берёт). Метод — прямой перенос arxiv 2412.16829 + 2510.08783:
  - **Рубрика ОБЯЗАТЕЛЬНА и фиксирована** (не «оцени дизайн») = 11 линз ниже. По КАЖДОЙ — явно «ок / нарушено», не молчание.
  - **PAIRWISE против эталона**, не абсолютная оценка: «что предпочёл бы человек — наш экран или эталон, по этому критерию» (там модель 90%+; абсолютная — хуже).
  - **Грундинг ОБЯЗАТЕЛЕН**: каждый дефект = **bounding box (координаты) + конкретная правка**. Нет bbox → дефект не засчитан (защита от «вообще плохо»-галлюцинаций).
  - **Multi-pass (2-3 прохода)**: модель уточняет и текст, и боксы (метод даёт −50% разрыва с человеком).
  - **Регион-by-регион**: дробить экран на зоны (hero/заголовок/CTA/соцпруф) — это ВТОРАЯ ось полноты, перпендикулярная рубрике.

🔴 **ПОЛНОТА = две оси: РУБРИКА (что искать, 11 линз) × РЕГИОНЫ (где искать, зоны экрана) × ШИРИНЫ (390/1024/1280).** Пропуск = явная дыра в матрице покрытия, а не молчание. Это и есть «закрытая проверка покрытия» вместо «открытой генерации списка» — поэтому новый класс не требует правки автора.

## 🔴 ЛУП СХОДИМОСТИ (минимум человека — он апрувит ЭКРАН, не каждую микроправку)
```
на КАЖДЫЙ экран:
  render(390,1024,1280) → Слой1(машина) → fix → render → повтор ДО НУЛЯ красных
                        → Слой2(регрессия vs эталон) → собрать диффы
                        → Слой3(vision: рубрика×регионы, pairwise, bbox+правки) → собрать критику
  объединить правки L2+L3 → агент применяет САМ → re-render
  повтор, ПОКА: 0 красных в L1  И  100% рубрики «ок»  И  L2-дифф<порог  И  все линзы ≥9
  СТОП по СХОДИМОСТИ (по критерию), не по числу итераций. Эмпирика: агент, который ВИДИТ/МЕРЯЕТ результат, сходится за 2-3 итерации вместо 10+.
```
Человек подключается ОДИН раз в конце экрана (паттерн Playwright Healer / Eyes), а не на каждую правку. Цель — автор не тратит время на ручные микро-указания.

**Источники (ресёрч по решению автора):** arxiv [2412.16829](https://arxiv.org/abs/2412.16829) (iterative design critique + bbox), [2510.08783](https://arxiv.org/html/2510.08783v1) (MLLM-as-Judge, 9-факторная рубрика, pairwise 90%+), [Applitools match-levels+RCA](https://applitools.com/docs/eyes/concepts/best-practices/match-levels), [axe-core](https://www.deque.com/axe/axe-core/), [Playwright Test Agents/Healer](https://playwright.dev/docs/test-agents), [design-lint](https://lapidist.net/articles/2025/introducing-lapidist-design-lint/), [Playwright MCP feedback loop](https://luca-becker.me/blog/level-up-agentic-coding-mcp-2-playwright/), [Nielsen 10 heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/).

## Закон гейта

ЗАПРЕЩЕНО показывать автору рендер, который не прошёл этот гейт. ЗАПРЕЩЕНО спрашивать автора «это высочайший уровень / всё ли идеально?» — на этот вопрос отвечает гейт, а не автор. Если по гейту НЕ идеально → чинить до идеала, потом показывать готовое. Автор согласовывает РАЗВИЛКИ (нейминг, состав тарифов, фактура), а не отлавливает брак, который агент обязан поймать сам.

## Шаг 9.1 — Снять живой рендер (улика, не на словах)

1. Открыть АКТУАЛЬНЫЙ файл (не кэш сессии): `open` + Playwright/headless скриншоты.
2. Снять **каждый экран** на **двух ширинах: 390 (моб) и 1280 (десктоп)**. Динамику (живой герой, scroll-reveal) — несколько кадров скролла, не один статичный.
3. Эти скриншоты — вход для критика. Без свежих скринов гейт не стартует (иначе оцениваешь воображаемое).

## 🔴🔴 Шаг 9.1b — ПОКОМПОНЕНТНЫЙ ЗУМ (обязателен; ось «компонент» ⟂ оси «экран»)
Прецедент по решению автора (автор, резкая эскалация): буква торчала за плашкой, а review её не поймал, потому что **критик смотрел НАРЕЗКУ всей страницы в пониженном разрешении** — на ней мелкий компонент (плашка 214px) нечитаем, пиксельный выступ невидим. Урок: **полностраничные/нарезанные скрины НЕ ловят микро-дефекты мелких элементов. Нужны ДВЕ ОРТОГОНАЛЬНЫЕ оси, ОБЕ обязательны:**

- **Ось «ЦЕЛОЕ»** — холистический проход всей страницы/стыков (композиция, ритм, иерархия) — это Шаг 9.2.
- **Ось «КОМПОНЕНТ»** — КАЖДЫЙ мелкий стилизованный элемент снять ОТДЕЛЬНЫМ кропом в ПОЛНОМ разрешении (DPR≥2, кроп вплотную к элементу) и осмотреть вплотную: **плашки/стикеры/бейджи/чипы/пилюли/кнопки/CTA/блоки цены/мокап-подписи/таймеры**. На этом кропе проверять: текст НЕ выходит за бокс ни на пиксель (все 4 стороны с воздухом-паддингом), нет орфана/кривого переноса, иконка+текст выровнены, скругление целое, тень не обрезана.
- 🔴 **ЗАКОН «тронул → зум»: ЛЮБОЙ компонент, который агент менял в этой сессии (текст/размер/позицию/стиль), ОБЯЗАН быть зум-реверифицирован отдельным кропом ПОСЛЕ правки.** Нельзя «починить снаружи» (зазор до соседа) и не проверить «внутри» (свой текст в своём боксе). Именно этот пропуск дал баг по решению автора.
- Машинный `container_overflow` (Шаг 9.0) — детерминированный дубль этой же проверки: он ловит выход за бокс измеримо, зум — глазами на вкус/перенос/выравнивание. Оба обязательны, не «или».

🔴 **Полнота review = РУБРИКА (что) × РЕГИОНЫ-экраны (где макро) × КОМПОНЕНТЫ (где микро) × ШИРИНЫ (390/1024/1280).** Пропуск любой оси = дыра покрытия. «Прошёл по экранам, но не зумил компоненты» = review НЕ сделан.

## Шаг 9.2 — Независимый критик-агент (НЕ тот, кто собирал)

Запустить субагента-арт-директора со скринами всех экранов **И с покомпонентными зум-кропами (Шаг 9.1b — плашки/чипы/кнопки/цена/таймеры в полном разрешении)** **И с референс-доской жанра (папка `refs/` из Фазы 2b + `references/flagship-style-reference.md`)**. Без покомпонентных кропов критик слеп к микро-дефектам (буква за плашкой) — на нарезке всей страницы они невидимы. Промпт-установка: **«Ты придирчивый арт-директор уровня Awwwards. Вот РЕФЕРЕНСЫ ЖАНРА (планка), вот наш билд. Цель — НАЙТИ, почему билд НЕ дотягивает до планки жанра и выглядит как сделано нейросетью. Презумпция: брак есть, найди его. По каждому экрану — балл и конкретные дефекты с координатами.»** (агрессивная цель против AI-подхалима — см. CLAUDE.md «презумпция AI-подхалим»).

🔴 **Критик ОБЯЗАН работать методом Слоя 3 (см. «МОДЕЛЬ ПО ИНДУСТРИИ» выше), иначе review невалиден:** (1) **pairwise против эталона** по каждому критерию, не абсолютная оценка «на вкус»; (2) проход по матрице **11 линз × регионы экрана (hero/заголовок/CTA/соцпруф/...) × ширины 390/1024/1280** — по каждой ячейке явно «ок / нарушено»; (3) **каждый дефект = bounding box (координаты) + конкретная правка** — балл без bbox невалиден; (4) **2-3 прохода** (iterative refinement); (5) на вход критику — вывод машинного аудита Шага 9.0 (чтобы не дублировать померенное и идти в вкусовое глубже). ≥2 судьи с разными линзами, свести по ХУДШЕМУ баллу.

## 🔴 ПОЛНАЯ ТАКСОНОМИЯ-ЛИНЗЫ слоя B (карта охвата — к КАЖДОМУ экрану, КАЖДОМУ стыку, на 390/1024/1280)
Это не «12 галочек», а карта, чтобы зрительный проход НИЧЕГО не пропустил по невнимательности. По каждой линзе критик ищет отклонения от ЭТАЛОНА, даёт балл 1-10 и координаты дефекта. Порог по каждой ≥9.

1. **Пространство и ритм** — единые отступы; ничего не прилипает/не зажато; секции разделены воздухом; поля сбалансированы; **стыки между экранами дышат** (не липнут).
2. **Сетка и выравнивание** — на сетке; края выровнены; нет съезда на пиксели; оптическое выравнивание.
3. **Наложения и коллизии** — ничто не закрывает текст/контент; стикеры в safe-zone; нет случайных перекрытий; **нет «прилепленного» декора (волна/дуга/блоб/линия), которого не должно быть** и который выглядит случайным.
4. **Иерархия и фокус** — ясная иерархия; один фокус на экран; сканируется за 3 сек.
5. **Типографика** — шкала, межстрочное, **НЕТ орфанов/висячих слов**, нет рек/дыр, единый шрифт, читаемые кегли, **нет кривых переносов**.
6. **Цвет и контраст** — WCAG; единая палитра; не мутно/не пёстро; дисциплина акцента; не «иишная» темнота/градиент-каша.
7. **Реализм и ассеты** — мокапы как реальные UI (НЕ вайрфрейм/плейсхолдер/плоский цветной блок), глубина+тени+реальный контент; нет стоков-клише («AI brain»/flat-SVG-блоб); устройство с перспективой; оплата = реалистичный пуш; без дублей-ярлыков.
8. **Консистентность + анти-slop pre-flight** — токены едины по ВСЕМ экранам; повторяющийся компонент = идентичный; один паттерн — один вид; видно применение frontend-design/ui-ux-pro-max/21st/motion/**design-taste-frontend** вглубь, не «на глаз». 🔴 **Анти-slop pre-flight `design-taste-frontend`** (срез по чек-листу): один акцент-цвет / одна система радиусов / одна тема на весь сайт; нет AI-tells (purple/mesh-blob-градиент, секция-нумерация-eyebrow, три одинаковые карточки подряд, scroll-cue, фейк-числа, дубль-CTA); hero ≤2 строки H1 + CTA без скролла; асимметрия вместо зигзага. 🔴 **Моушен по `emil-design-eng` + `references/motion-standards.md` §13:** каждая анимация с целью (не декор), длительности в норме (кнопки 100-160ms / крупное 200-500ms, UI под 300ms), только `transform`/`opacity`, есть `prefers-reduced-motion` (мягче, а не ноль). Плюс триггеры эскалации: нет `transition: all` · нет `scale(0)` · нет `ease-in` на UI · поповеры от триггера, не от центра (модалки — исключение) · нет keyframes на часто триггеримом · hover-моушен за `@media (hover: hover) and (pointer: fine)` · один авторский момент, а не одинаковый вход на каждой секции.
🔴 **Пол ремесла и детектор слопа (`references/craft-floor.md`):** прогнать VERIFY-восьмёрку по собранному + REFUSE-список + 59 правил + замки консистентности (один акцент / одна система скруглений / hero-дисциплина / навигация ≤80px / ≥4 семейства лейаута на 8 секций). Отдельно проверить то, что раньше проскакивало: **вложенных карточек нет** · **кикера над заголовком нет нигде** · над заголовком воздуха больше, чем под ним · функциональный текст не мельче 11px · нет серого текста на цветном фоне · нет фейкового продуктового UI из div-ов · иконки из реальной библиотеки, не самодельный SVG и не эмодзи.
9. **Адаптив + перф (mobile-first)** — чисто на 390/1024/1280; ничего не обрезано/не вылазит/не зажато на узком; логичный стек; absolute-композиции имеют чистый mobile-fallback; стикеры внутри. 🔴 **Скорость загрузки на мобиле** (автор): критический путь лёгкий (нет render-blocking JS), шрифты `font-display:swap` (нет FOIT), картинки ниже сгиба `lazy` / LCP-герой `preload`, вес в бюджете, «грузится мгновенно». Машинный пол `layout-audit.mjs` на 390 блокирует HARD-перф-дефекты; критик оценивает ось `mobile_perf` на вкус/бюджет.
10. **Крафт и полировка** — единые тени/радиусы/границы; нет грубых краёв; сломана «стопка секций» (editorial/асимметрия); нет чекбоксов-буллитов и текстовых стрелок `→`; премиум-ощущение «зафичерили бы на Awwwards».
11. **Содержание и смысл** (равноценно визуалу — см. Контур СМЫСЛА выше) — регистр копи верный, позиционирование = то, чем объект реально является, без плейсхолдер-текста и дублей, конкретика не вода, каждый блок до источника, факты реальны.

Премиум = ничего не криво, а не «галочки проставлены».

## Шаг 9.5 — Что показать автору (готовый результат + улика)

В показе: свежие скрины (моб+десктоп) · итог критик-гейта (балл по экранам, что чинил) · что закрыто из реестра правок · открытые РАЗВИЛКИ (только реальные авторские) одной строкой. Не «оцени уровень» — а «вот результат на пороге N/10, развилки такие-то».

## Anti-patterns фазы

- Показ сырья + вопрос «это тот уровень?» вместо самостоятельного доведения до порога.
- Оценка по памяти/воображению без свежих скринов живого рендера.
- Критик = тот же контекст, что собирал (защищает своё решение). Критик ОБЯЗАН быть свежим субагентом с агрессивной целью «найди брак».
- Потеря правки между кругами (нет сверки реестра 9.4).
- Бесконечные мелкие правки одного экрана вместо смены подхода.

## Выход

Рендер на пороге ≥8/10 по каждому экрану, ноль FAIL, реестр правок сверен → ТОЛЬКО тогда показ автору.
