# Фаза 8 — Запуск и проверка

**Вход:** анимированный фронт из Фазы 7.
**Цель:** живой сайт по ссылке с рабочим целевым действием.

## Шаги
1. Локальный запуск, проверка на реальных размерах (mobile-first, ключевые брейкпоинты).
2. Деплой:
   - Vercel для простого статичного/SSR фронта.
   - Свой хостинг по правилам: НЕ смешивать проекты на одном VPS; для РФ-хостинга проверять IP через check-host.net (роутинг).
   - Правило «один сайт для всего контента» — встраивать в основной сайт, если это раздел, а не отдельный домен.
   - Деплой на свой хостинг (Netlify / Vercel / GitHub Pages / FTP). Если сайт уже в проде - правку публикуй на прод сразу, не отдавай localhost-ссылку: бэкап живого, заливка, проверка https (curl 200). Localhost - только пока сайта нет в проде
   - 🔴 **Подвал с офертой и политикой конфиденциальности обязателен на лендинге ДО деплоя** (юр-минимум сбора заявок). Нет рабочих ссылок на оба документа → не деплоить.
3. 🔴 **Финальная проверка целевого действия — МАШИННО, обязательно** (: зелёный health ≠ рабочий путь):
   ```bash
   python3 ~/.claude/skills/website/scripts/check-deploy.py <DIR>/index.html --target "<целевой шаг из брифа Фазы 0>" [--url https://<домен>]
   ```
   Ловит мёртвый CTA (`#`/пусто/js:void) и CTA мимо target → exit 3 = чинить, не «готово». При живом URL — 200-чек; RU-доступность отдельно через check-host.net (гео РФ). НЕ заявлять «работает» без зелёного check-deploy + реального клика по пути оплаты/формы.
4. 🔴 **Финальная МОБАЙЛ-ПЕРФ проверка — обязательно** (автор: «на мобилке грузиться максимально быстро»):
   ```bash
   node ~/.claude/skills/website/scripts/layout-audit.mjs <DIR>/index.html 390   # exit 0 = перф-пол чист
   ```
   exit 1 = render-blocking JS / FOIT-шрифт / offscreen-img без lazy / вес сверх бюджета → чинить ДО деплоя. Advisory `_perf{weight_kb,requests}`/`lcp_ms` — глянуть, что вес и LCP разумны. На ЖИВОМ URL дополнительно прогнать Lighthouse mobile (PWA/Performance) — целевой Performance ≥90 на мобиле; узкое место (тяжёлый ассет/шрифт/скрипт) — устранить. «Грузится быстро на телефоне» — критерий готовности, наравне с рабочим CTA.
5. Показ готового сайта эксперту — ТОЛЬКО `show-screen.py <DIR>/index.html` (не `open`; гейт перепроверит цепочку+рендер+копи+перф).

## Выход
Живой сайт по ссылке + рабочая конверсия. Обновить статусы фаз в `tasks/projects/<site>.md`.
