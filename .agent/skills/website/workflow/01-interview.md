# Фаза 1 — Интервью и сбор сырья

**Вход:** бриф из Фазы 0.
**Цель:** собрать реальный материал. Запрет выдумывать факты — только из `.business/` или от эксперта. Нет данных → спросить, не сочинять.

## Что вытащить
- Продукт: что именно, как работает, что получает клиент
- Боли и желания ЦА — реальными формулировками (язык аудитории)
- Факты-доказательства: цифры, кейсы, результаты (только реальные)
- Дифференциация: чем отличаемся от конкурентов
- Возражения, которые надо закрыть на странице

## Как
- Сначала вычитать `.business/audience/objections.md`, `journey.md`, `products/`.
- Чего нет в `.business/` — задать эксперту прямые вопросы списком.
- Каждый факт помечать источником (откуда взят). Нет источника → это не факт, а гипотеза для вопроса эксперту, не для страницы.
- **Запрет переноса с другого объекта.** Кейс/цифра/суждение из контент-досье, прогревов или чужого продукта не становятся фактом про ЭТОТ продукт без подтверждения. Не заявлять непроверенное под видом данных.

## 🔴 SOURCE-TAG на КАЖДОЕ claim-число / факт (риск-факты под именем эксперта)
Каждое claim-число и публичный факт об авторе (доход, число учеников/клиентов, кейсы, результаты, статус/лидерство) помечать source-tag — одним из трёх:
- `[подтверждено экспертом]` — эксперт явно подтвердил (Blueprint факты-канон 00b или прямой ответ в интервью);
- `[внешний пруф]` — есть внешнее доказательство (скриншот Stripe/кабинета, публичный кейс, ссылка);
- `[.business-черновик]` — взято из `.business`, эксперт ещё НЕ подтвердил = ГИПОТЕЗА, не факт.

🔴 **Риск-факт со статусом `[.business-черновик]` (не `[подтверждено экспертом]` и не `[внешний пруф]`) → в раздел `promises_to_prove_later`, НЕ на страницу.** На публичную копи идут ТОЛЬКО `[подтверждено экспертом]` / `[внешний пруф]`. `.business` — источник истины для СТРУКТУРЫ/оффера, но для риск-цифр = черновик-гипотеза (см. `00-brief.md`, `00b-blueprint.md` факты-канон). Прецедент: «<громкая цифра> / №1 в нише» из `.business` оказались ложью на лендинге.

## Выход
Банк реального материала: факты / цитаты / цифры / возражения, **каждый с source-tag** `[подтверждено экспертом | внешний пруф | .business-черновик]`. Это сырьё для структуры и копи. Отдельным разделом — `promises_to_prove_later`: риск-факты со статусом `[.business-черновик]`, которые НЕ идут на страницу до подтверждения экспертом/внешним пруфом.
