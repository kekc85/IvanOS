# Фаза 3 — Структура и контент (3a концепция → микро-гейт → 3b копи)

**Вход:** бриф (с **типом сайта и регистром копи**) + сырьё + reference-паттерны.
**Цель:** спроектировать смысл сайта ДО дизайна И до копи. Разнесена на два шага с микро-гейтом между ними — чтобы не перескочить с концепции сразу в готовый текст (документированная первопричина брака: герой контент-хаба пишется как продуктовый лендинг). Концепция дешева в правке, копи — дорога.

## 3a — Концепция и раскладка экрана (БЕЗ единого слова копи)
═══════════════════════════════════════════════

**Цель:** автор видит и подтверждает КОНЦЕПЦИЮ и РАСКЛАДКУ ЭКРАНА раньше, чем написана хоть строка текста.

### Шаги
1. **Job сайта в одну строку:** «сайт нужен, чтобы [целевое действие] у [ЦА]». Один сайт = одно действие (из брифа).
2. **Sitemap:** для лендинга = порядок секций; для многостраничника = страницы. MECE: страницы не пересекаются, покрывают всё, ничего лишнего (lessons: не плодить страницы, не дублировать секции, тонкие смыслы — якорем).
3. **Раскладка экрана:** по каждой секции/странице зафиксировать ТОЛЬКО:
   - ОДНА задача секции (job) — одним предложением
   - нарратив (что человек понимает/чувствует здесь)
   - тип соц.доказательства (если есть)
   - целевое действие/CTA секции
   - **🔴 обоснование секции данными** — одна строка: почему этот экран вообще есть и почему именно здесь, со ссылкой на источник (боль/желание #N из опроса ЦА / `objections.md` / JTBD / карта смыслов). Прецедент по решению автора: «проходил курсы, а денег нет» вывели на 2-й экран — автор: «ты так и не объяснил, ПОЧЕМУ вывел, аргументировать надо». **Не можешь обосновать блок данными ЦА → блок не ставим** (догадка под именем автора = брак). На любой вопрос автора «почему этот экран?» ответ обязан существовать ДО показа.
   - **НИКАКОГО текста-копи. Только назначение.**
4. **Сверка регистра с типом сайта** (из брифа Шаг 1): концепция секций обязана соответствовать регистру. Контент-хаб = секции про контент/личность и подписку, НЕ про продажу продукта. Появилось «продай продукт» на хабе → стоп, это перескок регистра.

## 3b — Копирайтинг (ТОЛЬКО после микро-гейта)
═══════════════════════════════════════════════

> 🔴 **3b — это ДВИЖОК плотной копи ПО БЛОКАМ, а не «накидать тексты».** Прецедент по решению автора: взял канон-формулировки как финал, выдал тонкие абстракции («аппарат продаж» без раскрытия), сайт вышел «бета-черновик» против «мясного» Миллера. Канон 5.0 = СЕМЯ заголовка, не готовое тело. Копи не накидывается — ДОБЫВАЕТСЯ и РАЗВОРАЧИВАЕТСЯ до бенчмарк-плотности конкурентов.

### Шаг 0 — Пайплайн источников смысла (откуда берём, зафиксировать)
Каждый смысл копи происходит из цепочки добычи, не из головы: **JTBD / опрос базы / ДМ / `audience/objections.md` → Belief Map → Карта смыслов → Подтверждённые формулировки (канон) + ДЕТАЛЬНЫЕ артефакты (архитектура/программа/value stack)**. Для запуска автора это `5.1/5.2/5.0/5.3` + `Архитектура-марафона.md` (там дни расписаны конкретно — тащить ОТТУДА, не обобщать). Канон = заголовок-семя; деталь и мясо — из детальных артефактов + опроса.

### Шаг 1 — Бенчмарк плотности (ПАРАЛЛЕЛЬНЫЕ агенты по конкурентам)
ДО написания: запустить пачку параллельных агентов — на каждого ключевого конкурента того же типа (из Фазы 2) агент вытаскивает ДОСЛОВНУЮ копи по блокам и меряет ПЛОТНОСТЬ: сколько конкретик на блок, какие приёмы (перечисление / контраст «было→стало» / лестница масштаба / named-инструменты / числа / живой исход / раскрытый механизм). Прецедент-эталон плотности: Миллер `example-etalon.ru` (каждый блок = стек конкретик + раскрытый механизм «Второй мозг» + лестница ×1/×10/×100). Выход: целевая плотность и набор приёмов на КАЖДЫЙ наш блок.

### Шаг 2 — Развёртка ПО БЛОКАМ (под-фаза на каждый экран, детально)
Идти по экранам раскладки 3a по очереди. Для КАЖДОГО блока зафиксировать и наполнить:
- **job блока + ОДИН смысл** (из 3a),
- **источник смысла** (из Шага 0 — конкретная цитата/факт/артефакт),
- **целевая плотность** (из Шага 1 — бенчмарк),
- **развернуть в СТЕК конкретики:** named-инструменты, числа, сроки, before→after, осязаемый результат — НЕ абстракция. «Аппарат продаж» → раскрыть из чего и что человек реально унесёт по дням.
- **приём блока** (зеркало / контраст / лестница / risk-reversal / раскрытый механизм).
«Для кого» = реально НАЗВАТЬ сегменты ЦА (тебе сюда / не сюда), а не положить только боль.
3. **Mastery перед финалом (по `mastery/PROTOCOL.md`).** Копи лендинга = публичный продающий артефакт → consult mastery СООБЩЕНИЯ (не визуала): `copywriting` (заголовки/оффер), `positioning` (отстройка/onlyness в H1), `persuasion-psychology` + `offer-design` (структура убеждения). Inventory авторов → Select с обоснованием → Apply → **Evidence Report** (метод→цитата из копи) → независимый верификатор-скептик. Это «сообщение» (в отличие от Фазы 4, где визуал) — mastery живёт ЗДЕСЬ.
4. **Регистр-чек перед humaniser:** перечитать копи против типа сайта. Контент-хаб → герой = обещание контента/личности + подписка, НЕ «купи/собери продукт». Несовпадение = переписать, не маскировать.
5. **🔴 Чек оффера и обещаний :** (а) **один продаваемый тариф, остальные якоря**; **НЕ выдумывать тарифы/бонусы/«Fast-action»**, которых нет в оффер-каноне (`00b` Блок E) — нет в каноне → не на страницу; (б) **НЕ обещать сроки продаж** («через 6 недель продажи», «окупит первым запуском») и **НЕ давать гарантий результата/возврата денег** — канон «достижимо при внедрении всех шагов, результат зависит от тебя», рассрочка 0% и «налоговый вычет» ок; контент-завод = трафик-механика, не обещание.
6. **🔴 Чек запрещённых концептов/терминов :** вычистить «1 смысл на 6 площадок / перелив на N площадок», «авто-сторис», «авто-карусели», нераскрытые аббревиатуры (OSM/OSMK) — писать понятным языком; канон машины контента = «контент-завод 2.0».
7. **🔴 НЕ выносить отдельное слово на отдельную строку** в копи (правило humaniser); требования к железу (Mac M2/M3, RAM) на сайте запрещены.
8. **Публичная копи ОБЯЗАТЕЛЬНО через `Skill('humaniser', ...)`** — без рубки предложений, без AI-клише, без em-dash.

### Уроки (см. references/lessons-learned.md)
- Не плодить страницы под каждую услугу — группировать по смыслу (Янтарный: 5 страниц услуг → одна `/uslugi`).
- Проверить секции на смысловой дубль (были «Почему Джанхот» + «Что вокруг» — одно и то же).
- Тонкие смыслы (концепция) встраивать якорем в существующую страницу, не плодить отдельную.
- MECE-чистка IA обязательна перед гейтом.
