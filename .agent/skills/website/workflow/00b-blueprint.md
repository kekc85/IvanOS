# Фаза 0 — Blueprint (интейк-канон контекста)

**Вход:** запрос на сайт (раньше любого брифа).
**Цель:** УБИТЬ угадывание контекста — главный корень кругов правок. Один файл-канон `blueprint.md`, из которого строятся все экраны. Всё, что эксперт держит в голове (бренд-ДНК, голос, реальные факты, оффер, ЦА), собирается здесь ОДИН раз и запирается. Дальше скилл строит ТОЛЬКО из канона, никогда из догадки.

> **Порядок в скилле:** `00b-blueprint` → `00-brief` → `01-interview` → … Blueprint предшествует брифу: бриф отвечает «зачем сайт», Blueprint отвечает «из какого реального материала», и без запертого канона бриф угадывает.

---

## 🔴 Закон фазы: нет контекста → СПРОСИ, не выдумывай

Любое поле канона имеет ровно три исхода:
1. **Есть в файле** → подтянуть, показать эксперту, зафиксировать с пометкой источника.
2. **Нет/неполно в файле** → задать встроенный вопрос (промпты ниже), довести до ИЗБЫТОЧНОГО уровня, зафиксировать со словом эксперта.
3. **Эксперт не знает / нечем подтвердить (риск-факт)** → НЕ на страницу. Поле помечается `status: pending` и едет в блок «обещания, требующие доказательства позже». Выдумать, округлить, поставить плейсхолдер в финал — ЗАПРЕЩЕНО. Лучше один точный вопрос, чем фальшивый claim под именем эксперта.

«Избыточный уровень» = собрать БОЛЬШЕ, чем «идеально-достаточно». Лишний реальный факт переживёт фазу в архиве; недостающий факт стоит круга правок.

---

## Логика «pull-from-files → then interview» (по каждому блоку)

Для каждого блока канона агент идёт строго по шагам:

```
1. PULL  — Read путей из config.md (paths.*) + grep живого билда (если задан). Реальные файлы, не кэш сессии. 
2. SHOW  — показать эксперту в чат что подтянулось (что/откуда/одной строкой инсайт). Невидимое = несделанное.
3. GAP   — отметить чего НЕ хватает до избыточного уровня (нет файла / скелет project-starter / устарело / риск-факт без пруфа).
4. ASK   — задать встроенные вопросы блока ТОЛЬКО по дырам (не переспрашивать то, что уже в файле).
5. LOCK  — записать в blueprint.md с source-tag по каждому полю.
```

**Детект пустоты `.business` (обязательно ДО pull):** если пути из `config.md` указывают на отсутствующие файлы ИЛИ на скелет `project-starter` (заглушки/TODO/пустые секции) — это типичный ученик без контекста. Тогда Blueprint переходит в режим **принудительного онбординга**: ведёт эксперта интервью по всем блокам с нуля, а не молча читает несуществующие файлы и не делает вид, что контекст есть.

---

## ⚠️ Перенастройка источника истины для ЦИФР и публичных claims

Дефолт скилла «`.business` = source of truth» (00-brief / SKILL.md) НЕ распространяется на **риск-факты**: доход/выручка, число учеников/клиентов, кейсы и named-результаты, статус/лидерство/регалии, цитаты-отзывы, дифференциация («единственный / первый / №1 / работал с брендами»). Для них `.business` = **гипотеза-черновик**, не истина — внутренние файлы содержат завышенные/незаверенные claims.

Каждый риск-факт получает `source: [подтверждено-экспертом | внешний-пруф | .business-черновик]`. Статус `.business-черновик` для риск-факта **недостаточен** для попадания на публичную страницу — нужно подтверждение эксперта или внешний пруф. Машинный пол (`copy-lint`): claim-число со ссылкой только на `.business-черновик` → BLOCK с требованием подтверждения.

## Встроенные промпты (агент задаёт их САМ — по дырам после PULL)

> Задавать блоками, не вываливать всё разом. Внутри блока — нумерованным списком, чтобы эксперт отвечал по пунктам. Сначала показать что уже подтянулось, спрашивать только недостающее.

### Блок A — Бренд-ДНК (единственный источник цвета/шрифта)

**PULL сначала:**
- Есть одобренный билд эксперта? → снять токены: `grep -oE '\-\-[a-z0-9-]+:[^;]+' <build>/index.html | sort -u` + шрифты из `<head>` (`<link>`/`@font-face`/`font-family`). Это канон, не угадывать.
- Есть гайдлайн/`Design.md`/Распаковка бренда? → подтянуть палитру/типографику оттуда.

**ASK (если билда/гайда нет):**
1. Какие 1–3 цвета у тебя ассоциируются с брендом? Дай HEX или назови (подберём точный). Какой фон — светлый или тёмный? *(дефолт — тёплый светлый; тёмную «иишную» неонку НЕ предлагать. Это ТВОЙ бренд — НЕ копируем терракоту/палитру автора.)*
2. Есть фирменный шрифт или предпочтение (строгий гротеск / тёплый гуманистический / акцидентный заголовочный)? Если нет — предложим пару под нишу.
3. Настроение бренда тремя словами (тёплый-дружелюбный / строгий-премиум / технологичный / рукотворный)?
4. Логотип/фото/любой носитель бренда есть? Скинь — снимем палитру с него.

**LOCK → `Design.md` рядом с проектом** (single-source, locked `:root`):
- палитра HEX: accent / accent-hover / bg / surface / text / text-muted / border — по состояниям (default/hover/disabled), контраст WCAG (текст ≥4.5:1, UI ≥3:1)
- type-scale, spacing-scale, радиусы, тени
- шрифты с **`font-display: swap`** (НЕ `optional` — падает на system-ui в Simple Browser)
- система строится сверху вниз: DNA → токены (CSS-переменные, не хардкод) → компоненты → страницы

> Фаза 4/5 НЕ генерит палитру заново через ui-ux-pro-max, если DNA уже заперта здесь. `search.py` — только когда DNA нет вовсе.

### Блок B — Голос / ToV проекта

**PULL:** путь голоса из `config.md`. ⚠️ В `config.md` НЕТ ключа `paths.voice` по умолчанию — у автора голос лежит в `.business/voice-corpus/_voice-profile.md`, но для ученика этого ключа может не быть вовсе. Есть путь и файл → подтянуть тон/ритм/табу/лексику. Нет ключа/файла → НЕ молча брать профиль автора, идти в ASK и собрать нейтральный профиль проекта (см. LOCK).

**ASK (если профиля нет):**
1. Дай 2–3 своих реальных текста (пост / письмо / расшифровку голосового) — вытащим твой голос, не будем выдумывать.
2. Как обращаешься к аудитории — на «ты» или «вы»? Тон — дружеский / экспертно-строгий / провокационный?
3. Слова и обороты, которые ты НЕ употребляешь никогда (табу)?

**LOCK → `voice-profile.md` проекта:** тон, ритм, длина фраз, лексика-маркеры, табу. Обязательные табу копи (ToV):
- без точек в конце строк/заголовков/абзацев
- тире КОРОТКОЕ «–» (en-dash), НЕ длинное «—» (em-dash = AI-tell)
- без staccato/рубленых фраз
> Этот профиль использует **humaniser вместо профиля автора**. Нет голоса эксперта → humaniser работает на нейтральном профиле из этого файла с ЯВНЫМ предупреждением эксперту, НЕ молча на голосе автора.

### Блок C — Glossary (термины и англицизмы)

**ASK:**
1. Твои авторские термины/названия, которые НЕЛЬЗЯ переводить или менять (whitelist)?
2. *(агент сам предлагает)* типовые кальки под замену на русское: онбординг→адаптация, фреймворк→система/каркас, инсайт→озарение/находка, воркфлоу→процесс, комьюнити→сообщество/клуб, хайлайт→ключевое, кейс→пример/история. Эксперт правит список.

**LOCK → `blueprint.md › glossary`:** whitelist (собственные термины) + ban-list (кальки → русская замена). Для ученика whitelist по умолчанию пустой = строгий режим. Машина: `copy-lint` режим-словарь грепает по `copy.md` И рендеру `index.html`, кроме whitelist → BLOCK с заменой.

### Блок D — Реальные факты / кейсы / цифры (риск-канон)

**PULL:** `products/`, кейсы из `.business` — но КАК ГИПОТЕЗЫ для риск-типов, не как истину (см. перенастройку выше).

**ASK (по каждому риск-типу — прямой вопрос, не выдумывать):**
1. Доход/выручка, если ставим на страницу — какая цифра и чем подтверждается (скрин/договор/публичный пруф)?
2. Сколько учеников/клиентов/проектов — точное число и откуда оно?
3. Кейсы и результаты: имя/ник, что было → что стало, цифра, согласие на публикацию. Только реальные.
4. Статус/регалии/«единственный / №1 / работал с X» — чем доказываешь? Нет пруфа → НЕ ставим.
5. Отзывы-цитаты — реальные, с согласием? Дай дословно или источник.

**LOCK → `blueprint.md › facts[]`**, каждый факт:
```
{ claim: "...", value: "...", source: "подтверждено-экспертом|внешний-пруф|.business-черновик", proof_link: "...", status: "confirmed|pending" }
```
Риск-факт со `status: pending` (нет пруфа) → НЕ на страницу, а в `blueprint.md › promises_to_prove_later[]`. (закрыть реальным фактом, а не списком дыр — но риск-факт без пруфа НЕ закрывать выдумкой).

### Блок E — Оффер-канон (единственный источник тарифов/цен)

**PULL:** `products/`, файл решений запуска если есть. Читать файл решений ПЕРВЫМ — он точнее плана.

**ASK:**
1. Тарифы: названия, цена каждого (ОДНО число — диктовка через Wispr искажает цифры, страннóе число сверяю, не ловлю на дословности).
2. Что входит / НЕ входит в каждый пакет — пунктами.
3. Состав программы/модулей.
4. Гарантия (формулируем 3 словами) / условия возврата.
5. Дедлайны оффера.

**LOCK → `offer-canon.md`** — одна таблица как ЕДИНСТВЕННЫЙ источник цен и состава. Трассировка чисел И названий пакетов идёт сюда. Машина: `copy-lint` сверяет согласованность цены/состава между блоками hero/pricing/CTA внутри сайта → расхождение = BLOCK (правил цену на одном экране, в таблице старая — ловится). (характеристику тарифа — цена/лимит/что входит — не заявлять с чужих слов, только с официального ценника).

## Что запирается в `blueprint.md` (структура файла-канона)

Файл `blueprint.md` кладётся РЯДОМ с будущим `index.html` (в папке проекта, где `.website-state.json`). Это ЕДИНСТВЕННЫЙ источник смысла для всех экранов — дубли не плодить.

```markdown
---
project: <slug>
created: <YYYY-MM-DD>
subject: <имя эксперта>
site_type: landing | product | hub | promo | artifact | multipage
sources_pulled: [<пути файлов, откуда подтянут контекст>]
---

# Blueprint — <проект>

## A. Бренд-ДНК → см. Design.md (locked :root, шрифты swap)   [source: <билд grep | гайд | интервью>]
## B. Голос/ToV → см. voice-profile.md проекта                [source: <профиль | тексты эксперта>]
## C. Glossary: whitelist[…] / ban-list[…→замена]
## D. Факты-канон facts[]  (каждый: claim/value/source/proof/status)
##    promises_to_prove_later[]  (риск-факты без пруфа — НЕ на страницу)
## E. Оффер → см. offer-canon.md (тарифы/цены/состав, единственный источник)
## F. Аудитория: segment / pains[] / desires[] / objections[{text,source}] / big_idea / differentiation
## G. Hero-состав: slots[] + proof_facts[]  ·  scarcity{open_at,starts_at,total_M,source}  ·  infra{}
## H. references_intent[]  (≥10 sitewide + ключевые экраны)
## I. env{node, playwright}
```

Сопроводительные канон-файлы рядом: `Design.md`, `voice-profile.md`, `offer-canon.md`.

## Улика на диск + state

После сбора и согласования записать улику helper'ом (как другие фазы — паттерн из `_phases-state.md`):

```bash
# <DIR> = папка проекта (где .website-state.json и blueprint.md)
python3 - "<DIR>" '0_blueprint' '{"approved":true,"site_type":"<тип>","files":["blueprint.md","Design.md","voice-profile.md","offer-canon.md"],"facts_confirmed":<N>,"facts_pending":<N>,"audience_objections":<N>}' <<'PY'
import json,os,sys,time
d,key,fields=sys.argv[1],sys.argv[2],json.loads(sys.argv[3])
p=os.path.join(os.path.expanduser(d),'.website-state.json')
st=json.load(open(p)) if os.path.exists(p) else {"phases":{}}
st.setdefault("phases",{}).setdefault(key,{}).update(fields); st["phases"][key]["ts"]=int(time.time())
json.dump(st,open(p,'w'),ensure_ascii=False,indent=2); print("OK",st["phases"][key])
PY
```

**Гейт-намерение (захучивается отдельно, см. карту дыр):**
- продвижение любого экрана в `concept`+ без локнутого `Design.md` → BLOCK (`website-brand-dna-gate.sh` — построен в `hooks/`, требует регистрации в `settings.json`)
- риск-факт-число со ссылкой только на `.business-черновик` (не confirmed) → BLOCK (`copy-lint.py` — LIVE, `scripts/copy-lint.py`)
- `blueprint.md` / `interview.md` / `copy.md` — ОБЯЗАТЕЛЬНЫЕ артефакты: нет файла = BLOCK, не silent return
- счётчик дефицита без `scarcity.open_at` из blueprint, или якорь = прошлая дата при занято>0 → BLOCK (`scarcity-counter-audit.py` — построен в `scripts/`, требует регистрации в `settings.json`)

> 🔴 Статус принуждения. Все три гейт-скрипта построены на диске (`hooks/website-brand-dna-gate.sh`, `scripts/copy-lint.py`, `scripts/scarcity-counter-audit.py`), НО их регистрация в `settings.json` (matcher/событие) — задача оркестратора и на момент написания НЕ выполнена. Не заявлять «захучено/блокируется», пока запись в `settings.json` не подтверждена.

## ✋ СТОП — апрув канона перед Фазой 0-brief

Перед записью `approved=true` и переходом к брифу — ПОКАЗАТЬ эксперту канон в чат и получить явное подтверждение:

1. Показать сводку `blueprint.md` текстом в чат: тип сайта · бренд-ДНК (цвета/шрифт) · голос (1 строка) · оффер-таблица · топ-боли/возражения · факты со статусами (отдельно — confirmed, отдельно — pending/«докажем позже») · дата открытия счётчика если есть. Невидимое = несделанное (эксперт с телефона).
2. Явно перечислить, что попало в `promises_to_prove_later[]` и ПОЧЕМУ (нет пруфа) — это не дыра, это честность.
3. Спросить: «Канон верный? Что поправить / добавить?» Дождаться реплики-подтверждения эксперта.
4. ТОЛЬКО после явного «да/верно» от эксперта (не от агента самому себе) — записать `0_blueprint.approved=true` и идти в `00-brief`.

🔴 Апрув канона = реплика ЭКСПЕРТА после показа сводки, в ОТДЕЛЬНОМ ходу от сборки канона. Агент не штампует апрув сам себе.

## Выход

Запертый канон контекста: `blueprint.md` + `Design.md` + `voice-profile.md` (проекта) + `offer-canon.md` рядом с проектом, улика `0_blueprint.approved` в `.website-state.json`, риск-факты без пруфа честно вынесены в `promises_to_prove_later[]`. Дальше КАЖДАЯ фаза строит из этого канона, НИКОГДА из догадки. → `00-brief`.
