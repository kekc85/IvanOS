# GPT-image generation (фаза 3 generate)

## ОСНОВНОЙ путь - ТИХИЙ канал codex-imagegen (окон не открывает)
С этой редакции картинка к посту по умолчанию рисуется бесшумно: движок
`.business/scripts/codex_image.py` гоняет `codex exec` -> системный скилл
`imagegen` -> инструмент `image_gen`. Логин тот же самый, ChatGPT автора, но браузер не
запускается вообще: экран, буфер обмена и фронтмост-окно свободны, автор параллельно
работает. Ждать «пока откроется окно» и что-то поднимать заранее не нужно.

Запуск (системного python3 хватает, playwright и venv тут ни при чём):
```bash
PROMPT="$(cat /tmp/imgprompt.txt)"   # длинный промпт удобнее через файл
python3 ~/.claude/skills/post-image/scripts/gen-chatgpt-image-cdp.py \
  --prompt "$PROMPT" \
  --out ~/Desktop/post-<slug>.png
```
Промпт начинать с «Сгенерируй фотореалистичное изображение, вертикальное 3:4, без текста
на картинке.» + ULTRA-промпт. Выход - PNG ПРЯМО на рабочий стол `~/Desktop/post-<slug>.png`
(плоско, без подпапок - `feedback_flat_output_no_subfolders`).

Полезные флаги тихого канала:
- `--size og | square | slide | story` либо явные пиксели `--size 1024x1280`
- `--ref <файл>` - картинка-референс, до 5 штук (для поста обычно не нужен)
- `--attempts 2` - сколько раз пробовать до отказа
- `--no-fallback` - не откатываться на браузер, а честно вернуть код 8

Второй скрипт `gen-chatgpt-image.py` ведёт себя точно так же: без флагов - тихо,
с `--engine browser` - через свой Playwright-профиль. Оба скрипта приняли все прежние
аргументы, старые вызовы менять не нужно, они просто стали тихими.

### Если тихий канал не сработал
Скрипт печатает `QUIET_CHANNEL_FAIL: <причина>` и сам уходит на браузерный путь. Причины,
которые реально встречаются:
- движок не найден (скилл стоит на машине без папки `.business/scripts`)
- нет логина Codex - чинится одной командой `codex login`
- модель отказалась рисовать по контент-политике - переписать промпт
- 🔴 лимит аккаунта Codex выжжен - движок честно печатает `ЛИМИТ АККАУНТА CODEX выжжен` с
  датой, когда лимит откроется, это внешний блокер, не брак промпта. Проверить состояние
  заранее без расхода генераций: `python3 .business/scripts/codex_image.py --selftest`.
  Пока лимит закрыт - картинки идут только запасным браузерным каналом (`--engine browser`)

## Запасной путь - живой ChatGPT в браузере (`--engine browser`)
Включается явно, и вот он окно открывает. Два тракта:

1. Рендер-Chrome по CDP :9222 (профиль `~/.chrome-cdp-profile`) - `gen-chatgpt-image-cdp.py
   --engine browser`. Это ОТДЕЛЬНЫЙ машинный Chrome, не рабочий браузер автора. Мёртв
   (`curl 127.0.0.1:9222/json/version` пусто) - поднять командой из докстринга скрипта.
2. Свой Playwright-профиль `~/.playwright-chrome-data` - `gen-chatgpt-image.py --engine
   browser`. Системного `python3` хватает (playwright в нём уже стоит), отдельный venv не
   нужен. Профиль должен быть залогинен в ChatGPT (логин - `.business/scripts/
   auto-uniqualize/login-chatgpt.sh`) и не занят другим Chrome (`SingletonLock`) - если занят,
   закрыть тот инстанс.

Безопасность браузер-автоматизации на этом пути прежняя: одна своя вкладка за раз, чужие
вкладки не трогаем, timeout обязателен. Память `feedback_browser_automation_safe_parallelism_killswitch`.

### Селектор-дрифт (только для браузерного пути)
ChatGPT сменил вёрстку - подправить селекторы в браузерной ветке (`run_browser`): editor
`#prompt-textarea`/ProseMirror, send-button, картинка по `backend-api/estuary`, легаси
`oaiusercontent` фолбэком. Сверяться с актуальным `auto-uniqualize/driver.py`.

## Дальний fallback (только если оба канала недоступны)

  🔴 Только по явному «да» автора, сам не запускаю. Демонстративно НЕ основной.
- Ручной: отдать автору paste-ready ULTRA-промпт для его ChatGPT.

## Правила
- Картинка БЕЗ текста (GPT-image врёт буквы; текст несёт пост).
- После генерации - ОБЯЗАТЕЛЬНО фаза 4 QA (Read каждой картинки) до выдачи.
