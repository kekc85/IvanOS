# Подготовка документов: интервью + сборка комплекта

Используется когда пользователь говорит "сделай документы для запуска" / "нужен юр.пакет".

## Шаг 1. Интервью

Задай 7 вопросов одним сообщением (через AskUserQuestion):

1. **Форма ЮЛ:** Самозанятый (НПД) / ИП УСН 6% / ИП патент / ООО
2. **Тип продукта:** Курс с модулями / Клуб-сообщество (подписка) / Услуга 1 на 1 / Цифровой мини-продукт (PDF/файл) / SaaS-приложение
3. **Канал продаж:** Свой сайт (Lovable/Tilda) / GetCourse / TG-бот / Маркетплейс
4. **Юрисдикция:** РФ / США / Европа / Несколько
5. **Образовательная лицензия:** Есть / Нет (важно: без лицензии нельзя «образовательные услуги» и «сертификаты»)
6. **Обороты в год:** До 2.4М (укладывается в НПД) / 2.4М-60М (УСН без НДС) / 60М+ (УСН с НДС или ОСНО)
7. **Какие сервисы используешь:** платёжный провайдер (ЮКасса/Tinkoff/Stripe), email-рассылка (Sender/Kit), аналитика (Яндекс.Метрика/GA), мессенджеры

## Шаг 2. Сбор реальных данных

После выбора режима спрашиваешь реальные данные пользователя (если он не возражает - чтобы DOCX были полностью готовы):

```
ФИО (для ИП): 
ИНН: 
ОГРНИП (для ИП): 
Расчётный счёт: 
Банк: 
БИК банка: 
Корр.счёт банка: 
Email поддержки: 
URL основного сайта: 
Telegram поддержки: 
Название продукта: 
Дата редакции: (по умолчанию сегодня)
```

Если пользователь не хочет давать реальные данные - сообщает и тогда используем примеры (Петров И.И., ИНН 770000000000, example.ru) с пометкой "ЗАМЕНИ НА СВОИ ДАННЫЕ".

## Шаг 3. Выбор комплекта из legal-pack

В зависимости от ответов из Шага 1 определяем какой комплект из `materials/legal-pack/` подходит:

| Форма | Продукт | Канал | Комплект |
|---|---|---|---|
| ИП УСН | Курс/гайд | Свой сайт | `01-ip-usn-kurs-svoy-sayt/` |
| СМЗ | Услуга 1 на 1 | Свой сайт | `02-smz-usluga-svoy-sayt/` |
| ИП УСН | Клуб | GetCourse | `03-ip-usn-klub-getkurs/` |
| СМЗ | Цифровой мини-продукт | TG-бот | `04-smz-mini-produkt-tg-bot/` |
| ИП УСН | SaaS | Свой сайт | `05-ip-usn-saas-svoy-sayt/` |
| US LLC | SaaS | Свой сайт | `06-us-llc-saas/` |
| EU OÜ | SaaS | Свой сайт | `07-eu-gdpr-saas/` |

Если нестандартный кейс - берём ближайший комплект и адаптируем (например: ИП УСН + клуб + свой сайт → берём 01, адаптируем модель тарифа на подписку).

## Шаг 4. Замена плейсхолдеров

Через `sed` пробегаем все .md файлы выбранного комплекта и заменяем плейсхолдеры на данные из Шага 2.

Список плейсхолдеров для замены - см. файл `00-ustanovka.md` внутри каждого комплекта.

Если данные не предоставлены - используем стандартные примеры (см. `~/Desktop/Юр документы для запуска/` как образец).

## Шаг 5. Объединение и упрощение

По умолчанию (по запросу: cookies и условия возврата встроены в основные документы):
- Cookies-политика встроена в Политику ПДн (раздел 4), отдельным файлом НЕ выносим
- Условия возврата встроены в Оферту (раздел 5), отдельным файлом НЕ выносим
- Образец заполнения уведомления в РКН встроен в инструкцию РКН (не отдельный файл)

## Шаг 6. Финальная проверка

ОБЯЗАТЕЛЬНО перед конвертацией в DOCX:

```bash
grep -rn '{{' .   # Должно быть пусто - проверка остатков плейсхолдеров
grep -rn '\.md' . # Должно быть пусто - проверка кросс-ссылок на .md файлы
```

Если что-то осталось - чистим. Если плейсхолдер заменить нельзя (нет данных) - заменяем на понятный пример с пометкой "ЗАМЕНИ НА СВОИ ДАННЫЕ".

## Шаг 7. Конвертация в DOCX

```bash
cd <папка комплекта>
for f in *.md; do
  pandoc "$f" -o "${f%.md}.docx" --from markdown --to docx --standalone
done
rm *.md
```

## Шаг 8. Складывание на рабочий стол

Структура:

```

├── ЧИТАЙ ПЕРВЫМ.docx
├── 1. ОФЕРТА.docx
├── 2. ПОЛИТИКА ПДн.docx
├── 3. СОГЛАСИЕ ПДн (текст для чекбокса).docx
├── 4. СОГЛАСИЕ НА РАССЫЛКУ.docx
├── 5. РЕГИСТРАЦИЯ В РЕЕСТРЕ ОПЕРАТОРОВ ПДн.docx
└── COOKIE-БАННЕР (код для сайта).docx
```

Если юрисдикция США/Европа - добавляем подпапки `Зарубежка - США/` и `Зарубежка - Европа/`.

## Шаг 9. ЧИТАЙ ПЕРВЫМ

Файл-инструкция: что внутри, что заменить под себя, как разместить на сайте в 3 шага. Используй шаблон из `~/Desktop/Юр документы для запуска/ЧИТАЙ ПЕРВЫМ.docx` как образец, адаптируй под конкретный проект.

## Шаг 10. Архив

Финальный шаг - создаём zip-архив:

```bash
cd ~/Desktop && zip -r "Юр документы - <название>.zip" "Юр документы - <название>/" -q
```
