# Возврат: пошаговый workflow для специалиста по возвратам

Используется когда поступает запрос на возврат от ученика. Полный регламент - в `knowledge/refund-regulation.md`.

## Как использовать этот промпт

Скилл проводит специалиста или руководителя проекта **через каждый шаг последовательно**. На каждом шаге:
1. Получаешь информацию от специалиста
2. Принимаешь решение или предлагаешь готовый текст
3. Фиксируешь результат
4. Переходишь к следующему шагу

## Запуск

При запуске - спросить контекст одним сообщением:

> "Опиши ситуацию:
> - От кого пришёл запрос (ФИО, тариф, дата покупки)?
> - Что говорит ученик? (вкратце или скриншот)
> - Тон коммуникации: жалоба / категоричный возврат / конфликт?"

## Шаги

### Шаг 1. Оценка тона

После получения контекста - выбираем путь:

- **Жалоба / усталость / "не получается"** → переход к Шагу 2.1 (удержание через наставника)
- **Не заходят видео / нет результата** → переход к Шагу 2.2 (альтернатива)
- **Категоричный возврат** → Шаг 4 (сбор данных) + параллельно Шаг 12 если конфликт
- **Конфликт / агрессия** → Шаг 12 + параллельно Шаг 4

Готовый ответ ученику для первичного контакта - см. `prompts/04-refund-messages.md` шаблон "первичный ответ".

### Шаг 2. Удержание

**Обязательный этап перед возвратом.**

Спроси специалиста: "Какие действия предпринять для удержания?"

Варианты:
1. **Спасательный круг:** созвон с наставником проекта (10К затрат). Готовый текст ученику - см. `04-refund-messages.md` шаблон "спасательный круг".
2. **Альтернатива:** прогретый аккаунт + кейсы. Готовый текст - шаблон "альтернатива".
3. **Пропустить удержание** (если ученик уже отказался от всего раньше).

Зафиксируй: какое предложение сделано, что ответил ученик.

### Шаг 3. Если ученик настаивает на возврате

Если все попытки удержания отклонены - переходим к процедуре. Готовый текст подтверждения - шаблон "подтверждение возврата".

### Шаг 4. Сбор данных по ученику

Запрашиваем у специалиста (или вытягиваем из CRM):

```
ФИО:                _____________________________
Почта:              _____________________________
Тариф:              _____________________________
Дата покупки:       _____________________________
Сумма оплаты:       _____________________________
Сумма до компании:  _____________________________ (после комиссий)
Способ оплаты:      _____________________________ (карта / СБП / Edsoff / Манифест)
```

### Шаг 5. Проверка выполнения обязательств

По оферте проверяем что ученик получил:

```
Модули (1...N):       [список], каждый ✅ / ❗ / ❌
Закрытый чат:         ✅ / ❌
Кастомная GPT:        ✅ / ❌
Обратная связь:       ✅ / ❗ частично / ❌
Онлайн-встречи:       X из N проведено
```

### Шаг 6. Определение типа потока

- **Завершённый поток** (июль, октябрь, ноябрь, декабрь) → обязательства выполнены полностью, идём в чат юристов с этим обоснованием.
- **Активный поток** (март-апрель и далее) → индивидуальный расчёт, идём в чат юристов с детализацией.

### Шаг 7. Формирование запроса юристам

Готовый шаблон сообщения юристам - см. `04-refund-messages.md` шаблон "запрос юристам".

Параллельно отправляем ученику запрос на саморасчёт - шаблон "саморасчёт ученику".

### Шаг 8. Получение расчёта от юристов и отправка ученику

Когда юристы прислали расчёт - формируем сообщение ученику. Шаблон "расчёт ученику".

### Шаг 8.5. ⭐ Руководитель смотрит ответ ученика

**ОБЯЗАТЕЛЬНЫЙ ЭТАП.**

Когда ученик ответил на расчёт - **перед** Шагом 9 специалист передаёт ответ Руководителю.

Формат передачи:

```
@Руководитель
ОТВЕТ УЧЕНИКА НА РАСЧЁТ:
[скриншот переписки или текст]

КОНТЕКСТ:
- ФИО: ___
- Тариф: ___
- Изначальная сумма: ___
- Расчёт юристов: ___
- На что не согласен: ___ (если возражает)

ЖДУ КАК ДЕЙСТВОВАТЬ
```

**Руководитель оценивает и выбирает:**

- ✅ **Ученик согласен** → пишет специалисту "ОК, продолжай" → переход к Шагу 9.
- ⚠️ **Ученик не согласен / возражает / торгуется:**
  - А) Руководитель даёт готовый ответ специалисту для пересылки ученику
  - Б) Руководитель корректирует сумму (возврат к Шагу 7 с поправкой "вернуть еще X")
  - В) Руководитель эскалирует к юристам с дополнительными вопросами
  - Г) Руководитель пишет ученику лично (редкие случаи - крупная сумма, публичная фигура, давний клиент)

**После решения Руководителя** → специалист продолжает по выбранному пути.

**Зачем этот этап:**
- Не отпускать ученика автоматически на сухой юр.трек если можно сохранить отношения
- Дать частичный возврат + сохранить лицо ученика
- Повысить сумму если ученик объективно прав
- Руководитель видит проблемные кейсы и может улучшить продукт

### Шаг 9. Сбор реквизитов

После согласия ученика - запрашиваем реквизиты. Шаблон "запрос реквизитов".

```
ФИО:                _____________________________
Банк:               _____________________________
БИК:                _____________________________
Расчётный счёт:     _____________________________
Статус:             физлицо / самозанятый / ИП
[Если ИП/СМЗ] ИНН:  _____________________________
```

### Шаг 10. Передача в оплату

Передаём данные ответственному за финансы.

Шаблон сообщения Юле - см. "передача в оплату".

### Шаг 11. Работа с рассрочками

Если оплата была через рассрочку:

- **Эдсоф (Edsoff):** пишем в чат Edsoff, передаём почту ученика, приостанавливаем обучение. Шаблон "Edsoff приостановка".
- **Манифест:** пишем на почту сервиса, уведомляем о расторжении. Шаблон "Манифест расторжение".

### Шаг 12. Работа с конфликтными учениками

Параллельный трек (не последовательный). Применяется если на любом шаге ученик стал конфликтным.

См. шаблоны "конфликтный ученик".

Правила:
- Не игнорируем
- Не эскалируем
- Общаемся спокойно и чётко
- Все ссылки только на оферту

### Шаг 13. Закрытие кейса

После перевода денег - фиксируем в базе:

```
Кейс:               #2026-XXX
ФИО ученика:        ___
Дата запроса:       ___
Дата закрытия:      ___
Тариф:              ___
Изначальная сумма:  ___
Возвращено:         ___
Этап 8.5:           [согласен / возражал, Руководитель дал текст / возражал, Руководитель скорректировал сумму / Руководитель написал лично]
Удержание:          [получилось / не получилось / не пробовали]
Комментарий:        ___
```

## Сохранение контекста сессии

Если работа над одним возвратом идёт несколько дней - сохраняем контекст в `~/Documents/refunds/<ФИО ученика>-по решению автора.md`. Туда же скриншоты переписки и решения Руководителя на Шаге 8.5.

## Принципы коммуникации

1. Всегда сначала удержание, потом возврат
2. Все решения через факты и оферту
3. Спокойно. Без эмоций. По делу.
4. Шаблоны - база, под конкретный случай адаптируем
5. На Шаге 8.5 не пропускаем Руководителя даже если кажется что всё очевидно
