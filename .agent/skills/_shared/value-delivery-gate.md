# Value-Delivery Gate (shared, HARD) — что пост ОБЯЗАН доставить

> Источник истины для всех writer-скиллов. Прецедент по решению автора (пост по решению автора): текст прошёл форму, но автор: «огрызок, бот-сообщение, ноль пользы, ноль инсайтов» + «не нужно диагностические действия, бесполезно». Форму проверяют другие гейты; этот гейт проверяет ВЕЩЕСТВО.

Применять ПЕРЕД финалом (на стадии ценности и на ревью). Подробная типология — `~/.claude/skills/post/references/value-types-framework.md`.

## Правило 1 — Действие ГЕНЕРАТИВНОЕ, не диагностическое (HARD, универсально)
Если в тексте есть actionable-шаг, он обязан ДВИГАТЬ читателя — давать на руки то, чего у него не было (новый артефакт / результат / первый продукт). Диагностический шаг = брак: он лишь подтверждает то, что человек и так чувствует.
- ❌ диагностика: «посчитай, сколько денег принёс контент за месяц» (человек и так знает, что ноль)
- ✅ генеративное: «открой нейросеть, опиши тему и опыт, попроси 3 маленьких продукта собираемых самому, выбери один, распиши наполнение» → за полчаса на руках первый продукт
**Тест:** после действия у читателя появился НОВЫЙ результат/артефакт — или он только лишний раз убедился в проблеме? Второе → переписать на генеративное.

## Правило 2 — Реальная ценность ≥2 value-types, не «было→стало» (HARD, универсально по сути)
Текст обязан нести **≥2 типа ценности**, а не быть историей «было плохо → стало хорошо + призыв» (это бот-сообщение, не пост):
- **V1 инсайт** — то, чего читатель не знал, с обоснованием/пруфом
- **V5 модель** — ПОЧЕМУ механика работает (рамка, не «делай X»)
- **V2 генеративное действие** (см. Правило 1)
- **пруф-кейс** с реальной цифрой
Только «было→стало» без инсайта/модели/действия → **FAIL «ноль пользы»**. Это про вещество, не про длину: даже короткий формат обязан нести хотя бы инсайт или генеративное действие.

**Словарь цели (обязателен, иначе исключение не сработает).** Значение `brief.form_goal` - СЛОВО: `reactions | forwards | sales | gate`. Сравнение ниже идёт со словом и только со словом. Буква `R/F/S/A` значением цели не является, она живёт отдельным полем `brief.form_goal_letter` и годится только для печати улики человеку. Пришла буква вместо слова - цель записана в браке -> FAIL, единственный маршрут возврата: 01-router (Шаг 0.49 в post, Step 5.5 в longform и email, Step 5.5 в tweet, Шаг 4.5 в carousel) - перезаписать цель словом; плоские правила ниже действуют только ПОСЛЕ возврата. Соответствие: `R = reactions`, `F = forwards`, `S = sales`, `A = gate`.

**Исключение (канон формы v2 §3.1/§4.6/§8.2, .business/voice-corpus/_format-canon-v2.md):** при `brief.form_goal == "reactions"` (слово, не буква `R`) и теме из белого списка §4.6 (быт и отдых с близкими, уязвимость и провал, ценностная поддержка читателя, праздник) требование «≥2 value-types» **снимается** — носителем ценности объявляются **близость, разрешение вместо вины, прожитая слабость, перекличка** (§4.6): они закрывают правило по сути, а не по машинному счётчику типов. FAIL «ноль пользы» при этом остаётся в силе — пост-квитанция без единого носителя ценности (близость/разрешение/слабость/перекличка) всё равно брак. Для F и S исключение не действует, там правило прежнее и HARD без изменений. Без объявленного `form_goal` правило применяется как раньше, безусловно.

## Правило 3 — Объём и форматирование (ТОЛЬКО длинные форматы: educational / story / vulnerability / longform)
Для полноформатных постов: **объём — из профиля цели, канон формы v2 §3** (при пустом `brief.form_goal` — fallback ~2300-2500 символов, старое поведение). Число типов форматирования — профильное (канон §9: R-нарратив 1 жирный, R-разбор 1-2, F 3, S 4-5), а не универсальная квота «≥4 типа» — эта квота **отменена** канона §8.2 как воспроизводящая профиль слабого поста, не сильного. Голая простыня без единого приёма форматирования (`dev_total < 2` в `lint-post.py`) остаётся WARN, не HARD FAIL (`lint-post.py` L2 снял hard_fail на этом пороге).
**НЕ применять** к микроформатам: tweet (≤280), bot-message (короткая реплика), IG-caption (≤1100) — у них свой объём и своя (минимальная) разметка. Там работают только Правила 1-2 по сути.

## Где проверяется
- В `post`: канон `references/_voice-TEMPLATE.md` раздел 5 + независимый верификатор `04-review.md` 4.M.2 (блоки «ДЕЙСТВИЕ ГЕНЕРАТИВНОЕ» + «ПОЛЬЗА/НЕ ОГРЫЗОК») + value-gate 4.12 (≥2 vectors) + линтер (формат).
- В остальных writer-скиллах: проверять эти 3 правила на стадии ценности и на ревью; независимый верификатор включает вопрос «действие генеративное? ≥2 value-types? не огрызок?».
- Цель формы: Правила 2 и 3 читают `brief.form_profile`, выставленный Гейтом 0 (в `post` — `04-review.md` 4.0.2 / `01-router.md` Шаг 0.49, аналогично в сестринских скиллах). Профиля нет — оба правила работают в старом безусловном режиме (fallback).
- Словарь один на всю цепочку: цель сравнивается словом (`reactions | forwards | sales | gate`), буква (`R | F | S | A`) идёт только в `brief.form_goal_letter` для печати.
