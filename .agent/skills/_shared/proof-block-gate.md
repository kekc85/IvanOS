# Proof Block (обязательный вывод доказательства — для всех writer-скиллов)

> **Прецедент по решению автора:** доказательства применения скилла/мастеров не показывались автору → выглядело как «на словах», возник обоснованный скепсис «ты не имплементировал». Фикс: после КАЖДОГО поста обязателен видимый Proof-блок. Без него вывод считается недоделанным.

## Порядок (итеративно, как требует автор)
1. Сделать пост **полностью через стадии скилла** (router → finalize → structure → write → review).
2. **Наложить мастеров** (`mastery/copywriting/`, рассмотреть все 13 по `mastery/PROTOCOL.md`).
3. Вывести **Proof-блок** (ниже) — доказать по чек-листу + таблице.

## Формат Proof-блока (выводить в чат под постом КАЖДЫЙ раз)

### 0. Чек-лист критериев поста — Maxwell Ross 9 (полный, показывать всегда)
Прогнать пост по 9 пунктам `references/maxwell-ross-9-checklist.md`, вывести PASS/FAIL по каждому (мин. 8/9, п.9 — только sales):
```
1. Lead в шаг с читателем (боль/интерес сразу): PASS/FAIL — <как>
2. Lead ≤ 2 строки: PASS/FAIL
3. Открытие обещает выгоду: PASS/FAIL — <какую>
4. Biggest gun first (сильнейший аргумент/цифра в начале): PASS/FAIL
5. Big idea (одна мысль на пост): PASS/FAIL — <какая>
6. Логический порядок (hook→причина→решение→шаг): PASS/FAIL
7. Believable (правдоподобно, конкретика/пруф, без круглых пустых цифр): PASS/FAIL
8. Clear CTA (одно чёткое действие): PASS/FAIL
9. CTA связан с темой: PASS/FAIL/(N-A для не-sales)
```
+ Viral-check проекта (5 вопросов из voice-canon): хук стопит за 1с / узнаёт себя / какую кнопку жмём / какую мысль сформирует сам / тема закрыта.

### 3. Независимый верификатор (Слой 4 mastery/PROTOCOL)
Субагент, пост НЕ писавший: по каждому заявленному методу PASS|FAIL + цитата; voice-fidelity; факт-чек (нет выдуманных цифр/атрибуций). Итог: FAIL-список или «пусто» + вердикт.

### 4. SAMENESS-чек батча (НОВОЕ, HARD — прецедент по решению автора «10 постов вышли одной статьёй»)
> Per-post PASS НЕ доказывает разнообразие батча: 10 health-постов прошли каждый по отдельности, а вышли по одной формуле (один риторический движок / один финал / одна рамка-злодей). Per-post метод-чек это не ловит. Поэтому верификатор ОБЯЗАН смотреть на батч.
**Тому же независимому верификатору (п.3) передать ТЕКСТЫ 2-3 ПРЕДЫДУЩИХ постов** + текущий и вынести ОТДЕЛЬНЫЙ вердикт sameness по 4 глубоким осям:
```
SAMENESS-ВЕРДИКТ (текущий пост vs 2-3 предыдущих):
- Риторический движок: <тип тек.> vs <типы пред.> → РАЗНЫЙ ✓ / СОВПАЛ ✗
- Формула финала:      <тип тек.> vs <типы пред.> → РАЗНЫЙ ✓ / СОВПАЛ ✗
- Рамка-«злодей»:      <тек.>     vs <пред.>       → РАЗНАЯ ✓ / СОВПАЛА ✗
- Эмоц. арка:          <тек.>     vs <пред.>       → РАЗНАЯ ✓ / СОВПАЛА ✗
ИТОГ: PASS / FAIL-БАТЧА
```
**FAIL-БАТЧА** (переписать, НЕ выдавать), если ЛЮБОЕ: один риторический движок у 3+ постов подряд · одна формула финала у 3+ подряд · одна рамка-злодей у 3+ подряд · финал «дело не в тебе, дело в гормоне…» повторён подряд. Запрещено: «симптом → ты винишь себя → это кортизол → механизм → обычный совет не работает → снизишь, само вернётся» как дефолтный скелет всех постов.
Источник «предыдущих»: проектный `variation-log.md` / `structure-rotation.md` (когда канал без истории).
