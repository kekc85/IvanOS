# Bring-Your-Own-Account Gate — внешние сервисы работают на аккаунте УЧЕНИКА (HARD)

> Переиспользуемый гейт для всех скиллов, которым нужен внешний платный/авторизуемый сервис
> (HeyGen, ElevenLabs, Higgsfield, Instagram, Google Flow и любой будущий). Читается на том шаге,
> где скилл впервые обращается к сервису. Источник правила: автор — «мой HeyGen тут ни при чём,
> человек подключает СВОЙ; скилл должен запросить у человека его данные и работать на ЕГО аккаунте».

## Принцип (обязательный)

Любой внешний сервис работает на аккаунте **ученика**, НИКОГДА на аккаунте автора. Скилл не несёт в себе
ни ключей автора, ни его аватара, ни его сессии. При первом обращении к сервису скилл:

1. **Проверяет**, подключён ли у ученика этот сервис (есть ли его ключ / его аватар / его залогиненная сессия).
2. Если НЕТ — **останавливается и проводит онбординг**: объясняет что за сервис и зачем, даёт ссылку где
   завести аккаунт (free/платный), и ПРОСИТ ученика подключить СВОЁ (вставить свой ключ / войти в свой кабинет
   в браузере / выбрать свой аватар).
3. **Сохраняет** введённое в локальный конфиг ученика и дальше работает на нём.
4. **НИКОГДА не делает тихий фолбэк** в сломанную заглушку (чёрное видео, немой mp3, пустой результат).
   Нет аккаунта → онбординг, а не молча-плохой результат.

Тест перед шагом: «Я сейчас возьму ключ/аватар/сессию ИЗ конфига УЧЕНИКА? Если у него пусто — я СПРОШУ его,
а не подставлю аватар/ключ автора и не отрендерю заглушку?» Любое «нет» = брак.

## Где лежит конфиг ученика

`~/.business/processes/accounts.json` (резолвится в `~/IvanOS/.business/processes/accounts.json` через симлинк),
права `chmod 600`. Создаётся при первой записи через helper. В дистрибутиве уезжает ПУСТОЙ шаблон (все поля «»),
заполняет его сам ученик через онбординг. Реальные ключи/куки в дистрибутив НЕ кладём.

Схема:

```json
{
  "heygen":    { "mode": "browser", "avatar_name": "", "avatar_id": "", "voice_name": "" },
  "elevenlabs":{ "api_key": "", "voice_id": "" },
  "higgsfield":{ "mode": "browser" },
  "instagram": { "cookies_path": "~/.business/processes/.ig-cookies.json" },
  "google_flow":{ "mode": "browser", "cdp_profile": "~/.chrome-cdp-profile" },
  "openai":    { "api_key": "" }
}
```

- `mode: "browser"` = сервис работает через залогиненный Chrome ученика по CDP (порт 9222), ключ не нужен,
  нужна ЕГО сессия. `connected` для таких = факт живой залогиненной вкладки сервиса в CDP-профиле ученика.
- ключевые поля (`avatar_name`, `api_key`, `voice_id`, `cookies_path`) пустые = сервис НЕ подключён.

## Helper

`python3 ~/.claude/skills/_shared/bin/account.py <команда>`:

- `status <service>`            → `connected` / `missing` (exit 0/1)
- `get <service>.<field>`       → значение или пусто
- `set <service>.<field> <val>` → записать (создаёт файл с chmod 600 если нет)
- `onboard <service>`           → печатает блок-инструкцию «как ученику подключить СВОЙ <service>»

## Алгоритм гейта (каждый скилл на шаге сервиса)

```
1. KEY = account.py get <service>.<главное-поле>           # heygen.avatar_name / elevenlabs.api_key / ...
2. если KEY пусто (или account.py status <service> = missing):
     - показать ученику:  account.py onboard <service>
     - СТОП. Дождаться, пока ученик подключит своё и даст данные (ключ / имя своего аватара / вход в кабинет)
     - account.py set <service>.<поле> <значение ученика>
3. дальше использовать значение УЧЕНИКА (НЕ хардкод автора, НЕ тихую заглушку)
```

## Онбординг по сервисам (что печатает `onboard`)

### heygen (цифровой двойник в кадре)
1. Заведи аккаунт на https://www.heygen.com (есть бесплатный тариф для пробы; для рендера без вотермарки нужен платный).
2. В СВОЁМ кабинете HeyGen: Create avatar → Avatar V (Clone a real person) → загрузи СВОЁ видео-footage,
   доведи аватар в студии. Это ТВОЙ двойник в кадре.
3. Подними залогиненный Chrome по CDP (флоу `replicate-viral/knowledge/heygen-browser.md`, раздел под твою ОС),
   войди в СВОЙ HeyGen.
4. Скажи имя своего аватара и голоса (как они называются в твоём кабинете). Я сохраню и дальше рендерю двойника ТВОИМ аватаром.
> Аватар/голос автора курса в твоём кабинете не существуют — используется ТОЛЬКО твой.

### elevenlabs (озвучка твоим голосом)
1. Заведи аккаунт https://elevenlabs.io (free даёт лимит символов; клон голоса — на платном).
2. Profile → API key → скопируй ключ.
3. (опц.) Клонируй СВОЙ голос (Voice Lab) или выбери готовый из библиотеки, скопируй Voice ID.
4. Дай мне ключ и Voice ID — сохраню в твой accounts.json, озвучка пойдёт твоим голосом.

### higgsfield (вау-вставки / инфографика-анимация)
1. Заведи аккаунт https://higgsfield.ai.
2. Войди в СВОЙ кабинет в Chrome (CDP-профиль, порт 9222) — скилл водит браузер на ТВОЕЙ сессии.
3. Подтверди, что залогинен. Ключ не нужен, работаем через твой залогиненный браузер.

### instagram (парс виралок-доноров за login-wall)
1. Скилл откроет окно Chromium с формой входа Instagram.
2. Войди в СВОЙ аккаунт (включая 2FA). Скрипт сам сохранит ТВОИ cookies в `~/.business/processes/.ig-cookies.json` (chmod 600).
3. Это твоя сессия, на ней идёт парс. Cookies автора в дистрибутиве отсутствуют.

### google_flow (omni-flash, генерация в Google Flow)
1. Подними залогиненный Chrome по CDP (порт 9222, профиль `~/.chrome-cdp-profile`).
2. Войди в СВОЙ Google-аккаунт и открой Flow.
3. Подтверди вход — скилл работает на ТВОЕЙ сессии.
