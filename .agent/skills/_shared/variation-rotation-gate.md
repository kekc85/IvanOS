# Variation Rotation Gate (анти-шаблон, общий для всех writer-скиллов)

> **Прецедент по решению автора:** два поста подряд вышли на одном скелете (один тип заголовка, один тип первого абзаца, одна структура повествования, один архетип) и читались как шаблон. Причина — я НЕ прогнал rotation-gate скилла (в `post` это `01-finalize` Шаги 1-5 + `02-structure` Шаг 7) и писал «по памяти» в той же форме. Дыра: ротация читает историю канала, а у нового канала (`channel_url: null`) истории нет → «avoid last 3» нечего избегать, и сессионный вывод нигде не помнился.

## Правило (HARD, ДО написания)
Нельзя писать в той же форме, что прошлый пост. Перед write прогнать ротацию по 4 осям и **СУРФЕЙСИТЬ декларацию в чат** (видимая проверка против поверхностного исполнения).

### Источник «последних постов» для ротации
1. Есть история канала (`config.paths.recent_posts_source` ≠ `none`) → прочитать последние 3-5 (как `01-finalize` Шаг 1).
2. Истории нет (новый канал) → читать **проектный лог**: `<project-pack>/variation-log.md` (или `structure-rotation.md`). Это закрывает дыру «нет recent_posts → ротация мертва» + помнит сессионный вывод.
3. Лога нет → создать. Первый пост свободен, но его оси записать.

### Словарь цели формы (читать ДО осей)
Значение `brief.form_goal` — СЛОВО: `reactions | forwards | sales | gate`. Все проверки ниже сравнивают именно со словом. Буква `R/F/S/A` значением цели не является: она лежит отдельным полем `brief.form_goal_letter` и служит только печати улики человеку (в декларации ниже буквы стоят как подпись профиля, не как условие). «Цель объявлена» = в `brief.form_goal` лежит одно из четырёх слов. Пусто → цель считается НЕ объявленной, все оси работают в старом безусловном режиме (fallback). Лежит буква → цель записана в браке -> FAIL, единственный маршрут возврата: 01-router (Шаг 0.49 в post, Step 5.5 в longform и email, Step 5.5 в tweet, Шаг 4.5 в carousel) - перезаписать цель словом; плоские правила ниже действуют только ПОСЛЕ возврата. Соответствие: `R = reactions`, `F = forwards`, `S = sales`, `A = gate`. Тот же словарь у потребителя `~/.claude/skills/post/scripts/lint-post.py` (`--form-goal`) и в `_shared/value-delivery-gate.md`.

### 4 оси — ОБЯЗАНЫ меняться от поста к посту
- **Hook type** (тип заголовка) — из 15 (`references/hooks-15-templates.md`): Contrarian / Vulnerable / Results-first / Question / Myth-busting / Pattern-interrupt / Time-based / Numbered / Tension / Bold-prediction / Direct-address / Quote / Specific-number / I-was-wrong / Personal-failure. **Не повторять последние 2.** При объявленной `brief.form_goal` (слово `reactions` / `forwards` / `sales` / `gate`, канон формы v2 §2.1, .business/voice-corpus/_format-canon-v2.md) тип хука диктуется профилем цели, а не новизной (R — кадр или ярлык, F — опись с цифрой, S — ярлык или квитанция, канон §3): ось **выводится из ротации**, «не повторять последние 2» к ней не применяется. Без объявленной цели ротация по 15 типам работает как прежде.
- **Opening type** (тип первого абзаца / захода) — сцена-нарратив / прямой тезис / вопрос / цифра-факт / диалог-в-голове / контраст-парадокс. **Не повторять последний.**
- **Narrative structure** (тип повествования тела) — протокол-список / непрерывная история / миф→разбор / один приём вглубь / Q&A / манифест-рамка / кейс-цифры. **Не повторять последние 2.**
- **Archetype** (тон) — `01-finalize` Шаг 4: **avoid last 3**, из `config.voice.archetypes_allowed`.

### 4 ГЛУБОКИЕ оси — тоже ОБЯЗАНЫ меняться 
Ротация hook/opening/narrative/archetype НЕ ловит глубокую шаблонность. Дополнительно менять (каждую — не повторять 2-3 поста подряд):
- **Риторический движок** — чистая тактика (только шаги) / история-кейс (без лекции) / список-разоблачение / сравнение до-vs-норма / один провокационный тезис / вопрос из ДМ → ответ / тест-чеклист / манифест-рамка / один приём вглубь. НЕ дефолтить «симптом → винишь себя → это [гормон/причина] → механизм → совет не работает → само вернётся».
- **Формула финала** — ЗАПРЕЩЕНО подряд «дело не в тебе, дело в …» + многоточие. Чередовать: прямой шаг / вопрос / образ / вызов / без морали. Вариант **«открытая сцена» удалён** из перечня: канон формы v2 §6 называет незакрытую петлю прямым анти-паттерном («Открытая петля: финал не возвращает слово или образ хука», держат 96% верха против неё, канон §9 R-15). При объявленной `brief.form_goal` (слово) формула финала берётся из профиля цели (`reactions` — вывод и закрытая петля, `forwards` — ссылка в последних 250 знаках, `sales` — живая реплика без URL, канон §3-4) и **выводится из ротации**; без объявленной цели ротация по оставшимся вариантам работает как прежде.
- **Рамка «злодей»** — НЕ в каждом посте одна причина названа одинаково. Где-то механизм не разжёвывать (его несёт ссылка), где-то говорить о сне/свете/еде без слова «гормон».
- **Эмоц. арка** — не всегда «снятие вины». Бывает: любопытство, азарт, спокойная инструкция, тёплая история, провокация.

### Ось СКЕЛЕТА — порядок блоков (v4.5, прецедент по решению автора, все writer-скиллы)
Числовой профиль цели задаёт ЧИСЛА (сколько жирных, есть ли список, длина), НЕ порядок блоков — один профиль выполняется десятком построений (канон §4.2). Наливать каждую выдачу в один каркас «жирный хук → курсивная строка → тире-список → подзаголовки» = шаблонность, которую все прочие оси не ловят (прецедент: два поста подряд прошли ротацию смысловых осей и вышли с побайтно одинаковым скелетом). Правило: **порядок типов блоков** (хук-строка / курсив-строка / абзац / список / нумерация / цитата / CTA) не должен совпадать с последними 3-5 выдачами того же канала идентично или общим зачином из 3+ блоков. В post это машинный HARD-гейт: `scripts/lint-post.py` сверяет с журналом `.skeleton-log.jsonl` в каждом вызове (04-review «СКЕЛЕТ-ГЕЙТ», запись в журнал — 05-publish Шаг 1c). В longform/email/tweet/carousel линтера нет — сверять глазами против своего лога выдач и писать строку в декларацию. Ось из ротации НЕ выводится при объявленной цели: профиль порядок не диктует.

### Декларация (вывести ПЕРЕД/С постом — это и есть улика, что гейт прогнан)
```
ВАРИАТИВНОСТЬ (vs лог последних постов):
- Hook type:  <тип>      (прошлые: <h1,h2>)   → другой ✓
- Opening:    <тип>      (прошлый: <o1>)      → другой ✓
- Narrative:  <тип>      (прошлые: <n1,n2>)   → другой ✓
- Archetype:  <тип>      (прошлые: <a1,a2,a3>) → не из последних 3 ✓
- Скелет:     <порядок блоков> (прошлые: <s1>) → другой ✓  (в post — вердикт линтера)
ГЛУБОКИЕ ОСИ:
- Риторич. движок: <тип>  (прошлые 2-3: ...)   → другой ✓
- Формула финала:  <тип>  (прошлые 2-3: ...)   → другая ✓
- Рамка-злодей:    <тип>  (прошлые 2-3: ...)   → другая ✓
- Эмоц. арка:      <тип>  (прошлые 2-3: ...)   → другая ✓
```
**При объявленной `brief.form_goal`** (слово `reactions` / `forwards` / `sales` / `gate`, канон формы v2 §2.1) строки **Hook type** и **Формула финала** выведены из ротации (см. оси выше) и в декларации сравниваются не с логом последних постов, а с профилем цели: они пишутся как `Hook type: <тип> (профиль цели <reactions/forwards/sales>, буква <R/F/S>, канон §3) → по профилю` и `Формула финала: <тип> (профиль цели <reactions/forwards/sales>, буква <R/F/S>, канон §3-4) → по профилю` (буква тут подпись для глаз, сравнение идёт по слову), без плейсхолдеров `<h1,h2>` / `<прошлые 2-3>`, которых для снятых осей не существует. Обе оси в этом режиме не входят в набор «совпало с недавним → переписать». Без объявленной цели обе строки декларации заполняются как раньше, по логу.

Любая ось (поверхностная ИЛИ глубокая) совпала с недавним → переписать, НЕ выдавать. Глубокая шаблонность ловится также SAMENESS-чеком верификатора (`proof-block-gate.md` п.4).

Дописать строку в `variation-log.md`: дата · тема · hook · opening · narrative · archetype · финал · приписка.
