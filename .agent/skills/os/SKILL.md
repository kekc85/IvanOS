# Solo Launch OS - оркестратор запуска соло-бизнеса

Ведёт одного человека от сырой идеи до удержания под ЛЮБОЙ формат (консультации / мини-продукт / клуб / группа / интенсив / мастермайнд / бесплатник), а не только «школу». Тонкий слой: порядок, гейты, статус, маршрутизация к промптам и под-скиллам. Содержание фаз живёт в `prompts.md`.

## Когда применять

Триггеры:
- «запусти os» / `/os`
- «проведи меня по системе запуска» / «веди по фазам от идеи»
- «новый продукт по фазам» / «хочу запустить <продукт>, проведи по шагам»
- продолжение начатого запуска («где я сейчас по системе»)

НЕ применять: разовый GTM-план фичи (→ `launch-marketing`), только инвентаризация линейки (→ `setka-produktov-i-offera`), только проверка жизнеспособности идеи без запуска (→ фаза `idea/`).

## Носители (источники истины, не дублируются)

- **Навигатор** `~/.business/processes/solo-business-path.md` — путь 0→13, маппинг концепт→живой промпт, гейты, под-скиллы, ветвление по архетипу.
- **Тела фаз** `~/.business/processes/prompts.md` — HOW каждой фазы (Pre-0.0/0.4/0.5, Фаза 0-8.8, Приложение M).
- **Статус** `~/.business/scripts/launch-status.py` — где пользователь сейчас (артефакты + ручные гейты `_state.json`).
- **Шаблон статуса** `~/.business/processes/_os-manifest-template.json` — Установка копирует в папку продукта.

## Что делает (петля ведения)

1. **Старт.** Прочитать навигатор. Если папки продукта нет — фаза 0 (Установка): развернуть структуру, проверить скиллы/промпты/гейты, скопировать шаблон-манифест, создать `config`. Есть ⛔ → стоп, доустановить (новый скилл — через skill-craft).
2. **Где я.** Нет папки продукта или `_status-manifest.json` (новый продукт) → НЕ звать скрипт, идти в Установку (Шаг 1). Иначе `python3 ~/.business/scripts/launch-status.py <папка-продукта>` — ВСЕГДА с явной папкой (без аргумента скрипт читает чужой/легаси-запуск с другой моделью фаз). Текущая фаза — по реальным артефактам, НЕ по меткам.
3. **Веди фазу.** Открыть ТОЛЬКО промпт текущей фазы из `prompts.md` (по маппингу навигатора, progressive disclosure — не грузить всё). Выполнить его; результат — в чат + объяснение, затем артефакт.
4. **Под-скилл.** Где фаза = действие — дёрнуть существующий под-скилл (рынок→`resyorch-nishi`; оффер→`setka-produktov-i-offera`/`ценовая вилка по методичке .business/processes/pricing-methodology.md (решают оплаты, не модель)`; контент/запуск→`post/email/carousel/longform/website/bot-message`; продажи→`sales-council`; юр→`yurist`; экономика→`финстратег`; доставка/напоминание→`вайбкодинг`; удержание→`удержание/анти-churn (сегменты по engagement · cancel-flow + контр-оффер · save-offer), методичка .business/processes/pricing-methodology.md`).
5. **Гейт.** На HARD-гейтах (Pre-MVP: 7/10 интервью + 5 предоплат; Установка: нет ⛔) — СТОП, предъявить улику, развилка build/kill пользователю. Числовой гейт пройден → отметить флаг в `_state.json`.
6. **Развилка архетипа.** Архетип (Pre-0.4) параметризует дальнейшие фазы (доставка/цена/удержание/тип запуска). Recurring (club/group) → включить удержание (8.7), иначе пропустить.
7. **Дальше.** Закрыл фазу → следующая по навигатору. Между гейтами иду сам (правило №1), не спрашиваю лишнего.
8. **Петля.** После 13 → новый запуск (Фаза 7, бренд-ассеты переиспользуются) ИЛИ новый архетип (Pre-0.4).

## Принципы

1. **Тонкий слой.** Не дублировать тела фаз — ссылаться на `prompts.md`. Один источник истины.
2. **Статус из артефактов, не из меток.** Только `launch-status.py`..
3. **HARD-гейты не проскакивать.** «5 предоплат / 7 из 10» — нельзя объявить пройденным «чтобы не тормозить». Правило №1 (иду до результата) НЕ перекрывает числовой гейт валидации.
4. **Не выдумывать данные валидации.** Нет реальных интервью/предоплат/цифр → стоп, список «нужно от тебя» (`context-gap`), не плейсхолдер..
5. **Не «школа» по умолчанию.** Формат = архетип пользователя; термины под него (для `one_on_one` — серия сессий, не «поток»).
6. **[ТОЛЬКО ПРОЕКТ] честно.** Фазы доставки/удержания (8.6/8.7) ПРОЕКТИРУЮТ механизм; исполнение авто-напоминаний = отдельная сборка через `вайбкодинг`. Не рапортовать «работает», пока не собрано и не проверено на живых данных..
7. **Прогрессивное раскрытие.** Грузить промпт только текущей фазы, не весь `prompts.md`.

## Anti-patterns

- Копировать тело фазы в скилл (рассинхрон с `prompts.md`). Только ссылка.
- Объявить фазу закрытой по имени файла/метке вместо `launch-status.py`.
- Проскочить HARD-гейт спроса под предлогом «иду до результата».
- Сгенерировать «7 из 10 сказали да» / «5 предоплат», когда реальных данных нет.
- Тащить «курс/школу/когорту/ДЗ» в формат консультанта/клуба.
- Сказать «доставка работает / доходимость растёт», когда напоминание только спроектирован, но не собран кодом.
- Перехватывать атомарные запросы под-скиллов («напиши пост», «сделай оффер») — они идут в под-скилл напрямую, не через os.
- Звать `launch-status.py` без явной папки или навигировать по дефолтному легаси-запуску (его фазы 5–6.x ≠ модель 0→13).
