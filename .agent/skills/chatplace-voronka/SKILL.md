# chatplace-voronka - код-слово в build-sheet для ChatPlace под твою нишу

Называешь код-слово и даёшь вводные про проект - скилл выдаёт `build-sheet-<СЛОВО>.md`, полный
лист сборки флоу в конструкторе app.chatplace.io: собираешь руками блок-за-блоком без единого
решения по ходу. Каркас (GATE→ВЫДАЧА→M1→M2→M3 с таймингами) универсальный, тексты - под
твою нишу и оффер.

## Место в цепочке (почему этот скилл всегда ВТОРОЙ)

Сквозной путь человека по код-слову:

```
IG (карусель/рилз, слово в комменте/директе)
 → ChatPlace: GATE → ВЫДАЧА со ссылкой-входом в TG-воронку
 → TG: подписка на канал → бот за подписку выдаёт лид-магнит → в конце дожим C1-D7
 → параллельно ChatPlace дожимает: M1 (мостик слово→оффер) → M2 → M3
```

СНАЧАЛА `tg-voronka` (строит TG-воронку и даёт ссылку-вход), ПОТОМ этот скилл - он вставляет
эту ссылку в узел ВЫДАЧА. Нет готовой TG-воронки под слово = ChatPlace-воронке некуда вести →
СТОП, сначала `tg-voronka`. Ссылка выдачи «из головы» запрещена: человек попадёт мимо воронки.

## Когда применять

Триггеры:
- «сделай ChatPlace-воронку под слово X» / «воронка в директе под слово X»
- «IG-воронка под код-слово» / «собери флоу в ChatPlace»
- `/chatplace-voronka <СЛОВО>`

## Почему build-sheet, а не автоматизация

ChatPlace не умеет импорт JSON. Узлы конструктора рисуются в `<canvas>` (битмап, не DOM) -
автоматом тянуть стрелки и создавать блоки нельзя. Потолок системности = детерминированный лист
сборки, где думать уже не над чем. Собирать флоу браузером не пытаться - потеря времени.

## 🌉 ШАГ 0 - ПРОФИЛЬ ПРОЕКТА (единый мостик, обязателен)

Ниша, канал, бренд, мини-продукт берём из общего профиля, не переспрашиваем:
1. Есть `~/.business/profile.json` - читай его.
2. Нет - прогони `~/.business/onboarding-profile.md` (сам ищет данные, потом спрашивает недостающее,
   пишет профиль).

Из профиля: ниша/аудитория (для текстов), `brand.channel_url` (для M2/M3), мини-продукт для мостика M1:
- `offer.has_offer: true` → M1 ведёт на `offer.url`.
- `offer.has_offer: false` (продукта пока нет) → M1 ведёт на канал (`brand.channel_url`), тон = рост
  доверия без жёсткой продажи. Появится продукт - правится профиль, следующая сборка ведёт на него.

Под КОНКРЕТНУЮ воронку спрашиваем всегда:
- **Код-слово** воронки.
- **Ссылка-вход в TG-воронку** этого слова - из результата `tg-voronka` (нет - сначала он).
- **Суть лид-магнита** - из живой статьи (H1, лид, подзаголовки).

## Каркас (что в build-sheet)

Универсальный каркас: `~/.business/scripts/chatplace-funnels/etalon-universal-chatplace.md`
(карта узлов, тайминги, функции). Строится build-sheet:

```
Entry → GATE (Card-кнопка «Забрать инструкцию» + словесный фолбэк со словом)
   кнопка ──────────────────────────────→ ВЫДАЧА (ссылка-вход в TG-воронку)
   тело → Save message → Condition(слово) → ВЫДАЧА
ВЫДАЧА → +10 мин → M1 (мостик слово→оффер + offer_url)
       → +2 ч → M2 (польза + канал) → +20 ч → M3 (последнее касание + канал)
```

Сумма задержек ≈ 22ч 10м < 24ч - НЕ увеличивать (24-часовое окно IG).

## Workflow

### 1. Мостик (ШАГ 0) + входы

Слово, ссылка-вход из `tg-voronka`, offer_url, channel_url, суть статьи. Ссылку выдачи
строить из результата `tg-voronka`, не выдумывать и не подставлять ссылку другого слова.

### 2. Суть гайда - только из живой статьи

`curl -sL <article_url>` → H1, лид, H2. Боль в GATE, «что внутри» в ВЫДАЧЕ и мостик M1
опираются ТОЛЬКО на реальное содержимое. Никаких выдуманных фич.

### 3. Тексты - АВТОРСКИЕ под нишу, не шаблонные

Гейт / выдача / мостик пишутся ЦЕЛИКОМ под слово и нишу, каркасных фраз-заготовок нет. Функции
и лимиты узлов - в файле каркаса (`etalon-universal-chatplace.md`, раздел «Функции узлов»):
- GATE ≤460: боль темы + инструкция про кнопку + мотивация нажать сейчас + фолбэк со словом.
- ВЫДАЧА ≤460: конкретика ЭТОГО гайда + ссылка-вход, открытие своё.
- M1-мостик ≤190: персональная связка «запрос слова → твой оффер» + offer_url.
- M2/M3 ≤460: польза + мягкий зов в твой канал.
Финальная зачистка каждого текста через `~/.claude/skills/humaniser/prompt.md`.

### 4. Сборка build-sheet

Собери `build-sheet-<СЛОВО>.md`: по каждому узлу - тип блока, тексты (свои), кнопки, задержки,
условия - строго по каркасу. Проверь инварианты каркаса: каждый `{{...}}` заменён на твоё,
ссылка выдачи = вход именно в TG-воронку этого слова, нет длинных тире.

### 5. Доставка

Показать build-sheet в чат (или путь к файлу). Дальше человек руками собирает флоу в
app.chatplace.io по листу - решать по ходу нечего.

## Anti-patterns

- Выдумать ссылку выдачи или взять ссылку другого слова - только из `tg-voronka`.
- Каркасные фразы-заготовки вместо авторского текста под нишу.
- Пропустить мостик и собирать «вообще», не под конкретный оффер.
- Оставить плейсхолдер `{{...}}` в финальном листе.
