## 🛑🛑🛑 3 НЕРУШИМЫХ ЗАКОНА (нарушены по решению автора, перекрывают весь остальной файл)

Нет ссылки на оригинал = ты сочинил сам = грех. ЗАПРЕЩЕНО: писать контент/текст/углы/факты из головы, «авторить», рендерить из своей головы, выдумывать цифры. Нет подходящего донора → ПРОДОЛЖАЙ ИСКАТЬ через парсер, НИКОГДА не выдумывай взамен.

**ЗАКОН №2 — ФОРМАТ ДОНОРА = ФОРМАТ РЕЗУЛЬТАТА. Находи виралки УЖЕ В нужном формате.** Нужен формат заметок → находи карусели, которые УЖЕ в формате заметок (рукопись на бумаге), и переделывай заметка→заметка. 🔴 ЗАПРЕЩЕНО брать карусель в ДРУГОМ формате (editorial-постер / тёмная карточка / фото-хук / ролик / пиксель-арт / AI-арт) и КОНВЕРТИТЬ её в заметки — это та же грубейшая ошибка, что и сочинение. Формат ищем поиском (визуально по кадрам), не натягиваем на чужой.

**ЗАКОН №3 — оригинал-ссылка кнопкой ОБЯЗАТЕЛЬНА у каждой.** Доставка без ссылки на оригинал запрещена. Машинный guard в `deliver_carousel.py`: нет непустого `_source_url.txt` → отказ слать. Нет ссылки = карусель не привязана к реальному залетевшему оригиналу = по ЗАКОНУ №1 её быть не должно.

## 🛑 АВТОНОМНОСТЬ: НИКОГДА не подавать автору развилку/выбор

Карусели почти всегда запускаются автономно — **автор ушёл / на эфире / не у ПК и физически НЕ может ответить.** Поэтому: **НИКОГДА не заканчивать ход вопросом-выбором** («выбери 1/2/3», «text-prompt или image-in», «что приоритетнее»). Решаю САМ из контекста и довожу до результата. **Конфликт его же требований** (напр. «только image-in» + «10 чистых новых из иностранных источников» физически несовместимы — image-in держит чужой язык/лица, а свежих RU-источников мало) → выбираю путь, который РЕАЛЬНО даёт результат к дедлайну (image-in с сильным RU-промптом по слайду + удаление лиц/ника прямо в промпте; язык всё равно протёк → перерендер слайда жёстче, НИКОГДА не откат на текст-промпт-без-референса/nano), делаю до конца, ПОСТФАКТУМ одной строкой сообщаю что выбрал и почему. Развилка-вопрос = заморозка всей работы пока он не у ПК = провал. Прецедент по решению автора: выдал меню «1/2/3» вместо решения → «тупая мразь, я НЕ должен НИЧЕГО вбирать, я отхожу».,

## 🛑🛑 IMAGE-IN: ОРИГИНАЛ + ПРОМПТ ВМЕСТЕ через Custom GPT — единственный способ (0.0, нарушено)

Уникализация слайда = **я ЗАГРУЖАЮ ОРИГИНАЛЬНЫЙ слайд (референс-картинку) в инструмент картинок ВМЕСТЕ с RU-промптом** (тихий канал: `driver.py` шлёт донора через `codex exec --image`; браузерный: `set_input_files` в кастомку), и она трансформирует РЕАЛЬНЫЙ оригинал → это **`driver_parallel.py`** (делает `set_input_files` = грузит `queue/<pkg>/slide-NN.jpg` оригинал + читает `slide-NN.txt` как промпт по зонам). **ЗАПРЕЩЕНО** рендерить контент-слайд из ОДНОГО текст-промпта БЕЗ референса (`render-from-prompt.py` без картинки) и тем более через nano/higgsfield — это та же грубейшая ошибка, что self-render: выходит «похожий по дизайну» лукалайк, а не трансформация. Прецедент по решению автора: гнал render-from-prompt (текст без референса) и nano → «ты туда не скидываешь референсы», «ты должен ОРИГИНАЛ закидывать вместе с промптами», «конченный кусок говна». ЕДИНСТВЕННОЕ исключение — НАШИ from-scratch CTA-слайды (своя плашка, донор-оригинала нет): их можно текст-промптом через ту же кастомку.

## 🛑🛑🛑 3 ЗАКОНА УНИКАЛИЗАЦИИ (по решению автора — «иди всё переделывай, испортил процесс»)

**1. ВИЗУАЛ ОЧЕНЬ БЛИЗКО К ОРИГИНАЛУ, НЕ редизайн.** Результат ОБЯЗАН выглядеть почти как оригинал — та же композиция / имагери / раскладка / объекты / цвета. Уникализация = ТОЛЬКО: (а) перевод текста на грамотный русский, (б) убрать @ник/брендинг донора → наш бренд + код-слово. **image-in промпт МИНИМАЛЬНЫЙ:** «Сохрани это изображение МАКСИМАЛЬНО близко к оригиналу: та же сцена, объекты, фон, раскладка, цвета. Измени ТОЛЬКО текст (переведи на русский) и убери @ник автора. БОЛЬШЕ НИЧЕГО не перерисовывай.» 🔴 ЗАПРЕЩЕНО: from-scratch обложки, «пересоздай слайд в стиле бренда», elaborate описания нового дизайна — это даёт «абсолютно новое», теряется сходство с проверенной виралкой = брак (прецедент: оригинал Hermes с девушками/пиццей → я выдал терминал-Джарвис). CTA-слайд — единственный наш from-scratch.

**2. ТОЛЬКО МАССОВЫЕ ВИРАЛКИ.** Под реплику брать ТОЛЬКО верх по вовлечённости — тысячи лайков + сотни/тысячи комментариев (для код-слово-каруселей комменты = ключевая метрика). Сотня лайков / десятки комментов = невиральный треш, не реплицировать. ВСЕГДА ранжировать пул `account_fresh_carousels.py` по метрикам, резать низ. Свежесть/тема — НЕ замена виральности.

**3. ВСЕ СЛАЙДЫ, БЕЗ ДУБЛЕЙ.** Рендерить ВСЕ слайды оригинала (НЕ капать число под дедлайн — иначе «14 способов» на обложке vs 5 слайдов в теле = брак). Аудит ловит: (D) дубли — два слайда с одним смыслом/текстом; (N) число на обложке vs реальное число пунктов в теле. Лучше меньше каруселей целиком, чем много обрезанных.

**4. НОВОЕ КОД-СЛОВО + НОВАЯ ВОРОНКА ПОД КАЖДУЮ КАРУСЕЛЬ.** На каждую карусель — СВОЁ новое уникальное код-слово (reserve через `codewords.py`, НЕ из реестра живых) + СВОЯ новая статья-лид-магнит под её точную тему (скилл `lead-magnit` → `website` → FTP-деплой <твой-домен> → живой URL → привязка к боту). 🔴 ЗАПРЕЩЕНО переиспользовать существующие код-слова/магниты (КИТ/ПРИМЕР/АРСЕНАЛ…) ради экономии — всплывают слова, которых автор не ждёт, и тема статьи не совпадает с каруселью. Лучше меньше каруселей, но каждая со своим словом + живой статьёй.

**5. ЧЕЛОВЕК НА СЛАЙДЕ = ТОЛЬКО АВТОР / АТРИБУТИРОВАННАЯ ЗНАМЕНИТОСТЬ / НИКТО (0.0, две правки подряд «полное говно, мозг включи»).** Разобрать КАЖДОГО человека по роли ДО рендера (в `_faces.txt` + `slide-NN.txt`):
- **Слот «я/автор»** (донор показывает себя; или сцена «человек рядом со знаменитостью / у результата») → ставим ЛИЦО АВТОРА (Soul ID / реальное фото, _faces=author/all + face ref, в тексте «замени на меня по фото, лицо 1:1, сцену/позу сохрани»). НИКОГДА не оставлять автора-донора.
- **Знаменитость-КРЮЧОК** (Илон жмёт руку, известный в кадре как ценность сцены) → ОСТАВИТЬ знаменитость (она и есть хук «я рядом с X»). 🔴 НИКОГДА не вырезать знаменитость (прецедент sdv_stm: вырезал Илона → убил смысл «он здоровается якобы со мной»).
- **Знаменитость, чью ЦИТАТУ берём** → оставить лицо + ПОДПИСАТЬ имя, подать как «его цитата» (Тиньков ок; Маргулан без имени = «бредово»). Снятие @ника донора ≠ снятие имени автора цитаты.
- **Никто** → убрать ТОЛЬКО безликого сток-человека без роли.
🔴🔴 **МЕХАНИЗМ ЛИЦА АВТОРА: ChatGPT face-swap РАБОТАЕТ** (автор: «всё получилось идеально, я справа»). 🚫 Higgsfield/Soul ID ЗАПРЕЩЁН автором - НЕ предлагать. Своп = приложить фото автора (`face_image`) вторым вложением + промпт «замени правого на меня по фото, лицо 1:1, Илона/сцену/дизайн сохрани». 🔴 БАГ БЫЛ В МАШИНЕ, не в ChatGPT: своп МЕДЛЕННЫЙ (5-8+ мин), драйвер на `generation_timeout` хватал ОРИГИНАЛ-пассхру вместо готового свопа → ложное «не работает». ФИКС: на свопах таймаут ≥600с + хватать РЕАЛЬНУЮ картинку из ответа ассистента (`fetch` src последней крупной img), не сохранять вход при таймауте; обычный ChatGPT-чат тянет 2 картинки надёжнее карусельной кастомки.

## 🛑🛑 ЖЕЛЕЗНОЕ ПРАВИЛО РЕНДЕРА (нарушалось по решению автора — два дня подряд)

**Слайды рисует ТОЛЬКО инструмент картинок OpenAI по донорскому слайду-референсу. Claude НИКОГДА не рисует слайды сам:** ни `higgsfield-generate`/`gpt_image`, ни кодом (HTML/CSS→Playwright PNG, PIL, matplotlib), ни ASCII, ни «соберу макет руками». Моя работа = ТОЛЬКО подготовка пакета (текст по зонам `slide-NN.txt` + `_design.json` + конфиги) и запуск драйвера. Рисование - исключительно GPT

Законных каналов рендера ДВА, оба гоняются одним и тем же `driver.py`:

1. 🟢 **Тихий, по умолчанию (врезан по решению автора по прямой просьбе автора: «чтобы окна браузера не открывались и не мешали»).** `driver.py <pkg>` без флагов → движок `.business/scripts/codex_image.py` → `codex exec` → системный скилл `imagegen` → встроенный `image_gen`. Донорский слайд и фото лица уходят теми же вложениями (`--image`), то есть это ТА ЖЕ уникализация образ-в-образ, только процессом в фоне: ни одного окна, экран и буфер обмена свободны, слайды рисуются в несколько полос сразу (`--lanes N`, по умолчанию 3). Живой прогон: 2 слайда параллельно, окон Chrome 0, геометрия донора 1080x1350 сохранена один-в-один, кириллица без брака
2. 🟡 **Браузерный, запасной.** `driver.py <pkg> --engine browser` → Custom GPT `carousels-<твой-бренд>` через Playwright (или `driver_parallel.py`). Занимает экран и держит очередь на один браузер. Держим для случая, когда нужна именно кастомка с её системным промптом

🔴 **Лимит аккаунта Codex может быть выжжен.** Тогда тихий канал честно печатает `ЛИМИТ АККАУНТА CODEX выжжен` с датой, когда лимит откроется - это внешний блокер, не брак промпта. Проверить состояние заранее без расхода генераций: `python3 .business/scripts/codex_image.py --selftest`. Пока лимит закрыт - карусели рендерим только запасным браузерным каналом (`--engine browser`)

Почему правило вообще есть: автор много раз получал «лютое говно», когда слайд рисовался НЕ инструментом картинок OpenAI по референсу. ## 🛑 ГЕЙТ перед доставкой: бенчмарк выдачи против ОРИГИНАЛА (правило по решению автора)

Рендер каруселей ОБЯЗАТЕЛЬНО одной вкладкой с паузой ≥30с (`--parallel 1 --delay 30`). Параллель (2 вкладки) скрещивает картинки ChatGPT-веба — слайд возвращается дублем соседнего/обложки . НИКОГДА не рендерить карусель в параллель.

Перед `telegram-deliver.py` прогнать бенчмарк ВЫДАЧИ против исходных слайдов:
1. **Кол-во**: число PNG в output = число исходных слайдов минус удалённые follow-слайды. Расхождение → разобраться, не слать.
2. **md5-уникальность**: `md5 -r output/<pkg>/*.png | awk '{print $1}' | sort | uniq -d` — ПУСТО. Любой дубль = скрещенный рендер, перерендерить одной вкладкой.
3. **Последовательность (для листиклов)**: счётчики на слайдах (1/N … N/N) присутствуют ВСЕ по разу, по порядку, ни один номер не пропущен и не задвоен. Проверять глазами (OCR счётчика), сверяя с оригиналом — каждый исходный смысловой слайд (инструмент/пример/шаг) есть в выдаче и на своём месте.
4. **Сверка контента**: бегло открыть КАЖДЫЙ слайд и сверить с соответствующим оригиналом — тот же субъект, не английский passthrough, не чужой слайд. Зелёный «успех N/N» драйвера ≠ корректный рендер.

После каждого прогона: `bash check_pkg_complete.sh <pkg>` - сверяет НОМЕРА queue slide-NN.txt + cta/prompt-NN.txt против output PNG + md5-дубли. Только COMPLETE → ревью → доставка.
5. **КОРРЕКТОР ПЕРЕД РЕНДЕРОМ.** Свои/агентские тексты в slide-NN.txt и cta/prompt-NN.txt вычитывать ДО рендера (агент-корректор: грамматика, повелительные формы, опечатки). Прецедент: «Наняй все 34» уехало в рендер и стоило перерендера CTA. Ревью выдачи глазами это НЕ заменяет.
6. **РУКОПИСЬ ТЕКСТОЁМКАЯ = ЗОНА СИСТЕМНОГО БРАКА ГЛИФОВ** (в→ь, л→п, м→т, н→h; рецидив даже после побуквенных предупреждений - ВКУС: 2 ретрая, 3 слайда снова брак). На ночных батчах такие доноры в конец или скип; побуквенная расшифровка ломаных слов в промпте чинит только часть. Короткие рукописные CTA проходят.
7. **ДОПУСКИ РЕВЬЮ ПРОГОВАРИВАТЬ РЕВЬЮЕРУ ЯВНО**, иначе ложные FAIL: подпись «<your name>» на CTA-визуале = наш бренд, допустимо; точки-пагинации, бывшие в оригинале донора = зеркалим 1:1, допустимо; McDonald's и пр. бренды СЦЕНЫ новости (не донора) = оставляем. В шаблон ревью-промпта включать блок «Допуски».
8. **CTA-промпты: явно запрещать длинное тире «—» и внутри мокапов** (протекло в чат-мокапы ПОРОГ/РОБОТ), и промпт кавера обязан содержать тот же блок зачистки брендов/лого, что контентные (яблоко на ноутбуке СТОРИС прошло из-за пропуска в моём промпте кавера).
9. **Prep-агенты - строго батчами ≤5-6 параллельно** (лимит уже был в скилле, по решению автора нарушен: 12 одновременно; обошлось, но правило держать).

## 🔴🔴 Уроки по решению автора - ДНЕВНОЙ АВТОНОМНЫЙ БАТЧ (8 каруселей в бот, движок re-make из иностранных доноров). Ключевые приёмы, разблокировавшие рендер

1. **ОБХОДКА-БАЗОЙ для устойчиво застрявшего слайда.** Если конкретный `slide-NN.jpg` таймаутит 3-5 раз ПОДРЯД, а слайды-соседи того же лейаута встают - это висяк на самой картинке (не квота, не промпт). ФИКС: `cp slide-<рабочий-сосед>.jpg slide-NN.jpg` (бэкап оригинала), рендерь slide-NN с ЕГО текстовым промптом на чужой рабочей базе. Лейаут/цвет возьмутся с базы, текст - с промпта. Разблокировал DaRxpoXHFIR slide-03 (5 таймаутов) и DaNJ7hHmKQA slide-08 (3 таймаута) с первой попытки.
2. **ЛИЦА: ДЕКОРАТИВНЫЕ (аватары) заменяемы на иконки, СУБЪЕКТ-лица - нет.** Донор с мелкими круглыми аватарами-фото в дизайне (charliehills-списки скиллов, «34 сотрудника») - ГОДЕН: в промпте «замени круглые аватары-фото плоскими иконками-кружками без лиц» - GPT делает надёжно. Донор, ПОСТРОЕННЫЙ на человеке (селфи/портрет/фото-персонаж/news-лицо CEO как суть) - НЕгоден, скип. Это расширяет пул: дизайн-карусели с аватарами больше не «off-brand».
3. **ОБЛОЖКА С ФОТО ЛЮДЕЙ: prep-агент её ПРОПУСКАЕТ.** Агенты описывают лейаут, но не видят, что центр обложки = групповое ФОТО людей (не аватары). В промпте обложки ЯВНО: «на оригинале по центру фото людей - УБЕРИ полностью, замени тёмным фоном + краб-иконкой, никаких лиц». Прецедент: DaAqUMaDCVx обложка вышла с чужими лицами, чинил отдельным перерендером.
4. **СЛОЖНЫЙ ПРОМПТ → МИНИМАЛ-МИРРОР.** Обложки/плотные слайды с детальной реконструкцией схемы (терминал+кружки+COPY, дерево-схема с 7 карточками) таймаутят - GPT пытается ПЕРЕрисовать из спеки. Укоротить до «сохрани картинку 1:1, включая схему/крабов/мокап, меняй ТОЛЬКО текст» - встаёт быстрее и надёжнее. Разблокировал обложки DaIZ2jsCFEl и DaAqUMaDCVx.
5. **`_faces=author-only` ставит 600с - и жжёт 10 мин/провал.** Висяки интермиттентны (не медленны): слайд, что таймаутил на 600с, встаёт на ретрае за 240с. Для пакетов, где нужна только зачистка углового аватара автора (не своп лица автора), ставить `echo none > _faces.txt` → таймаут 240с, дешевле провал, больше ретраев в окно.
6. **МЕТКИ ТРИАЖА НЕНАДЁЖНЫ - реальный фильтр = prep-агент.** Триаж по 2 слайдам путает доноров (DaNki-4FLXK помечен «charliehills-автоматизация», реально = @milamarksonofficial «sugar daddy» фото-персонаж; DaNlOstiJuh «alexmerzliakov Fable5» = реально charliehills). Prep-агент читает ВСЕ слайды + `_meta.txt`/`_faces.txt` и STOP на браке (RU→RU конкурент / фото-персонаж / не тот пакет). Всегда давать агенту право STOP.
7. **RU→RU конкурент на паузу, иностранных локализую.** См.. Свежий prep-агент отказался препать alexmerzliakov (RU→RU «антибан»-репак) - valid IP-флаг. Развожу: EN-донор → RU-локализация делаю; RU-донор русского конкурента с ник-футером → выношу автору на решение.
8. **CTA-подзаголовок задавать ЯВНЫМ текстом.** Если промпт CTA лишь упоминает «подзаголовок» в раскладке без текста - GPT переводит ДОНОРСКИЙ (у DaL5AUniOaq протёк оффер донора «100+ бесплатных гайдов»). Всегда прописывать наш текст подзаголовка дословно.
9. **🔴🔴 ЕДИНОЕ СООТНОШЕНИЕ 4:5 = 1080x1350 НА ВСЕХ СЛАЙДАХ (автор: «у нас одно расширение, чтобы ничего не обрезалось, ты вообще не попадаешь»).** Custom GPT выдаёт РАЗНОБОЙ соотношений даже внутри одной карусели (замечено: 1024x1536=0.667, 1092x1440=0.758, 1122x1402=0.800, 1159x1357=0.854). IG применяет к карусели ОДНО соотношение (по первому слайду) и РЕЖЕТ остальные под него → контент обрезается по краям. ФИКС ВШИТ: `stamp_watermark.normalize_45()` приводит КАЖДЫЙ слайд к ровно 1080x1350 БЕЗ обрезки (fit-inside + паддинг медианным цветом 4 углов - для full-bleed дизайна с однородным фоном бесшовно). Видео-слайды уже 1080x1350 (video_overlay2). Перед доставкой проверять размеры PNG (`identify`/PIL): любой ≠1080x1350 = брак соотношения. Не полагаться на промпт «сделай 4:5» - GPT его игнорирует, чинит только пост-нормализация.
