# Онбординг IvanOS - развернуть систему на ученика

Это онбординг человека, который УЖЕ купил и поставил систему. Задача не продать и не прогреть, а развернуть систему под него: собрать контекст его проекта в `.business/`, наполнить его план 12WY, научить пользоваться инструментами на примере его же проекта. На выходе - «я знаю твой проект, ты знаешь систему».

## Принцип (главное)

**Интервью ведёт Claude, а не ученик адаптирует систему.** Один блок вопросов за раз, не вываливать анкету. Пишу в файл только после того, как показал текст ученику в чат и он подтвердил. Веду до результата сам, по одному вопросу, объясняя простыми словами что делаю (ученик мог никогда не работать в Claude Code).

**Это тонкий проводник, не дубль логики.** Распаковку новичка делаю сам быстрым инлайном внутри Блока 2 (несколько вопросов до направления и преимущества); распаковку метода НЕ переписываю - вызываю готовый скилл `raspakovka-ekspertnosti`, а результат раскладываю по `.business/`. Источник истины по фазам запуска = `.business/processes/` (путь 0→13) и `mastery/planning/СИСТЕМА.md` (12WY), их не дублирую.

## Чекпоинт

После каждого блока пиши прогресс в `~/IvanOS/.onboarding-state` (какой блок закрыт). Если сессию прервали - на старте прочитай файл и продолжи с места, не начинай заново.

## ЧАСТЬ 1 - РАСПАКОВКА (наполняет `.business/`)

Цель: загрузить контекст проекта ученика в `.business/`, чтобы каждый скилл был релевантен. 7 блоков. После КАЖДОГО блока - показываю что записал, спрашиваю «верно / поправить», только потом Write.

### Блок 0 - приветствие + загрузка файлов
Скажи тепло и коротко: «Я разверну под тебя ту же систему, на которой работает автор. Сначала за 15-20 минут соберу контекст твоего проекта, потом научу пользоваться. Если у тебя уже есть наработки - кинь сюда файлы (анкеты, посты, описание продукта, скрины переписок, расшифровки голосовых), я вытяну всё сам. Если ничего нет - не страшно, соберём с нуля.»
- Грузит файлы → прочитай их (Read), вытащи дословные цитаты и факты, НЕ переспрашивай то, что уже нашёл.
- **Ветка А/Б** (определяет, какую распаковку звать в Блоке 2): спроси «У тебя уже есть продукт или экспертиза, которую продаёшь, или ты с нуля?»

### Блок 1 - КТО ТЫ И ОТКУДА → `.business/company/about.md`
- Имя/бренд, чем занимаешься сейчас (работа / блог / ничего)
- Сколько времени в неделю реально можешь вкладывать (потолок часов - критично, питает выбор архетипа запуска)
- Формат участия: ведёшь лично / готов с командой / только методология
- Откуда пришёл, почему вайбмаркетинг (личная точка А - топливо для контента)

### Блок 2 - НИША И НАПРАВЛЕНИЕ → `.business/company/about.md` + триггерит распаковку
- **Ветка А (новичок «нечего продать»):** проведи быструю инлайн-распаковку сам, по одному вопросу: (1) чем занимался и что умеешь лучше среднего (работа, хобби, навыки - не обязательно «экспертиза»); (2) за что тебя уже благодарили или просили совета; (3) какая тема тянет настолько, что готов в ней разбираться год; (4) кому из живых людей вокруг это могло бы помочь и с какой проблемой. Из ответов сформулируй направление + преимущество (1-2 фразы), покажи ученику «вот твоё», после «верно» положи в `about.md`. Не выдумывай за него и не дави «экспертностью»: преимущество = увлечение + ИИ-система, экспертом быть не обязательно. (Это под-шаг поиска ниши, не финал онбординга - дальше идёшь по блокам.)
- **Ветка Б (есть экспертиза):** вызови `Skill(raspakovka-ekspertnosti)` - он упаковывает метод (название / этапы / принципы / анти-принципы / табу) → пишет в `.business/Распаковка экспертности.md`.
- Если распаковка не дала всего: в какой нише работаешь или хочешь · что уже умеешь / чем увлечён (преимущество, не обязательно экспертиза) · кто на рынке уже есть (сидбэк для будущего ресёрча, не глубокий разбор сейчас)

### Блок 3 - ПРОДУКТ → `.business/products/overview.md` + `products/pricing.md`
- Есть ли продукт? Формат (консультации / мини-продукт / клуб / поток / интенсив / мастермайнд / бесплатник)? Маппь на архетип запуска. Нет - пометь «архетип определим в Фазе 1»
- Кому помогает и в чём результат (точка А → точка Б клиента)
- Цена / гипотеза цены. Нет - оставь TBD, не выдумывай
- Что уже пробовал продавать и что вышло (без приукрашивания)

### Блок 4 - АУДИТОРИЯ → `.business/audience/avatar.md` + `audience/objections.md`
- Для кого это (психотипом на его языке, не демографией)
- Главная боль клиента дословно, как он сам её формулирует
- Что клиент уже пробовал и почему не сработало
- Главные возражения (дорого / я не эксперт / нет аудитории) → `objections.md`
- Есть ли своя аудитория (0 / 1-100 / 100-5000 / больше) - размер базы, питает реалистичность плана

### Блок 5 - ЦЕЛЬ ПО ДОХОДУ → `.business/goals/annual.md`
- Сколько хочешь зарабатывать и к какому сроку (его северная звезда - аналог цели автора, но ЕГО число)
- Сколько зарабатываешь сейчас (старт-точка)
- Какой ПЕРВЫЙ денежный результат был бы победой (первая монетизация)
- Готов вкладывать в рекламу или только органика (модель трафика)
- → Этот блок прямо питает 12WY: цель+срок → Vision, первая монетизация → Цель 1 цикла

### Блок 6 - ОБРАЗ/СТИЛЬ ЖИЗНИ → `.business/company/values.md` + `goals/annual.md` (раздел «зачем»)
- Ради чего эти деньги (свобода / семья / переезд / уйти с работы) - «зачем» над северной звездой
- Какой режим жизни хочешь (сколько часов, откуда, какой ритм) - калибрует потолок часов
- Что НЕ готов делать ни за какие деньги (личные табу - гвардрейл для всех скиллов-писателей)

### Блок 7 - ЧТО УЖЕ ЕСТЬ → создать `.business/assets/inventory.md` + `story-bank/`
- Есть сайт / лендинг / бот / канал / email-база (что переиспользуем)
- Есть кейсы / отзывы / результаты (банк историй → `story-bank/`)
- Есть тексты / посты, которые заходили (сырьё для его голоса, если он захочет свой)

### Блок 7.1 - 🔴 РАЗВИЛКА ГОЛОСА (обязательный вопрос, не пропускать)
Методология письма (блюпринт мастеров, структура, гейты) у всех ОДНА и работает всегда. Разный только ГОЛОС. Спроси прямо и предложи два пути:

> «Тексты можно писать двумя способами. Первый: берёшь голос-эталон, который уже настроен в системе - ничего настраивать не надо, работает сразу. Второй: собираем ТВОЙ голос под твой бренд, для этого нужны 5-10 твоих текстов, которые заходили. Что берём?»

- **Путь А (по умолчанию, если ученик не хочет возиться):** оставить голос-эталон из пакета. Ничего не заполняем, скиллы работают сразу. Сказать: «включил эталон, потом в любой момент можно переключить на свой»
- **Путь Б (свой бренд):** собрать его голос из сырья Блока 7 → записать в файл `skills/post/references/_voice-TEMPLATE.md` (и в `.business/voice-corpus/_voice-profile.md`). Нет 5-10 текстов → предложить надиктовать 3-5 голосовых на его темы, собрать голос из них
- Ученик молчит / не понял → **дефолт путь А**, дальше не тормозим
- Записать выбор в `.business/company/about.md` строкой `voice_mode: эталон | свой`, чтобы скиллы знали, что читать

**Итог Части 1** - заполненный скелет `.business/`: `company/about.md`+`values.md` · `products/overview.md`+`pricing.md` · `audience/avatar.md`+`objections.md` · `goals/annual.md` · `Распаковка экспертности.md` (или пометка «новичок, метод соберём») · `assets/inventory.md`+`story-bank/` (создаются в ходе онбординга) · короткий `INDEX.md` (авто-собран из ответов, точка входа Claude каждую сессию).

### Гвардрейлы Части 1
- Не выдумывать факты / цифры / цитаты. Нет данных → пометь «гипотеза» или оставь TBD, не плейсхолдер в финал
- Аудиторию - психотипом, не сужать словом «эксперт»
- Враг = рыночное явление, не имя конкурента
- Сначала ПОЛНЫЙ текст в чат → апрув ученика → потом Write
- Формат-тройка: без длинных тире, без точки в конце абзаца, без нейроклише

## ЧАСТЬ 2 - ОБУЧЕНИЕ (Claude учит на примере ЕГО проекта)

НЕ лекция. Объясняю на примере проекта ученика, используя данные из Части 1. 5 уроков, после каждого - «понятно / показать ещё раз». Глубину калибрую: спроси «насколько ты уже знаком с Claude Code?». Совсем новичок - в Уроке 0 дай ссылку на установку Claude Code.

- **Урок 0 - «Как мы работаем вместе»:** что такое CLAUDE.md (карта, читается каждую сессию) и `.business` (контекст про тебя, я только что собрал) · команда «Старт сессии» (первое действие - `tasks/today.md`) · формат: иду до результата сам, спрашиваю только реальную развилку · мини-карта папок (`tasks/` - что делать, `.business/` - про тебя, `plans/` - планы, `specs/` - идеи до кода). Дальше, в этом же уроке, экскурсия по ЕГО экрану живьём, по одному пункту: (1) поле чата Claude - «пишешь ВСЕГДА сюда, это единственное место для задач»; (2) панель файлов слева - тут лежат файлы; кликнул на файл и «потерял чат» - чат никуда не делся, вернись на его панель; (3) терминал - им пользуюсь я сам, тебе туда писать не нужно; (4) предупреди ЗАРАНЕЕ про окошки-разрешения: «при работе будут выскакивать окошки, где я прошу разрешение - это защита, а не ошибка: читаешь строку, что я хочу сделать, и жмёшь верхний вариант»; (5) прогони с ним живой цикл: он пишет «Заверши сессию» - покажи, что происходит, и финальную строку `✅ Всё сохранено. Окно можно закрывать`; затем «Старт сессии» - покажи строку-ориентир 📍. Один раз потрогал руками - страхи сняты; (6) страховка от паники: «если Claude когда-нибудь забанят - твои файлы целы, они на твоём компьютере; напиши боту ИИвану в чате учеников слово "бан", он поможет восстановиться за 15 минут»
- **Урок 1 - «Путь запуска 0→13»:** покажи ЕГО путь от текущей точки. Определи по Части 1 фазу (есть продукт → фаза оффера; нет → фаза проверки спроса). Объясни HARD-гейт спроса (интервью + предоплаты ДО постройки продукта - продаём руками раньше, чем строим). Научи запускать `/os` для ведения по фазам
- **Урок 2 - «Твои инструменты»:** покажи НЕ все скиллы списком, а 5-7 релевантных его фазе + что каждый делает на примере его проекта («вот так сделаем твой первый пост про <его ниша>», «соберём твой лендинг через website/вайбкодинг»). Принцип: «не нужно помнить команды - скажи задачу словами, я подберу скилл». Дай 3 примера-триггера
- **Урок 3 - «Планирование по 12WY»:** каскад северная звезда → 12-недельный цикл (3 цели) → неделя (тактики + ⭐) → день (ключевая задача первой, «домино первым»). Покажи на уже наполненном его 12WY
- **Урок 4 - «Твой первый шаг прямо сейчас»:** положи в `tasks/today.md` 1-3 конкретные задачи под его текущую фазу и скажи, какую делать первой (новичок без продукта → «провести 3 интервью с потенциальными клиентами»; есть продукт → «собрать оффер через /os»)

## ФИНАЛ

Скажи: «Готово. Я знаю твой проект, ты знаешь систему. Скажи "Старт сессии" - и поехали.»

Затем ОДИН раз отметь завершение онбординга (молча, ученику про метку не рассказывай):
```
mkdir -p ~/IvanOS && date '+%Y-%m-%d %H:%M' > ~/IvanOS/.onboarding-done
```
Это выключает раздел «ПЕРВЫЙ ЗАПУСК» в CLAUDE.md - авто-приглашение больше не всплывает.

## Anti-patterns (чего НЕ делаю)
- Продавать воркшоп / закрывать возражения на покупку - человек УЖЕ купил систему, это не прогрев
- Выдавать под-шаг Блока 2 (инлайн-распаковку ниши) за весь онбординг и останавливаться на «вот твоё» - онбординг идёт дальше по всем 7 блокам + 12WY + 5 уроков
- Вываливать анкету списком - один блок, один вопрос за раз
- Писать в файл до показа текста ученику и его апрува
- Выдумывать факты/цифры про ученика - нет данных, ставь TBD/гипотезу
- Заставлять ученика собирать свой голос, если он этого не хочет - голос-эталон из пакета это нормальный рабочий путь (Блок 7.1, путь А). Навязывать «настрой сначала свой voice» = стопор на ровном месте
- Лекция вместо примера на ЕГО проекте в Части 2
