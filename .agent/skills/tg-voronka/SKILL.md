# tg-voronka - код-слово в готовую TG-воронку под твою нишу

Называешь код-слово и рассказываешь про свой проект - скилл выдаёт `voronka-<СЛОВО>.json`,
который твой технарь (или ты сам) импортирует в SaleBot без правок: воронка разворачивается
сама. Каркас воронки (14 узлов, дуга A0→B0→C1-C4→D1-D7 с таймингами) - универсальный и
проверенный. Тексты пишутся ПОД ТВОЮ нишу и оффер. Ни к какому конкретному эксперту, продукту
или нише каркас не привязан.

## Когда применять

Триггеры:
- «сделай воронку для слова X» / «воронка под код-слово X»
- «TG-воронка» / «сгенери воронку под слово»
- `/tg-voronka <СЛОВО>`

НЕ этот скилл: одиночный пуш/рассылка (это `bot-message`), IG-сторона воронки в ChatPlace
(это `chatplace-voronka`). «Воронка целиком / обе стороны» = этот скилл ПЕРВЫЙ, потом
`chatplace-voronka` (он берёт ссылку-вход из результата этого скилла).

## 🌉 ШАГ 0 - ПРОФИЛЬ ПРОЕКТА (единый мостик, обязателен)

Не переспрашивай всё заново на каждой воронке. ШАГ 0 = профиль проекта эксперта:
1. Есть `~/.business/profile.json` и заполнен - читай его, ниша/канал/бренд/мини-продукт уже там.
2. Нет или пуст - прогони онбординг `~/.business/onboarding-profile.md`: он СНАЧАЛА сам ищет данные
   (готовые воронки/статьи/конфиги эксперта), потом спрашивает ТОЛЬКО недостающее и пишет profile.json.

Из профиля берёшь нишу/аудиторию (для текстов), `brand.channel_url` (канал) и мини-продукт:
- **`offer.has_offer: true`** → продающая воронка, кнопки дожима C1-D6 на `offer.url`.
- **`offer.has_offer: false`** (у новичка продукта ещё нет) → воронка растит доверие и ведёт на канал:
  `offer_url` = `brand.channel_url`, тон C1-D7 = прогрев без жёсткой продажи. Появится продукт -
  эксперт правит `offer` в профиле, следующая сборка сама начинает вести на него, перестраивать нечего.

Под КОНКРЕТНУЮ воронку нужны ещё два входа, их спрашиваем всегда:
- **Код-слово** - слово-триггер (кириллица), напр. РАЦИОН, СТАРТ, ДОСТУП.
- **Лид-магнит** - ссылка на статью-гайд (`article_url`), её делает скилл `lead-magnit`. Нет статьи -
  СТОП: сначала лид-магнит, потом воронка.

Проверку подписки НЕ спрашиваем (по умолчанию её нет, см. ниже).

## 🚪 Вход в воронку

Трафик из карусели/рилз/ChatPlace ведёт СРАЗУ в бота эксперта по deep-link:
`t.me/<его_бот>?start=<КОДСЛОВО>`. Никакого закрытого канала по заявке (это сложно, ученик не настроит).

**По умолчанию (`subscribe_check: false`) - БЕЗ подписки:** первое сообщение бота (A0) сразу даёт кнопку
«Забрать», человек нажал - бот тут же отдаёт лид-магнит. Ничего не проверяем, настраивать нечего. Это
дефолт для всех: ученики технические новички, лишний шаг им не нужен.

### Проверка подписки - ТОЛЬКО по явной просьбе эксперта

Добавляем, лишь если эксперт САМ сказал «хочу, чтобы бот проверял подписку». Тогда `subscribe_check: true`:
A0 просит подписаться на канал, кнопка «Я подписался». Проверка РЕАЛЬНАЯ и зашита прямо в JSON -
калькулятор блока выдачи зовёт официальную функцию SaleBot `tg_get_chat_member(-100<id_канала>,
platform_id)` (docs.salebot.pro, «Проверка подписки»): подписан - отдаём гайд, нет - просим подписаться
и нажать снова. Ничего в SaleBot руками не докручивают, всё в файле.

Для этой ветки нужны два условия:
- поле `channel_id` в батче - ЧИСЛОВОЙ id канала (без `-100`, его добавляет генератор), напр. `1552326755`.
  Узнать id: переслать любой пост канала боту @username_to_id_bot или @getmyid_bot.
- бот эксперта должен быть АДМИНОМ канала (иначе Telegram не даёт проверить членство).

Без явной просьбы эту ветку не предлагаем и не строим.

## Архитектура (что генерится)

Универсальный эталон: `~/.business/scripts/salebot-funnels/etalon-voronki.json` (структура
воронки: 14 узлов, 11 связей; при R-расширении +2 узла). Дуга:

```
A0 (deep-link по слову; просит подписаться на канал + кнопка)  ← вход + подписка
 → B0 (condition = кнопка A0, inline-кнопка на лид-магнит)      ← выдача гайда
 → TECH (condition: link_was_pressed <статья>)          ← фиксирует, что гайд забрали
 → C1 +30 мин · C2 +1 ч · C3 +2 ч · C4 +8 ч             ← продажа оффера, день 1
 → D1..D7 ежедневно 07:01                               ← прогрев-дуга, дни 2-8
D7 - прощание + ссылка на твой канал
```

**Функции узлов дуги - что писать под нишу** (эти тексты скилл пишет сам, под тему из мостика):
- **C1** (+30 мин): личная история - что изменилось, когда клиент/ты САМ перешёл от изучения к делу.
- **C2** (+1 ч): снятие главного возражения ниши («это не для меня / не получится / нет времени»).
- **C3** (+2 ч): срочность без давления - «идеального момента не будет», окно действия.
- **C4** (+8 ч): развилка «прочитать и забыть vs внедрить» + мягкая подводка к офферу.
- **D1** (день 2): зеркало - «сколько ты уже знаешь, а дело стоит».
- **D2** (день 3): «знания есть, а результата нет - потому что не показали весь путь целиком».
- **D3** (день 4): настоящий тормоз ниши (не тот, что на поверхности).
- **D4** (день 5): «поздно не бывает» - снятие возраста/опыта/старта.
- **D5** (день 6): ответ на самое частое возражение-вопрос из личных сообщений.
- **D6** (день 7): закрытие набора - дедлайн, что получит, финальный призыв.
- **D7**: прощание по-человечески + код-слово + ссылка на твой канал.

**R-расширение (опционально):** пара полей `r1_text`/`r2_text` добавляет пуши тем, кто вошёл
по слову, но НЕ нажал «Забрать»: A0 +1ч → R1, R1 +23ч → R2, та же кнопка «Забрать».

## Workflow

### 1. Мостик (ШАГ 0) - собрать нишу/оффер/слово/ссылки

Без 6 входов не идём дальше. Нет статьи лид-магнита - СТОП.

### 2. Суть гайда - только из живой статьи

`curl -sL <article_url>` → вытащить H1, лид-абзацы, H2. Тексты A0/B0 и вся дуга C1-D7
опираются ТОЛЬКО на реальное содержимое статьи и нишу: никаких выдуманных цифр и фич.

### 3. Тексты дуги под нишу (пишет скилл)

Запиши в `~/.business/scripts/salebot-funnels/content/<batch>.json` объект `{"words":[ {...} ]}`,
где для слова заданы поля:
- `word`, `article_url`, `idx` (порядковый номер, любой уникальный)
- `a0_mid` - «Держи то, ради чего зашёл. Гайд про [тема]: [что получишь], даже если [барьер]»
- `b0_body` - «Это не лонгрид, а карта по шагам: [суть]. Внутри - [состав]»
- `b0_start` - «С чего начать: [первый шаг ИЗ статьи]»
- `c1_text`…`c4_text`, `d1_text`…`d7_text` - тексты узлов дуги по функциям выше, под нишу
- `offer_url` - кнопки C1-D6; `channel_url` - канал подписки в A0 и кнопка D7
- (опц.) `subscribe_check` - ставим `true` ТОЛЬКО если эксперт сам попросил проверку подписки; по умолчанию false (не спрашиваем, простая версия)
- (опц.) `channel_id` - при `subscribe_check: true` обязателен: числовой id канала для `tg_get_chat_member`
- (опц.) `r1_text`, `r2_text`

Финальная зачистка КАЖДОГО текста через `~/.claude/skills/humaniser/prompt.md`: без нейроклише,
без длинных тире (только дефис), абзацы без точки в конце, живой голос.

### 4. Генерация + бенчмарк (оба обязательны)

```bash
cd ~/.business/scripts/salebot-funnels
python3 generate.py content/<batch>.json      # строит output/voronka-<СЛОВО>.json
python3 benchmark_universal.py                # структурный бенчмарк каждого файла
```

Бенчмарк проверяет: топологию связей и тайминги = как в эталоне (каркас не сломан), что КАЖДЫЙ
узел заполнен под нишу (не осталось плейсхолдеров `{{...}}`), что offer_url/channel_url реально
подставлены, код-слово в A0, отсутствие длинных тире. Любой FAIL = чинить причину, файл не отдавать.

### 5. Доставка

Показать: слово, статья, вердикт бенчмарка, 1-2 фрагмента текста. Файл лежит в `output/` -
назвать путь. Технарь импортирует `voronka-<СЛОВО>.json` в свой SaleBot как есть.

## Принципы

1. Каркас (топология + тайминги + дуга C1-D7) - универсальный, не трогаем. Меняется тема текстов.
2. JSON руками не писать - только `generate.py` глубокой копией эталона.
3. Результат без бенчмарка = не результат. PASS обязателен.
4. Всё под нишу из мостика: ни одного плейсхолдера `{{...}}` в финале.
5. Единственное действие читателя = регистрация/переход по офферу. Не давать другую «домашку».

## Anti-patterns

- Выдумать факты «что внутри гайда» или ссылку статьи - только живая статья + вводы мостика.
- Собрать JSON вручную, минуя generate.py.
- Отдать файл при FAIL бенчмарка или с оставшимся плейсхолдером.
- Пропустить мостик и генерить «вообще» - воронка обязана быть под конкретную нишу и оффер.

## Файлы конвейера

```
~/.business/scripts/salebot-funnels/
├── etalon-voronki.json          ← универсальный эталон (структура + плейсхолдеры)
├── generate.py                  ← генератор (deep copy эталона + твои тексты и ссылки)
├── benchmark_universal.py       ← структурный бенчмарк
├── content/<batch>.json         ← твои тексты дуги per слово
└── output/voronka-<СЛОВО>.json  ← готовый файл под импорт в SaleBot
```
