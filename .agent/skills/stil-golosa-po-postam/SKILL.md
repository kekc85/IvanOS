# Стиль голоса по постам

Извлекай характерный голос эксперта **эмпирически из его реальных опубликованных постов**, не из его слов о себе. Результат — детальный профиль стиля по каждому каналу (TG-посты / IG-карусели / разговорные рилзы / overlay-рилзы), который скиллы-писатели используют как образец для генерации в его голосе.

Читай данные **из локальных `.md` файлов архива** `.business/growth/content-archive/Мой контент/записи/` через Glob+Read, парси YAML-frontmatter и текст. Эксперт ничего не выгружает руками — Claude в Cowork видит файлы напрямую.

Записывай результат в один файл `.business/Мой стиль для разных каналов.md` (база знаний) с разделами по каналам — без подстраниц, без MCP-вызовов.

## Что скилл НЕ делает (чтобы не пересекаться с соседями)

- Распаковка экспертности (метод, принципы, табу) — отдельный скилл.
- Сегментация ЦА — отдельный скилл.
- Outliers и «что зашло у аудитории» — это работа скилла Аналитика своего профиля. Здесь только характерный голос автора, без слоя «что отличает зашедшие посты». Outliers как признак не используются.
- Темы и темник — скилл Сетка контента.

Без эмпирического стиля скиллы-писатели сваливаются к усреднённому ChatGPT-голосу: правильно, гладко, но не «твоё». Поэтому стиль вытаскивается из его собственных текстов через систематический анализ, не через вопрос «опиши свой стиль» (на такой вопрос эксперты отвечают плохо и неправдиво).

Скилл одноразовый при онбординге, повторяется раз в 3–6 месяцев или при заметном дрейфе. Запускается **после** скилла Скрапинг архива (иначе папка пустая) и скилла Распознавалка постов (иначе у IG-каруселей и разговорных рилзов пустой `recognized_text`).

## Жёсткие принципы

1. **Только эмпирически.** Стиль голоса строится из реальных постов, не из распаковки / ЦА / описаний. Исключение — pre-baseline режим (см. `references/pre-baseline-mode.md`), где источник = слова эксперта, и это явно помечено в статусе.

2. **Не путать стиль и темы.** Стиль = «как пишет» (ритм, конструкции, эмодзи). Темы = «о чём пишет» — задача других скиллов.

3. **Не путать стиль и метод.** Метод эксперта (что он делает с клиентами, какие принципы работы) — в Распаковке экспертности. Стиль — только речевой / типографический отпечаток.

4. **Цитаты-иллюстрации внутри каждого слоя обязательны.** Любой описанный паттерн сопровождается 1–3 дословными цитатами из постов (15–40 слов). Без отсылок и ссылок — нейронка-писатель не открывает внешние ссылки, всё нужное должно быть в самом тексте профиля. Цитаты идут прямо после описания приёма в кавычках.

5. **Анти-стиль через отсутствие.** «Чего нет» (мат / канцелярит / капс / превосходные степени / штампы) — отдельным блоком в каждом канале. Это сильный сигнал для скиллов «чего НЕ делать».

6. **Соблюдение минимумов.** При недоборе порога — ограниченный профиль с пометкой или пропуск канала; не «натягивать сову». На малой выборке стиль шумный, паттерны ложные — лучше честный «рано, накопи» чем выдать неверный профиль.

## Фаза 0.0. Пути (источник — `.business/`)

Перед стартом фаз определи корневые папки `.business` через Glob. Паттерны содержат подстановку, чтобы найти папку с префиксом цифры (`1. Контекст`) или без (`Контекст`) — ученик может убрать префиксы и скилл всё равно найдёт:

- Все артефакты эксперта живут в `.business/` (наш источник под git). Подпапки ниже.
- контекст (ЦА, метод, продукты, голос) → `.business/`
- архив контента → `.business/growth/content-archive/`
- аналитика → `.business/growth/analytics/`
- производство и план → `.business/growth/production/`
- внешние материалы → `.business/growth/materials/`

Если корень не найден — сообщи эксперту: «Не нашёл папку „<имя>"». Если корень релевантен скиллу (`.business/growth/content-archive`, `.business`) — стоп; иначе продолжай без него.

Дальше во всех фазах используй переменные вместо хардкода путей.

Если у эксперта совсем нет архива (папка пустая или <5 записей в каждом канале) — предложи pre-baseline режим (см. референс).

## Источник данных и обработка

Архив постов лежит в `.business/growth/content-archive/Мой контент/записи/<YYYY-MM-DD> <тип> <id>.md`. Каждый файл: YAML-frontmatter + опциональное тело.

Пример frontmatter:

```yaml
---
id: "DXwMNfika2D"
published: 2026-04-30
network: Instagram
type: карусель
url: "https://www.instagram.com/p/DXwMNfika2D/"
caption: "Залетай в моё сообщество по нейронкам для экспертов..."
recognized_text: "Слайд 1: ...\nСлайд 2: ..."
likes: 25
comments: 2
outlier: false
---
```

**Маппинг полей для анализа:**

| Что нужно скиллу | Поле frontmatter |
|---|---|
| Соцсеть (фильтр) | `network` (Instagram / Telegram) |
| Тип контента (фильтр) | `type` (карусель / рилз / пост) |
| Подпись (overlay-рилзы, IG-посты с короткой подписью) | `caption` |
| Распознанный текст (карусели, разговорные рилзы, TG-посты) | `recognized_text` |
| URL для drill-down | `url` |
| ID | `id` |

Поля `outlier`, `likes`, `viewers` и аналитика — **не используются** в стилевом профиле. Стиль одинаков и для зашедших, и для не зашедших постов.

**Алгоритм чтения:**

1. `Glob ".business/growth/content-archive/Мой контент/записи/*.md"` — список всех записей.
2. Для каждой записи `Read`, парсинг YAML-frontmatter и тела.
3. Сгруппировать через code execution в Python: `defaultdict(list)` по ключу `(network, type)`.
4. Получить 3–4 группы:
   - `(Telegram, пост)` → источник: `recognized_text` (у TG он приходит из скрапа сразу)
   - `(Instagram, карусель)` → источник: `recognized_text` (после распознавалки)
   - `(Instagram, рилз)` → классифицировать на разговорные/overlay (см. Фазу 1)
5. Передать группы в Фазы 2–5.

Используй code execution для статистик (длина предложения/абзаца, частоты слов, эмодзи) — LLM в уме считает плохо. Для извлечения паттернов и формулировок — обычный LLM-проход.

## ФАЗА 1. Классификация рилзов: разговорные vs overlay

Рилз бывает двух жанров — разговорный (эксперт в кадре, голос → транскрипция в `recognized_text`) и overlay (b-roll с наложенным текстом, голоса нет → транскрипция пустая/«Music», смысл живёт в `caption`). У них принципиально разный стиль: разговорный — устная речь, overlay — короткая письменная заявка под видео. Если их смешать в одну выборку — профиль будет шумным.

**Алгоритм классификации каждого рилза:**

```
если recognized_text содержит >200 символов И не равен «Music» / placeholder
    → РАЗГОВОРНЫЙ. Анализируем recognized_text.
иначе если caption содержит >200 символов И содержательна
    → OVERLAY. Анализируем caption.
иначе если caption содержит 50–200 символов И содержательна
    → OVERLAY-короткий. Анализируем caption отдельной веткой (см. Фазу 5).
иначе
    → ПРОПУСКАЕМ. Слишком мало текста для стиля.
```

«Содержательна» = не «👀», не «🔥🔥🔥», не «комменты», не одна ссылка — а связный текст в 2+ предложения.

Если разговорных кандидатов <20 — Фаза 4 идёт в ограниченном режиме. Если overlay-кандидатов с подписями ≥200 знаков <20 — Фаза 5 пропускается. Если overlay-кандидатов 50–200 знаков ≥20 — есть отдельный профиль «короткий формат overlay» (см. Фазу 5).

## Восемь слоёв описания (единый шаблон для каждого канала)

Все каналы описываются по одному шаблону из восьми слоёв. Какой именно текст идёт на анализ — зависит от канала.

### 1. Тон и голос

- **Обращение к читателю.** На «ты» / «вы» / нет обращения / смешанное. Если смешанное — отметь когда какое.
- **Эмоциональный фон по умолчанию.** Тёплый / разбирающий / провокационный / саркастичный / мечтательный / сдержанно-аналитический / прямой-без-смягчений. Бывает несколько режимов — отметь основной и побочные.
- **Степень формальности.** Разговорный / нейтральный / профессиональный.
- **Позиция автора.** От первого лица / от лица сообщества / отстранённый-наблюдатель / смешанная.

### 2. Ритм и длина

- **Средняя длина предложения** в словах (считай эмпирически через code execution).
- **Средняя длина абзаца** в предложениях.
- **Средняя длина поста / слайда / скрипта целиком** в словах и в знаках.
- **Однородность ритма.** Любит ли короткие рубленые предложения вперемешку с длинными или ровный поток? Если есть характерный приём («длинный заход — точка — короткое утверждение») — опиши.

### 3. Архитектура

- **Как заходит** (хук). Вопрос / факт / личная сцена / провокация / цитата / диалог / контраст. Перечисли с примерами и долей: «личная сцена ≈40%, прямой тезис ≈30%, вопрос ≈15%».
- **Как разворачивает.** 3-act (проблема → анализ → решение) / нумерованный список / FAQ / поток сознания / разбор кейса / метафорическая развёртка. Часто несколько режимов — отметь основные.
- **Как закрывает.** Призыв / вопрос аудитории / афоризм / личная сцена / без закрытия / ссылка / следующий пост.

### 4. Форматирование (особенно критично для TG)

- **Жирный** — частота, на чём ставится акцент (тезисы / имена / цифры / эмоциональные слова).
- **_Курсив_** — частота, для чего.
- **Списки** — нумерованные / маркированные, длина.
- **Пустые строки между мыслями** — частота, где (после абзаца / между ходами мысли / для пауз).
- **Разделители** — `—`, `***`, эмодзи как разделитель.
- **Цитаты-блоки** — использует ли, для чего.

Для каруселей: акцентируй текстовые приёмы на слайдах (первый слайд = крючок, последний = призыв или вывод).

Для рилзов разговорных: форматирование текста минимально, но отметь разбивку на смысловые куски. Для overlay-рилзов: подпись короткая, форматирование редкое.

### 5. Лексика и обороты

- **Любимые слова** — повторяющиеся знаменательные (не предлоги): существительные / глаголы / прилагательные. Минимум 5 примеров с указанием частоты «слово X встречается в N постах из M».
- **Фирменные конструкции** — повторяющиеся обороты-сцепки. Примеры разной природы: «короче», «давайте сразу скажу», «не мороси», «и вот тут самое интересное», «правда в том, что». Это **сигнатуры голоса**, скиллам-писателям критично иметь список.
- **Англицизмы и заимствования** — какие приживаются («контент», «ниша», «стек») и какие выглядят чужими / не встречаются.
- **Идиомы, поговорки, профессиональный сленг** — что регулярно использует.

### 6. Образный слой

- **Метафоры из каких сфер** — спорт / война / кухня / стройка / театр / медицина / IT / финансы / природа. Отметь основные источники и для каких типов мыслей.
- **Фирменные сравнения и образы** — повторяющиеся формулы.
- **Конкретика vs абстракция** — пишет в живых сценах с деталями (имена, цифры, места) или больше в абстракциях.

### 7. Эмодзи и типографика

- **Эмодзи** — какие конкретно повторяются (выпиши топ-10 с частотой через code execution), их положение (начало строки / конец / разделитель в середине), частота (среднее на пост / на слайд).
- **Тире** — `—` (длинное) vs `-` (короткое) vs `–` (среднее). Что выбирает.
- **Кавычки** — различай строго по unicode-кодам, не по визуальному рендерингу:
  - «ёлочки» русские: `«…»` (U+00AB … U+00BB)
  - английские двойные: `"…"` (U+201C … U+201D)
  - немецкие низкие: `„…"` (U+201E … U+201D)
  - прямые ASCII двойные: `"…"` (U+0022)
  - одинарные прямые ASCII: `'…'` (U+0027)
  - без кавычек
  При сканировании архива различай эти типы строго по unicode-кодам, не по визуальному рендерингу.
- **Многоточия** — частота, где (обрыв мысли / пауза перед откровением).
- **Восклицательные** — частота, тон (нейтральный / эмоциональный взрыв).
- **Капс** — есть / нет, для чего.
- **Точки в конце предложения-абзаца** — ставит ли всегда или часто опускает в коротких репликах.

### 8. Юмор и игра + анти-стиль

- **Самоирония** — частота, на чём (профессия / неудачи / контент-машина).
- **Сарказм** — есть / нет, направление (на индустрию / на типичные ошибки / на себя).
- **Игра слов и каламбуры** — встречается / нет, примеры.
- **Гиперболы** — частота, для чего.

Дальше **анти-стиль** — отдельный обязательный подблок «Чего НЕТ в текстах»:

- Мат — есть / нет.
- Канцелярит («осуществить», «в рамках», «вышеуказанный») — есть / нет.
- Капс ради эмоции — есть / нет.
- Восклицательные подряд (!!!) — есть / нет.
- Превосходные степени без обоснования («лучший», «уникальный», «революционный») — есть / нет.
- Кликбейтные конструкции («ты не поверишь», «секрет, который скрывают») — есть / нет.
- Обращения «друзья», «дорогие подписчики» — есть / нет.
- Прямой призыв «подпишись / поставь лайк» — есть / нет.

«Нет» → в финальном профиле это правило для скиллов: «не использовать X».

### Принцип «цитаты внутри слоёв, не отсылки»

**Все примеры идут текстом прямо в профиль, без ссылок на посты.** Нейронка-писатель не открывает внешние ссылки и не делает drill-down — она работает только с тем, что есть в контексте. Эксперт-человек при чтении профиля тоже не идёт кликать на каждую отсылку. Поэтому отдельного блока «RAC-якоря» в конце профиля нет.

Вместо этого **в каждом из 8 слоёв при упоминании любого паттерна обязательно даётся 1–3 конкретные короткие цитаты** (15–40 слов каждая) — как иллюстрация прямо в описании. Без даты, без ID, без URL. Просто цитата в кавычках после описания приёма.

Пример:

> **Хук через личную сцену** (≈40% постов). Эксперт начинает с конкретного момента, времени и места, потом разворачивает мысль.
>
> > «Утром в Улувату, мотоцикл, кофе на берегу — и тут понимаю: я и есть та самая нейро-команда»
> >
> > «Сижу 5 утра, кружка кофе, два экрана, и в этот момент Claude закрывает за меня третий час работы»

Цитаты должны быть **дословные**, не пересказ. Бери куски реальных постов из архива. Если цитата длинная — сокращай через многоточие, сохраняя характерную часть. ~200 знаков на цитату достаточно для иллюстрации — не нужно тащить весь пост.

В каждом слое 1–3 цитаты-иллюстрации **в среднем**. Где приёмов несколько (например, разные типы хука) — даёшь по одной цитате на каждый. Где приём один характерный — 2–3 разнообразные иллюстрации, чтобы скилл-писатель видел вариативность.

Не повторяй одну и ту же цитату в разных слоях — выбирай куски, каждый из которых иллюстрирует именно тот аспект, который описывается. Один пост может дать цитату для «архитектуры» и **другую** цитату из того же поста для «лексики».

## ФАЗА 2. Стиль TG-постов

Источник: `recognized_text` всех записей с `network=Telegram` и `type=пост` (TG-посты приходят с распознанным текстом сразу из скрапа). Если выборка >200 — бери все (Cowork справится). Если <30 → ограниченный профиль (см. ниже).

Прогони данные через шаблон 8 слоёв. На TG особое внимание форматированию (Слой 4) — там оно ключевой стилевой маркер: эксперты различаются именно по тому, как режут абзацы, где ставят жирный и т.п.

**Ограниченный профиль (15–29 TG-постов):** можно надёжно извлечь — Слой 1 (обращение/тон), Слой 5 (фирменные конструкции если повторяются), Слой 7 (эмодзи и типографика), Слой 8 (анти-стиль). Нельзя надёжно извлечь — Слой 2 (статистики длины — шумные), Слой 3 (доли хуков — нужна выборка для оценки частот). Эти слои оставляй с пометкой `требует валидации после накопления архива`.

## ФАЗА 3. Стиль IG-каруселей

Источник: `recognized_text` всех записей с `network=Instagram` и `type=карусель` (распознавалка должна была заполнить).

Особенности канала:
- Текст структурирован по слайдам (1 карусель = N коротких фрагментов).
- Первый слайд — крючок; последний — призыв или вывод. Это часть архитектуры (Слой 3).
- Длина текста на слайде ограничена композицией — отметь среднюю длину фрагмента в Слое 2.
- Форматирование (Слой 4) — другое: жирный/курсив редко работают на слайде, акценты делаются через размер шрифта/выноску, чего в тексте не видно. Не выдумывай — пиши «форматирование на уровне текста минимально, акценты делаются визуально в Gamma».

**Ограниченный профиль (10–19 каруселей):** аналогично TG — Слои 1, 5, 7, 8 надёжно; Слои 2, 3 с пометкой.

## ФАЗА 4. Стиль разговорных рилзов

Источник: `recognized_text` рилзов классифицированных как разговорные (Фаза 1).

Это **устная речь, расшифрованная в текст**. Отсюда специфика:

- Длина предложения и абзаца (Слой 2) — обычно короче, чем в письменном тексте, разбивка дыхательная.
- Архитектура (Слой 3) — почти всегда первые 1–2 предложения это хук (борьба за внимание в первые 3 сек). Опиши какие именно хуки эксперт использует.
- Лексика (Слой 5) — устные обороты, междометия, разговорные связки («ну», «короче», «слушай»). Они важны для скрипта в рилзе.
- Форматирование (Слой 4) — неприменимо в исходном видео, но при генерации скрипта скилл может задать структуру (тире-абзацы как маркеры пауз). Опиши только если у эксперта есть такая привычка в постах.

**Ограниченный профиль (10–19 разговорных рилзов):** Слой 1, Слой 5 (устные обороты), Слой 8 надёжно; Слой 2 и доли в Слое 3 — с пометкой.

## ФАЗА 5. Стиль overlay-рилзов

Включается, только если кандидатов после фильтра Фазы 1 ≥20. Иначе фаза пропускается с пометкой «overlay-рилзы: накопи 20+ подписей ≥200 знаков, возвращайся».

Источник: `caption` рилзов классифицированных как overlay.

Особенности:
- Это **короткая письменная заявка под видео**, а не транскрипция. Жанрово ближе к посту-анонсу.
- Архитектура обычно сжата: 1–2 предложения хука + 2–4 предложения раскрытия + опциональный призыв.
- Стиль в подписи часто плотнее (мало воды, каждое слово работает).

**Если есть отдельная группа overlay-короткий (50–200 знаков, ≥20 штук)** — собери ещё один профиль «короткий формат overlay» рядом с обычным. Часто эта группа — «вирусные кнопочные посты», у них своя стилистика (одна фраза-приговор, ноль раскрытия).

Если по обычной overlay (≥200 знаков) профиль заметно отличается от Фазы 4 (разговорные) — отметь это в Фазе 6.

## ФАЗА 6. Сводный мета-стиль

После Фаз 2–5 у тебя есть 3–4 профиля по каналам (плюс возможно «короткий overlay»). Сведи их в один документ.

### Что одинаково во всех каналах (ядро голоса)

Перечисли элементы, которые повторяются стабильно везде:

- Обращение (например, «всегда на „ты"»)
- Эмоциональный фон по умолчанию
- Фирменные конструкции (если повторяются и в TG, и в IG)
- Метафорические сферы
- Анти-стиль (что эксперт не делает нигде)

Это **ядро голоса** — то, что скиллы-писатели должны выдавать на любом канале.

### Чем каналы различаются

Таблица или список «параметр × канал»:

| Параметр | TG | Карусель | Разговорный рилз | Overlay-рилз |
|---|---|---|---|---|
| Длина предложения | ... | ... | ... | ... |
| Архитектура хука | ... | ... | ... | ... |
| Форматирование | ... | ... | ... | ... |
| Эмодзи | ... | ... | ... | ... |

Это **карта канальных настроек** — скилл-писатель «Карусели» читает её колонку, скилл «Пост в Telegram» читает свою.

### Сверка с Распаковкой экспертности

Если `.business/Распаковка экспертности.md` есть — отдельным блоком сверь:

- Что эксперт декларирует в табу (Распаковка) vs что эмпирически отсутствует в постах (анти-стиль). Совпадает?
- Что эксперт описывает как принципы метода vs что проявляется в тоне/архитектуре?

Если есть расхождения — не молчи, опиши как находку. Пример: «В распаковке заявлено „избегаю провокации", но в TG ≈15% постов открываются провокационным тезисом. Возможно, провокация эксперта — часть метода, а не нарушение его». Решение что с этим делать — за экспертом.

## Запись результата в базе знаний

Один файл `.business/Мой стиль для разных каналов.md`. Без подстраниц.

### YAML-frontmatter (обязательный)

```yaml
---
тип: стиль-голоса
статус: боевой   # боевой | ограниченный | pre-baseline
обновлено: YYYY-MM-DD
каналы_проанализированы: [TG, карусели, разговорные_рилзы, overlay_рилзы]
каналы_пропущены: []     # каналы ниже минимума
выборка:                 # сколько постов по каждому каналу пошло в анализ
  TG: N
  карусели: N
  разговорные_рилзы: N
  overlay_рилзы: N
основа_профиля: эмпирическая   # эмпирическая | pre-baseline_декларация
валидация_после: ''      # для статусов «ограниченный»/«pre-baseline»: «накопление архива до минимумов»
---
```

Значения статуса:

- `боевой` — все 3–4 канала прошли минимумы (TG 30+ / карусели 20+ / разговорные 20+ / overlay 20+), профиль эмпирический полный.
- `ограниченный` — хотя бы один канал в ограниченной ветке (15–29 / 10–19). Скиллы-писатели читают с дисклеймером «слои 2, 3 предварительные, требуют валидации».
- `pre-baseline` — архив пустой/недостаточный, профиль собран со слов эксперта. Скиллы-писатели работают с явным дисклеймером.

### Структура тела


## Ограничения и формат

- Только характерный голос автора. Слой «что отличает зашедшие посты» (Outliers) в этом скилле не делается — это работа скилла Аналитика своего профиля.
- Минимумы для **боевого** профиля: TG 30 / карусели 20 / разговорные рилзы 20 / overlay-рилзы 20 (caption ≥200 знаков).
- Ограниченная ветка: TG 15–29 / карусели 10–19 / разговорные 10–19. Для overlay ограниченной ветки нет.
- Pre-baseline ветка только когда у эксперта нет архива и он хочет начать; источник = слова эксперта, не тексты; явная пометка в статусе. Подробности — `references/pre-baseline-mode.md`.
- Цитаты-иллюстрации обязательны внутри каждого слоя описания (не отдельным блоком, не ссылками).
- Анти-стиль обязательно отдельным подблоком в каждом канале.
- Не путать стиль с темами, методом, ЦА.
- Не выдумывать. Если в текстах сигнала нет — пиши «не выявлено», не угадывай.
- Code execution — для статистик длины/частот/эмодзи (LLM в уме считает плохо).
- **Источник массива** — `.md` файлы архива через Glob+Read, не CSV-экспорт из Notion (как было в v1.x). Эксперт ничего не выгружает руками.
- **Multiple-аккаунты в одной папке** (например, русский и английский IG-аккаунт) — стиль смешается, профиль будет шумный. Скилл предполагает один аккаунт на тип (один IG, один TG). Если у эксперта два аккаунта одного типа — это пока открытый вопрос архитектуры (две папки `/Мой контент RU/` и `/Мой контент EN/`?).

## Начало диалога

Начни с **gate-проверки** (Фаза 0.1): через Glob+Read посчитай записи по каналам в `.business/growth/content-archive/Мой контент/записи/`, сравни с минимумами, сообщи эксперту что готово к анализу, что в ограниченной ветке, что пропускается. Если архива нет вообще — предложи pre-baseline режим (читай `references/pre-baseline-mode.md` для шагов). После согласования объёма — иди по фазам.
