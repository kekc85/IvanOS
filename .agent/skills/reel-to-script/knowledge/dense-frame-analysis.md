# Dense frame analysis: как смотреть, чтобы не пропустить вау-триггер

## Прецедент, ради которого этот файл существует

2026-06-21. Wave-ролик @wedjo.studio (18с, 580K-реплика). Реконструкция шла по `grid.jpg`
одним взглядом и по 18 кадрам, снятым 1 fps в мелком превью. Результат: пропущена **падающая
звезда / метеор** (чертит <1с на ~2-2.5с), которая и вызывает волну. Скрипт додумал «волна
растёт из ниоткуда», регенерация вышла мусором, дорогая генерация сожжена впустую.

Вывод: короткий вертикальный ролик несёт вау-триггеры длиной меньше секунды (метеор, вспышка,
рез, beat трансформации, микро-жест). На разрежённой выборке и в мелком превью они исчезают.

## Правило плотности

`scripts/dense-frames.sh` режет:
- ≤20с → **6 fps**, ≤45с → 4 fps, длиннее → 2 fps;
- собирает **секционные контактные листы** окнами по ~6с, крупными tiles (≈3700px ширина),
  плюс один overview.

## Порядок чтения (обязательный)

1. **Каждый `sheet_NN_*.jpg` по порядку** - это главное. Секционный лист крупный, мелкие/быстрые
   детали (метеор в углу неба) на нём видно. Один общий overview их теряет.
2. **`overview.jpg`** - в конце, для глобальной структуры: где резы, как меняется план, общая дуга.
3. При сомнении в конкретном моменте - открыть отдельные кадры `frames/f_XXXX.jpg` вокруг секунды.

Никогда не писать пошотовый разбор «по overview без секционных листов» - это тот самый промах.

## Что выцеплять на каждом листе (чек-лист наблюдений)

- **Быстрые события:** падающая звезда/метеор, вспышка, искра, появление объекта, момент удара,
  beat трансформации. Они часто и есть вау-триггер и причина следующего события.
- **Резы и смена плана:** крупный ↔ сверхширокий ↔ средний. Считать количество планов и где границы.
- **Движение камеры:** статичная / медленный наезд / отъезд / орбита / FPV-тряска / дрон.
- **Субъект:** поза, действие, что в руках, реагирует или нет, со спины или лицом.
- **Свет и цвет:** время суток, источник, тёплый/холодный контраст, грейдинг.
- **Среда и масштаб:** что растёт/приближается, насколько колоссально относительно субъекта.
- **Текст/UI в кадре:** субтитры, оверлеи, водяные знаки, счётчики платформы.
- **Признаки апскейла:** неестественно чистый 4k60 → вероятен Topaz-слой (см. production-pipeline).

## Связь с причинностью

Главная ценность плотного просмотра - восстановить ПРИЧИННОСТЬ, а не только список кадров:
не «появилась волна», а «звезда упала в точку моря (sheet_01, ~2с) → ИЗ ЭТОЙ точки поднимается
волна (sheet_02)». Без плотных листов причинно-следственная связь теряется и заменяется выдумкой.

## Если ingest-reel уже дал кадры

`ingest-reel` кладёт `frames/` (4 fps ≤20с) и `grid.jpg`. Этого достаточно по плотности, но
`grid.jpg` мелкий для быстрых деталей. Всё равно прогнать `dense-frames.sh` на скачанном
`{video_id}.mp4` ради КРУПНЫХ секционных листов, либо читать `frames/` группами по секциям,
не один grid.
