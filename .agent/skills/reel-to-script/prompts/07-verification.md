# Фаза 7: Verification gate (ОБЯЗАТЕЛЬНО перед «готово»)

Скилл сам себя верифицирует ДО любого заявления «готово / собрал / исправил». Не полагаться на
внешний хук. Без зелёного verify задача НЕ закрыта (автор: «всегда их в скилле внеси»).

## Когда

- Любая правка кода/скриптов/структуры скилла reel-to-script (фиксы, новые фазы, правила).
- Перед тем как сказать автору «скилл готов / исправил / обновил».

## Как

Один прогон, показать exit-код:
```bash
bash ~/.claude/skills/reel-to-script/scripts/verify.sh; echo "exit=$?"
```
Опционально e2e на своём ролике:
```bash
REEL_TEST=/path/to/reel.mp4 bash ~/.claude/skills/reel-to-script/scripts/verify.sh; echo "exit=$?"
```

`verify.sh` прогоняет: синтаксис bash-скриптов, L1 frontmatter (name + description 80-500),
em-dash 0, целостность cross-refs, L6 prompt-injection защиту, ключевые принципы (один промпт /
потолок 15с / референс), и e2e dense-frames на реальном ролике (если есть). Падает `exit 1` при
любом red.

## Правило

- `exit 0` → можно заявлять готово, приложив вывод как улику.
- `exit 1` → НЕ заявлять готово. Прочитать какие строки FAIL, починить, прогнать снова. Повторять
  до зелёного. Сказать прямо что red, не маскировать (Stage 13 вайбкодинга).

## Что НЕ делает (границы)
verify.sh проверяет САМ скилл (его код и структуру), а не качество конкретного выходного скрипта.
Качество разбора (пойман ли вау-триггер, причинность, верный пайплайн) проверяется Фазой 5
(верификация против оригинала) и трекается в `examples/track-record-*` (catch_rate).
