# ig-bio — конвертящая шапка Instagram по доказательной формуле

Делает name-поле + bio, которые превращают визит профиля в подписку и клик, а не декорируют профиль. Опирается на 2 источника: формулу works-шапок (ресёрч 56 растущих авторов, 10 works) и линзу топ-маркетологов (positioning / copywriting / persuasion / storytelling / offer-design / solopreneur).

## Когда применять

Триггеры:
- "сделай шапку профиля" / "Instagram bio" / "bio для инсты"
- "перепиши / улучши мою шапку"
- "что написать в профиле IG"
- `/ig-bio`

Платформа-ядро — Instagram (лимиты name ≤30, bio ≤150). Формула переносима на X/LinkedIn/TikTok с другими лимитами — но это ig-skill, для других платформ адаптировать осознанно.

## Главный принцип (зачем скилл вообще нужен)

**Размер аудитории НЕ предсказывает качество шапки.** Works встречаются у любого масштаба — и у малых на органике (dickiebush 88 при ~27K, ai.withphil 79 при 34K), и у крупных (amjad_masad 76, 40M users). Vanity-декор тоже бывает у любого размера: у части авторов трафик идёт с виральных reels, а bio при этом декоративна. Связь «размер↔качество» ненадёжна — это НЕ закон «чем больше, тем хуже».

Следствие: оценивай шапку по rubric и тесту холодного визитёра, **а не по числу подписчиков**. Не считай шапку хорошей только потому, что автор крупный, — но и не отвергай по размеру. Копируй то, что works по формуле, у автора любого масштаба.

**Тест холодного визитёра:** закрой имя, аватар и число подписчиков — читается ли за 3 секунды кто ты / что даёшь / зачем подписаться? Нет → шапка не работает.

## Что делает (2 режима)

- **BUILD** (по умолчанию): вход → context-gap check → выбор угла → name+bio в лимитах с подсчётом → self-score по rubric → анти-вода → humaniser → 2-4 варианта RU и/или EN. См. `prompts/01-build-bio.md`.
- **AUDIT**: дана существующая шапка → прогон по rubric (works/vanity/mixed) + дискриминаторы vanity + конкретные правки. Использует тот же `knowledge/rubric.md`.

## Core principles

1. **Одно слово/идея** (Ries-Trout): шапка столбит ОДНУ позицию (name + первая строка + CTA служат ей), а не перечисляет 4-5 разнородных пунктов. «Владеть многим = не владеть ничем».
2. **Первая строка = заголовок-исход** (Ogilvy, Caples): выгода + конкретика + слово-адресат. НЕ титул, НЕ миссия, НЕ каламбур. На ней принимают решение подписаться.
3. **Один релевантный пруф ПОД обещание** (Bencivenga): конкретное число/факт-результат метода рядом с обещанием. НЕ дубль числа подписчиков (оно и так на виду).
4. **Ровно один CTA → один лид-магнит** (Welsh, Fogg B=MAP): одно крошечное действие на одну ссылку под обещание. НЕ linktree из 8 ссылок (конвертит <1%), НЕ два конкурирующих CTA.
5. **Name-поле работает** ([Имя] | 1-2 рыночных ключа): самое весомое поисковое поле. RU обязательно «нейросети»/«ИИ»; EN — рыночные ключи ниши. НЕ голое имя, НЕ слоган без ключа.
6. **Без воды** (Ильяхов, см. `anti-water.md`): каждый личный/lifestyle-маркер — только конкретный факт, не глянцевый штамп. Каждое оценочное прилагательное = выброшенный символ.
7. **Реальные факты под именем** (см. gates): цифры/кейсы/пруфы НЕ выдумывать — спросить пользователя. Что из реальных фактов публиковать (напр. доход) — решает сам эксперт; уважать его границы приватности.

## Anti-patterns (что делает шапку vanity — из ресёрча)

- Открывать титулом/регалией («CEO of…», «Главный по X», «Founder @…») — место под зрителя отдано под себя.
- Дублировать число подписчиков как пруф («Trusted by 1.5M», «750k on YT») — строка впустую.
- Шапка без CTA даже при сильном пруфе (теряют works: Amjad, Lovable, Чурилова).
- Два+ конкурирующих CTA (паралич выбора).
- Linktree-помойка из равнозначных ссылок вместо одного лид-магнита.
- Cutesy/мета-титулы которых нет в поиске («chief vibe officer», «digital alchemist»).
- Lifestyle-вода: «свобода», «<покупка>», «X в гараже», «без команды/боссов», «живи на своих условиях» (см. `anti-water.md`).
- Копировать чужую шапку вслепую, ориентируясь на размер автора: у крупного трафик может идти с контента, а bio быть декором («Documenting the singularity» Riley Brown). Проверяй по rubric, не по числу подписчиков.

## Жёсткие лимиты Instagram (проверять при изменениях платформы)

- **Name-поле (жирная строка): ≤30 символов.**
- **Bio: ≤150 символов** (включая переносы строк и эмодзи).
- Всегда считать длину программно перед выдачей (`python3 len()`), не на глаз. Превышение = IG обрежет.

## Gates (вшиты, см. ниже)

- **context-gap** (`_shared/context-gap-gate.md`): нет реальной ниши/пруфов/оффера/цели ссылки → СПРОСИТЬ списком, НЕ выдумывать. Для bio критично — факт под именем = обещание.
- **mastery** (`_shared/mastery-gate.md` + `knowledge/mastery-lens.md`): применять линзу маркетологов с Evidence + верификатором.
- **humaniser**: финальный антиклише-проход текста шапки.

## MASTERY+CONTEXT GATES (shared, injected)

> Два обязательных гейта перед написанием публикуемого текста. Общие для всех writer-скиллов, источник истины в `_shared/`.

### Гейт 1 — Context-gap (нет реального контекста → СПРОСИ, не выдумывай) — HARD
`Read(~/.claude/skills/_shared/context-gap-gate.md)` и примени ДО draft. Если для текста нужны цифры / инфоповоды / новости / цены / даты / кейс / цитата, которых НЕТ в источниках (config / карта смыслов / story-bank / транскрипт / то, что дал автор) → **СТОП, не писать**, вывести в чат нумерованный список «нужно от тебя:» и ждать. Выдумывать, округлять, ставить плейсхолдер в финал — запрещено. Вывести секцию `Context-gap: нет / список вопросов`.

### Гейт 2 — Mastery (линза мастеров) — HARD
`Read(~/.claude/skills/_shared/mastery-gate.md)` (полный регламент — `mastery/PROTOCOL.md`). До draft: Inventory ВСЕХ авторов `mastery/copywriting/` + Select с обоснованием + bind. После draft, до humaniser: Evidence Report (метод→цитата) + независимый верификатор (субагент-скептик; нет цитаты→FAIL; верификатор запускается ВСЕГДА, без исключений — v4.2, `--fast`/облегчённый режим устранён).

**Порядок:** Context-gap → (если полно) Mastery Inventory+Select → write → Evidence+Verifier → Humaniser → output.
