# Шаблон записи результата в базе знаний

Линейка пишется в один файл `.business/Сетка продуктов и оффера.md`. Без подстраниц.

## YAML-frontmatter (обязательный)

```yaml
---
тип: сетка-продуктов
статус: боевой   # боевой | черновик-рамка | черновик-скелет
b2b: false       # true для B2B-моделей (партнёрки/товарная поставка/договоры)
продуктов: 3
есть_воронка: false
создан: YYYY-MM-DD
обновлён: YYYY-MM-DD
валидация_после: ''   # для черновик-рамка: например, «запуск продукта»
---
```

Значения статуса:
- `боевой` — все продукты с дословными ценами и офферами, минимум 3 поля по каждому заполнены из материалов эксперта.
- `черновик-рамка` — pre-baseline режим (эксперт планирует, но не запустил). Скиллы-писатели работают с дисклеймером «продукт в разработке».
- `черновик-скелет` — hard-stop из Шага 0.4 (ничего не продаёт и не планирует). Скиллы-писатели не вставляют CTA.

## Что делать, если файл уже существует

Не перезаписывай молча. Сообщи: «В `.business/Сетка продуктов и оффера.md` уже есть содержимое от <дата_из_frontmatter>. Обновить (старая версия уйдёт в git/iCloud-историю) или сохранить рядом как `.business/Сетка продуктов и оффера (v<N>).md`?»

## Если что-то мешает писать в файл

Спроси эксперта, куда писать. Не выдавай документ артефактом «на скачать» молча — `.business` это нативное место.
