# Структура лид-магнитной воронки (КАНОН) - evergreen на трипваер

> Воронка каруселей/рилсов и поиска evergreen и ведёт на ТРИПВАЕР (платный продукт), а не на
> бесплатный воркшоп. 🔴 Половин у статьи НЕТ (закон владельца 29.08.2026, прежняя раскладка
> «50/50 техничка + прогрев» отменена): статья целиком, от первой строки до последней, решает
> задачу человека, пришедшего из поиска, и объясняется простым языком новичка - тройка «куда нажать
> → что увидишь → что даёт» на каждом шаге, `knowledge/novice-standard.md`. Приглашение живёт
> компактным хвостом по CTA-канону, а не половиной текста. Анатомия статьи - `article-anatomy.md`,
> анти-вода - `anti-water-gate.md`, визуал - `visual-layer.md`.

Источники (абсолютные пути в `config.md`): `value_ladder` (лестница ценности), `funnel_canon`
(Механика 1 - кодовые слова), `mari_funnel_canon` (методология воронки),
раздел «Лид-магнит-гайды» в `~/.claude/skills/website/SKILL.md`.

## 1. Место в лестнице ценности

```
ОРГАНИКА              ЛИД-МАГНИТ                      ТРИПВАЕР
карусель / рилс   →   статья-гайд (этот скилл)    →   платный продукт (главная цель)
(код-слово)           вся статья решает задачу        глубина: настройка под себя,
ПОИСК (тот же ключ)   человека простым языком;        сборка продукта, система
                      приглашение - компактный хвост
```

Лид-магнит = бесплатная ступень, которая даёт НАСТОЯЩИЙ результат: человек по шагам ставит и
запускает инструмент. На трипваер уезжает не базовая инструкция, а глубина - как настроить под
свою задачу и собрать этим продукт. Целевой продукт - в `config.md` → target_* (меняется одной
строкой config, не в каноне).

🔴 Почему именно так: прежняя логика «ничего не показываем, метод весь за платной дверью» давала
воду и была разнесена автором. Доверие строится результатом, а не обещанием и не объёмом
продающей части.

## 2. Вход в воронку - две холодные двери

**Дверь 1 - код-слово.** Человек видит карусель/рилс → в описании кодовое слово (КАПСОМ, ёлочки,
≥2 раза - это держит writer-скилл + `_shared/lead-magnet-description-structure.md`) → пишет слово
в DM/комменты → автосценарий присылает ссылку на эту статью.

**Дверь 2 - поиск.** Человек гуглит запрос → попадает на ТУ ЖЕ статью из выдачи. Код-слово =
поисковый ключ (`target_keyword`): одно слово = одна тема = одна статья = один URL.

- 🔴 Код-слово под конкретный магнит **читаю из контекста автора или приписки самого поста**
  (`yt-dlp --skip-download --cookies-from-browser chrome --print "%(description)s" <url>`),
  а НЕ угадываю по реестру/смыслу. Реестр (`codewords.py`) - для сверки пары `слово → магнит`,
  не для гадания.
- 🔴 Одно кодовое слово = ОДИН конкретный магнит. Если текст обещает «напиши X - пришлю весь
  список», бот по X обязан прислать ИМЕННО это. Текст не должен врать про механику выдачи.
- Единственная домашка читателя - поставить среду из Шага 0 (prereq), всё остальное он делает
  внутри статьи по шагам.

## 3. Единственная вороночная цель = переход на трипваер

Главный CTA статьи = **трипваер** (`config.md` → target_url). Всегда.

- Мостик на трипваер опирается на то, что читатель ТОЛЬКО ЧТО сделал руками: «база у тебя
  работает; как настроить под свою задачу и собрать этим реальный продукт - это уже система,
  она на трипваере». Мостик живёт ВНУТРИ блока приглашения, а не россыпью по телу статьи.
- 🔴 Число и позиции блоков приглашения задаёт CTA-канон движка статей
  (`article-template/CTA-STRATEGIYA.md`): контентный блок после последнего содержательного раздела
  + хвостовой после памятки перед FAQ; унаследованный компактный блок после быстрого ответа
  допустим, но не обязателен. Четвёртая точка = брак. Порядок держит код-гейт `cta-position`.
- 🔴 Блока код-слова в тексте статьи НЕТ (решение владельца, CTA-канон §9): слово живёт
  в реестрах и front-matter, вход открывает кнопка.

## 4. Prereq-вход = гайд установки среды

Среда, без которой шаги статьи не поедут (`config.md` → stack), ставится в **Шаге 0** со ссылкой
на гайд установки (`config.md` → install_guide_url). Сказать «открой в Claude Code» без шага
установки = дыра в инструкции: новичку некуда вставлять команды.
🔴 Называется среда на языке новичка - «окно, где ты словами пишешь ИИ, что сделать», слово
«терминал» как понятие-пререквизит не употребляется (`knowledge/novice-standard.md` §6).

## 5. Скелет страницы (порядок блоков)

Мобайл-first, полная раскладка - `article-anatomy.md`:

1. **Хук-герой** - H1-обещание + подзаголовок «ниже по шагам: что нужно, куда нажать, что вставить»
   + визуал шапки (мем или hero-обложка) + уникальный og:image.
2. **Быстрый ответ** - 1-2 предложения прямого ответа на запрос, потолок 3, до любых подводок (GEO-слой).
3. **ТЕЛО СТАТЬИ** (это и есть вся статья) - Шаг 0 prereq → шаги по тройке «куда нажать → что
   увидишь → что даёт» (скрин реального UI ИЛИ `.vizblock.vizsteps`, неизбежная команда - один
   копи-блок из четырёх тактов, `knowledge/novice-standard.md`) → как пользоваться (конкретный
   пример) → частые грабли. Продающих врезок и мостиков к платному внутри тела нет.
4. **Контентное приглашение** - блок CTA-канона после последнего содержательного раздела:
   точка → дыра → мост → кнопка с microcopy.
5. **Хвост** - Источники → чек-лист-памятка «сохрани себе» → финальный блок приглашения →
   FAQ 4-7 (= FAQPage-схема 1:1); порядок держит код-гейт `cta-position`.
6. Дальше карточки «Читайте также» в кластер.

## 6. Правила публикации (держит website, дублируем как чек)

- Только **свой домен** через деплой `tools/ftp_publish.py` (бэкап → заливка → curl 200 → откат),
  только на ТВОЙ хостинг/домен, даже превью.
- Чистый URL `/guide-<slug>/` без `.html`; картинки статьи - в `assets/` рядом с `index.html`.
- В финале автору - **живая ссылка** (curl 200), не localhost.
- **Лёгкость**: webp + jpg-фолбэк, вес страницы < 600 КБ, мобайл-перф-гейт website.

## 7. Чем эта воронка отличается от контента запуска

- **Отдаём реальную пользу.** Рабочие шаги с настоящими командами и промптами, объяснённые простым
  языком, - ядро статьи. За платной дверью остаётся глубина (настройка под себя, сборка продукта),
  а не базовая инструкция.
- **Ведём на платный трипваер**, не на бесплатный воркшоп. Это evergreen-acquisition, не запуск.
- **Один актив работает дважды**: спайк с ролика по код-слову + вечный органический трафик из
  поиска по тому же ключу.
