# 🌉 ШАГ 0 - МОСТИК ПОД ТВОЙ ПРОЕКТ (lead-magnit)

Прежде чем писать статью-лид-магнит, собери у пользователя вводные и запиши в `config.md`.
Без них не начинаем: статья и публикация должны быть под ЕГО проект, а не абстрактные.

## Сначала профиль (не переспрашивай зря)

1. Есть `~/.business/profile.json` - читай нишу/аудиторию/бренд/канал/мини-продукт оттуда.
2. Нет - прогони `~/.business/onboarding-profile.md`: сам ищет данные, спрашивает недостающее, пишет профиль.

Мини-продукт для CTA статьи берём из профиля:
- `offer.has_offer: true` → `target_url` = `offer.url` (действие читателя = перейти на продукт).
- `offer.has_offer: false` (продукта пока нет) → `target_url` = `brand.channel_url`: статья зовёт
  подписаться на канал/сообщество эксперта, а не на несуществующий продукт. Появится продукт -
  правится профиль, следующая статья ведёт на него.

## Что ещё спросить, если нет в профиле (спроси прямо, не выдумывай)

1. **Ниша / тема и ЦА** - о чём эксперт и для кого.
2. **Оффер (трипваер)** - что продаём статьёй + цена + ссылка. Нет продукта - см. выше, ведём на канал.
3. **Код-слово / тема статьи** - ключ, вокруг которого статья (он же поисковый ключ).
4. **Твой домен** (`domain`) - где живёт сайт эксперта.
5. **Как публикуем** (`deploy`) - ТВОЙ хостинг: Netlify / Vercel / GitHub Pages / свой FTP / Tilda /
   конструктор. Дай доступ или CLI своего хостинга. Публикуем на ТВОЙ сайт, не на чужой.
6. **Фирменный цвет / бренд** - его палитра. Визуал верстает скилл `website` по бренд-токенам эксперта,
   поэтому цвет/логотип/шрифт берём его, а не дефолтные.

## Куда это идёт

- Тексты/структуру статьи скилл пишет под нишу из п.1-3 (голос эксперта, не шаблон).
- Форму (вёрстку, мобилку, ревью) собирает `website` по бренду из п.6.
- Публикация - на хостинг из п.5, на домен из п.4. Готовая живая страница (https, curl 200), не идея
  и не localhost. Ученик получает URL своей статьи, который сразу вставляет в свою воронку/контент.

## Публикация универсальна

`publish_target: auto` сам определяет, куда лить: если у эксперта поднят свой статейник-CMS на
`<домен>/guides/` - публикует туда; если нет (обычный случай) - website деплоит готовую страницу
на его хостинг (Netlify/Vercel/FTP/…). Никакой привязки к чужой инфраструктуре: домен, хост и бренд -
эксперта. Флаги в `config.md` руками не трогаем, цель выбирается сама.
