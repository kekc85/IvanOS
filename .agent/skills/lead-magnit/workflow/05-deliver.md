# Этап 5 — ВЫДАЧА

**Вход:** опубликованная статья (Stateinik `/guides/<slug>` ИЛИ мост `/guide-<slug>/`).
**Выход:** автор получает живую ссылку + подтверждение, что машина работает (обе двери + SEO).

## Шаги

1. **Публикация + индекс** (по факту авто-детекта Этапа 4, Шаг 0):
   - цель = Stateinik — статья уже в движке (залита Этапом 4 через `tools/stateinik_publish.py`),
     отдельная заливка не нужна; движок сам в индексе /guides.
   - цель = ftp (мост) — страница уже залита Этапом 4 **ТОЛЬКО через `tools/ftp_publish.py`**
     (сырой curl запрещён - SKILL.md, «Деплой моста»): `--dir $WORK/<slug>` кладёт файл с бэкапом
     живого состояния и авто-откатом при провале curl-верификации. 🔴 Карточка гайда в `blog.html` —
     часть того же вызова, не отдельная ручная правка:
     `python3 tools/ftp_publish.py --update-blog --url /guide-<slug>/ --card-title "<заголовок>" --card-desc "<description>" --card-thumb /assets/thumbs/guide-<slug>-thumb.webp` (тумб уже на проде после --dir; без --card-thumb карточка соберётся текстовой, без превью)
     (мерж-протокол: свежий blog.html с прода, чужие карточки нетронуты, иначе стоп без заливки).
     Без карточки гайд не попадает в индекс — часть конвейера, не опция. Этап 5 здесь только
     проверяет, что Этап 4 это уже сделал (curl 200 на итоговый URL, п.2 ниже) - заливку не повторяет.

1a. **🔴 Закрыть реестры, журнал и обе ноги** (`seo-engine/methodology/01-parallel-i-emkost.md` §4, §6):
   - записи прогона в `$WORK/_registry/*.jsonl` переводятся в `status: published` (дописыванием
     второй строки, старые записи не редактируются); откат или падение - `released`
   - в `$WORK/_journal/cadence.jsonl` дописывается строка касания: `date`, `slug`, `kind` (new или
     revision), `own_blocks`, `own_kinds`, `reviewed_by`, `next_revision` (дата + 60 дней для
     быстро меняющихся инструментов, + 90 для стабильных тем)
   - 🔔 обе ноги уведомления закрыты КОД-ГЕЙТОМ, не прозой:
     ```bash
     python3 tools/ftp_publish.py --index-legs --url "<полный URL статьи>"
     ```
     Один вызов = нога Яндекс (прямой IndexNow, отправляется сразу) + нога Google (ставится в очередь
     `.business/growth/seo/gsc-pending.json`, ненулевой exit если старейшая запись в очереди
     старше 7 дней - тогда открыть живую сессию GSC руками и вычеркнуть отправленные из очереди).
     Вывод команды сохранить дословно в `$WORK/<slug>/etap-12a-index-legs.md`
   Без этих трёх записей статья считается незавершённой, даже если страница отдаёт 200

   🔴 **Правило:** статья НЕ считается опубликованной, пока вывод `--index-legs` по ОБЕИМ ногам
   (Яндекс "отправлено N" + Google "в очереди/старейший X дней") не приведён дословно в отчёте этапа -
   и в `etap-12a-index-legs.md`, и в предъявлении автору (п.4 ниже). Одна нога в отчёте = статья НЕ
   опубликована, Этап 5 не закрывается

2. **Живая ссылка.** Дать автору ЖИВУЮ ссылку: `/guides/<slug>` (канон) или `/guide-<slug>/` (мост).
   Проверить `curl -sI <url>` → 200 ДО выдачи.
   Ссылку показать кликабельным URL в чат, не файловый путь.

3. **Проверить машину (чек-лист предъявления):**
   - [ ] Открывается, грузится быстро на телефоне (автор открывает с мобилы)
   - [ ] Вся статья простым языком (тройка «куда нажать → что увидишь → что даёт» на каждом шаге,
         простые слова, минимум кода, ноль терминальных сцен), ноль воды; половин нет, ни один
         раздел не продаёт вместо ответа, приглашение = два компактных блока CTA-канона в хвосте
   - [ ] Вход в инструмент: ссылка на гайд установки Claude (config install_guide_url) на месте
   - [ ] Финал ведёт на трипваер (config target_url, главный CTA), мостик релевантный
   - [ ] 🔵 SEO: target_keyword (= код-слово), meta_title/meta_description/slug/excerpt, ответ первой фразой в каждом H2,
         ≥3 внутренние ссылки в кластер /guides
   - [ ] Дверь 1: код-слово → DM/бот → эта ссылка (вход с рилз замкнут, бот присылает ИМЕННО этот магнит)
   - [ ] Дверь 2: статья отвечает на поисковый запрос по этому ключу (заголовок + первая фраза раздела закрывают интент)
   - [ ] Обе ноги уведомления: `python3 tools/ftp_publish.py --index-legs --url "<полный URL статьи>"` прогнан (не проза - код-гейт), вывод "нога Яндекс: отправлено N / нога Google: в очереди M, старейший X дней" дословно в `$WORK/<slug>/etap-12a-index-legs.md`
   - [ ] Гейт собственного материала: `structure-check.py <страница> --own-blocks-hard` = PASS (≥3 блока); 🔴 НОВАЯ статья (не ревизия) - тот же вызов с `--tool-article-hard` тоже = PASS (ось tool-article, И9.2, норматив возвращаемости); ревизия эту ось HARD не гоняет
   - [ ] `article_gates.py <slug> --stage page` = PASS - прогнан Этапом 4 ДО деплоя (структура/визуал/strip-notes/ритм собранной страницы), и `article_gates.py <slug> --stage publish` = PASS - прогнан ПОСЛЕ публикации (двери/claim/reflections/хабы против живого корпуса).
         Вердикты читаем в `$WORK/<slug>/gates.json` ключом `verdicts` (последний вердикт КАЖДОЙ стадии отдельно) и `verdict_publish_ready` (PASS только когда draft, page и publish зелёные в своих последних прогонах, блокеры названы поимённо). Прежнего ключа `verdict_last` больше нет - он показывал вердикт последнего по времени прогона любой стадии и затирал в шапке живой PASS страницы.
         Диагностический прогон - `article_gates.py <slug> --stage <стадия> --no-write`: гоняет и печатает, `gates.json` не трогает.
         Стадия `draft` на УЖЕ ОПУБЛИКОВАННОЙ статье - ретро-диагностика, не замок: CTA на оффер и часть блоков живут в собранной странице (build_page подставляет их из spec.json), в `draft.md` их нет по устройству конвейера, и structure-check обязан краснеть строкой «нет ссылки на оффер». Такой прогон помечается `applicable: false`, publish-ready не блокирует, код выхода 0. Замок собранной страницы - стадия `page`
   - [ ] `python3 artifacts_gate.py $WORK/<slug> --post` = PASS - минимум артефактов конвейера ПЛЮС следы, которые появляются только после публикации (обе ноги уведомления). Это и есть машинное условие «статья готова к выдаче» (не проза, код-гейт; входит в `--stage publish` выше, отдельно проверяю только если гнал деплой с `--unsafe-skip-artifacts`).
         Уровни: `artifacts_gate.py $WORK/<slug>` (= `--min`, режим по умолчанию) - замок ПЕРЕД деплоем · `--post` - замок выдачи · `--full` - замер долга по 16 этапам, exit 0 всегда, деплой не роняет.
         Состав MIN считается по маршруту статьи: новая (datePublished >= 2026-08-12 в реестре публикаций либо в реестре её нет вовсе) - полный минимум; легаси - страница + источник текста. Признак печатается строкой «маршрут по признаку: …», спорить с ним по памяти не нужно
   - [ ] После ФАКТА индексации (site:) - раздача по внешним площадкам на этот же $WORK/<slug>/draft.md:
         **Дзен → Skill('dzen-engine')** (отдельный движок площадки, канон дзен-правил там);
