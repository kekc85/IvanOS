# Этап 4 — ПУБЛИКАЦИЯ (маршрут статьи: article_build → build_page → article_gates → ftp_publish / Stateinik)

**Вход:** `copy` (готовый текст через humaniser) + `blueprint` (карта секций + SEO-поля + план визуалов) + `funnel`.
**Выход:** живая статья на <твой-домен> (по `/guides/<slug>` через движок ИЛИ по `/guide-<slug>/` через сборщик шаблона 2.0).

> 🔴 Цель публикации НЕ выбирается руками. `config.md → publish_target: auto` (дефолт). Этапы 0-3 от
> цели НЕ зависят, развилка только здесь. Значения `stateinik`/`ftp` — форс-режим, обычно не нужен.
>
> 🔴 Форма статьи конвейера (Цель B) — КОД, не ручная вёрстка: `article_build.py` → `build_page.py`
> по шаблону из `config.md → template.path` (путь НЕ хардкодить — у каждого автора свой, у учеников
> этого тулинга может не быть вовсе). Это не анти-паттерн «вёрстка мимо website» — это детерминированная
> сборка, ровно то, для чего слой сделан. `Skill('website')` остаётся мостом ТОЛЬКО для НЕ-статейных
> страниц этого конвейера или когда build_page-тулинг недоступен (портативная раздача без
> article-template).

## Шаг 0 — АВТО-ДЕТЕКТ цели (автор: «делай сам, я флаг не трогаю»)


- Дальше иду строго по выбранному варианту. Переключение происходит само на следующем прогоне, как
  только `/guides` начнёт отдавать 200, без правок этого файла и config.

## Шаг 1 — СБОРКА СТРАНИЦЫ (Цель B; Цель A публикует draft.md напрямую, сборки нет — см. Вариант A)

Путь инструментов — из `config.md → template.path`, не хардкод (у учеников этот каталог может
отсутствовать — тогда сборка недоступна, см. фолбэк «Skill('website')» ниже):

```bash
TEMPLATE="$(grep -A2 '^template:' config.md | grep path | sed -E 's/.*: *//;s/ *#.*//')"
```

1. **Собрать черновик** `$WORK/<slug>/draft.md` по контракту `article_build.py --help` (единственный
   шов, полный контракт в `--help`): frontmatter с маркером `engine: article_build` + обязательные
   поля (slug/title/description/h1/date_published) + target_keyword = код-слово + meta_title/
   meta_description/excerpt (нормы Этапа 2); тело — markdown + блочные директивы (`:::figure`,
   `:::table`, `:::pre`, `:::faq`, `:::sources`, `:::related`, `:::cta`); авторская специфика ТОЛЬКО
   токенами `{{domain}} {{site}} {{target_url}} {{cta_url}} {{install_guide_url}} {{target_product}}` —
   литерал домена/оффера в черновике роняет сборку. 🔴 Подстановки код-слова
   (`{{codeword}} {{codeword_span}} {{codeword_block}}`) ВЫВЕДЕНЫ ИЗ ОБОРОТА по решению автора: блока
   код-слова в тексте статьи нет вообще, попытка его вставить роняет сборку (`gate_no_codeword_in_text`).
   Слово живёт в front-matter `codeword:` как метаданные атрибуции и в реестрах.

2. **Собрать спеку и страницу:**
   ```bash
   python3 "$TEMPLATE/article_build.py" $WORK/<slug>/draft.md -o $WORK/<slug>/spec.json
   python3 "$TEMPLATE/build_page.py" $WORK/<slug>/spec.json -o $WORK/<slug>/index.html
   ```

3. **🔴 Гейт воспроизводимости (К.4, HARD перед деплоем).** Пересобирает страницу из источника в
   песочницу и сверяет семантическим диффом с `$WORK/<slug>/index.html` — ловит расхождение, если
   страницу после сборки правили `Edit` вручную (канон это запрещает: правка только через
   draft.md/spec.json и пересборку, не по собранному html):
   ```bash
   python3 "$TEMPLATE/article_verify.py" <slug> --work "$WORK"
   ```
   Ненулевой выход блокирует деплой — чинить источник и пересобирать, не редактировать html.

## 🖼 Шаг 2 - ГЕЙТ СТАДИИ page (до публикации, оба варианта) - HARD

Гоняется по СОБРАННОЙ странице, не по черновику: картинки, alt и блок «Источники» живут в
готовом html, в `.md` их физически нет. Один вызов вместо перечисления одиночных чекеров:

```bash
python3 "$TEMPLATE/article_gates.py" <slug> --stage page --work "$WORK"
```

Раннер закрывает ВСЕ гейты стадии page одним вердиктом. Состав стадии печатает сам раннер -
`python3 "$TEMPLATE/article_gates.py" --list` (единственный источник: число гейтов и их имена
руками не переписываем, состав плывёт с правками движка); среди них - `frame-provenance`
(происхождение кадров, пункт ниже) и `frame-density` (плотность кадра, пустая полоса и
текст-плашка вместо реального скрина). Те, что краснеют чаще прочих:
`structure-visual` = `structure-check.py` по собранной странице (визуал/плотность/H2/alt/
перелинковка + `--own-blocks-hard --render-hard --toc-hard`, плюс `--tool-article-hard` для НОВОЙ
статьи, не ревизии), `strip-notes` = служебных комментариев на странице нет, `cadence-body` = ритм
и AI-почерк по тексту черновика. Машинный отчёт — `$WORK/<slug>/gates.json`. Ненулевой вердикт
стадии — не деплоить, чинить и пересобирать (Шаг 1).

Дальше глазами по `checklists/visual.md` (канон правил - `knowledge/visual-layer.md`), каждый
пункт закрывается уликой — машинный гейт эти пункты не покрывает:

- [ ] hero = кейс-превью (own-run «окно-чат» для тем без стороннего UI) в шапке, единственный eager + fetchpriority, width/height заданы
- [ ] og:image - тот же кадр hero или его плотный кроп 1200x630, уникальный на статью, отвечает 200 (`curl -sI <og-url> | head -1`), читаем уменьшенным до ~300px
- [ ] пол = иллюстрации + .vizblock-блоки, минимум `min_images` единиц (дефолт 3, `tools.visual.min_images`); таблицами и листингами кода не закрывается; плотность: визуальных блоков (иллюстрация+vizblock+таблица+код) ≥1 на ~350 слов ПРОЗЫ, потолок 10
- [ ] alt у каждой картинки 50-125 знаков, осмысленный; все не-hero картинки lazy; figcaption несёт дату съёмки
- [ ] вес страницы < 600 КБ (html + css + картинки)
- [ ] 🔴 **каждый `<figure>`-кадр + hero + og несут класс из манифеста** `$WORK/<slug>/shots-manifest.json` (result/step/own-run/inherited); гейт `frame-provenance` (`article_gates.py <slug> --stage page`) - WARN дефолт / FAIL на `--provenance-hard`; отсутствие записи или class=result с url корня сервиса (не результат функции) = замечание, не декорация
- [] шаги закрыты скрином реального UI класса step или `.vizblock.vizsteps`; терминальных сцен в новой статье нет (`knowledge/novice-standard.md` §5), а НОВЫЙ генеративный кадр не производится ни в новой, ни в ревизуемой статье - генеративный канал в SEO-контуре закрыт целиком (решение 4 закона по решению автора), на ревизии легаси вместо него пересъёмка `shot.py` или `.vizblock`. Легаси-мокап при ревизии старой страницы - вывод совпадает
      с файлом реального прогона в `$WORK/<slug>/terminal-outputs/`
- [ ] пути картинок статьи - относительный `assets/<имя>.webp` (корневой `/assets/` только для общих ассетов сайта); имена файлов по конвенции `<slug>-result-N` / `<slug>-step-N`
- [ ] мобильная проверка скрином 390x844: hero не превращается в кашу, TOC и копи-кнопки работают, мобильную отдачу hero даёт сам сборщик (picture + webp_srcset + sizes), отдельный файл-кроп не обязателен

🔴 Любой незакрытый пункт = статья НЕ публикуется. «Облегчённый прогон» без визуального гейта и без манифеста - брак.

## Вариант A — Stateinik (TARGET=stateinik, `/guides` отдаёт 200) — КАНОН

Движок-CMS сам рендерит статью из `draft.md` (визуал/токены/мобилка — его забота), Шаг 1 (сборка
шаблоном 2.0) здесь НЕ применяется — MDX/фронтматтер CMS парсит сам, `article_build.py`/`build_page.py`
для этой цели не нужны.

1. **Собрать черновик** `$WORK/<slug>/draft.md` по `seo-engine/templates/draft-skeleton.md`:
   frontmatter (slug, title, title_variants[2] для A/B, target_keyword = код-слово, meta_title ~60,
   meta_description ~155, excerpt, type, cta_url из config target_url) + ЦЕЛЬНОЕ тело статьи
   (половин нет, закон владельца 29.08.2026) + два компактных блока приглашения по CTA-канону,
   8-14 H2, каждый открывается ответом первой фразой (без ярлыка-метки и без врезки),
   перелинковка на соседние статьи кластера `/guides`.

2. **Опубликовать адаптером** (общий слой `tools/`):
   ```bash
   python3 tools/stateinik_publish.py \
     --env "$(grep -A4 '^cms:' config.md | grep engine_env | sed -E 's/.*: *//;s/ *#.*//')" \
     --author-id <твой-author-id> \
     --type tutorial --status published --json \
     $WORK/<slug>/draft.md
   ```
   Адаптер: login → создаёт guide → заливает MDX (валидируется движком) → публикует → печатает живой URL.
   SEO-поля (meta_description/excerpt/target_keyword) берёт из frontmatter.

3. **Забрать живой URL** из вывода адаптера (`/guides/<slug>`). Дальше → Шаг 3 (обе ноги уведомления).

### Гейт выхода (A)
- [ ] Визуальный чек-лист (Шаг 2) закрыт: hero = кейс-превью, пол = иллюстрации + .vizblock-блоки, минимум `min_images` единиц (дефолт 3), уникальный og того же кадра, alt в норме, манифест `shots-manifest.json` на месте
- [ ] Адаптер вернул `published` + живой URL без ошибки

- [ ] Тело цельное (половин нет), ни один раздел не продаёт вместо ответа, ответ первой фразой в каждом H2 и ни одного ярлыка-метки резюме, ≥3 внутренние ссылки в кластер, приглашение двумя блоками CTA-канона, финал на трипваер

## Вариант B — маршрут статьи (сборщик шаблона 2.0) → FTP (TARGET=ftp, `/guides` ещё 404) — КАНОН статей конвейера

Сборка (Шаг 1) и гейт стадии page (Шаг 2) уже сделаны выше — здесь только деплой и пост-проверка.

1. **Деплой - ТОЛЬКО через `tools/ftp_publish.py`** (сырой curl не используем: он не делает ни
   бэкапа, ни верификации, ни отката). Каталог статьи = `index.html` + `assets/` с картинками;
   служебные артефакты этапов (`etap-*.png`, бэкапы) скрипт на прод не заливает. Артефакты уже
   проверены встроенным гейтом `python3 artifacts_gate.py $WORK/<slug>` (уровень MIN — режим по
   умолчанию, флаг `--min` необязателен) — обход только явным `--unsafe-skip-artifacts`,
   осознанно и с обоснованием в отчёте. Уровень MIN считается ПО МАРШРУТУ статьи (новая /
   легаси, признак — реестр публикаций) и НЕ требует post-publish артефактов: обе ноги
   уведомления спрашиваются позже, уровнем `--post`.

   ```bash
   python3 tools/ftp_publish.py --dir $WORK/<slug> --dry-run   # сначала посмотреть план
   python3 tools/ftp_publish.py --dir $WORK/<slug>             # бэкап → артефакты-min → заливка → curl 200 → откат при провале
   python3 tools/ftp_publish.py --update-blog --url /guide-<slug>/ \
       --card-title "<заголовок>" --card-desc "<описание>" \
       --card-thumb /assets/thumbs/guide-<slug>-thumb.webp     # карточка в индекс гайдов, чужие целы; без --card-thumb соберётся текстовой без превью
   python3 tools/ftp_publish.py --update-rss --url <полный URL> --card-title "<заголовок>"
   ```
   Если сайт уже в проде - правку публикуем на прод сразу, localhost-ссылку не отдаём.
   Уведомление поисковиков - не здесь, а общим Шагом 3 ниже (он одинаков для обеих целей).

   **Заливка НЕ с этой машины (релей, когда локальный IP забанен).** Гейт прогоняется там,
   где физически лежит каталог конвейера, и кладёт рядом расписку `gates-manifest.json`
   (вердикт + sha256 страницы + время + волна). Расписку везём на релей ВМЕСТЕ с
   `index.html` и `assets/` - без неё релейная заливка при `strict_gates: true` не пойдёт
   (раньше боевая дверь релея работала вообще без гейта). Правка страницы после прогона
   гейта расписку обесценивает: sha разойдётся, заливка встанет - прогнать гейт заново.

   ```bash
   python3 tools/ftp_publish.py --dir $WORK/<slug> --dry-run          # локально: гейты + расписка
   scp $WORK/<slug>/{index.html,gates-manifest.json} relay:<каталог>/ # расписка едет с артефактом
   scp -r $WORK/<slug>/assets relay:<каталог>/
   ssh relay "python3 ~/.claude/skills/lead-magnit/tools/ftp_publish.py --dir <каталог>"
   ```

2. **Не-статейный/безтулинговый фолбэк.** Когда страница этого конвейера НЕ статья (редкий случай)
   или каталог `config.md → template.path` не резолвится (портативная раздача без article-template) —
   вёрстку отдаю `Skill('website')` пакетом (контракт из SKILL.md «Контракт публикации», Цель B):
   ```
   ТИП САЙТА: лид-магнит-статья (одностраничник, мобайл-first)
   КАРТА ЭКРАНОВ: <screens[] из Этапа 2>
   КОПИ ПО ЭКРАНАМ: <готовый текст из Этапа 3, уже через humaniser> + SEO-поля (meta/slug/ключ)
   ПРАВИЛА ЛИД-МАГНИТА (раздел «Лид-магнит-гайды» в website SKILL.md):
     - вся статья для новичка простым языком (у каждого шага «куда нажать → что увидишь → что
       даёт», термины переведены в той же фразе, кода минимум, терминальных сцен нет); половин у
       статьи НЕТ, приглашение = два компактных блока CTA-канона в хвосте, не половина текста
     - вход в инструмент = ссылка на гайд установки Claude (config.md → install_guide_url) в Шаге 0
     - финал ВСЕГДА на трипваер (config.md → target_url)
     - лёгкость: JPEG, мобайл-перф; только <твой-домен>, чистый URL /guide-<slug>/, не github.io
   SLUG / URL ПУБЛИКАЦИИ: <page_path_pattern / page_url_pattern из config>
   ```
   `Skill('website')` входит со СТАДИИ A с заполненным смыслом, идёт по своим фазам (визуал → токены →
   сборка → моушен → Фаза 09 per-screen → Фаза 10 макро-ревью → 08 деплой) и сам гонит свои гейты —
   не дублирую его ревью. Деплой в этой ветке — тем же `tools/ftp_publish.py`, не сырым curl.

3. **После деплоя — пост-публикационная проверка стадии publish (HARD):**
   ```bash
   python3 "$TEMPLATE/article_gates.py" <slug> --stage publish --work "$WORK"
   ```
   Закрывает гейты стадии publish против живого корпуса одним вердиктом. Состав печатает
   `python3 "$TEMPLATE/article_gates.py" --list` (единственный источник, число и имена руками не
   переписываем): `artifacts-post` (обязательный минимум артефактов конвейера плюс следы, которые
   появляются уже после публикации - условие «статья готова»), `door-titles` (байт-лок `<title>`
   кодословных дверей),
   `claim-shared` (разделяемые файлы не заняты чужой волной), `reflections` (страница отражена в
   sitemap/ленте/llms.txt), `hub-counts` (числа хабов и чипы главной сходятся с корпусом). Отчёт —
   тот же `$WORK/<slug>/gates.json` (стадии копятся, не перезаписываются).

### Гейт выхода (B)
- [ ] Шаг 2 (`article_gates.py <slug> --stage page`) = PASS
- [ ] `article_verify.py` = 0 (страница воспроизводима из источника, ручного Edit не было)
- [ ] Страница задеплоена через `ftp_publish.py` (бэкап есть, каждый URL проверен на 200, встроенный гейт артефактов `artifacts_gate.py --min` = PASS)
- [ ] `article_gates.py <slug> --stage publish` = PASS (после деплоя, против живого корпуса)
- [ ] Чистый URL /guide-<slug>/ (не `.html`), картинки отдаются по `assets/…` и все 200
- [ ] Смысл доехал: цельное тело простым языком + приглашение компактным хвостом, финал на трипваер, SEO-поля (meta/slug/ключ) на месте
- [ ] Шаг 3 закрыт: обе ноги уведомления отправлены, улики в `$WORK/<slug>/etap-12a-index-legs.md`

## 🔔 Шаг 3 - ОБЕ НОГИ УВЕДОМЛЕНИЯ (общий для целей A и B) - HARD

🔴 **Статья НЕ опубликована, пока не отправлена в ОБА поисковых контура.** Механизмы у них разные:
у одного есть мгновенный push-протокол, у другого push-эндпоинта нет вообще. Закрыть одну ногу и
считать статью выпущенной - брак: половина рынка узнаёт о странице через обычный обход, то есть
недели вместо часов. Канон - `seo-engine/methodology/00-methodology-16-stages.md`, Этап 12a.

**Нога 1 - IndexNow (Яндекс, Bing и остальные участники протокола).** Машинная:

```bash
# один вызов закрывает ногу 1 и машинную половину ноги 2:
# пересобирает и заливает sitemap.xml + шлёт IndexNow-пинг
python3 ~/.claude/skills/_shared/tools/seo_publish.py --url "<полный URL статьи>"

# повторный пинг, когда sitemap уже актуален и трогать его не нужно:
python3 tools/ftp_publish.py --ping --url "<полный URL статьи>"
```

Улика - JSON вывода со списком `pinged`.

**Нога 2 - Google, через Search Console.** Отдельного HTTP-пинга у Google НЕТ: старый
`google.com/ping?sitemap=` отключён в 2023 (зафиксировано в докстринге `seo_publish.py`). Нога
закрывается двумя частями, обе обязательны:

1. **Sitemap.** Проверить машинно, что URL реально в карте сайта:
   `curl -s https://<твой-домен>/sitemap.xml | grep "<slug>"` → ровно одна строка. Сам файл подан
   в Search Console один раз на домен, дальше Google перечитывает его сам
2. **Запрос переобхода** конкретного URL в кабинете Search Console. 🔴 Это чужой интерфейс:
   названия пунктов меню НЕ выдумываем и в канон не хардкодим - открываем живой кабинет и делаем
   по фактическому экрану. Indexing API сюда не годится, Google принимает в него только отдельные
   типы страниц, обычные статьи - нет

**Улики обеих ног складываются в `$WORK/<slug>/etap-12a-index-legs.md`:** JSON IndexNow-пинга + вывод
`grep` по живому sitemap + запись о запросе переобхода (какой URL, когда, что ответил кабинет). Для
Варианта B сюда же — вывод `article_gates.py <slug> --stage publish` (Вариант B, шаг 3). Нет улики
хотя бы по одной ноге - статья не считается выпущенной, Этап 5 не стартует.
