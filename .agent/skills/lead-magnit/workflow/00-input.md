# Этап 0 — ВХОД + КЛЮЧ

> Генераторы картинок и сборщики запросов в пакет НЕ входят: ниже описан их интерфейс,
> по которому Клод соберёт такой же инструмент на твоём проекте. Команды даны как описание
> интерфейса, а не как готовый запуск

**Вход:** запрос автора + (опционально) контекст: карусель/рилс, тема, кодослово, материалы.
**Выход:** `brief` — тема + результат гайда + код-слово (= поисковый ключ) + вторичная ссылка + источник темы.

> **ТОЛЬКО через `demand_gate.py --take-next`** (`seo-engine/methodology` Этап 1.9) - гейт спроса
> HARD E>=10, чтение очереди в обход этой команды запрещено (закрывает класс «написано-но-не-
> вызывается», см. правку скептика по решению автора). Полный поиск по 9 осям (Этап 1-2) гоняю ТОЛЬКО когда

> «Объединение»).

## Шаги

1. **Определить источник темы.**
   - **Дан контекст** (карусель/рилс/тема/ссылка на оригинал) → строю гайд от него. Тема гайда
     = тема контента, который ведёт на эту страницу.
   - **Контекста нет** → 🔴 тема выбирается ТОЛЬКО этой командой, чтение `topics-state.json`
     напрямую (минуя гейт) запрещено - обход гейта спроса = нарушение канона:
     ```bash
     python3 .business/growth/seo/demand_gate.py --take-next --commit
     ```
     Гейт HARD E>=10 (спрос >= 1000): берёт верхнюю по эффективному E тему со `статус: "очередь"`
     из боевого `growth/seo/state.json` (реальный файл гейта - не `$WORK/_queue/topics-state.json`,
     тот путь был не более чем описанием в старом каноне и физически не существует; схема реальная -
     `тема/кластер/статус/ключи/спрос`, статусы по-русски), печатает тему/кластер/спрос/E, при
     `--commit` сам пишет `статус: "в работе"` с бэкапом - отдельно помечать статус вручную не
     нужно. Тема должна быть «Claude собрал мне <результат>» (кейс-результат, который зажигает
     «хочу так же») - это уже гарантировано на этапе батч-поиска (Этап 1.3a).
     **Exit 1** («Очередь пуста ИЛИ ни одна тема не проходит HARD-гейт E>=10») → это триггер контура
     добычи, НЕ повод брать тему в обход гейта: сначала смотрю отчёт
     `collect_queries.py --dobycha` (read-only: новые головы
     кустов, прошедшие HARD-гейт, + запас очереди в рабочих днях против темпа - сам в state.json
     ничего не пишет), затем ОДИН РАЗ батч-поиск (`seo-engine/methodology` Этап 1: пул 20+
     кандидатов из голов отчёта добычи, взвешивание по 9 осям, дописывание в `state.json` со
     `статус: "очередь"`), затем повторяю `--take-next --commit`. Не блокирую автора вопросом —
     беру и говорю что взял.

2. **Код-слово = поисковый ключ.** Достать из реестра проекта (`codewords.py`). Серия про одну тему =
   одно код-слово. 🔵 То же слово/фраза = `target_keyword` статьи (под него заголовок и структура на
   Этапах 1-2). Нет реестра под рукой → context-gap (спросить автора код-слово), не выдумывать.

2a. **🔴 ЗАХВАТ ОБЩИХ РЕСУРСОВ В РЕЕСТР - ПРЯМО ЗДЕСЬ, ДО ПЕРВОЙ СТРОКИ ТЕКСТА**
   (`seo-engine/methodology/01-parallel-i-emkost.md` §4). Пока прогонов было по одному в час, хватало
   сверки с продом. При параллельных прогонах она врёт: чужой захват до прода ещё не доехал - так
   по решению автора две статьи вышли с одной обложкой. Дописать строку `status: queued` в `$WORK/_registry/`:
   `codewords.jsonl` (код-слово + ключ), `assets.jsonl` (имена файлов ассетов), `links.jsonl`
   (какие внутренние ссылки эта статья собирается поставить). Обложки/сцены - свой уже готовый
   реестр `uniq.py` + `cover-index/index.json`, второй не заводим.
   Занятость проверяется ПО РЕЕСТРУ (последняя запись на пару ресурс+значение), не по проду.
   Значение занято чужим `queued`/`published` → беру следующее. Без записи `queued` письмо не
   начинается.

2b. **Кэш куста** (`01-parallel-i-emkost.md` §3). Определить, в какой куст (кластер из 3-8 статей
   вокруг одного инструмента/интента) входит тема, и зафиксировать имя куста в брифе. Есть
   `$WORK/_cache/<cluster>/` и он свежий (TTL: выдача 7 дней, ресёрч 14 дней + сверка sha
   источников) → ресёрч Этапа 3 читает его, а не повторяет. Куста нет → эта статья его создаёт.

3. **Результат-узнавание (обещание).** Одной фразой: какую мою историю-кейс человек увидит и
   узнает в ней свою мечту («Claude собрал мне <X> - смотри, что вышло»). Это будущий
   заголовок-герой. НЕ «ты соберёшь за 15 минут» (как - на трипваере).

4. **Трипваер.** Зафиксировать целевой продукт из `config.md` → target_product/target_* (ровно один,
   боевое значение живёт в config, не в каноне). Это главный CTA финала. URL нет в config (TODO) →
   context-gap, спросить автора.

5. **Slug и URL публикации.** Сформировать slug из темы (транслит, kebab-case). Адрес зависит от
   `config.md → publish_target`: `stateinik` → `<твой-домен>/guides/<slug>` (рендерит движок);
   `ftp` (мост) → `<твой-домен>/guide-<slug>/` (чистый URL без .html). Нужен на Этапе 4
   (куда публиковать) и Этапе 5 (что проверять curl). Зафиксировать сразу, не на деплое.

5. **Context-gap гейт.** Чего реально не хватает для конкретики (цифры/кейсы/факты/реальные
   названия инструментов) → нумерованный список «нужно от тебя», жду. Не выдумываю под именем
   автора (`_shared/context-gap-gate.md`,).
