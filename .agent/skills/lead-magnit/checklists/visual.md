# Гейт визуальной приёмки статьи

> Генераторы картинок и сборщики запросов в пакет НЕ входят: ниже описан их интерфейс,
> по которому Клод соберёт такой же инструмент на твоём проекте. Команды даны как описание
> интерфейса, а не как готовый запуск

> **Когда:** Этап 4, Шаг 2 (после гейта стадии page) - перед публикацией, по СОБРАННОЙ странице `$WORK/<slug>/index.html`
> (в markdown-черновике картинок и блока «Источники» физически нет). Канон правил -
> `knowledge/visual-layer.md`. Это гейт: любой незакрытый пункт = статья НЕ публикуется.
> Пункт закрывается галочкой `[x]` только с уликой (команда + вывод / файл в `$WORK/<slug>/`).
>
> Машинная часть одной командой:
> `python3 tools/structure-check.py $WORK/<slug>/index.html --visual` (должен дать exit 0)
>
> Инструменты кадра (`shot.py`, `uniq.py`) зовутся по пути из `config.md` → `image.path`, не хардкодом:
> `CFG="$HOME/.claude/skills/lead-magnit/config.md"; IMAGES="$(grep -A3 '^image:' "$CFG" | grep -m1 'path:' | sed -E 's/[[:space:]]*#.*//; s/^[^:]*:[[:space:]]*//; s/[[:space:]]+$//')"; IMAGES="${IMAGES/#\~/$HOME}"; case "$IMAGES" in /*) ;; *) IMAGES="$HOME/$IMAGES" ;; esac`
>
> 🔴 **Закон владельца: картинка легальна ТОЛЬКО ультра-реалистичной и ТОЛЬКО ценной.**
> Легальные классы кадра - result (кейс-превью функции в реальном интерфейсе), step (путь клика,
> рамка «жми сюда»), own-run (свой прогон - окно-чат Claude Code в VS Code или веб-панель
> результата; окно оболочки/терминала в класс НЕ входит), inherited (кадр перенесён с уже
> существующей страницы при её ревизии, съёмку инструмент не подтверждал, класс переходный).
> Генеративные сцены, надписи-картинки, «скрин главной» вместо функции, декорация
> ради пола - брак. Гейт происхождения кадров `frame-provenance` (часть `article_gates.py <slug>
> --stage page`) - WARN по умолчанию, HARD только на `--provenance-hard`.
