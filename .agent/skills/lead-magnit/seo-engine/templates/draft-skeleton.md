# Скелет черновика статьи (Этап 6)

> **Метод (Этап 6 методологии).** Один длинный заход записи в `$WORK/<slug>/draft.md`: служебные поля (frontmatter) сверху + тело. Публикация и точный формат вёрстки - забота адаптера `cms.adapter` на Этапе 9; здесь задача написать чистый переносимый текст в GitHub-flavored Markdown, без компонентов конкретного движка.
>
> **Как использовать этот файл.** Скопируй всё, что ниже разделителя `==== НАЧАЛО ЧЕРНОВИКА ====`, в `$WORK/<slug>/draft.md` и заполни плейсхолдеры. Блоки в `<...>` - заглушки под содержимое; квадратные пометки `[блок ...]` - места, где `cms.adapter` подставит ваш визуальный компонент при публикации.
>
> **Дефис, не длинное тире.** В заголовке, meta-полях, теле, цитатах, источниках - везде дефис `-`. Длинное тире - маркер ИИ-текста, под запретом по всей методологии.

# twitter:image:alt), и превью в соцсетях опишет тему вместо картинки.
# Терминальные слова тут ловит гейт novice тем же шаблоном, что alt и hero_alt.
quick_answer: "<1-2 предложения прямого ответа на запрос, потолок 3 - рендерится сразу под H1, до любых подводок>"

  - q: "<вопрос как его гуглят>"

checklist_memo:              # чек-лист-памятка (блок с кнопкой «скопировать список»)
  - "<пункт 1>"
  - "<пункт 2>"
shares:                      # кнопки шаринга (%%SHARE_URL_ENC%% / %%SHARE_TEXT_ENC%%), чистые share-URL без JS-трекеров
  enabled: true
  channels: [telegram, whatsapp, vk]
  text: "<что подставить в текст репоста; по умолчанию = title>"
# поле meme упразднено законом владельца: шапка = кейс-превью (result/own-run),
# надпись-картинка и обложка-плашка в SEO-статье запрещены
