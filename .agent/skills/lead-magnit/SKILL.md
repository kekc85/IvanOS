`website` уже несёт turnkey-контракт, машинные гейты качества и раздел «Лид-магнит-гайды».

## Когда применять

Триггеры: «сделай лид-магнит под эту карусель/рилс», «статья-гайд за кодовое слово»,
«собери лид-магнитную страницу», «лид-магнитная воронка под тему X», «гайд-страница для
кодослова», `/lead-magnit`, `/lead-magnit <тема>`.

**Не применять** для: caption/описания под сам ролик (это writer-скиллы + `_shared/lead-magnet-description-structure.md`);
обычного лендинга/сайта без лид-магнитной механики (прямой `website`); поста/письма/карусели
(свои скиллы).

🔴 **Арбитраж с `website`.** У `website` есть свой раздел «Лид-магнит-гайды», но это правила
ФОРМЫ для случая, когда его вызывает `lead-magnit`. При любой задаче «лид-магнит / страница
за кодовое слово» ПЕРВЫМ идёт `lead-magnit` (слой смысла: воронка + техничка 50/50 + прогрев +
план визуалов + mastery), а он уже вызывает `website` (форма). `website` НЕ инициирует лид-магнит
сам — иначе выпадает слой смысла. Прямой `website` — только для НЕ-лид-магнитных сайтов.

## Как машина работает (карта системы) — две холодные двери, одна статья

```
ДВЕРЬ 1: КАРУСЕЛЬ / РИЛС ──(код-слово в DM/комменты, Механика 1)──┐
   (writer-скиллы, тело = кейсы-результаты)                       │
                                                                  ▼
                              ОДНА SEO-СТАТЬЯ-ГАЙД  ──▶  ТРИПВАЕР
   ДВЕРЬ 2: ПОИСК ──(тот же код-слово = ключ)──▶   (этот скилл: смысл 50/50           (платный,
   (Яндекс/Google по target_keyword)               + авто-SEO; форма/рендер =          config
                                                    Stateinik /guides, мост FTP)        target_url)
```

Лид-магнит = бесплатная ступень evergreen-лестницы И постоянный SEO-актив одновременно: холодная
органика (рилз/карусель ИЛИ поиск) → **одна статья-гайд (этот скилл)** → **трипваер**. Обе двери
ведут на ОДИН URL в кластере `/guides` (код-слово = поисковый ключ, не плодим дубли). Финал статьи
**ВСЕГДА** переливает на трипваер - это закон.
Целевой продукт берётся из `config.md` → target_product/target_url (боевое значение - живая строка
в config, не в каноне; меняется одной строкой config, канон название продукта не хранит и не
хардкодит).

**Форма/рендер статьи = движок Stateinik** (CMS, отдаёт статьи по `/guides/<slug>`), публикация через
`seo-engine` адаптер `stateinik_publish.py`. 🔴 ЦЕЛЬ ПУБЛИКАЦИИ ВЫБИРАЕТСЯ САМА (config `publish_target:
auto`): на каждом прогоне Этап 4 пробит `<твой-домен>/guides/` → 200? Да = публикую в
статейник на /guides; нет (сейчас 404) = временный мост website→FTP на `/guide-<slug>/`, живой гайд не
прерывается. Переключение АВТОМАТИЧЕСКОЕ, в ту же секунду как статейник в проде - ни автор, ни я флаг
руками не трогаем (автор: «я сам менять ничего не хочу, делай сам»).

## Непропускаемый минимум этапов - HARD (против облегчённых прогонов)

Для КАЖДОЙ статьи обязательны ВСЕ пункты ниже. Пропуск любого = статья НЕ готова, к выдаче не предъявлять:

1. **Ключ (Этап 0):** поисковый ключ + код-слово зафиксированы (одна сущность, сверка по реестру).
2. **Структура (Этап 2):** скелет с быстрым ответом первым блоком, FAQ (4-7 вопросов) и чек-листом-памяткой; 8-14 H2.
3. **Длина по интенту (Этап 2):** инструкция **2000-3500** слов · опорная статья **от 4000** · разбор/новость **1200-2000** (пороги - `seo-engine/seo-config-reference.yaml` → `tools.length`). Недобор лечится раскрытием темы, не водой.
4. **Контент (Этап 3):** ресёрч (реальные команды/факты, не из головы) + написанный контент + обязательный humaniser на финале + 🔴 **стандарт новичка** (`knowledge/novice-standard.md`): у каждого шага «куда нажать → что увидишь → что даёт», термины переведены в той же фразе, кода минимум, терминальных сцен нет. Четыре признака брака (шаг без «что увидишь» · шаг без «что даёт» · непереведённый термин · терминальная сцена) роняют стадию, а не пишутся в замечания.
5. **Визуальный слой (планируется на Этапе 2, производится на Этапе 3):** по `knowledge/visual-layer.md` - два порога: пол = иллюстрации + .vizblock-блоки, минимум `min_images` единиц (дефолт 3, `tools.visual.min_images`; таблицами и кодом не закрывается) и плотность не реже 1 визуального блока (иллюстрация/.vizblock/таблица/код) на ~350 слов ПРОЗЫ, потолок 10 (канон = код structure-check: have считает все четыре типа). 🔴 Кадр легален ТОЛЬКО одного из четырёх классов - result (кейс-превью функции) · step (путь клика с рамкой «жми сюда») · own-run (свой прогон, окно-чат, не оболочка) · inherited (перенесён со старой страницы при ревизии, съёмку инструмент не подтверждал) - закон владельца 22.08.2026; hero = кейс-превью (для темы без стороннего UI - own-run «окно-чат»), og = тот же кадр или его плотный кроп 1200x630, alt 50-125, дата съёмки в figcaption, у каждого кадра запись в `shots-manifest.json`; визуал шага - скрин реального UI класса step или .vizblock.vizsteps, терминальных и генеративных сцен у новой статьи нет, легаси-мокап при ревизии - только с реального прогона. **ЧТО внутри кадра - по `knowledge/visual-engine.md`:** каждый визуал выведен из своего раздела и несёт его якоря (команды, пути, имена окон, версии, ошибки, цифры) не ниже нормы своего типа, у доказательного кадра якоря питают СЦЕНАРИЙ СЪЁМКИ; приёмка по осям A1-A13 с порогами (раздел 6), а не по «понятно ли, о чём статья».

## ⚡ Ёмкость и параллелизм: 15 касаний в день

🔴 **Ёмкость дня - 15 КАСАНИЙ, а не 15 новых статей.** Раскладка: **3-5 новых + 10-12 ревизий**
существующих. Полная механика - `seo-engine/methodology/01-parallel-i-emkost.md`, здесь - контракт.

**Почему не 15 новых подряд.** Три независимые причины: издания, которые держат объём органики,
публикуют доли новой статьи в день и держат масштаб ревизией архива · 15 новых страниц в день с
одинаковым скелетом = профиль scaled abuse, который антиспам ловит по формальным признакам ·
ревизия работает по уже накопленным показам, новая статья стартует с нуля.

**Где взялась скорость** (аудит боевых прогонов, `_rebuild/research-wave1-2026-08-04.md`, раздел speed):

| Что было монолитом | Стоило | Стало |
|---|---|---|
| черновик всех 8-14 разделов одним вызовом | 3м45с простая · 41-59 мин сложная | N параллельных суб-агентов по разделам + шов (§1) |
| хуманайзер всего текста одним вызовом | 13 мин простая · 51 мин сложная | секции параллельно + финальный проход целиком (§2) |
| ресёрч и снимки выдачи заново на каждую статью | на каждую статью куста | кэш куста, один раз на кластер (§3) |
| три пост-аудита, три скачивания одной страницы | последовательно | один снимок, три параллельных агента (§5) |

**Реестры общих ресурсов - захват в момент СТАРТА** (§4). Код-слово/ключ, имена ассетов, ссылки
кластера пишутся строкой `queued` в `$WORK/_registry/*.jsonl` до первой строки текста; занятость
проверяется по реестру, НЕ по проду. Обложки - свой готовый реестр (`uniq.py` + `cover-index/index.json`),
второй не заводим. Прецедент, породивший закон: по решению автора два параллельных прогона выпустили одну обложку,
каждый честно сверился с продом - где чужой картинки ещё не было.

**Гейт на каждое касание:** `structure-check.py <страница> --own-blocks-hard` (≥3 блока собственного
материала); НОВАЯ статья добавляет к тому же вызову `--tool-article-hard`
(`structure-check.py <страница> --own-blocks-hard --tool-article-hard`) - ревизия эту ось HARD не

## Принципы

1. **Смысл — мой, форма — website.** Не верстаю руками, не дублирую гейты website. Кормлю его готовым контентом + структурой.
2. **50/50: техничка + прогрев.** Половина 1 = пошаговый план для новичка (установка по шагам + использование, подача по `knowledge/novice-standard.md`), половина 2 = прогрев к воркшопу. Не одно без другого (см. `knowledge/article-anatomy.md`).
3. **🔴 НОЛЬ ВОДЫ + ПОНЯТНО НОВИЧКУ (двойной гейт с этой редакции).** Техчасть обязана быть и конкретной, и понятной: каждый шаг = тройка «куда нажать → что увидишь на экране → что это тебе даёт», при необходимости копи-блок, визуал шага - скрин реального UI или `.vizblock.vizsteps`. Запрещены «вдохновляющие» абзацы вместо шагов, обещания вместо инструкций, общие слова, непереведённый жаргон. Тест двойной: «человек может прямо сейчас СДЕЛАТЬ этот шаг?» И «понимает ли новичок, что увидит и зачем?» Провал любого → переписать (`knowledge/anti-water-gate.md`).
4. **Реальность, не выдумка .** Команды/шаги/названия только настоящие — каждую достаю РЕСЁРЧЕМ (WebFetch README/офиц. доки), НЕ из головы, НЕ по памяти. Не уверен в команде → research, не уверен после research → context-gap, а не правдоподобный черновик. Техничная половина = пошаговый план новичка: что нужно до старта → куда нажать → что увидишь → что это даёт → как пользоваться; команда реальная, но подана копи-блоком четырёх тактов, визуал шага - скрин реального UI или `.vizblock.vizsteps`. Небезопасное новичку (`curl|bash`, запуск непроверенного) не даём. Глубокая настройка/сборка продукта → трипваер, но БАЗОВАЯ установка+использование = в статье.
   🔴🔴 **ПОД РЕПЛИКУ РОЛИКА — СТАТЬЯ ПРО ТОТ ЖЕ КОНКРЕТНЫЙ ТУЛ, что в ролике, НЕ общая по теме (автор, взбешён «статья про агентов, а ролик про конкретный репозиторий, переделай»).** Ролик показывает конкретный инструмент → СНАЧАЛА идентифицировать ТОЧНЫЙ тул (репозиторий/сервис) по кадрам ролика (читать GitHub-хедер/URL: `gh search repos "<name>"`, `gh api repos/<owner>/<repo>/readme`), достать реальный README, и статья = супердетально про ИМЕННО ЭТОТ тул (как открыть/запустить именно его). Общая статья по теме при ролике про конкретный тул = обман ожидания = брак. Код-слово под такую статью — ТОЛЬКО `СВОБОДНО` (`codewords.py check`), занятое/активное не брать.
5. **Понятно бабушке = стандарт `knowledge/novice-standard.md` ЦЕЛИКОМ** (тройка на шаге, перевод термина в той же фразе, метафоры и аналогии, мотивация и прогресс-маркеры, минимум кода, ноль терминальных сцен), а не отдельное пожелание про простые слова. Стек - `config.md` → stack, не «технически можно иначе».
6. **Финал ВСЕГДА на трипваер.** Главный CTA = трипваер (`config.md` → target_url). Целевой продукт - РОВНО ОДИН, меняется только в config (`target_product`), НЕ несколько параллельных продуктов - автор разносил «три воркшопа» как нарушение этого закона.
7. **Публикация только на <твой-домен>, цель = авто-детект.** Канон = движок Stateinik на `/guides/<slug>`; мост (пока `/guides` отдаёт 404) = website→FTP на `/guide-<slug>/`. Цель выбирает сам скилл (`publish_target: auto`), флаг руками не трогаем. Только ТВОЙ хостинг/домен, не чужой. В финале — живая ссылка (curl 200), публикуем на твой хостинг.
7a. **🔵 SEO встроен и АВТОМАТИЧЕН.** Каждая статья = SEO-актив: target_keyword (= код-слово), meta_title/meta_description/slug/excerpt, структура 8-14 H2, каждый открывается ответом первой фразой, перелинковка в кластер /guides, проверки originality/cadence/structure из общего слоя. Не «отдельный SEO-проход потом», а наложение в Этапах 0-3. Код-слово и поисковый ключ = одна сущность.
8. **Дан контекст — строю от него; нет — собираю сам по канону.** Не блокирую автора выбором, который вывожу из контекста/канона.
9. **🔴 ПРЕРЕКВИЗИТ СРЕДЫ ОБЯЗАТЕЛЕН, И ПОДАЁТСЯ ОН КАК «ОКНО, ГДЕ ТЫ ПИШЕШЬ ИИ СЛОВАМИ» (правка 19.08.2026).** Если в технической половине ты просишь читателя что-либо открыть или выполнить в Claude Code, статья ОБЯЗАНА в Шаге 0 нести явную инструкцию + ссылку на гайд установки (`config.md` → `install_guide_url`). Логика прежняя: у новичка среды может не быть, и без неё некуда вставлять то, что мы просим вставить. Что изменилось - ФОРМУЛИРОВКА: Claude Code описывается как «окно, где ты обычными словами пишешь ИИ, что сделать», а не как «терминал, куда вводят команды»; слово «терминал» как понятие-пререквизит не употребляется вообще, вместо категории показывается место на экране (`knowledge/novice-standard.md` §6). Сказал «открой/выполни» без шага «вот как это себе поставить» = брак, дыра в инструкции. То же для любой другой среды, которую гайд предполагает: либо ставится в Шаге 0 со ссылкой, либо это явный prerequisite со ссылкой на установку. Стек не меняется, меняется только то, как он назван читателю.

## Reader-action: что читатель делает

🔴 ЛОГИКА v3.0 (0.0, запрос автора «это вода, распиши детально как поставить и пользоваться»).
Откат прежнего v2.0 «ничего не показываем, два действия — завести Claude и уйти на трипваер»: это
давало воду. Теперь читатель внутри статьи РЕАЛЬНО ставит и запускает инструмент по шагам:
1. **Половина 1 (техничка):** проходит установку по шагам (нажимает/вставляет команды/видит результат)
   и пробует использовать — получает рабочий инструмент. Это реальная польза, а не «обещание».
2. **Половина 2 (прогрев):** видит, что это меняет, и переходит на воркшоп за глубокой настройкой и
   сборкой реального продукта.

Логика: дать настоящую пользу в технической половине (доверие через результат) → прогреть и увести
на трипваер за тем, что в статью не помещается (настройка под себя, сборка продукта, система). Финал
ВСЕГДА = трипваер (`config.md` → target_url)..

## Кодовое слово: читать, не угадывать  — HARD

🔴 Одно кодовое слово = ОДИН конкретный лид-магнит. Код-слово под этот магнит **читаю из контекста**
(что дал автор) **или из приписки самого поста** (`yt-dlp --skip-download --cookies-from-browser chrome
--print "%(description)s" <url>`, куки `<твой-cookie-файл>`), а НЕ угадываю по реестру/транскриптам/смыслу.
Дал ссылку на пост → один `yt-dlp` → код-слово (прецедент: гадал 6 раз, слил доверие,
).

🔴 НЕ врать в тексте про механику бота. Если в статье/посте/CTA написано «напиши X — пришлю весь
список / всю подборку / весь гайд», то по кодослову X автосценарий обязан прислать ИМЕННО это, не
другое. Перед сборкой сверяю пару `слово → какой магнит присылается` по реестру (`config.md` →
codewords_registry) и по факту сценария бота. Несовпадение текста и реальной выдачи = брак, чинить
текст или сценарий, не оставлять.

## Выдача новых магнитов: только новые ссылки  — HARD

🔴 На запрос «сделай/выложи новые лид-магниты» отдаю в чат ТОЛЬКО новые живые ссылки (curl 200) —
то, что собрал в этой задаче. НЕ скидываю полную карту всех существующих ссылок, НЕ предлагаю
заново уже выложенное. автор видит результат конкретной задачи, не реестр. Полный список — только
если автор явно попросил «дай все ссылки / карту гайдов».

  > 🔴 **Карту сайта собирает РОВНО ОДИН скрипт - `sitemap_rebuild.py`** (путь у каждого свой, задаётся полем `sitemap_rebuild` в `~/.config/seo-publish.json`). `seo_publish.py` карту больше не собирает и не заливает: он делегирует пересборку владельцу, а без владельца в конфиге отказывается громко и с ненулевым кодом. Причина (разбор по решению автора, «два владельца sitemap.xml»): живая карта несёт слой картинок (`image:image`/`image:title`, namespace sitemap-image) и даты из реестра содержимого, а внутренняя `build_sitemap()` пишет голый `urlset` - её заливка молча затирала оба слоя на первом же штатном прогоне хвоста. `build_sitemap()` осталась библиотечной: её вызывает сам `sitemap_rebuild.py` в аварийном режиме `--без-картинок`, из хвоста она не вызывается.
  > 🔴 **Деплой только через `ftp_publish.py`, своих скриптов заливки не писать.** Каталожная страница - `--dir <каталог>`; плоская (файл в корне сайта, картинки в общем `/assets/<slug>/`) - `--dir <каталог> --remote-dir "" --page <файл>.html --remote-page <файл>.html --assets-remote assets/<slug>`. Белый список того, что вообще может уехать на прод, живёт в одной функции `ftp_publish.whitelist_assets()`: если для разовой задачи всё же нужен скрипт-обёртка (например с гейтом гонки параллельных сессий), список файлов он обязан брать оттуда, а не из `os.listdir`. Прецедент по решению автора: волны ретрофита писали свои циклы по `listdir` без фильтра, и один `render-*.png` уехал бы на прод.
- `article-template/` (путь — config.md → template.path; станок статьи, физически НЕ в раздаваемом `skills/` — портативной раздаче без него служит мост `Skill('website')` выше) — `article_build.py` (`draft.md` → `spec.json`, единственный шов черновик→спека, контракт см. `--help`), `build_page.py` (`spec.json` → `index.html`, шаблон 2.0), `article_gates.py <slug> --stage draft|page|publish` (единый раннер гейтов стадии, один exit-код, `--list` печатает состав), `article_verify.py <slug>` (гейт воспроизводимости: пересборка в песочницу + семантический дифф — ловит ручной Edit по index.html), `artifacts_gate.py <slug> --min|--full` (обязательный минимум артефактов конвейера / полный 16-этапный след, замок публикации перед деплоем).

## Anti-patterns

- **Верстать страницу руками мимо сборщика** — дублирование, теряются гейты сборки. Форма статьи конвейера (Этап 4) - КОД: `article_build.py` → `build_page.py` по шаблону из config.md → template.path, это детерминированная сборка, не ручная вёрстка, и это НЕ анти-паттерн. Анти-паттерн - (а) писать HTML руками мимо этой сборки или мимо `Skill('website')` (мост - для не-статейных страниц/без build_page-тулинга), и (б) 🔴 **ручной Edit по уже собранному `index.html`** (канон К.4, по решению автора) - правка идёт в `draft.md`/`spec.json`, страница пересобирается заново; `article_verify.py` ловит расхождение семантическим диффом пересборки против задеплоенного/собранного html.
- **🔴 ВОДА вместо технички (ГЛАВНЫЙ анти-паттерн v3.0)** — «вдохновляющие» абзацы, общие слова, обещания и пересказ «как это круто» вместо конкретных шагов. автор: «это вода, кусок говна». Каждый техничный абзац обязан давать действие+команду/клик+что увидишь. Нет конкретики → вода → переписать (страхуется `anti-water-gate.md`).
- **Техчасть из головы / небезопасные шаги** — команды/названия выдуманы или непроверены; `curl|bash` и запуск непроверенного даны новичку. Только реальные шаги (research) + безопасные новичку.
- **Перекос половин** — только техничка без прогрева (не ведёт на воркшоп) ИЛИ только прогрев без технички (опять вода). Нужны ОБЕ половины ~50/50.
- **Финал не на трипваер** — забыть главный CTA или увести в сторону. Трипваер (config target_url) — всегда.
- **чужой хост (не твой домен)** — публикация только <твой-домен> через FTP, даже превью.
- **Отправить автора «залей файл»** — деплой на твой хостинг.
- **🔴 Жаргон без перевода В ТОЙ ЖЕ ФРАЗЕ** — «repos/workflow/stars/флаг/пайп» новичок не понимает. Термин переводится простыми словами или метафорой сразу же («репозиторий - это папка проекта, которая помнит все свои прошлые версии»), а термин, не нужный для действия, вычёркивается вместе с абзацем (`knowledge/novice-standard.md` §2).
- **🔴 Терминальная стена и шаг без «что увидишь / что даёт» (главный анти-паттерн по решению автора)** — скриншоты терминалов, многострочные конфиги, пайпы и флаги без перевода, шаг, после которого читателю не сказано, что появится на экране и зачем это ему. Владелец: «никто это не поймёт». Лечится тройкой на каждом шаге и заменой терминальной сцены на скрин реального UI или `.vizblock.vizsteps`.
- **Тяжёлая страница** — автор открывает с телефона; сжимать картинки в JPEG, лёгкость (это держит website мобайл-перф-гейт).
- **Выдумывать факты/цифры/кейсы** — нет реального → context-gap-гейт, спросить, не выдумывать под именем автора.
- **🔴 Угадывать кодовое слово ** — гадать по реестру/смыслу/транскриптам вместо чтения приписки поста (`yt-dlp --print description`) или контекста автора. Дал ссылку → один yt-dlp → код-слово. Гадание = слив доверия.
- **🔴 Текст врёт про механику бота ** — в статье/CTA «напиши X — пришлю весь список», а по слову X бот шлёт другое. Одно слово = один конкретный магнит, текст и реальная выдача обязаны совпадать.
- **🔴 Скинуть карту всех ссылок вместо новых ** — на запрос новых магнитов вывалить полный список существующих / предложить уже выложенное. Отдаю ТОЛЬКО новые ссылки этой задачи.
- **🔴 Читательский адрес оканчивается на `.html` (автор; ужесточено по решению автора)** — ЛЮБАЯ страница, которую видит читатель (гайд, каталог, об авторе, политика, оферта), живёт по ЧИСТОМУ URL: папка `<имя>/index.html` → адрес `<твой-домен>/<имя>/`. Прежнее исключение «старые.html работают как есть» ОТМЕНЕНО владельцем (увидел `.html` в адресной строке каталога и потребовал убрать). Старый `.html`-адрес = папка + 301 в `.htaccess`. Новую ссылку на `…/<имя>.html` не отдавать никогда.
- **🔴 Plain text запечён в картинку (автор, по решению автора)** — схема шагов, чек-лист, сравнение, «карточка с текстом» НЕ рендерятся в PNG/JPG: медленная загрузка, текст не выделяется, не индексируется, не адаптируется к тёмной теме. Это HTML-блоки `.vizblock` (vizsteps / vizcheck / vizcompare) из шаблона. Картинкой в статье живут ТОЛЬКО реальные кадры интерфейсов классов result/step/own-run/inherited (в том числе hero и его кроп под og) и «до-после» из реальных скринов; генеративная обложка закрыта законом владельца, терминал-мокап выведен из списка по решению автора и остаётся легаси на старых страницах. Полный канон - `knowledge/visual-layer.md`, раздел «plain text в картинки не запекаем».
- **🔴 «Открой/выполни в Claude Code» без шага установки (автор)** — если гайд просит что-то открыть/выполнить в среде, а в Шаге 0 нет инструкции+ссылки на её установку (`install_guide_url`) = дыра, новичку некуда вставлять то, что мы просим вставить. Пререквизит обязателен (принцип 9), формулировка - «окно, где ты словами пишешь ИИ», не «терминал».
- **⚡ Монолитный черновик или монолитный хуманайзер** — писать все 8-14 разделов одним вызовом. Это главный и второй боттлнеки конвейера (до 59 и до 51 минуты на статью). Только фан-аут по разделам, и только со швом.
- **🧵 Сборка без шва** — склеить секции и пойти дальше. Секционный агент не видит соседей: повтор определений, дубли цифр, обрыв связок и сбитая нумерация приезжают на прод. Шов не сливается с хуманайзером и не режется на секции.
- **📊 Гонять `ai-cadence-check` по кускам** — плотность считается на 1000 слов, на секции в 250 слов она врёт в обе стороны. Машинные гейты — только по собранному телу.
- **🔁 Сверять общий ресурс с продом вместо реестра** — «на проде такого нет, значит свободно» при параллельных прогонах ложно: чужой захват туда ещё не доехал. Прецедент — одна обложка на двух статьях по решению автора.
- **🔔 Одна нога уведомления** — отправить IndexNow и закрыть задачу. Google HTTP-пинга не имеет с 2023, его нога закрывается sitemap + переобход в Search Console. Одна нога = статья не опубликована.
- **💸 Кэшировать цену, тариф, лимит или номер версии** — эти факты живут только в живом источнике на каждом касании (закон 11). В кэше куста они лежат как «было на дату» и в текст не попадают.
- **📅 Ревизия как `touch` даты** — сдвинуть дату без содержательной правки. Ревизия обязана нести факт-чек (закон 17) и минимум один новый блок собственного материала.

## Memory cross-refs

- — финал всегда переливает на трипваер (config target_url)
- — статья = 50/50: техничка с реальными командами и промптами + прогрев → трипваер (логика «статья без промптов» v2.0 отменена как вода)
- — код-слово ПРИМЕР → гайд установки (вход в инструмент)
- — код-слово читать из приписки поста (yt-dlp), не угадывать; одно слово = один магнит, текст не врёт про механику
- — только свой домен
- — в финале живая ссылка
   - Деплой на свой хостинг (Netlify / Vercel / GitHub Pages / FTP). Если сайт уже в проде - правку публикуй на прод сразу, не отдавай localhost-ссылку: бэкап живого, заливка, проверка https (curl 200). Localhost - только пока сайта нет в проде
- — переводить англицизмы для новичка
- — стек обучения автора, не «технически можно»
- — отличие лид-магнита от прогрева (см. раздел выше)
- — нет контекста → спросить, не выдумать
- `[[website]]` — вызываемый скилл формы (Этап 4)
- `[[humaniser]]` — обязательный финальный проход копи
- — между этапами не дёргать вопросами
- — устоявшийся конвейер, структуру/CTA не спрашивать
- — отдавать live, не localhost
- — новые ссылки без `.html` (чистый URL папка/index.html)
- — «открой в Claude Code» → обязателен Шаг 0 со ссылкой на установку Claude Code
