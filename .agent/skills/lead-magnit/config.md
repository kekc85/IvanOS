## Методические дефолты (общие для всех авторов, боевых значений тут нет)

> Этот блок НЕ про твой домен, доступы и пути - только про нормы производства одной статьи.
> Переопределять его руками обычно не нужно: значения общие, потому что выведены из разбора
> рынка, а не из настроек конкретного проекта. Машинные пороги живут в
> `seo-engine/seo-config-reference.yaml` (`tools.length`, `tools.structure`), здесь - смысл.

### Глубина статьи задаётся ИНТЕНТОМ, а не единой нормой объёма

```yaml
# целевая длина ТЕЛА статьи по интенту запроса (слов)
depth_by_intent:
  tail:        [900, 1200]    # узкий хвостовой: «<инструмент> для <задачи>», «X против Y», термин
  review:      [1200, 2000]   # разбор / новость / обзор
  instruction: [2000, 3500]   # инструкция «как сделать» - основной тип лид-магнита
  pillar:      [3000, null]   # опорная статья кластера (флагман), верхней границы нет
```

Как это читать:

- **Тип выбирается по интенту запроса, а не по привычке.** Хвостовой задачный или сравнительный
  запрос закрывается на 900-1200 словах: рынок показывает страницы этого размера, выигрывающие
  выдачу у крупных отраслевых изданий, потому что попадают в интент и структурно извлекаемы.
  Дальше начинается вода, которую потом режет хуманизация.
- **3000+ слов - формат флагманской единицы, а не норма корпуса.** Обратный полюс на рынке тоже
  замерен: свежий слой на 2000-3500 слов у одного из доноров терял клики месяц к месяцу. Решает
  соответствие интенту и структура, а не словосчёт.
- **Экономия здесь не в буквах, а в ресёрче.** Под хвостовую единицу не запускается тот же объём
  deep research, что под флагман. Ошибка в обе стороны стоит одинаково: раздутый хвост это вода,
  недокормленный флагман не держит позицию.
- **Вилка фиксируется на Этапе 2** (в метаданных темы) и проверяется `wc -w` на Этапе 6.
  Ключ `tail` в `tools.length` пока не заведён: три исторические вилки (`instruction_*`,
  `pillar_min`, `review_*`) там есть, четвёртая держится методологией и метаданными темы.
  Машинный `pillar_min` строже живой нормы (4000 против 3000) и остаётся как есть.
- **Хвостовая вилка держит НИЖНИЙ край разделов: ровно 8 H2 по 120-150 слов.** Гейт структуры
  требует 12-20 контентных H2 (`tools.visual.h2_min` / `h2_max`, вилка снята с эталона по решению автора: лучшая страница топ-3 несёт 19 контентных H2), чанк терпит 120-450 слов -
  на 900-1200 словах это единственная сходящаяся раскладка. Хочешь 5-6 разделов на хвосте -
  это осознанная правка `tools.visual.h2_min` в своём конфиге, а не молчаливый провал гейта.

```yaml
mandatory_blocks:
  quick_answer:  { sentences: [1, 2], hard_max: 3 }   # сразу под H1, текст = meta_description
  faq:           { questions: [4, 7], schema: FAQPage }  # текст в схеме дословно = видимому
  checklist:     true                                  # чек-лист в конце статьи
  tables:        { min: 2, comparative_min: 1 }        # минимум 2 таблицы, одна сравнительная
  inline_links:  { words_per_link: [150, 200] }        # контекстные ссылки ИЗ ТЕЛА, виджеты не в счёт
  local_wedge:   required_if_applicable                # доступ / оплата / локальные условия рынка
```

Неприменимый к теме элемент закрывается явным `[x] SKIP: <причина>` в чек-листе статьи.
Молчаливый пропуск обязательного элемента = зелёная ложь: гейт, который никто не запускал,
отчитывается так же, как пройденный.

## SEO-хвост: конфиг публикации `~/.config/seo-publish.json`

> Раздел, на который ссылается сообщение об ошибке `seo_publish.py` («Шаблон - в lead-magnit/config.md,
> раздел SEO-хвост»). Инструменты публикации (`tools/ftp_publish.py`, `_shared/tools/seo_publish.py`)
> читают НЕ этот markdown, а отдельный JSON: домен, FTP и счётчик аналитики нужны им в машинном виде,
> и один и тот же файл переиспользуют другие скрипты. Значения yaml-блока выше и JSON ниже обязаны
> совпадать (домен, ftp_host, ftp_dir = ftp_root)

Создать один раз: `mkdir -p ~/.config && $EDITOR ~/.config/seo-publish.json`

```json
{
  "domain": "https://<твой-домен>",
  "ftp_host": "<твой-ftp-host>",
  "ftp_user": "<твой-ftp-логин>",
  "ftp_root": "/public_html",
  "metrika_id": "110740463",
  "page_prefix": "guide-",
  "author_name": "автор",
  "author_url": "https://<твой-домен>/about.html",
  "indexnow_key": "",
  "sitemap_rebuild": "/полный/путь/до/sitemap_rebuild.py",
  "root_pages": {"index.html": ["/", "1.0"]},
  "redirected": [],
  "skip_flat": [],
  "landing_dirs": [],
  "skip_schema": []
}
```

Поля:

| Поле | Обязательное | Что это |
|---|---|---|
| `domain` | да | адрес сайта со схемой, без слеша в конце |
| `ftp_host` · `ftp_user` · `ftp_root` | да | доступ к хостингу; `ftp_root` = корень сайта (в yaml-блоке выше это `ftp_dir`) |
| `metrika_id` | да | номер счётчика аналитики; по нему гейт проверяет, что счётчик стоит на новой странице |
| `page_prefix` | нет | префикс каталогов статей, дефолт `guide-` |
| `author_name` · `author_url` | нет | подставляются в JSON-LD автора |
| `indexnow_key` | нет | пусто = ключ сгенерится сам и ляжет файлом в корень сайта (по стандарту IndexNow ключ публичный) |
| `sitemap_rebuild` | нет | необязательный путь к ТВОЕМУ сборщику карты с image-слоем и датами реестра (пишешь сам, когда понадобится). Пусто или файла нет - `seo_publish.py` сам соберёт ПЛОСКУЮ карту и честно предупредит об этом в выводе, публикация статей не останавливается (см. ниже) |
| `root_pages` · `redirected` · `skip_flat` · `landing_dirs` · `skip_schema` | нет | карта корневых страниц и списки исключений для sitemap/self-heal |
| `sitemap_exclude` | нет | пути, которые формально проходят фильтры, но в публичном индексе им не место (noindex-страницы, мёртвые формы); наследуется каждым читателем индекса, который соберёшь себе (сборщик карты, опциональный генератор своего llms.txt) |

### 🔴 Карта сайта: свой сборщик опционален, есть честный фолбэк

Полная карта `sitemap.xml` (со слоем картинок `image:image`/`image:title` и датами из реестра
содержимого) собирается ТВОИМ СОБСТВЕННЫМ сборщиком - в пакете его нет, потому что он завязан на
твой личный реестр содержимого. Путь к нему кладётся в поле `sitemap_rebuild`, когда он появится.

Поле пустое или файла по пути нет - `seo_publish.py` НЕ падает: он сам собирает ПЛОСКУЮ карту
(`urlset` без слоя картинок и без дат) и печатает в вывод честное предупреждение об этом. Так
устроено нарочно: у автора свой сборщик подключён с первого дня, у ученика на старте его нет -
и это не должно останавливать публикацию статей.

Когда напишешь свой сборщик с image-слоем и датами - впиши его путь в `sitemap_rebuild`, и
`seo_publish.py` начнёт делегировать пересборку ему. Тогда же вернётся отказ с ненулевым кодом,
если ТВОЙ сборщик сломается - это уже не фолбэк, а настоящая ошибка твоего инструмента.
`build_sitemap()` остаётся библиотечной функцией, которую можно переиспользовать в своём сборщике.

Холостая проверка всей связки, без единой заливки: `python3 seo_publish.py --dry-run`
(карта уходит владельцу в режиме `--проверка`, страницы не лечатся, IndexNow не пингуется)

🔴 Пароль FTP в JSON НЕ кладём. Он живёт в связке ключей:
`security add-internet-password -a <ftp_user> -s <ftp_host> -w <пароль>`

Проверка, что конфиг принят: `python3 tools/ftp_publish.py --ping --url /<любая-живая-страница>/ --dry-run`
(нет обязательного поля - скрипт скажет какого именно и остановится)

## Ученик курса (пример переопределения)

```yaml
domain: <свой-домен>
target_kind: tripwire
target_product: <свой трипваер>
target_url: https://<свой-домен>/<страница-трипваера>/
install_guide_url: /<свой-гайд-установки>/
publish_target: auto                 # auto (сам детектит движок) | stateinik | ftp/хостинг
content_path: /guides                 # раздел статей-кластера на твоём домене
deploy: <FTP | Vercel | хостинг>

# cta (необязательная секция). Нет своих именных инвайтов - просто НЕ пиши секцию cta
# вовсе: CTA соберётся по старому маршруту (target_url выше + utm), гейты это штатно
# пропускают. Заводишь секцию - веди её ПОЛНОСТЬЮ СВОИМИ значениями, не копируй chужую:
cta:
  accepted_prefixes:
    - t.me/+                          # свой формат именных ссылок, если он есть; иначе не пиши ключ
  invites_map: <убери ключ, если своей карты «слаг → инвайт» нет (обычный режим без карты)>
  forbidden_literals:
    - /<свой-старый-лендинг>/          # СВОИ прошлые маршруты, которых в статьях быть не должно
                                        # 🔴 не копируй forbidden_literals автора (/<твой-продукт>/ и т.п.) - это
                                        # ЕГО прошлый маршрут, для тебя это будет лишним запретом. Без
                                        # invites_map литерал, равный ТВОЕМУ ЖЕ target_url выше, гейт не
                                        # ловит (фолбэк-режим легитимен) - но постороннюю чужую ссылку
                                        # в этом списке лучше не оставлять вовсе
work:
  path: <свой рабочий каталог вне скилла, напр. ~/.business/growth/lead-magnit-work>
codewords_registry: <свой реестр или ручной список>
voice_profile: <свой voice-profile>
audience_pains: <свой кастдев>
stack: <свой стек обучения>
```
