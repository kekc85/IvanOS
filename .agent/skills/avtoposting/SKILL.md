# avtoposting - публикация по расписанию на трёх площадках

## Что этот скилл делает

Разворачивает у человека собственный движок автопостинга и доводит его до первой
живой публикации. Движок берёт публикацию из очереди и отправляет её в нужную
минуту в Telegram, Instagram и VK, а сам живёт файлами на его машине или сервере

Публикация идёт ТОЛЬКО по официальным API площадок. Автоматизация под живой
сессией владельца в браузере в этом скилле не используется и не предлагается:
именно она приводит к блокировкам аккаунта

## Когда включаться

- «настрой автопостинг», «хочу постить автоматом», «выкладывать по расписанию»
- «отложенный пост в канал», «пост выйдет завтра в 9 утра»
- «постить сразу в инстаграм и телеграм», «публиковать в несколько соцсетей»
- «почему пост не ушёл», «пост ушёл дважды», «упёрся в лимит публикаций»
- «как выложить карусель через API», «как опубликовать рилс из скрипта»
- `/avtoposting`

## Когда НЕ включаться

- Просят написать текст поста, собрать карусель, снять сторис - это скиллы
  `post`, `carousel`, `сторизмейкер`, `video`. Этот скилл берёт готовое и доставляет
- Просят автоответы на комментарии и сообщения в директ - это другой продукт
- Просят посчитать охваты и подобрать лучшее время - это аналитика, здесь её нет

## Как вести человека

### Шаг 1. Понять, что у него уже есть

Спроси по одному вопросу за раз, не списком: какие площадки нужны, есть ли
телеграм-канал и права администратора в нём, профессиональный ли аккаунт в
Instagram, есть ли сообщество VK. Ответы определяют, какие шаги распаковки
вообще понадобятся: ненужную площадку просто не настраиваем, движок от этого
не ломается

### Шаг 2. Развернуть движок

Скопируй `kostyak/` туда, где человек держит проекты, и запусти установку:
`bash setup.sh` на macOS и Linux, `powershell -NoProfile -ExecutionPolicy Bypass
-File setup.ps1` на Windows. Установка сама поставит зависимость, создаст файл
ключей из образца и спросит доктора

### Шаг 3. Пройти RASPAKOVKA.md

Веди строго по нему, шаг за шагом. У каждого шага есть «готово, когда» -
не переходи дальше, пока признак не выполнен. Экраны чужих кабинетов не
описывай по памяти: либо человек присылает скриншот, либо ведёшь по тому,
что он видит, и спрашиваешь, что на экране

### Шаг 4. Довести до первой публикации

Первая публикация всегда в тестовый канал или тестовое сообщество, а не в
боевое. Признак успеха один и он машинный: `cli.py status` показывает строку
со статусом `published` и ссылкой на запись

### Шаг 5. Поставить расписание

Шаблоны лежат в `raspisanie/`, по одному на систему. Проверка расписания тоже
машинная: поставить публикацию на две минуты вперёд, ничего не запускать руками
и через три минуты увидеть `published`

## Что важно объяснить человеку, а не умолчать

**Instagram качает медиа сам.** Он не принимает файл в запросе: он идёт по
ссылке, которую вы дали, и скачивает файл со своей стороны. Значит картинка
обязана лежать в вебе и открываться без пароля. Локальный путь не сработает
физически, сколько ни повторяй. За это отвечает слой публичного адреса, у него
три режима: `ready`, `git`, `ssh`

**Токен Instagram живёт 60 дней.** Это не поломка, это устройство площадки.
Доктор скажет заранее, когда пора перевыпускать

**Лимит Instagram 100 публикаций за скользящие сутки.** Движок читает счётчик
сам и показывает его в докторе

**Сеть решает не меньше токена.** В части сетей адрес API Telegram закрыт, и
лечится это не токеном, а каналом: прокси, свой сервер Bot API либо запуск
движка на узле, где адрес открыт. Доктор показывает это отдельной строкой,
чтобы человек не менял токен там, где виновата сеть

## Команды движка

| Команда | Что делает |
|---|---|
| `python3 cli.py doctor` | диагноз по площадкам и по сети, со следующим шагом |
| `python3 cli.py add --platform telegram --text "..."` | поставить публикацию в очередь |
| `python3 cli.py add ... --at "+2h"` | отложить |
| `python3 cli.py run` | отправить всё, чему пришло время |
| `python3 cli.py run --loop` | крутиться для расписания |
| `python3 cli.py status` | что в очереди и чем закончилось |
| `python3 cli.py retry` | вернуть упавшее в очередь |
| `python3 cli.py media put <файл>` | положить файл в веб и получить адрес |

## Чего не делать

- Не предлагать обходные пути через браузер под живой сессией аккаунта: это
  прямой путь к блокировке, и весь смысл движка в том, чтобы его не было
- Не выдумывать маршрут по меню чужого кабинета. Не видишь экран - скажи прямо
  и попроси скриншот
- Не класть ключи в код и не показывать их в чате. Ключи живут только в `.env`
- Не публиковать в боевой канал ради проверки. Для проверки заводится тестовый

## Проверки перед тем, как сказать «готово»

```
python3 -m pytest tests -q     # набор проверок движка
bash leak_scan.sh              # в папке не осталось ничего личного
python3 cli.py status          # есть строка published со ссылкой
```

Готово - это строка `published` со ссылкой на живую запись, а не «настроили»
