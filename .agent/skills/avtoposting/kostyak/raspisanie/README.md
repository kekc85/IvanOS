# Расписание: чтобы движок просыпался сам

Движок умеет две вещи: отправить всё, чему пришло время (`cli.py run`), и крутиться
вечно, просыпаясь раз в минуту (`cli.py run --loop`). Расписание нужно, чтобы это
происходило без тебя, в том числе после перезагрузки компьютера

Выбирай по своей системе. Шаг один и тот же: подставить свой путь и включить

| Система | Файл | Команда включения |
|---|---|---|
| macOS | `launchd.plist.example` | `launchctl load ~/Library/LaunchAgents/autopost.plist` |
| Linux | `systemd.service.example` + `systemd.timer.example` | `systemctl --user enable --now autopost.timer` |
| Windows | `windows-task.ps1` | `powershell -File windows-task.ps1` |

## Что подставить

Во всех трёх шаблонах есть ровно два пропуска:

- `{{ПУТЬ_К_ПИТОНУ}}` - что выводит команда `which python3` (на Windows `where python`)
- `{{ПУТЬ_К_ДВИЖКУ}}` - папка, где лежит `cli.py`

Больше ничего менять не нужно

## Как проверить, что расписание живое

Поставь публикацию на две минуты вперёд и не запускай ничего руками:

```
python3 cli.py add --platform telegram --text "проверка расписания" --at "+2m"
```

Через три минуты посмотри `python3 cli.py status`. Строка со статусом `published`
означает, что движок проснулся сам. Строка со статусом `queued` означает, что
расписание не включилось: смотри лог в `~/.autopost/autopost.log`

## Ноутбук закрыт

Расписание на ноутбуке работает, пока ноутбук включён. Нужен постинг круглосуточно
и без тебя - тот же движок ставится на сервер той же командой `bash setup.sh`,
файлы движка от системы не зависят
