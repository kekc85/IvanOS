# Чертёж движка автопостинга

Один файл, по которому видно всю систему: что где лежит, как устроена единица
работы, какой контракт у площадки, где живут ключи и что происходит при отказе

## Карта каталога

```
kostyak/
├── cli.py                 единственный вход: doctor / add / run / status / retry / media
├── autopost/
│   ├── config.py          что настроено: читает .env и переменные окружения
│   ├── net.py             как ходим в сеть: прокси, таймаут, ретраи, единая форма ответа
│   ├── store.py           очередь в SQLite: идемпотентность, статусы, время
│   ├── runner.py          планировщик: берёт готовое, отдаёт адаптеру, разбирает отказ
│   ├── media.py           публичный адрес медиа: ready / git / ssh
│   ├── doctor.py          диагноз по каждой площадке и по сети
│   └── platforms/
│       ├── base.py        контракт адаптера и типы ошибок
│       ├── telegram.py    Bot API: текст, фото, альбом, видео
│       ├── instagram.py   Graph API: контейнер, ожидание, публикация
│       └── vk.py          wall.post и загрузка фото на стену
├── tests/                 набор на подменённом транспорте, в сеть не ходит
├── raspisanie/            шаблоны автозапуска: macOS, Linux, Windows
├── env.example           все ключи с пустыми значениями
├── setup.sh / setup.ps1   установка, 7 одинаковых шагов на обеих системах
└── leak_scan.sh           проверка, что в папке не осталось личного
```

Рабочие данные лежат ВНЕ этой папки, в `~/.autopost` (меняется переменной
`AUTOPOST_HOME`). Так обновление движка не затирает очередь, а копия движка,
отданная другому человеку, не тащит с собой чужие публикации и лог

## Единица очереди

Одна строка таблицы `posts` = одна будущая публикация. Поля и смысл каждого:

| Поле | Что значит |
|---|---|
| `id` | короткий идентификатор, по нему человек говорит про публикацию |
| `idem_key` | отпечаток единицы, уникальный. На нём стоит первый замок от дублей |
| `platform` | `instagram`, `telegram`, `vk` |
| `kind` | `text`, `photo`, `album`, `video`, `carousel`, `reels` |
| `text` | текст поста либо подпись к медиа |
| `media` | список публичных ссылок либо локальных файлов, json |
| `publish_at` | когда публиковать, отметка времени |
| `status` | `queued`, `sending`, `published`, `retry`, `failed` |
| `attempts` | сколько раз пытались |
| `last_error` | причина последнего отказа человеческими словами |
| `remote_id` | номер публикации на площадке |
| `remote_url` | ссылка на опубликованное, если у площадки она есть |

Жизненный путь: `queued` -> `sending` -> `published`, а из `sending` возможны
`retry` (вернётся сам) и `failed` (ждёт человека, возвращается командой `retry`)

## Идемпотентность: два замка, а не один

Повтор не должен публиковать дважды. Одного замка тут мало, потому что дубль
приходит с двух разных сторон

**Замок на входе.** `idem_key` = отпечаток от площадки, типа, текста, списка
медиа и минуты публикации. Та же команда, отданная дважды, попадает в ту же
строку, а не создаёт вторую. Нужно намеренно опубликовать тот же текст ещё раз -
задаётся свой ключ через `--key`

**Замок на выдаче.** Строка забирается атомарным обновлением со сверкой статуса:
`UPDATE ... SET status='sending' WHERE id=? AND status IN ('queued','retry')`.
Забрать может только один: вторая копия движка и повторный запуск получают отказ
и молча проходят мимо. Это и защита от гонки, и защита от повторного запуска
после сбоя

## Контракт адаптера площадки

У всех площадок он один, и добавление четвёртой площадки не меняет ни очередь,
ни планировщик:

```python
class Adapter:
    name: str                       # как зовут в очереди и у доктора
    def check(self) -> Diagnosis    # что настроено, что отвечает, что делать
    def publish(self, item) -> PublishResult   # опубликовать и вернуть след
```

`Diagnosis` несёт вердикт (`ok` / `not_configured` / `broken`), человеческое
описание и следующий шаг. `PublishResult` несёт номер публикации и ссылку на неё

Адаптер не знает ни про очередь, ни про расписание. Он получает готовый транспорт
и единицу работы. Поэтому тесты подменяют транспорт и проверяют адаптер целиком,
не касаясь сети

## Ошибки: три класса, три реакции

| Класс | Что это | Что делает движок |
|---|---|---|
| `RateLimited` | площадка назвала срок ожидания | откладывает ровно на названный срок |
| `Temporary` | моргнула сеть или сервис | откладывает с нарастающей паузой, до 5 попыток |
| `Permanent` | токен, права, неподходящее медиа | помечает `failed` и пишет причину словами |

Гадание тут запрещено принципиально. Сказали ждать 17 секунд - ждём 17, а не
«примерно минуту»

## Где живут ключи

Только в `.env` рядом с движком либо в переменных окружения процесса. В коде их
нет, в репозиторий они не попадают (`.gitignore`), в логи не пишутся. Файл
`env.example` показывает полный список ключей с пустыми значениями

Имя образца намеренно без точки в начале. Файл с точкой операционная система
прячет: в Finder и в проводнике новичок его просто не увидит, а увидеть обязан -
это единственный список ключей, который он заполняет руками. Точка появляется
у рабочей копии `.env`, которую делает установщик, и там она к месту: рабочий
файл с секретами и должен быть незаметным

Ключи площадок и рабочие данные разделены намеренно: `.env` это то, что знаешь
только ты, `~/.autopost` это то, что движок нажил сам

## Публичный адрес медиа

Instagram не принимает файл в запросе. Он КАЧАЕТ медиа со своей стороны по
ссылке, которую ты дал. Значит между твоим диском и площадкой обязан стоять
слой публичного адреса. Три пути, два бесплатны:

- `ready` ссылка уже публичная, движок только проверяет её живьём
- `git` публичный репозиторий, файл коммитится, адрес собирается из raw-раздачи
- `ssh` свой сервер, файл кладётся по scp, адрес собирается из твоего домена

Живая проверка обязательна в обоих случаях: если по адресу отвечает страница
вместо файла, площадка не скажет ничего внятного, а движок скажет

## Сеть

Один вход в сеть на весь движок, потому что условия у всех площадок общие:
прямой канал, канал через прокси (`AUTOPOST_PROXY`), либо запуск на другом узле,
где адрес открыт. Адрес API каждой площадки вынесен в переменную, поэтому
переезд на свой сервер Bot API меняет одну строку, а не код

## Границы, сознательно оставленные снаружи

Движок публикует и не делает ничего сверх этого. Он не сочиняет контент, не
считает охваты, не подбирает время. Это отдельные задачи, и смешивать их с
доставкой значит получить систему, которую нельзя ни починить, ни объяснить
