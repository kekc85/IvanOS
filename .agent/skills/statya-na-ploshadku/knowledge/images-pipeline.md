# Картинки к статье: генерация и вставка

Тракт генерации + правила размещения. Проверено живьём по решению автора боевой генерацией (SAVED, 1.8 МБ, exit 0)

🔴 Правка канала по решению автора (причина: окна браузера мешали владельцу работать за компьютером). Раньше единственным трактом был живой CDP-браузер. Теперь по умолчанию генерация идёт тихим headless-каналом без единого открытого окна, живой браузер остаётся запасным путём под явным флагом. Ниже - актуальный порядок

## 1. Основной тракт: тихий headless-канал (codex_image.py)

Генератор по умолчанию - `.business/scripts/codex_image.py`. Внутри: `codex exec` → системный скилл imagegen → встроенный инструмент image_gen. Логин тот же ChatGPT-аккаунт владельца, ключ API не нужен, окно браузера не открывается вообще. Замер живьём по решению автора: фото-обложка 3:2 вышла ровно 1536×1024 за 78 секунд, окон Chrome до и после - ноль. Слайд картинка-в-картинку сохранил геометрию донора 1080×1350 и отрисовал кириллицу без ошибок

Команда:

```bash
python3 .business/scripts/codex_image.py \
  --prompt "<промпт>" \
  --out work/<slug>-<площадка>/images/NN-название.png \
  --size og
```

Размеры (флаг `--size`): `og` = 1536×1024, `square` = 1024×1024, `slide` = 1024×1280, `story` = 1024×1536. Под конкретный размер площадки (раздел 3 ниже) генерь ближайшим `--size`, а докадрируй/домасштабируй после. Можно передать до 5 файлов-референсов флагом `--ref`

Проверка готовности канала БЕЗ расхода генераций:

```bash
python3 .business/scripts/codex_image.py --selftest
```

🔴 Изолированный дом `~/.codex-image` обязателен и держится движком сам: обычный `codex` подтягивает `~/.codex/AGENTS.md` (навигацию системы) и вместо картинки уходит проводить онбординг. Проверено живьём, отдельно настраивать ничего не нужно - скрипт готовит свой `CODEX_HOME` автоматически

🔴 Запреты (актуальны для обоих каналов):
- НЕ использовать `~/.business/scripts/auto-uniqualize/python3` - этого пути НЕ существует. Только системный `python3`
- НЕ звать higgsfield - заблокирован хуком no-higgsfield-without-permission.sh (кредиты = деньги, exit 2)

Код возврата скрипта: `0` = SAVED (картинка сохранена), любой другой = ОШИБКА, причина текстом в stderr после `ОШИБКА:` (`--help` эту причину не покажет, у скрипта всего два кода). Ненулевой код = повторить запуск или честно доложить блокер. ЗАПРЕЩЕНО выдавать статью «с картинками», когда картинок нет

🔴 **Лимит аккаунта Codex может быть выжжен.** Тогда вместо картинки скрипт честно печатает `ЛИМИТ АККАУНТА CODEX выжжен` с датой, когда лимит откроется - это внешний блокер, не брак промпта. Проверить состояние заранее без расхода генераций: `python3 .business/scripts/codex_image.py --selftest`. Пока лимит закрыт - картинки идут запасным браузерным каналом (раздел 1.1)

**Общего ресурса больше нет.** Раньше все генерации шли через один живой Chrome и держали межпроцессный лок - предупреждения «работай в одной вкладке», «жди пока откроется окно», «один прогон за раз» относились именно к нему. Для тихого канала это не действует: параллельные прогоны не делят браузер и не встают в очередь друг за другом - можно генерировать несколько картинок статьи одновременно

## 1.1 Запасной путь: живой браузер (CDP :9222), только под явным флагом

Держать браузер как основной путь запрещено - именно открытые окна мешали владельцу работать за компьютером. Живой канал остаётся доступным на случай отказа тихого:

```bash
cat > /tmp/imgprompt.txt <<'EOF'
<промпт>
EOF
python3 ~/.claude/skills/post-image/scripts/gen-chatgpt-image-cdp.py \
  --engine browser \
  --prompt "$(cat /tmp/imgprompt.txt)" \
  --out work/<slug>-<площадка>/images/NN-название.png \
  --timeout 240
```

🔴 Флаг `--engine browser` обязателен: у скрипта дефолт теперь тоже тихий (`--engine codex`), без флага он снова уйдёт в headless-канал вместо браузера

Если CDP мёртв (`curl -s 127.0.0.1:9222/json/version` пусто) - поднять рендер-Chrome (это ОТДЕЛЬНЫЙ машинный Chrome, НЕ рабочий браузер автора):

```bash
rm -f "$HOME/.chrome-cdp-profile/SingletonLock"
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --remote-debugging-port=9222 '--remote-allow-origins=*' \
  --user-data-dir="$HOME/.chrome-cdp-profile" --no-first-run \
  --no-default-browser-check --disable-session-crashed-bubble \
  "https://chatgpt.com/" >/dev/null 2>&1 & disown
sleep 9
```

🔴 Урок по решению автора (автор: «ты не в том браузере запускаешь - 50 раз одна ошибка»): скрипт gen-chatgpt-image.py без `--engine browser` открывает ИЗОЛИРОВАННЫЙ профиль ~/.playwright-chrome-data (или уходит в тихий канал), где ChatGPT НЕ залогинен на нужную сессию - из него всегда NO_IMAGE_TIMEOUT, который ВЫГЛЯДИТ как «профиль разлогинился». Это ложный диагноз: логин живёт в другой Chrome-сессии. Звать только с явным `--engine browser`, хук gpt-image-wrong-browser-guard.sh блокирует старый вызов без него (exit 2). Работать только в СВОЕЙ новой вкладке рендер-Chrome (скрипт делает это сам и закрывает её за собой)

Коды возврата `gen-chatgpt-image-cdp.py` на браузерном пути (из докстринга скрипта, `--help` их не печатает):

| Код | Значение |
|---|---|
| 0 | SAVED - картинка сохранена |
| 2 | NO_EDITOR - поле ввода ChatGPT не найдено (не залогинен/страница не та) |
| 3 | NO_IMAGE_TIMEOUT - картинка не появилась за timeout |
| 4 | NO_SRC - у картинки нет src |
| 5 | DOWNLOAD_FAIL - скачивание сорвалось |
| 6 | ERROR - прочая ошибка |
| 7 | CDP_DEAD - рендер-Chrome на :9222 не отвечает |
| 8 | тихий канал не сработал, а откат запрещён флагом `--no-fallback` |

Не-ноль = повторить запуск или честно доложить блокер

Если тихий канал недоступен (селфтест не прошёл) - сначала чинить его, и только если починить нельзя за разумное время, объявлять о переходе на браузер

## 2. Куда класть

- Рабочая папка: `work/<slug>-<площадка>/images/` внутри скилла
- 🔴 НИКОГДА в `.business/growth/produced` - хук блокирует запись (exit 2)
- 🔴 НИКОГДА не отдавать автору картинку markdown-ссылкой на локальный путь - Stop-хук бракует ответ. Показывать через Read инлайн в чат или открываемым файлом

## 3. Что генерим под статью

Обложка - размер из `platforms/<площадка>.md`:

| Площадка | Размер обложки | Примечание |
|---|---|---|
| VC | 1920×1080 | смысл в центральных 600×315 - ленты режут края |
| TenChat | 1080×1080 | квадрат |
| Хабр | 780×440 | |
| Дзен | 1920×1080 | минимум 960×540, 16:9, до 10 МБ, без анимации |

Плюс 2-4 внутренних иллюстрации к ключевым разделам статьи

Для скриншотов интерфейсов - НЕ генерить фейковые скрины нейросетью. Либо реальный скриншот, либо честная схема-диаграмма. Фейковый скрин = обман читателя и брак

## 4. Промпт-канон (из visual-anchors/manifest.md скилла post-image)

Эталон - живая editorial-документалка, не wellness-сток:

- фотореализм editorial: плёнка Kodak Portra 400 / 35mm, мягкое зерно
- живая кожа: поры, текстура, лёгкая асимметрия, без ретуши-глянца
- реальный свет: от окна, раннее утро, пасмурно; мягкие направленные тени, без студийной вспышки
- кадр-репортаж: чуть несимметрично, воздух, реальный бытовой интерьер
- БЕЗ текста и букв на картинке

Negative (вписывать в промпт): plastic skin, CGI, 3D render, stock smile, glossy retouch, oversaturated, text, letters, watermark, extra fingers

🔴 ВАЖНОЕ ИСКЛЮЧЕНИЕ для VC: аудитория VC не любит нейросетевую стилистику на обложках - считывает как контент-ферму. Для VC обложка = скриншот реального интерфейса или реального результата. Генерация на VC допустима только для концептуальных иллюстраций внутри статьи

## 5. QA-гейт картинок (блокирующий)

Открыть и посмотреть КАЖДУЮ картинку через Read - не по имени файла, глазами. Проверить:

1. кожа живая, не пластик/воск
2. пальцы целые, текст на картинке отсутствует, артефактов нет
3. вотермарок нет
4. размер соответствует площадке: `sips -g pixelWidth -g pixelHeight <файл>`
5. вес файла в лимите площадки (лимит из `platforms/<площадка>.md`)

Провал любого пункта = перегенерить. Выдавать брак запрещено

## 6. Alt-тексты

Каждой картинке - alt до 120 знаков:

- описывает что на картинке и зачем она в этом разделе
- без слов «изображение», «картинка», «фото»
- вставляется при публикации, если редактор площадки поддерживает alt

Alt пишется вместе с генерацией и хранится рядом: `work/<slug>-<площадка>/images/alts.md`
