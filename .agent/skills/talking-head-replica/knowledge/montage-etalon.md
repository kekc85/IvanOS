# Эталон монтажа + разбор источника на атомы

Взято готовым из replicate-viral по указанию автора (по решению автора): планки монтажа из разборов
топ-конкурентов и формат покадровой деконструкции. Старый скилл не трогаем, здесь адаптация
под talking-head реплику.

**Источник истины по числам и разборам:** `~/.business/growth/materials/reel-design-corpus/_canon.md`
(36 рилзов, 10 авторов; покадровые карточки лежат рядом в той же папке). Числа тут не дублируем -
при расхождении истина в каноне.

## Что из канона копируем в talking-head реплике

- Человек-якорь = константа, пруф ротируется: наш спикер весь ролик, демо-вставки окнами поверх. Это ровно continuous-anchor из канона.
- Демо-зона живёт микро-движением: вставка со скроллом/курсором из оригинала лучше статичного скрина. Если окно длинное, а сегмент короткий - forward-loop, не заморозка.
- Спокойный pace допустим: удержание делает полиш и постоянное микро-движение, не частота катов.
- Честный демо: реальный UI автора 1:1 (совпадает с законом 3 скилла).
- SFX (whoosh/click на крупных переходах, тихо под голосом, кит `~/.business/growth/assets/sfx/`) - опционально, в базовый пайплайн v1 не входит.

## Планка реплики = max(источник, эталон)

Реплика повторяет раскладку источника посекундно (закон 4), поэтому дефолтная планка = не ниже
источника. Эталоны включаются при выборе версии из дублей и на приёмке: если и источник, и наша
сборка проседают по категории (мёртвая статика в демо-зоне, нечитаемый субтитр) - чиним по эталону.

## Override субтитров (решение автора)

Категория «субтитры» старого лексикона допускала box-plate (стиль Cintas). В ЭТОМ скилле
перекрыто: чистый белый текст с обводкой, БЕЗ плашки-подложки. На спикере плашки не бывает никогда.
Текст автора глушится при нарезке вставки (закон 2).

## Разбор источника на атомы (формат Фазы 1)

Упрощённая деконструкция из replicate-viral/knowledge/source-deconstruction.md. Смысл: реплицируем
из верифицированных кадров, не из догадки - каждая строка привязана к реально извлечённому кадру.

```
| t_start | t_end | frame | layout | shows | motion | text |
```

- `frame` = путь к реально извлечённому кадру (`ffmpeg -ss <t> -i orig.mp4 -frames:v 1 ...`). Строка без существующего кадра = догадка = FAIL.
- `layout` из enum: `full-head` (спикер) / `full-ui` (демо на весь кадр) / `split`.
- `shows` = что реально показано (какой экран, есть ли лицо автора, есть ли его вшитый текст и в какой зоне y).
- `motion` = механизм: `static` / `video` / `push-in` / `cursor-trace` / `scroll` (scroll только если в источнике реально скролл).
- `text` = титр/караоке автора в этот бит: `caption:<...>` / `none`.

Правила покрытия:
1. Сплошное покрытие 0 -> длительность источника, без дыр.
2. Первые 3с - шаг не больше 0.5с (хук решает всё).
3. На динамике (layout `full-head`/`split` или смена layout у соседнего бита) бит не длиннее 1.0с.
4. Статичный длинный `full-ui` встык с тем же layout можно держать одним битом.

Из таблицы собирается `layout.json`: окна `full-ui`/`split` = окна вставок (t0, t1, зона текста
автора для drawbox), остальное = спикер.
