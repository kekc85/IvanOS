# Acceptance Criteria: Контролист приёмки реплики

## Критерии приёмки (все обязательны, с уликой)

**1. Субтитр = белый текст с обводкой, без плашки**

Требование: чистый белый текст с чёрной обводкой (PIL-рендер draw_subs.py, логика ASS BorderStyle 1). На груди спикера ничего не висит.

Улика: Read контактного листа, кадр спикера - видно зону груди чистой.

---

**2. Субтитр на фикс-высоте, виден только один текст**

Требование: субтитр на фикс-позиции низ-центр. На всех кадрах виден ОДИН субтитр (наш). Текста автора нигде нет.

Улика: сравнить y-координату в 3+ кадрах разных частей ролика - одинакова. Кадры из демо-вставок - авторский текст отсутствует.

---

**3. Демо-вставки = реальный экран 1:1, резкие, статичные**

Требование: вставка = прямой сегмент из оригинала. Без crop-растяжки, без zoompan-дрейфа. Лица автора нет.

Улика: кадры каждой вставки из contact_sheet.py. Сравнить с кадрами оригинала на том же таймкоде - совпадают. Сравнить соседние кадры вставки - дрейфа нет, текстура резкая.

---

**4. Спикер (наш) в кадре, конкурента нет**

Требование: наш спикер виден в кадрах. Автор-конкурент не виден и не слышен нигде в ролике.

Улика: контактный лист целиком (кадры спикера и вставок) - конкурента нет. Прослушать фонограмму - голос конкурента отсутствует.

---

**5. Звук: поток есть, loudness -14 LUFS ±1.5, синхрон <50мс**

Требование: audio-поток в файле. Интегральная громкость -14 LUFS плюс-минус 1.5. Синхронизация губ со звуком <50 мс.

Улика: qc_check.py отчёт в консоли - строки audio-stream и LUFS. Синхрон обеспечивается пайплайном (vad_tight режет видео и звук одним select из одного источника, finalize добавляет aresample после loudnorm) - vad_tight печатает дельту синхрона, при сомнении спот-чек просмотром фрагмента.

---

**6. Пилюля-CTA с код-словом на экране**

Требование: пилюля с код-словом появляется с назначенного момента и стоит до конца.

Улика: кадр пилюли из contact_sheet.py (время кадра после cta_t0) + вывод finalize.py со строкой CTA@<t>. qc_check пилюлю не видит - только глаза.

---

**7. Доставка: копия готового ролика на ~/Desktop + кадр показан в чат**

Требование: финальный файл лежит на `~/Desktop` (заберёшь со стола) и его кадр (контактный лист) показан инлайн в чат. Если ты настроил опциональный локальный сервер раздачи (переменные `REEL_DELIVERY_DIR`/`REEL_BASE_URL`), скрипт дополнительно вернёт рабочую ссылку - но это не обязательно.

Улика: `ls -lh ~/Desktop/<имя>.mp4` + инлайн-кадр в чате (Read контактного листа png).

---

## Процедура контактного листа (перед выдачей КАЖДОГО ролика)

### Шаг 1. Собрать contact_sheet

Запустить:

```bash
python3 scripts/contact_sheet.py <ролик.mp4> contact.png --times "t1,t2,t3,..."
```

Кадры в contact_sheet должны содержать:
- 2-3 момента чистого спикера (обязательно смотреть зону груди)
- середина каждой демо-вставки
- кадр CTA-пилюли

### Шаг 2. Read и визуальная проверка

Открыть contact.png через Read в чате.

Проверить критерии 1-4 глазами:
1. Зона груди спикера - плашка висит или текст чистый?
2. Высота субтитра одинакова на всех кадрах? Авторский текст виден?
3. Вставки резкие? Лица конкурента есть?
4. Спикер наш есть? Конкурента точно нет?

**Не смотрел глазами = не выдавать.**

### Шаг 3. Автоматическая проверка

Запустить:

```bash
python3 scripts/qc_check.py <ролик.mp4> --expect-dur X
```

Проверяет детерминированно:
- файл существует, размер (часть критерия 7)
- видео-поток 1080x1920, fps 30
- audio-stream (критерий 5)
- длительность против ожидаемой
- полный декод без ошибок
- LUFS -14 в допуске (критерий 5)

Вывод содержит `PASS` или `FAIL` для каждого пункта, exit 0 только если все PASS. Критерий 6 (пилюля) и curl 200 (критерий 7) закрываются контактным листом и deliver.sh.

### Шаг 4. Отчёт о приёмке

Формулировка только факты с уликами:

```
Ролик: <имя>.mp4
Контактный лист: [Read path/contact.png]

Критерий 1-2-3-4 (visual): PASS
- Груди спикера чисты, плашки нет
- Субтитр на фикс-высоте y=XXX пх, авторский текст отсутствует
- Вставка "Экран фреймворка" резкая, лицо конкурента не виден
- Спикер наш, конкурента нет

Критерий 5-7 (auto): PASS
$ qc_check.py <имя>.mp4 --expect-dur 41.5
  PASS file: 28.4 MB
  PASS video: 1080x1920 30fps
  PASS audio: поток есть
  PASS duration: 41.52с (ждали 41.5)
  PASS decode: без ошибок
  PASS lufs: -14.1 (допуск -14±1.5)

Критерий 6 (CTA): кадр t=38.0 на контактном листе - пилюля с код-словом видна

$ bash deliver.sh <имя>.mp4 <имя>.mp4
  200
  ~/Desktop/<имя>.mp4  (+ опц. ссылка, если настроен свой сервер раздачи)
```

---

## Флоу приёмки

1. Собрал ролик → contact_sheet.py
2. Read контактного листа → визуальная проверка критериев 1-4
3. qc_check.py → вывод в консоль
4. Финальный отчёт с уликами → выдача ролика

Если ЛЮБОЙ критерий FAIL:
- Перечислить какой и почему (с путём / кодом / скриншотом)
- Не выдавать
- Пересобрать, повторить с шага 1
