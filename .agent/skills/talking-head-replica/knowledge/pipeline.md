# Pipeline talking-head-replica

Сборка вертикальной 1080x1920 реплики виральных Reels: спикер-дубль говорит в камеру + короткие демо-вставки экрана из оригинала конкурента. Скрипты скилла лежат в `~/.claude/skills/talking-head-replica/scripts/`.

9 фаз, идут по порядку. Каждая фаза опирается на выход предыдущей - пропуск фазы или проверки ломает сборку не сразу, а на середине, когда откатывать дороже всего.

---

## Фаза 0. Инвентарь

Зачем: собрать пайплайн без одного из входов - гарантированно упасть на середине и переделывать с начала. Дешевле проверить всё за минуту в начале.

### Вход
- Оригинал конкурента.
- Дубли спикера (сырые записи в камеру).
- Пилюля-CTA (png).
- Рабочая папка проекта.

### Шаги

```bash
ls -la orig.mp4
ls -la дубли/*.mp4
ls -la pill.png
mkdir -p work/
# (опц.) если поднят свой сервер раздачи: curl -s -o /dev/null -w "%{http_code}\n" "$REEL_BASE_URL/"
```

Каждый вход подтверждается уликой (вывод `ls` с размером файла, не «наверное есть»). Доставка готового ролика по умолчанию = копия на `~/Desktop`, отдельный сервер поднимать не нужно (он опционален, см. фазу 8).

### Выход
Подтверждённый комплект: `orig.mp4`, дубль(и), `pill.png`, `work/`.

### Грабли
Начинали сборку без проверки комплекта, падали на середине пайплайна (например на фазе 7, когда пилюли не было на месте) и теряли всю проделанную работу по видео и субтитрам.

## Фаза 1. Разметка оригинала (посекундная)

Зачем: демо-вставки нарезаются по оригиналу вслепую по памяти - без визуальной сверки легко попасть на кадр с лицом автора или на вшитый текст конкурента, и это всплывёт только на приёмке.

### Вход
`orig.mp4`.

### Шаги

```bash
mkdir -p work/orig_frames
ffmpeg -i orig.mp4 -vf fps=1 work/orig_frames/frame_%04d.png
```

Открыть кадры глазами (Read), не полагаться на таймкоды из головы. Построить таблицу сегментов оригинала:

```
[t0-t1] спикер
[t1-t2] демо-вставка (что на экране, есть ли лицо автора, есть ли вшитый текст-караоке автора и в какой зоне y)
...
```

Зафиксировать окна вставок с таймкодами оригинала в `layout.json`.

Правило пропорции: если база-дубль отличается по длительности от оригинала, окна масштабируются коэффициентом:

```
k = base_dur / orig_dur
```

(формула и пример - в конце документа).

### Выход
`layout.json` со списком окон вставок (таймкоды оригинала + метаданные: лицо автора да/нет, зона текста-караоке).

### Грабли
Резали по таймкодам не глядя на кадры - попадали на лицо автора внутри вставки. Собирали сплит-набор скриншотов там, где в оригинале на самом деле полноэкранное чередование (а не сплит), - разметка без просмотра кадров даёт неверную структуру сегментов.

## Фаза 2. База из дубля

Зачем: сырой дубль спикера содержит паузы и мёртвый воздух - без чистки итоговый ролик тянется и теряет темп.

### Вход
Дубль спикера (сырая запись).

### Шаги

```bash
python3 scripts/vad_tight.py <дубль> <outdir> <tag> 1.15
```

Режет мёртвый воздух по VAD, ускоряет 1.15x, выдаёт `<tag>_tight.mp4` в 1080x1920 30fps.

Замерить длительность результата:

```bash
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 <tag>_tight.mp4
```

### Выход
`<tag>_tight.mp4` - база 1080x1920 30fps, известная точная длительность (`base_dur`).

### Грабли
Нет.

## Фаза 3. Транскрипт базы

Зачем: субтитры собираются не по интуиции, а по точному пословному таймингу распознавания речи - иначе титры плывут относительно голоса.

### Вход
`<tag>_tight.mp4`.

### Шаги

```bash
# Модель распознавания речи (~1.6ГБ) общая для всех видео-скиллов IvanOS.
# Если её ещё нет (первый видео-скилл) - скачать один раз, дальше используется всеми:
MODEL="$HOME/whisper-models/ggml-large-v3-turbo.bin"
if [ ! -f "$MODEL" ]; then
  mkdir -p "$HOME/whisper-models"
  curl -L -o "$MODEL" https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo.bin
fi

ffmpeg -i <tag>_tight.mp4 -ar 16000 -ac 1 work/base.wav
whisper-cli -m "$MODEL" -f work/base.wav -l ru -oj -of work/<prefix>
# -oj пишет work/<prefix>.json
python3 scripts/make_subs.py work/<prefix>.json work/subs.json
```

Модель качается один раз в `~/whisper-models/` и переиспользуется всеми видео-скиллами (ingest-reel, reel-to-script и др.) - если ты уже пользовался любым из них, она на месте и скачивание пропускается.

`make_subs.py` группирует слова в блоки до 3 слов, переводит в UPPERCASE, стыкует тайминги без наложений между соседними блоками.

### Выход
`subs.json` - готовые группы субтитров с таймингами без наложений.

### Грабли
Нет.

## Фаза 4. Вставки автора 1:1

Зачем: демо-вставка должна выглядеть как настоящий экран конкурента, а не как имитация - любое искажение геометрии (crop, zoompan) сразу видно глазом как подделку.

### Вход
`orig.mp4`, `layout.json`.

### Шаги

```bash
# на КАЖДОЕ окно из layout.json отдельный вызов:
python3 scripts/cut_insert.py orig.mp4 <t0> <t1> work/inserts/<tag>.mp4 \
    [--crop W:H:X:Y] \
    [--box X,Y,W,H,0x0a0a0a] \
    [--loop-to WIN_DUR]
# --crop: зона демо в пикселях исходника, аспект строго 9:16 (иначе скрипт откажет)
# --box: глушение зоны текста автора, координаты выхода 1080x1920, можно несколько
# --loop-to: если сегмент короче окна, forward-loop до длительности окна
```

Правила нарезки (зашиты в скрипт, но проверяются на выходе):
- Резать по `-ss`/`-to` сегмент оригинала как есть.
- Без crop-растяжки - тянет пиксели, мылит картинку.
- Без zoompan - дрейф координат даёт эффект мыла и плавания кадра.
- Единственное допустимое преобразование - равномерный `scale` всего кадра до 1080x1920 через `lanczos`.
- Если у автора в сегменте вшит его текст или караоке - заглушить ПРИ НАРЕЗКЕ: на однотонном тёмном фоне - drawbox цвета фона; на светлом/текстурном - scripts/band_patch.py (патч полосы из чистого кадра той же сцены, AP-24); нет чистых якорей на светлой сцене - сцену не брать.
- Если сегмент короче окна - forward-loop (проигрывать вперёд с начала повторно), не boomerang: reverse-проигрывание ломает восприятие скролла экрана.

После нарезки открыть глазами (Read) по одному кадру из каждой вставки, проверить:
- резкость (нет мыла от растяжки),
- нет лица автора в кадре,
- нет текста автора (заглушено полностью).

### Выход
Набор файлов вставок `work/inserts/*.mp4`, каждый проверен визуально.

### Грабли
Рисовали свои мокапы экрана вместо использования реального footage оригинала. Crop+scale растяжка мылила картинку. Zoompan давал плавающий дрейф кадра вместо чистого статичного скрина.

## Фаза 5. Композит

Зачем: база и вставки существуют раздельно - собрать их в один таймлайн нужно так, чтобы звук всегда шёл от базы (спикер говорит непрерывно, вставки - только визуальный слой поверх).

### Вход
`<tag>_tight.mp4` (база), `work/inserts/*.mp4`.

### Шаги

```bash
ffmpeg -i base.mp4 \
  -itsoffset t1 -i insert1.mp4 \
  -itsoffset t2 -i insert2.mp4 \
  -filter_complex "[0:v][1:v]overlay=0:0:enable='between(t,t1_start,t1_end)'[v1]; \
                   [v1][2:v]overlay=0:0:enable='between(t,t2_start,t2_end)'[vout]" \
  -map "[vout]" -map 0:a \
  -c:v libx264 -crf 18 -r 30 -c:a aac \
  work/comp.mp4
```

Вставки цепляются через `-itsoffset` и `overlay=0:0:enable='between(t,t0,t1)'` цепочкой фильтров. Звук всегда берётся `-map 0:a` (от базы), сколько бы вставок ни было.

Проверить длительность результата:

```bash
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 work/comp.mp4
```

Должна совпасть с длительностью базы.

### Выход
`comp.mp4` - композит база + вставки, длительность равна `base_dur`.

### Грабли
Длинные `enable`-выражения с ошибками в таймкодах молча пропускают вставку или накладывают не там - проверять сразу после рендера, что файл создался и реально играбелен (не просто существует на диске), не откладывать проверку на конец пайплайна.

## Фаза 6. Субтитр чистый

Зачем: субтитры должны читаться на любом фоне (спикер или демо-вставка), но не закрывать спикера плашкой - на груди спикера закрывать нечего, а плашка выглядит как брак.

### Вход
`work/subs.json`, `work/comp.mp4`.

### Шаги

```bash
python3 scripts/draw_subs.py subs.json comp.mp4 subbed.mp4
```

Правила рендера (зашиты в скрипт):
- Белый текст с чёрной обводкой. Реализация: PIL-рендер PNG с альфой + overlay по таймингам,
  потому что локальный ffmpeg (homebrew) собран без libass/freetype - фильтров ass/subtitles/drawtext нет.
  Рядом с выходом кладётся .ass sidecar для ручной сверки таймингов (в рендере не участвует).
- Шрифт Nunito Bold (эталонные сборки автора), fallback Arial Bold.
- Фикс-позиция низ-центр, `--margin-v 290` (нижний край текста на y=1630), высота строки из метрик
  шрифта, не из bbox текста - базовая линия не дрожит между репликами.
- Максимум 3 слова на группу.
- Без плашки-подложки под текстом вообще.

Точечная плашка (drawbox) допустима только внутри вставки - она уже поставлена в фазе 4 при нарезке, здесь повторно не добавляется.

### Выход
`subbed.mp4` - композит с субтитрами, без плашки на спикере, без дублирующего текста от автора.

### Грабли
Жирная чёрная плашка-корыто на груди спикера - главный брак прошлой сессии. Режим `--detect` скакал по высоте, ловил лицо и дёргал субтитр. Два субтитра одновременно на экране - авторский текст не заглушили в фазе 4 при нарезке, и он остался виден рядом с новым.

## Фаза 7. Финал

Зачем: ролик без звука в норме и без CTA-пилюли не готов к показу - выдать такой tape как финал означает нести недоделанный продукт на приёмку.

### Вход
`subbed.mp4`, `pill.png`, `cta_t0` (момент старта CTA).

### Шаги

```bash
python3 scripts/finalize.py subbed.mp4 <cta_t0> pill.png out.mp4
```

Что делает скрипт:
- Overlay пилюли-CTA с `cta_t0` до конца ролика.
- `cta_t0` считается пропорцией от оригинала через тот же коэффициент `k` (см. секцию про пропорцию окон в конце документа).
- Двухпроходный `loudnorm` (`I=-14 TP=-1.5 LRA=11 linear=true`) + `aresample async` для нормализации звука.
- CFR 30 (постоянный frame rate) на выходе.

### Выход
`out.mp4` - финальный ролик со звуком в норме, CTA-пилюлей, постоянным frame rate.

### Грабли
Выдавали промежуточный tape (без нормализованного звука, без пилюли) как готовый финал - разрыв между «файл существует» и «файл готов к показу».

## Фаза 8. Приёмка и доставка

Зачем: пачка роликов, сданная без покадровой проверки, доезжает до зрителя с браком (плашка на груди, битый звук, мёртвая ссылка) - это дороже, чем 5 минут проверки на каждый ролик.

### Вход
`out.mp4`, ожидаемая длительность `X`, имя для доставки.

### Шаги строго по порядку, на КАЖДЫЙ ролик отдельно

```bash
# 1. Автоматические проверки
python3 scripts/qc_check.py out.mp4 --expect-dur X
# все пункты должны быть PASS

# 2. Контактный лист кадров (--times подбираются по layout: спикер / вставки / CTA)
python3 scripts/contact_sheet.py out.mp4 work/contact_sheet.png --times "2.0,8.5,14.2,21.0,27.5"
# кадры: 2-3 момента чистого спикера (смотреть грудь - там висела плашка),
# середина КАЖДОЙ вставки, кадр CTA
```

3. Открыть контактный лист глазами через Read, сверить с критериями приёмки (`knowledge/acceptance.md`).

```bash
# 4. Доставка (только после пункта 3, без замечаний)
bash scripts/deliver.sh out.mp4 <имя>.mp4
```

Имя файла - только латиница и цифры с дефисом, без пробелов и юникода. `deliver.sh` обязан вернуть `curl 200` на конечную ссылку - без этого доставка не считается состоявшейся.

Ролик можно называть готовым только после прохождения всех 4 пунктов по порядку, ни один не пропускается и не переставляется.

### Выход
Готовый ролик скопирован на `~/Desktop` (+ опц. рабочая ссылка, если настроен свой сервер раздачи).

### Грабли
Гнали пачку роликов вслепую, без открытия контактного листа - брак уезжал пачками. Битые ссылки со звёздочками (не долитый или неверно названный файл). Отчёт «готово» по роликам, у которых на самом деле нет звука - потому что `qc_check.py` не был прогнан или его результат не читали.

## Пропорция окон при другой длине базы

Если база (дубль спикера после VAD-чистки и ускорения) отличается по длительности от оригинала, все таймкоды окон вставок и `cta_t0` пересчитываются пропорционально:

```
k = base_dur / orig_dur
nt0 = t0 / orig_dur * base_dur
```

Пример: оригинал 40 секунд, окно вставки в оригинале `[12-15]` (t0=12), база после VAD-чистки и ускорения 1.15x получилась 33 секунды.

```
k = 33 / 40 = 0.825
nt0 = 12 / 40 * 33 = 9.9
```

Окно вставки в композите начнётся не на 12-й секунде оригинала, а на 9.9-й секунде базы. Тот же расчёт применяется к концу окна и к `cta_t0` из фазы 7.

## Фаза 4.5. HARD-гейт вставок (добавлено по стратегии автора)

Зачем: правило в доке не удержало брак (fable d1/d4) - нужен машинный бенчмарк по кадрам, не заметка.

На КАЖДУЮ вставку до композита:

```bash
python3 scripts/insert_gate.py work/inserts/<tag>.mp4            # фуллскрин-вставка
python3 scripts/insert_gate.py work/inserts/<tag>.mp4 --expect-static-margins   # окно-вставка
```

Скан каждого кадра 30fps: лицо (YuNet), skin-ratio, строгие торцы (12 кадров), живые поля для окно-вставок. Exit 1 = сборка стоит, чинить вставку (не порог). Брендовый оранж/беж фон автора даёт ложный skin - визуально верифицировать кадры и поднять --skin-max явно, с пометкой в отчёте.

Окно-вставки режутся не cut_insert, а window_insert.py: кроп внутри рамки окна автора, только стабильный отрезок (анимацию входа не брать), наш фон 0x16161a + рамка 0xE07850.

Субтитры (фаза 6) с этой редакции = золотой Hormozi-караоке: группы 1-2 слова (make_subs v2 пишет words), draw_subs красит активное слово золотом word-by-word, шрифт Oswald-Bold из fonts/ (Anton без кириллицы - авто-фолбэк по глифам).

## Дубль без начала и склейка кусков (автор, reel-4)

Если tight-дубль начинается с середины скрипта - НЕ занимать хук из другого дубля сразу: сначала искать в ~/Downloads соседние КОРОТКИЕ IMG-файлы (автор снимает хук и связки отдельными дублями-кусочками рядом с телом, например IMG_3345 хук + IMG_3346 связка + IMG_3347 тело). Склейка concat с одинаковым темпом (короткий кусок без пауз обрабатывать вручную scale+fps+setpts/atempo 1.15, VAD на нём откусывает первое слово).

Транскрипт склейки НЕ гнать одним whisper-прогоном - он мажет слова на стыках. Каждый кусок транскрибировать отдельно (или взять уже чистый пер-кусковый транскрипт) и сшить тайминги оффсетами = суммами длительностей кусков. Монтажный стык прятать под окно демо-вставки.

## Доставка результата

Базовая доставка (работает у всех, ничего настраивать не надо):
1. Готовый несжатый ролик -> копия на `~/Desktop` (заберёшь прямо со стола)
2. Инлайн-кадр в чат: Read контактного листа (png), чтобы ты глазами увидел результат, не открывая файл

Опционально, если ты настроил свой TG-бот доставки (см. `connections.md`, креды в твоём `.env`):
3. Пары в свой бот: sendDocument (несжатый, НЕ sendVideo) + описание ЧИСТЫМ текстом reply_to к файлу. Перед отправкой сверить бота через getMe (проверить, что это именно твой бот). Без техобёрток в тексте
4. Файл >50МБ в бот не лезет (Request Entity Too Large) - слать бот-копию crf21, несжатый остаётся на диске/столе
5. Батч из многих файлов - фоном с логом и ретраями на каждый файл, чтобы обрыв по таймауту на середине не оставил тебя без части роликов
