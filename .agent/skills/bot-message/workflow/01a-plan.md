# 01a - Mode A: Plan (из карты воронки)

> Берёт следующий шаг воронки из `funnel_map`, определяет тип сообщения и контекст. Источник истины - `paths.funnel_map`.

## Вход

- Загружен config
- Mode определён = Plan
- Опционально: `funnel_step` (если указан явно типа «Day 3» или «после вебинара»)

## Шаг 1: Read funnel map

Read файл по пути `config.paths.funnel_map`.

### Если файл отсутствует или пуст

→ Fallback на Spark-B2 с warning:
```
Карта воронки `<path>` не найдена. Переключаюсь в Spark-B2.
Дай trigger context: «напоминание о вебинаре» / «winback холодных» / etc.
```
Передать управление в `01b-spark.md` с пометкой `mode_override: spark-b2`.

### Если файл существует

Парсить формат `funnel_map_format`:

- **step-based**: список шагов с номерами (Step 1 / Step 2 / ...). Найти текущий или следующий шаг.
- **day-based**: dripping по дням (Day 0 / Day 1 / Day 3 / ...). Найти подходящий день.
- **trigger-based**: реакция на действие пользователя. Найти подходящий триггер.

## Шаг 2: Определить текущий шаг

Если `funnel_step` указан в input → искать конкретно его.

Если нет - определять автоматически:
1. Read `paths.recent_push_log` (если есть).
2. Найти последний отправленный push.
3. Следующий шаг = тот, что следует за ним в карте.

Если recent_push_log пуст или отсутствует - взять первый невыполненный шаг или спросить пользователя «с какого шага?».

## Шаг 3: Извлечь из шага воронки

Из найденной записи в карте воронки извлечь:

- **Цель шага** (что должен сделать подписчик после получения push)
- **Тип сообщения** (один из 8) - если указан явно, иначе определит `02-structure.md`
- **Целевой сегмент** (на кого летит push)
- **CTA-кнопка** (куда ведёт, какой текст, какой тип URL/callback)
- **Контекст** (что произошло до этого шага, что произойдёт после)
- **Запрещённое** (если шаг прямо запрещает упоминать что-то - например, не упоминать цену до Дня 5)

## Шаг 4: Подтверждение в чат

```
Шаг воронки: <Step N / Day N>
Цель: <одно предложение, что должен сделать подписчик>
Тип: <auto или конкретный>
Сегмент: <all или конкретный>
CTA: <текст кнопки + куда>
```

## Шаг 5: Передать управление

Передать управление в `02-structure.md` со всеми извлечёнными параметрами + полным содержимым шага воронки как контекст.

## Anti-patterns Mode A

- **Не дополнять** воронку «своим» контентом. Если в карте написано «push про доступ к workshop» - push про workshop, не про что-то рядом. Если хочется дополнить - это правка карты, а не отступление от неё.
- **Не выдумывать** цели шагов. Если в карте указано «цель: клик в Skool» - финальный CTA = клик в Skool. Не «прочитать пост в канале».
- **Не сливать шаги**. Один push = один шаг воронки. Если хочется сделать «два в одном» - это два отдельных push в разные дни.

## Карта воронки - формат (для ученика)

Минимальный formato `funnel_map.md` (step-based):

```markdown
# Карта воронки <название запуска>

## Step 1 - Welcome push
- Цель: подписчик кликает «Получить разбор»
- Сегмент: new (только что подписался)
- Тип: voronka-push
- CTA: callback_data «get_breakdown» → выдать lead magnet
- Триггер: подписка на бот
- Контекст: первое касание с подписчиком

## Step 2 - Activation reminder
- Цель: подписчик возвращается и применяет lead magnet
- Сегмент: new + не открыл lead magnet за 24 часа
- Тип: reminder
- CTA: callback_data «open_breakdown»
- Триггер: 24 часа после Step 1, не было открытия lead magnet
- Контекст: ученик подписался, но застрял

...
```

Если карта в другом формате - адаптировать парсинг или просить переформатировать.
