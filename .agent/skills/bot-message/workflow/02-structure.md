# 02 - Structure (detect type + scaffold + button strategy)

> Превращает выбранный угол / кандидат / шаг воронки в скелет push: тип + структура + кнопочная стратегия. На выходе - scaffold для `03-write.md`.

## Вход

От Mode A/B/C:
- Выбранный угол (тема + hook + контекст)
- Сегмент аудитории
- Желаемый/предполагаемый тип (если задан явно)
- Контекст шага воронки (если Mode A)
- Дословная лексика автора (если Mode C)

## Шаг 1: Detect type

Если тип задан явно - pass-through. Если нет - определить из контекста по таблице:

| Сигналы в контексте | Тип |
|---|---|
| «следующий шаг воронки» / «day N» / «после вебинара» | voronka-push |
| «через час» / «окно закрывается» / «не забудь» / «осталось N часов» | reminder |
| «новый пост» / «новый видос» / «посмотри статью» / анонс материала | content-tease |
| «day N серии» / «прогрев» / «прошлый push был про …, сейчас следующий» | drip-segment |
| «купил» / «зарегался» / «открыл lead magnet» - реакция на действие | event-trigger |
| «не открывал >30 дней» / «холодные» / «вернуть» | re-engagement |
| «запуск» / «продукт открылся» / «всем сообщить» | broadcast-news |
| «опрос» / «голосование» / «что выберешь» | survey-poll |

При неопределённости - спросить пользователя одной строкой.

## Шаг 2: Load template

Read `templates/<type>.md` (см. `SKILL.md` таблица 8 типов). Если v1.0 и тип не в [voronka-push, reminder, content-tease] - warning «тип v1.1+, использую voronka-push как fallback».

Template содержит:
- Минимальный scaffold (где hook, где наблюдение, где CTA)
- Целевую длину (`length.target_short/medium/long` из config)
- Рекомендованное количество кнопок (1-3)
- Допустимые hook frameworks (не все frameworks подходят всем типам)

## Шаг 3: Определить button strategy

По типу и контексту выбрать:

### Один из вариантов кнопочной стратегии

1. **Single URL** - одна кнопка с URL на лендинг / пост / видео
2. **Single callback** - одна кнопка с callback_data на действие внутри бота (выдать lead magnet, открыть FSM)
3. **Two-choice callback** - две кнопки «да / нет», «иду / напомнить позже», «вариант А / вариант Б»
4. **Three-choice callback (survey)** - три кнопки-варианта для опроса
5. **Primary + secondary** - одна основная кнопка («иду на вебинар») + одна вторичная («не сейчас» - для сегментации)
6. **Web App** - кнопка открывает мини-апп (только если `bot.supported_button_types` включает `web_app`)
7. **Pay** - кнопка оплаты через Telegram Payments (редко, только для прямых продаж в боте)

### Правила выбора

- Если есть **внешняя ссылка** (Skool / лендинг / Нельзяграм / видео) → URL
- Если **внутреннее действие** (выдать lead magnet, открыть FSM, сегментировать) → callback
- Если **сегментация по выбору** (хочу А или Б) → two-choice или three-choice
- Если **mini-app** (платежи внутри / интерактив) → web_app
- Если есть сомнения - single URL или single callback (минимум вариативности = максимум conversion)

## Шаг 4: Зашивать в scaffold

Заполнить scaffold из template:

```
HOOK (первые 50 знаков, должны нести смысл в notification preview):
<hook фрагмент>

ТЕЛО (50-220 знаков, доводит до клика):
<наблюдение / boby>

CTA-привязка (мост от тела к кнопке, опционально):
<одна строка-связка>

КНОПКИ:
- <кнопка 1>: текст + тип + куда (URL / callback / ...)
- <кнопка 2 если есть>: текст + тип + куда

Сегмент: <all / cold / warm / hot / buyer>
Тип: <один из 8>
Hook framework: <Numbered / Contrarian / Vulnerable / ...>
```

## Шаг 5: Передать управление

Scaffold + контекст + must-keep лексика (от Mode C) → `03-write.md`.

## Output type-specific guidance (v1.0)

### voronka-push
- Длина: 100-200 знаков
- Кнопок: 1-2
- Hook: Curiosity-Gap или Results-First работают лучше всего
- CTA: глагол + объект («Получить разбор», «Открыть демо»)

### reminder
- Длина: 80-150 знаков
- Кнопок: 1
- Hook: время + действие («Через 1 час старт вебинара»)
- CTA: глагол действия («Иду», «Напомнить»)
- Без декоративных элементов - чистая утилитарная информация

### content-tease
- Длина: 150-250 знаков
- Кнопок: 1
- Hook: интрига или результат («Один пост принёс 47 покупок»)
- CTA: глагол потребления («Читать», «Смотреть», «Открыть»)
- Намёк на ценность без раскрытия всей сути

## Anti-patterns Structure

- **Не разделять CTA между текстом и кнопкой**. Кнопка - единственный CTA. Текст подводит, но не дублирует «жми кнопку».
- **Не делать 3 кнопки если хватит 1**. Каждая дополнительная кнопка = шум.
- **Не использовать одинаковые кнопки в разных push** подряд. Если 3 push'а подряд с «Узнать» - это паттерн, который аудитория считывает как «спам бот».
- **Не выбирать web_app без явной необходимости**. Простой URL/callback покрывает 90% кейсов.
