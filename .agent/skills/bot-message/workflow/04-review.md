# 04 - Review (3 слоя + bot-specific gates)

> Финальный gate перед output. Никакой push не выходит без явного «3 слоя пройдено, флагов нет» или развёрнутого списка флагов + митигаций.

## Вход

Готовый блок от `03-write.md`:
- TEXT (черновик)
- BUTTONS (microcopy)
- A/B альтернатива
- Внутрянка

## Pass 4.0 - Hard validators (regex / deterministic)

Pass или Fail по каждому пункту. Любой Fail - стоп, переписать.

### 4.0.1 - Length

Лимит длины зависит от типа push (fix 2026-05-29). Короткие типы остаются короткими, тизер-анонсы разворачиваются на 2-3 абзаца.

| Проверка | Threshold | Действие |
|---|---|---|
| `len(text) > 300` для reminder / voronka-push / event-trigger / survey-poll | hard fail | переписать короче |
| `len(text) > 800` для content-tease / broadcast-news / drip-segment | hard fail | переписать короче |
| content-tease / broadcast-news = 1 абзац | warning | развернуть до 2-3 абзацев (тизер должен показать ценность, не только намёк) |
| `len(text) < 80` | warning | подтвердить с пользователем |
| `len(button_text) > 24` | warning | сократить или переписать |
| `len(button_text) < 8` | warning | расширить (если возможно) |
| `count(buttons) > 3` | hard fail | сократить до 1-3 |
| `count(buttons) < 1` | hard fail | push без кнопки = не push, добавить CTA |

### 4.0.2 - Banned characters / patterns

| Паттерн | Действие |
|---|---|
| Em-dash «-» внутри строк | hard fail → заменить на «-» или запятую |
| «Instagram» | auto-correct → «Нельзяграм» |
| Восклицательных «!» >0 (или config.voice.exclamation_max) | hard fail → удалить |
| Многоточие «...» или «…» | hard fail → удалить |
| Вопросительных «?» >1 | hard fail → 1 максимум |
| Списки/буллеты (`- `, `* `, `1. `) | hard fail → не формат push |
| Эмоджи в первых 50 знаках >1 | warning → оставить 1 или 0 |
| Эмоджи всего >2 | warning |

### 4.0.3 - Banned terms (из config.voice.banned_terms)

Regex по списку. Любое попадание - hard fail.

### 4.0.4 - Generic CTA в кнопках (Action-skill Gate D)

**Гипер-правило: каждая кнопка = verb + object pair** (regex `^\S+\s+\S+`), КРОМЕ whitelist одиночных.

#### 4.0.4a - Banned одиночные глаголы (hard fail)

- «Узнать», «Узнать больше», «Подробнее», «Подробности»
- «Click here», «Тык», «Сюда»
- «OK», «Да», «Нет» (без объекта)
- «Записаться», «Подать», «Заявка», «Начать» - **одиночные без объекта** (расширение v1.0.2)
- «Открыть», «Получить», «Забрать», «Войти», «Перейти» - **одиночные без объекта** (расширение v1.0.2)

#### 4.0.4b - Whitelist одиночных (PASS)

- «Иду», «I'm in», «Join», «Pay» - короткие, но **семантически self-contained**, контекст из push'а полностью раскрывает объект
- Только если push явно содержит объект action в первых 50 знаков (например text = «Через 1 час старт вебинара» + кнопка «Иду» = OK, объект «вебинар» в hook'е)

#### 4.0.4c - Verb-object pair test

Если кнопка состоит из 2+ слов - regex check:
- `^[A-ZА-Я][а-яё]+\s+[А-Яа-яё]+\b` (RU)
- `^[A-Z][a-z]+\s+[a-z]+\b` (EN)
- Pass если есть и глагол и объект.

Примеры PASS: «Получить разбор», «Открыть пост», «Иду на эфир», «Read post», «Get prompt»
Примеры FAIL: «Записаться», «Открыть» (одиночные)
- «Ссылка», «Перейти» (без объекта)
- Одиночные эмоджи без слова

Любое попадание - hard fail.

### 4.0.5 - Banned filler words

Regex по списку:
- «просто», «довольно», «достаточно»
- «по сути», «буквально», «сразу же», «вот»
- «короче», «короче говоря», «итак»

Любое попадание - hard fail (исключение: если слово реально несёт смысл, не filler - warning с проверкой).

## Pass 4.1 - Notification preview test

### 4.1.1 - Hook readability

Извлечь первые 50 знаков. Прочитать без контекста. Понятен ли смысл?

- Если да → pass
- Если нет → fail, переписать hook

### 4.1.2 - Button clarity

Для каждой кнопки: понятно ли куда ведёт из её текста + первые 50 знаков push'а?

- Если да → pass
- Если нет → fail, переписать microcopy

### 4.1.3 - Single action gate

Один push = одно действие? Если push требует выбора между 2+ разными целями (а не сегментацию) → fail, разбить на 2 push.

## Pass 4.2 - Voice fidelity

### 4.2.1 - Сравнение с gold-standard

Сравнить ритм / лексику / структуру с `examples/_TEMPLATE.md` (если файл заполнен).

- Совпадение «походит на голос» → pass
- Generic / похоже на любой бот → fail, переписать через Pass 0 mandatory reads

### 4.2.2 - Mode C verbatim check

Если был Mode C - проверить что must-keep обороты автора попали в финальный текст без парафраза.

- Все попали → pass
- Хотя бы один потерян → fail, переписать

### 4.2.3 - Banned AI-конструкции

Из `post/references/_voice-TEMPLATE.md` - 26 классов banned A-Z. Любое попадание - hard fail.

## Pass 4.3 - 3 слоя финальный gate

### Слой 1 - Валидаторы

Регекс выше + banned terms + banned filler + banned AI-конструкции. Все ли pass?

### Слой 2 - 4 концепции

- **Pre-mortem 5 причин провала**: почему этот push не получит клик?
  - Перечислить 5 причин (например: «hook generic», «кнопка размытая», «время плохое», «сегмент неправильный», «тема не актуальна»). Если хотя бы 1 → fail, fix.
- **Калибровка уверенности 90%+**: уверен ли что этот push принесёт CTR ≥ среднего по боту?
  - Если <90% → flag, обозначить в внутрянке.
- **Multi-perspective Маркетолог-Инвестор-Клиент**:
  - Маркетолог: ведёт ли это к конверсии в воронке?
  - Инвестор: окупает ли усилие на создание?
  - Клиент: захочу ли я открыть кнопку прямо сейчас, без принуждения?
  - Если хотя бы один «нет» → flag.
- **Адаптивность**: появляется ли в этом push новая ошибка, которой ещё нет в anti-patterns? Если да → добавить в `references/bot-anti-patterns.md` и в config.banned_terms.

### Слой 3 - 7 контуров

- **Контекст**: подходит ли push текущему шагу воронки / сегменту / контексту?
- **Соответствие предпосылкам**: соответствует ли тому, что было обещано подписчику ранее?
- **Целесообразность**: правильное ли это действие сейчас или есть высокоуровневая зона (например, «не время для холодных, нужен warm-touch сначала»)?
- **Релевантность**: релевантен ли push сегменту?
- **Фактология**: все факты в тексте верны? Цифры/даты/имена корректны?
- **Реализуемость**: кнопка ведёт куда обещано? URL валидный? callback_data зарегистрирован в боте?
- **Достоверность**: не выдумал ли я что-то от себя (особенно в Mode B2)?

## Pass 4.4 - Подтверждение в чате (с Action-skill Gate E)

### 4.4a - Self-Review Cross-Check (Action-skill Gate E)

Перед «3 слоя пройдено» обязательно произвести fact-list:

1. **Перечислить все utterances в push** содержащие: числа / даты / именованные события / суммы / brand mentions / personal facts автора
2. Для каждой - указать source verification:
   - ✓ verified in `<file>` (paths.products / paths.avatar / paths.business_index / raw_transcript)
   - ✓ confirmed by user в этой сессии
   - ✗ UNVERIFIED

3. Если хотя бы один ✗ UNVERIFIED → НЕ писать «3 слоя пройдено». Вместо этого:
```
3 слоя ПОЛУПРОЙДЕНО - flag UNVERIFIED:
- «<quote>» (UNVERIFIED, причина: <не найден в SOURCES>)
- ...
ACTION: вернуться в Pass 0.7 ИЛИ переписать draft без unverified фактов.
```

4. Если все ✓ → выдать fact-list и далее «3 слоя пройдено».

### 4.4b - Итоговое подтверждение

Только после Gate E PASS:

```
Fact list:
- «<utterance 1>» → verified in <source>
- «<utterance 2>» → confirmed by user
- ...

3 слоя пройдено, флагов нет.
```

или с флагами:

```
Fact list: ... (как выше)

3 слоя пройдены с флагами:
- <флаг> → митигация: <как поправил>
```

**Без fact-list + явного «3 слоя пройдено» - НЕ передавать в `05-publish.md`.** Это hard gate из CLAUDE.md, расширенный Action-skill Gate E.

## Re-iteration

Если в Pass 4.0-4.3 возник fail → вернуться в `03-write.md` с пометкой что именно failed. Не больше 3 итераций - после третьей переформулировать угол через возврат в `02-structure.md` или `01b-spark.md` за новым углом.

## Output

Передать в `05-publish.md`:
- Финальный TEXT (после всех iterations)
- Финальный BUTTONS
- A/B альтернатива (тоже прошла Pass 4.0-4.3, минимум)
- Внутрянка («как писал»)
- Список флагов (если были)

## Финальная фаза — Humaniser (HARD GATE для всех text-skills)

**ОБЯЗАТЕЛЬНО перед output:**

Вызови Skill tool: `Skill('humaniser', args=<финальный текст>)` ПЕРЕД любым output. НЕ читай humaniser/prompt.md inline и НЕ применяй mentally — это shallow execution которое пропускает AI-tics. Только полный pass через Skill tool invocation документированный в чате.

Humaniser v2 ловит 11 категорий AI-паттернов:
1. Ложная глубина
2. Фальшивая близость
3. Пустые связки
4. Канцелярит
5. Fake-энергия
6. Шаблонные призывы
7. Рубленые фразы (3+ из 1-2 слов подряд)
8. Кинематограф
9. Структурные клише
10. Интонационные клише
11. **Slap-эмфаза (длинное + 1-3-словное короткое для эмфазы) — главный AI-tic социалок 2025-2026**

**HARD GATE:** Output финального текста ТОЛЬКО после green CHECKER (все 5/5 в «Клише удалены»). Если CHECKER не green — REWRITER ещё раз. Без этого = брак.

**Прецеденты:**
- 2026-05-28: post v3.0 выдал «Zero ads. Zero funnels. Zero sales calls.» (triple-negation AI tic)
- 2026-05-29: caption выдал «Бесплатно. 30 минут работы и ожидание ответа.» (slap-эмфаза, новая категория 11)

Оба = провал shallow inline pass. HARD GATE через Skill tool решает.

### Humaniser Inline Reminder (fallback если Skill tool недоступен)

Перед output финального текста — проверь по 11 категориям AI-tics:

1. Ложная глубина («Это не X, это Y», «Секрет в том»)
2. Фальшивая близость («Знакомо?», «Представьте»)
3. Пустые связки («Давайте разберёмся», «Важно понимать»)
4. Канцелярит («В современном мире», «Является неотъемлемой»)
5. Fake-энергия («Спойлер», «Бонус», «Лайфхак»)
6. Шаблонные призывы («Хватит X», «Перестаньте X начните Y»)
7. Рубленые фразы (3+ предложения подряд из 1-2 слов: «Просто. Быстро. Эффективно.»)
8. Кинематограф («Воскресенье, 10 вечера», «Понедельник, 9 утра»)
9. Структурные клише (параллелизм X/Y/Z, всегда 3 пункта)
10. Интонационные клише («невероятно простой!», «истина в том»)
11. **Slap-эмфаза**: короткое standalone (1-3 слова) после длинного для эмфазы. SMELL TEST: «можно ли слить через запятую?». YES → SLAP, слить. Исключения: structural separator перед list / hook / punchline finale.

Прецеденты провала которые этот block ловит:
- post v3.0 2026-05-28: «Zero ads. Zero funnels. Zero sales calls.» (triple-negation, cat 7+9)
- caption 2026-05-29: «Бесплатно. 30 минут работы и ожидание ответа.» (slap-эмфаза, cat 11)

При нахождении любого pattern → REWRITER (переписать) → re-CHECKER → если clean → output.

## VALUE-DELIVERY GATE (shared, injected)

> Обязательный гейт «что текст ОБЯЗАН доставить» (вещество, не форма). Источник истины — `~/.claude/skills/_shared/value-delivery-gate.md`. Прецедент: пост-«огрызок» без пользы + диагностическое действие.

`Read(~/.claude/skills/_shared/value-delivery-gate.md)` и примени на стадии ценности и на ревью:

1. **Действие ГЕНЕРАТИВНОЕ, не диагностическое (HARD).** Actionable-шаг даёт на руки новый результат/артефакт, а не подтверждает известное («посчитай свою цифру» = диагностика = FAIL; «собери первый продукт через нейросеть» = генеративное). Тест: появился ли у читателя НОВЫЙ результат?
2. **Реальная ценность ≥2 value-types (HARD).** Текст несёт ≥2 из: V1 инсайт / V5 модель «почему» / V2 генеративное действие / пруф-кейс с цифрой. Только «было плохо → стало хорошо + призыв» = бот-сообщение = FAIL «ноль пользы».
3. **Объём+формат — ТОЛЬКО длинные форматы** (educational/story/longform): ~2300-2500 символов, богатое форматирование ≥4 типов (<2 = брак). НЕ применять к микроформатам (tweet ≤280 / bot-message / IG-caption) — там только правила 1-2 по сути.

Независимый верификатор обязан проверить: действие генеративное? ≥2 value-types? не огрызок? Память.
