# 01b - Mode B: Spark (ситуативный)

> Два подрежима: B1 - есть тема, расширяю в углы. B2 - нет темы, есть триггер, генерирую кандидатов.

## Вход

- Загружен config
- Mode определён = Spark-B1 или Spark-B2
- Параметры из router:
  - B1: `topic` (тема push, дана пользователем)
  - B2: `trigger` (контекст триггера: «вебинар через час», «winback холодных», «новый пост в канале»)

## Шаг 0: Mandatory reads (no-repeat защита)

Перед генерацией углов / кандидатов - обязательно прочитать `paths.recent_push_log` (если задан). Извлечь:

- Последние 10 push: дата / тип / hook / результат (если зафиксирован)
- Использованные hook frameworks (для rotation)
- Использованные типы (для rotation)
- Использованные кнопочные стратегии

Это входит в no-repeat фильтр на Шаге 2.

## Mode B1: расширение темы в углы

### Шаг 1: Read avatar + objections

Read `paths.avatar` и `paths.objections`. Извлечь:
- Главные боли / желания / страхи аудитории
- Возражения которые могут быть актуальны для темы

### Шаг 2: Генерация 3-5 углов

Для темы `topic` сгенерировать 3-5 ортогональных углов, каждый с разным hook framework:

| # | Угол | Hook framework | Тип сообщения | Кнопочная стратегия |
|---|---|---|---|---|
| 1 | <угол> | <Numbered/Contrarian/Vulnerable/Results-First/Curiosity-Gap/etc.> | <один из 8> | <1 кнопка URL / 2 кнопки callback / etc.> |
| 2 | ... | ... | ... | ... |

**Hook frameworks (RU-адаптация из post):**
- Numbered: «3 ошибки в воронке»
- Contrarian: «забудь про А/Б тесты на push»
- Vulnerable: «потерял 30% базы за неделю»
- Results-First: «12% CTR на push - вот как»
- Curiosity-Gap: «один пост в боте принёс 47 покупок»
- Myth-Busting: «push не работает, если…»
- Question-Hook: «знаешь почему твои push открывают, но не кликают?»

### Шаг 3: No-repeat фильтр

Из 3-5 углов отбросить:
- Повтор hook framework за последние 3 push (`voice.hook_rotation_window`)
- Повтор типа сообщения за последние 5 push (`voice.type_rotation_window`)
- Точный повтор темы за последние 10 push

Если после фильтра <2 углов - расширить до 7 и фильтровать ещё раз.

### Шаг 4: Презентация в чат

Plain text список (не AskUserQuestion в CLI - см. `feedback_no_askuserquestion_in_cli`):

```
3-5 углов для «<topic>»:

1. <угол> - <hook framework> - <тип> - <кнопочная стратегия>
2. ...

Какой берём (номер или «свой угол: …»)?
```

Если в IDE с открытым файлом - можно использовать AskUserQuestion с 3-5 опциями.

После выбора → передать управление в `02-structure.md` с выбранным углом + всем контекстом.

## Mode B2: генерация под триггер

### Шаг 1: Read контекст триггера

В зависимости от `trigger`:

- **«вебинар через час»** - read `paths.products_dir` + найти упоминание о вебинаре / событии. Извлечь время, тему, ссылку.
- **«winback холодных»** - read `paths.avatar` + сегмент `cold`. Извлечь главные хуки для возврата.
- **«новый пост в канале»** - спросить пользователя «о чём пост, какая ссылка?» или прочитать `paths.recent_posts_url` (если есть).
- **«купил клуб → onboarding»** - read `paths.products_dir/product-1.md`. Извлечь первое действие новичка.
- **Кастомный trigger** - спросить пользователя «какой контекст? что нужно сообщить?».

### Шаг 2: Генерация 3-5 кандидатов

Каждый кандидат - отдельный push с разным углом / hook / кнопкой:

| # | Подход | Тип | Hook | Кнопка |
|---|---|---|---|---|
| 1 | прямой анонс | reminder | время + действие | 1 callback «иду» |
| 2 | через FOMO | reminder | «через час окно закроется» | 1 callback «успеть» |
| 3 | через ценность | content-tease | «что узнаешь на вебинаре» | 1 URL «открыть» |
| 4 | через сегмент | drip-segment | «ты в группе X - это для тебя» | 2 callback «иду / напомнить позже» |

### Шаг 3: No-repeat фильтр

То же что в B1: rotation hook framework / тип / тема.

### Шаг 4: Презентация в чат

Plain text список → выбор → передать управление в `02-structure.md`.

## Output для следующего шага

В `02-structure.md` передаётся:
- Выбранный угол / кандидат
- Hook framework
- Предполагаемый тип сообщения (verify в structure)
- Кнопочная стратегия
- Контекст (вся релевантная информация из avatar / products / триггера)
- Сегмент аудитории
- Что НЕ упоминать (если есть запреты от карты воронки или явные из config.banned_terms)

## Anti-patterns Spark

- **Не генерить углы которые автор не одобрит**. Если в trigger «winback холодных» - не предлагать угол «извини что давно не писал» (slabnly), лучше «вот что произошло за это время».
- **Не дублировать**. 5 углов с одним и тем же hook framework - это 1 угол с 5 формулировками, не 5 углов.
- **Не выдумывать factual**. Если не знаешь точное время вебинара - спросить, не подставлять placeholder.
- **Не давать generic углов**. «Расскажи про продукт» - не угол, а отсутствие угла. Каждый угол должен иметь хук + наблюдение + переход к CTA.
