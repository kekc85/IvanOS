# Bot message anatomy

> Анатомия рабочего bot push в notification stream. Базируется на эмпирике Telegram bot ux + конверсионных данных по push маркетингу.

## Notification preview - правило 50/95/300

Лимиты превью на разных платформах:

| Платформа | Lock screen | Notification center | Banner |
|---|---|---|---|
| iOS | ~50 знаков | ~80 знаков | ~50 знаков |
| Android | ~65 знаков | ~100 знаков | ~95 знаков |
| Telegram Desktop | ~120 знаков | (full text) | n/a |
| Telegram Web | full text | full text | n/a |

**Главное правило:** первые 50 знаков должны нести смысл. Если в этих 50 знаках только декорация («Привет! 👋 У нас тут…») - push прочитан как spam, открытие не происходит.

## Структура push'а

```
[0 - 50 знаков]      HOOK (notification preview)
[50 - 220 знаков]    BODY (доводит до CTA)
[220 - 300 знаков]   CTA-bridge (опционально, тонкая стрелка)
[external]           КНОПКИ (1-3 inline)
```

## Зачем hook важнее всего

Аудитория увидит push в 3 контекстах:

1. **Lock screen** - первые 50 знаков, нет тапа
2. **Notification center** - первые 80-95 знаков, можно свайпнуть
3. **Открытый бот** - full text

В ~70% случаев решение «открыть или нет» принимается на этапе (1) или (2). Если hook не несёт смысла - push не открывают.

## Buttons в notification stream

Inline-кнопки **не отображаются** в notification preview. Их видно только после открытия бота.

Это значит:
- Текст push должен **подвести** к ожидаемой кнопке без её видимости
- Кнопка должна **подтвердить** ожидание из текста (одно прочтение → одно действие)
- Если кнопка не соответствует ожиданию из текста - frustration, отписка

## Длина - зависимость от типа

| Тип | Min | Target | Max |
|---|---|---|---|
| reminder | 80 | 100-150 | 200 |
| voronka-push | 100 | 120-180 | 220 |
| content-tease | 150 | 180-220 | 250 |
| broadcast-news | 150 | 200-280 | 300 |
| drip-segment | 150 | 200-250 | 280 |

Не больше 300. После 300 - notification обрезается, кнопки уходят за экран на mobile.

## Тон голоса в bot push

В отличие от поста в канал (где читают лежа), push читают:
- На ходу
- Одной рукой
- Между других дел
- В уведомлении что отвлекает от другой задачи

Это значит:
- **Brevity > completeness**
- **Imperative > descriptive** («Открой», не «Можешь открыть»)
- **Direct address «ты» > formal «вы»** (если бренд позволяет)
- **One sentence ideal** (1-2 максимум, не «1, 2, 3, и кстати ещё…»)
- **Zero waffle** (банни-слова «просто», «довольно», «по сути» - фильтрация)

## Timing - best practices

Часы пиковой открываемости push (RU аудитория):

- 8:00-9:00 (утро, дорога на работу)
- 12:00-13:00 (обед)
- 19:00-21:00 (вечер, после работы)

Часы плохой открываемости:
- 0:00-7:00 (спят - отметится в notification center, но открывают редко)
- 14:00-16:00 (работают - отвлекаются позже)

Не критично для cold аудитории - там пик в 21:00-23:00 (вечерний листинг).

Если push привязан к событию (вебинар, окно открытия) - таймать на событие, не на пиковые часы.

## Anti-patterns notification stream

- **Hook = «Привет!»** - generic, не несёт смысла, prediction-low
- **Hook = decoration emoji + текст** - emoji в начале могут резаться на старых клиентах
- **Hook >50 знаков с обрезкой** - обрезка может срезать ключевое слово, hook ломается
- **Анонс без CTA** - push без кнопки = маркетинг-сообщение, низкая конверсия
- **Two CTA в тексте** - «и не забудь про X, и про Y, и про Z» - выбор парализован
- **Длинная преамбула перед action** - «как ты знаешь, мы давно говорим про…» - теряет 80% open в первой строке

## Тест на качество hook

Прочитать первые 50 знаков push'а без контекста (как будто видишь push'а впервые от незнакомого бота). Если:

- Понятно о чём → pass
- Понятно зачем открывать → strong pass
- Нет ничего из этого → fail, переписать

## Связь с другими skills

- `post` - для поста в канал, который потом анонсится через `content-tease`
- `produce-reel` - для видео, который потом анонсится через `content-tease`
- `longform` - для эссе, который потом анонсится через `content-tease`
- `email` - параллельный broadcast channel, MECE граница: email длиннее, имеет subject + preheader + body, открывается в почтовом клиенте
