# Kit build-sheet - порядок сборки, тарифы, double opt-in, deliverability

Все факты о платформах - из R2 (документация help.kit.com и beehiiv.com, проверено
2026-08-02), про доставляемость - из R1. Правило формулировок: «создай Sequence с
настройками X», названия кнопок и пункты меню НЕ выдумывать - интерфейс меняется по
версиям и тарифам, build-sheet оперирует сущностями, не пикселями

## Подтверждённые сущности Kit

Существуют и называются в документации именно так (R2, help.kit.com):
**Forms** (формы подписки embed/modal/inline с настройками confirmation email) ·
**Landing pages** (отдельные страницы подписки) · **Broadcasts** (разовые рассылки) ·
**Sequences** (многошаговые цепочки писем) · **Visual Automations** (визуальный конструктор:
Entry point → Actions → Conditions, до 5 точек входа на автоматизацию) · **Tags** ·
**Segments** (сохранённые фильтры по тегам/полям)

Только эти сущности допустимы в build-sheet как факты об UI Kit

## Порядок сборки минимальной воронки в Kit (R2, п.3)

1. **Landing page или Form** - точка входа. Настроить confirmation email (двойное
   подтверждение + выдача лид-магнита). Проверить, что double opt-in НЕ выключен - в Kit
   он включён по умолчанию, выключается только осознанной настройкой auto-confirm (R2)
2. **Visual Automation** с Entry point = «подписка через эту форму/лендинг»
3. Внутри автоматизации - Action **Add Tag** (тег лид-магнита, например `lead-magnet-<slug>`,
   плюс служебный `welcome-in-progress` - он исключает подписчика из nurture-сегмента на время
   welcome-серии) для сегментации
4. Следом Action **Subscribe to Sequence** - запускает welcome-серию
5. **Sequence** - сама цепочка W1-W5 с таймингами (дни 0-4)
6. Финальный шаг автоматизации - после завершения Sequence снять служебный тег
   `welcome-in-progress` действием «убрать Tag» (R2 подтверждает: Actions Visual Automation
   включают «добавить/убрать Tag»; точное название действия смотрим в живом конструкторе,
   логика: убрать тег). Без этого шага подписчик навсегда останется исключён из
   nurture-сегмента и не получит регулярную рассылку
7. Дальше опционально **Condition**-ветвления по поведению (открыл/кликнул) внутри той же
   автоматизации, ведущие к разным Tags/Segments для последующих Broadcasts

Nurture и петли ездят на **Broadcasts** по **Segments** (фильтры по статусным тегам
cold/engaged/member/buyer из funnel-arc.md); renewal и win-back - отдельные Sequences
со входом по тегу

**Импорта автоматизаций файлом НЕТ ни у Kit, ни у Beehiiv** - сборка только руками в UI
(R2, однозначный ответ). Отдать готовую воронку ученику можно через share-link: в любой
Visual Automation включается шаринг, по публичной ссылке автоматизация копируется целиком
в чужой Kit-аккаунт - вместе с тегами, sequences (с текстами писем), custom fields и
формами; у кого аккаунта нет, тому предлагается 14-дневный триал (R2,
[help.kit.com/…/how-to-share-a-visual-automation](https://help.kit.com/en/articles/2502664-how-to-share-a-visual-automation)).
Работает только Kit → Kit. У Beehiiv аналога в открытых источниках не найдено (R2)

## Double opt-in для EU (R2, п.6)

Юридический факт: сам GDPR double opt-in НЕ требует - он требует свободного, конкретного,
информированного и доказуемого согласия. Double opt-in как требование закона введён на
уровне отдельных стран: подтверждено для Германии, упоминается для Греции, Австрии,
Люксембурга (R2, termsfeed.com + suped.com)

Асимметрия дефолтов - главный источник ошибки новичка:
- **Kit**: double opt-in включён ПО УМОЛЧАНИЮ, выключается настройкой auto-confirm.
  Инструкция ученику: «проверь, что НЕ выключен»
- **Beehiiv**: double opt-in нужно ВКЛЮЧИТЬ на уровне формы или всей публикации
  (плюс Smart Nudge - дожим неподтвердивших). Инструкция ученику: «проверь, что включён»

## Deliverability-чеклист (R1)

Требования Gmail/Yahoo для bulk-отправителей (от 5000 писем/день; Microsoft - с этой редакции),
но аутентификацию проверяют у ВСЕХ отправителей:

- [ ] **SPF + DKIM** настроены на домене отправки - обязательны для всех
- [ ] **DMARC** - обязателен для bulk-отправителей, минимум политика `p=none` с alignment
  по SPF или DKIM. В 2026 `p=none` расценивается как временный этап мониторинга, ожидается
  движение к `p=quarantine`/`p=reject`; кривой alignment в 2025-2026 всё чаще даёт прямой
  отказ приёма (SMTP 5.7.27 / 5.7.30), а не спам-папку
- [ ] **Spam rate ниже 0.10%** по Google Postmaster Tools - рабочая цель; 0.30% - порог
  принудительных мер, не безопасная зона
- [ ] **One-click unsubscribe** по RFC 8058: заголовки `List-Unsubscribe` +
  `List-Unsubscribe-Post` (только первый без второго = НЕ соответствие). Kit/Beehiiv как
  ESP закрывают это штатно - проверить, что письма уходят через ESP, а не самопал-SMTP
- [ ] **Отписка обрабатывается в течение 2 дней** - требование платформ жёстче закона
  (CAN-SPAM даёт 10 рабочих дней). Штраф FTC по CAN-SPAM с этой редакции - до $53 088
  за нарушение
- [ ] **Прогрев нового домена**: 4-8 недель минимум; старт 10-20 писем/день на тёплые
  адреса, прирост 5-10 писем/неделю, боевые кампании не раньше 7 недели. Пометка R1:
  цифры из индустрии cold-email (Mailreach/Warmy/Mailivery), для newsletter-кейса это
  обоснованная экстраполяция, не 1-в-1 измеренный бенчмарк
- [ ] **Разнести потоки по поддоменам** (транзакционные vs маркетинговые) - общая best
  practice deliverability-индустрии, измеренного бенчмарка под solo-creator нет (R1)
- [ ] **Гигиена базы**: не открывавших 60+ дней - в re-engagement или на выпил, мёртвый
  вес тянет open rate и репутацию вниз

## Ориентиры метрик для сверки после запуска (R1)

| Метрика | Ориентир | Источник |
|---|---|---|
| Open rate | 35-45% хорошо | сводка R1 (Beehiiv 41.24% в среднем за 2025, MailerLite 43.46%) |
| CTR | 2-6% | сводка R1 (не путать CTR от отправленных с CTOR от открытых) |
| CTOR | 10-20% сильно, рынок 6.81% | MailerLite 2025 |
| Unsubscribe | 0.2-0.4% норма | сводка R1 |
| Каденс | 1-2 письма/нед | MailerLite, 12+ млрд писем |

Цифра «98.2% deliverability у Kit» существует только во вторичном агрегаторе без
первоисточника - R1 пометил как непроверенную, в build-sheet не использовать как факт
