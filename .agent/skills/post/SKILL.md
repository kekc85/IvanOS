## Архитектура (v3.0 - Hybrid Architecture C + Platform axis, approved 2026-05-28)

Скилл portable: один и тот же код работает у автора и у учеников курса вайбмаркетинга. Различие - только в `config.md` и данных проекта, на которые он указывает.

**Четыре ортогональных axes (v4.2 убрал Lane — путь всегда один, глубокий):**

| Axis | Значения |
|---|---|
| **Mode** (откуда смысл) | Plan (Карта смыслов) / Spark-B1 (идея пользователя) / Spark-B2 (генерация под JTBD) / Transcript (надиктовка) / **Rewrite** (улучшить готовый пост, NEW v4.1) |
| **Subject** (кто автор) | автор / ученик (свой config + свой `.business/`) |
| **Platform** (где публикуется) **NEW v3.0** | **Telegram** (канал, ≤2500 chars, soft tone, no see-more cutoff) / **LinkedIn** (1300-2200 chars optimal, peer-to-peer, see-more cutoff ~210 chars, hook spacing 62/62/50 chars) |
| **Language** (на каком языке) **NEW v3.0** | **RU** (автор primary) / **EN** (автор EN-launch июнь 2026 + ученики EN рынка) |

**Backward compatibility:** default `platform=telegram, language=ru` - все существующие RU-TG вызовы продолжают работать. Explicit overrides через флаги `--telegram`, `--linkedin`, `--ru`, `--en`.

### Глубокий конвейер и ТРИ МАРШРУТА (v4.2 Lane убран · развилка по решению автора, дефект Д11)

Быстрого/облегчённого режима нет: гейты одинаковы на всех маршрутах, срезать углы под именем автора нельзя. Различаются маршруты ОБЪЁМОМ ЧТЕНИЯ и числом проходов сборки, а не строгостью проверок. Маршрут выбирается в `workflow/01-router.md` Шаг 0.7-Р и объявляется строкой `маршрут: …`.

| `brief.route` | Когда | Что исполняется |
|---|---|---|
| `full` | одиночный флагманский пост · новая форма (класс/профиль/платформа впервые) | router → finalize → 02b (факт-база AC5) → **02b1 (добыча сцены, HARD)** → 02c → 02d → 02e → 02f → **03-dry** → 04-review (с независимым верификатором) → 05-publish, всё с нуля |
| `packet` | **пакет дня от 3 единиц** (ячейки одного дня, серия информеров, дуга запуска) - дефолт для пакетов | обязательное чтение ОДИН РАЗ на пакет в `.post-packet-по решению автора.json`; на каждой единице - своя факт-база, **своя добыча сцены `02b1` (одна сцена = одна единица, сцену пакета не переиспользовать)**, тело, `03-dry`, линт+хук-гейт, гейты класса |
| `short-event` | `form_class = event` (анонс, звено каскада доходимости, финальный пуш) | 3 фазы E1-E3 вместо 10, закрытый набор из 12 гейтов (`01-router.md` 0.49-К) |

**Router** в `workflow/01-router.md`:
- Шаг 0.55: banned list refresh check
- Шаг 0.7-Р: развилка маршрута (`full` / `packet` / `short-event`), Шаг 0.7-П: пакетный режим
- Шаги 1-3: Mode detection (auto-detect по сигналам)

Override через флаги:
- Mode: `--plan` / `--spark` / `--transcript`
- Флагов скорости/глубины (`--fast` / `--co-create`) больше нет: глубокий прогон — единственный и обязательный.

**Onboarding** для нового пользователя - `workflow/00-onboarding-student.md`. Срабатывает при отсутствии или неполном `config.md`. После onboarding ученик имеет заполненный config + `intake/` файлы и может запускать `/post`.

## Когда применять

Триггеры (auto-detect mode в router):

| User input | Mode | Что делает |
|---|---|---|
| `/post` без аргументов | Plan | Берёт смысл дня из Карты смыслов запуска |
| «по плану», «смысл дня», дата | Plan | То же |
| `/post про X` / «напиши пост про X» | Spark-B1 | Расширяет тему X в 5-7 углов, ты выбираешь |
| «дай идеи» / «что писать сегодня» | Spark-B2 | Генерит 5-7 идей под JTBD/avatar, ты выбираешь |
| Длинный текст (>500 знаков), «надиктовал», «вот мои мысли» | Transcript | Извлекает 3-10 атомарных смыслов, выбираешь top-1-3 |
| «лог: пост X — охват / клики / реги» | — (журнал) | Дописать строку в `references/post-performance-log.md` (создаётся при первом логе; петля метрик v5.0), пост не пишется |

**Не применять** для:
- Постов в Нельзяграм / X / LinkedIn → `paips-post` / `spiky-one-liner` / `long-form-essay`
- Бот-рассылок → планируется `bot-broadcast` v2
- Email → планируется `email-broadcast` v2

## Workflow

Полная карта workflow + Mandatory Reads per combo + override flags вынесена в **`knowledge/workflow-overview.md`** (per skill-anatomy.md рекомендация SKILL.md ≤250 строк).

**🔴 Запуск ТОЛЬКО по 5 СЛОЯМ, каждый со своими фазами — читать `workflow/_phases-state.md` ПЕРВЫМ.** Слои: **1 Канон** (смысл→якоря→заголовок→контекст→тело→ценность→CTA) · **2 Голос** (внешний `config.voice_canon`, AC8) · **3 Mastery** · **4 Эмпирика** (паттерны 30 виральных + язык ЦА + benchmark) · **5 Гейты/ревью** (**03-dry осушение** → линтер v2 → Blueprint → 4.B.9 → checklist_ivana AC4 → верификатор → humaniser → 3 слоя). СЛОЙ ≠ ФАЗА: пост СОБИРАЕТСЯ слоями 1-4, ПРОВЕРЯЕТСЯ слоем 5; готовый пост — результат слоёв, не «фаза». Развёртывание: слой за слоем, внутри слоя фаза за фазой → показать → СТОП → ✋-апрув автора → следующая. НИКОГДА не бандлить и не пропускать (главный саботаж). Машинные гейты (Слой 5) — молча с уликой. Каждая фаза пишет улику в `.post-state-по решению автора.json`. Приём как у `website` v1.3.

Краткая суть:

- Router (Шаги 0.4/0.45/0.47/0.49) определяет platform / language / combo / form_goal-form_class (lane-селекции нет — v4.2)
- Mode detection (Plan / Spark-B1/B2 / Transcript / Rewrite) → mode-ideate → 01-finalize → единый глубокий конвейер
- Конвейер (всегда): 02b-research (факт-база, AC5) → **02b1-scene-mining (ДОБЫЧА СЦЕНЫ, HARD GATE, NEW по решению автора)** → 02c-tuple → 02d-components → 02e-value → 02f-polish → **03-dry (осушение, НОВАЯ v2.0)** → 04-review (полный, с независимым верификатором) → 05-publish
- **Сцена как входной гейт тела (NEW по решению автора).** Факт-база меряет объём контекста в знаках, и объём прекрасно набирается тезисами карты смыслов - поэтому единица проходила гейт и всё равно выходила без живого слоя (замер боевого корпуса: 0-2 числа в теле против 11-21 у эталонов автора). `02b1-scene-mining.md` добывает КОНКРЕТНЫЙ ЭПИЗОД по фиксированному порядку источников (клетка дня → личный канон фактов → аналитика/разборы → корпус отзывов → банк историй → корпус своих постов → рефлексии → логи сессий) и записывает карточку `scene` (кто · когда · что делал · цифра · что сломалось · что получилось · улика `файл:строка`). Карточки нет - тело не пишется, агент идёт добывать дальше. Пусто во ВСЕХ источниках - единственный легальный выход это один вопрос владельцу строкой, не выдумка. В пакете сцена нужна КАЖДОЙ единице, а не дню: одна сцена = одна единица.

1. **Portable by config.** Один и тот же скилл работает у автора и у ученика. Различие - только `config.md` и данные проекта. Никаких hardcoded paths.
2. **Voice over format.** Стилистика автора важнее структуры. Если шаблон ломает голос - голос побеждает.
3. **Single idea per post.** Один пост = один тезис. Multi-tезисные посты - split на серию.
4. **1/3/1 rhythm.** Первая строка короткая. Тело - чередование длин. Финал - короткий + CTA.
5. **Archetype rotation.** Не повторять архетип последние 3 поста (`config.voice.rotation_window`).
6. **«How I» вместо «How to».** Personal-experience-driven framing (по Lara Acosta / convergence у 5 EN авторов).
7. **No-repeat hard в Spark-B2.** Перед генерацией идей читаются последние 30 постов канала. Повторы темы/угла фильтруются.
8. **Карта смыслов = source of truth для Mode A.** Не дополнять, не выдумывать. Пустая запись = fallback на Mode B2, не вымысел.
9. **Транскрипт в Mode C - цитата, не парафраз.** Лексика автора важнее «причёсанной» формулировки.
10. **Maxwell Ross 9-checklist gate.** Никакой post не выходит без 9/9 PASS.
11. **3 слоя проверки - финальный gate.** Перед output обязательное явное подтверждение.
12. **Внутрянка после поста.** Каждый output включает блок «Как писал»: Mode / контекст / тип / hook framework / archetype / angle / HSO / voice / что отброшено / A/B логика. Глубина видна через обоснования «почему это, а не то».
13. **Каждая правка = системная.** Любая обратная связь от автора закрывается на ДВУХ уровнях: (1) точечный fix в текущем посте + (2) системная правка в скилле - config / workflow stage / review gate / memory / SKILL.md - чтобы нарушение не повторилось. См. [[feedback-each-correction-becomes-system-rule]].

15. **Канон строит пост, generic — только вспомогательно.** Заголовок строится по блюпринту заголовков канона (раздел 2), контекст по 7 типам захода (раздел 3), тело по примеры+ценность (разделы 4-5). Раскрытие идёт **шестью фактами, собранными в одну причинную цепь** (`02e-value-injection.md` Шаг 3.5), а НЕ блоками-рубриками: формульные ярлыки в тексте поста запрещены прямой правкой автора 6.08 («Никаких формульных блоков»). Вода = брак (Ильяхов: оценочные суждения и абстракции вместо конкретики - FAIL). Метафора-подмена (образ вместо сущности, смысл исчезает при удалении образа) = HARD-брак; окрасочный эпитет/идиома РЯДОМ с конкретикой (образ не заменяет, а украшает названную своим именем сущность) - желанен, не ограничивать.

## Portability - для ученика курса

> **v3.2 (репликуемость):** проект-контекст вынесен СНАРУЖИ скилла в **проектный пакет** и подключается флагом `/post --project <name>`. Движок (`workflow/*`, generic `references/*`, `templates/*`) общий и не трогается. Резолвинг — `workflow/00-project-context.md` (читается первым в `01-router.md` Шаг 0.0), реестр проектов — `config.md` → `projects:`. Дефолт без флага = `ivan` (backward compat). Пример второго инстанса: `health` → `.business/проекты/здоровье/post-pack/` (voice-canon / gold-standard / jtbd-value-map / post-config). Все стадии читают `{active.*}` вместо литеральных авторских-путей; линтер project-aware (`--allow-em-dash` / `--allow-end-period`). Ученик подключает свой пакет, код не трогает.

Ученик клонирует папку `~/.claude/skills/post/` в свою машину и заменяет ТОЛЬКО:

1. **`config.md`** - пути и лексика под свой проект (онboarding это делает за него при первом запуске).
2. **`examples/gold-standard-<your-name>.md`** - свои лучшие посты (5-10 штук).
3. **`intake/`** (или `.business/`) - `avatar.md`, `jtbd.md`, `brand-dna.md`, `products/`. По путям из config.

Что НЕ трогаем:
- `workflow/*` - общая методология
- `references/*` - references (Maxwell Ross, hooks, archetypes, AI-tells) одинаковы для всех
- `templates/*` - шаблоны 8 типов постов

Это делает скилл **product курса**: ученики курса вайбмаркетинга получают тот же инструмент, который автор использует ежедневно.

## Anti-patterns

См. `references/ai-tells-catalog.md` (живой источник; раздел «что НЕ переносить» из `ru-author-patterns.md` уехал в `references/_archive/ru-author-patterns.md`, в маршруте не участвует). Ключевые:

- Em-dash «-» внутри строк (memory правило)
- «Instagram» вместо «Нельзяграм»
- **Метафоры-подмены** (слово в небуквальном значении ВМЕСТО прямого - «ломает», «закрывает», «выстрелил», «вынесли мозг»). Red flag = симптом непонимания контекста (автор): метафора в выводе = диагноз, что задача не понята / скилл применён неверно. Проверка в `04-review.md` 4.1.7. **NB: красочная аналогия (явное «как/словно/будто», 1-2 на пост) — это НЕ метафора, а поощряемый приём оживления (см. 4.1.7 Проверка 1.5 + канон голоса `config.voice_canon.voice_profile`); демаркация по точности значения, не по вкусу (см. также принцип 16: окрасочный эпитет рядом с конкретикой - желанен)**
- **Несуществующие словосочетания** («собирать рилсы руками», «склеивать рилсы руками», «гоняю тексты» - никто так не говорит; прецедент по решению автора: «можно гонять собак на улице», глагол в связке обязан существовать в живой речи). Тест каждой связки глагол+существительное: «говорят ли так вслух». Проверка в `04-review.md` 4.1.7
- Технический жаргон в публичной части
- Negативные статистики в публичном (типа «20% доходят»)
- DM-only ценообразование («цена в личке»)
- Эзотерический регистр («девочки», «вахвахвах», «мур мур»)
- Мат как идентичность
- Travel-флекс («40 стран», «Бали», «Golden Gate»)
- «Архитектор ИИ-систем» статусная Identity
- Списки/буллеты >1 в одном посте
- >1 восклицательного знака
