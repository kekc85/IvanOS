# AI-tells Catalog (TG-RU adaptation)

## Зачем
TG-аудитория автора отличает AI-текст от человека. Главный signal - отсутствие индивидуальности и шаблонные обороты. Этот файл = pre-publish gate против generic AI-выгляда поста.

Note: концепция из aaaronmiller/create-viral-content (100+ EN tells, https://github.com/aaaronmiller/create-viral-content) - adapted для RU TG context. **НЕ копия** - оригинальная компиляция под автора с учётом RU-синтаксиса и его memory rules.

Применение: skill автоматически прогоняет драфт через 3 категории + regex auto-detect в `workflow/04-review.md`. На детект → flag + replacement.

## Категория 1: Универсальные AI-маркеры (EN + RU)

### 1.1 Transition phrase abuse
**EN tells:** "moreover", "furthermore", "in conclusion", "additionally", "however"
**RU аналоги:** «более того», «кроме того», «в заключение», «дополнительно», «однако» (как formal-transition в каждом параграфе)
**FAIL:** >1 transition phrase per post / появление в каждом абзаце как formal connector
**Fix:** удалить или заменить разговорными «и ещё», «короче», «вот что» (только 1 на пост)

### 1.2 Em-dash «-» abuse внутри строк
**Pattern:** AI-модели массово используют em-dash как разделитель внутри предложений
**Memory rule автора (verbatim):** *«В текстах автора только дефис «-» или запятая. Em-dash «-» допустим ТОЛЬКО в начале buллет-списка»*
**FAIL:** em-dash между двумя словами в одной строке
**Fix:** заменить на дефис «-» или запятую
**Regex:** `[А-Яа-я]\s*-\s*[А-Яа-я]` → fail

### 1.3 Bullet point lists everywhere
**Pattern:** AI делает буллет на каждый аргумент, превращает linear text в structured list
**FAIL:** >1 буллет-список на пост (короткий) / >2 на пост (длинный)
**автор-pattern:** буллеты как редкий приём, чаще - нумерованный 3-5 пунктов или просто разбивка через emoji-маркеры абзацев (🆘 ❗️ 📍 💰)
**Fix:** превратить buллет-список в running text с 1/3/1 rhythm

### 1.4 Hedge phrases
**EN tells:** "it's important to note", "ultimately", "it's worth noting", "essentially", "fundamentally"
**RU tells:**
- «важно отметить»
- «в конечном счёте»
- «стоит отметить»
- «по сути»
- «фундаментально»
- «безусловно»
- «несомненно»
**FAIL:** >0 hedge phrase per post (любое появление = AI tell)
**Fix:** удалить полностью. Если мысль не работает без хеджа - переписать прямо.
**Regex:** `(важно отметить|в конечном счёте|стоит отметить|по сути|безусловно|несомненно|фундаментально)` → fail

### 1.5 Emoji overuse
**Pattern:** AI-модели украшают каждое предложение emoji
**FAIL:** >5 emoji на 200 RU слов / emoji в каждом предложении
**автор-pattern (per gold-standard):**
- Emoji в заголовке (🆘 ❗️ 📍 💰 🫠 ✖️ 🤫) = 1 шт
- Emoji-маркер начала ключевого абзаца = 1-2 шт
- Emoji в close-формуле или CTA («ставь 🔥», «👉🏻 ссылка») = 1-2 шт
- Total: 3-5 emoji на пост 1500-2500 chars
**Fix:** удалить все emoji кроме headline + critical accents
**Memory rule:** *«НЕ юзает emoji-перегруз внутри текста - emoji-маркеры в заголовке + точечно в ключевых местах + в close»*

### 1.6 Generic greetings / closings
**EN tells:** "Hope this helps", "I hope you enjoyed", "Let me know what you think", "Thanks for reading"
**RU tells:**
- «Надеюсь, было полезно»
- «Надеюсь, вам понравилось»
- «Спасибо за внимание»
- «Делитесь мнением в комментариях»
**FAIL:** generic closing без личной формулировки
**Fix:** автор-style closes: «Берегите себя на этом рынке», «Всем желаю ленивого продвижения 🔥», «Никогда еще вход в мир ИИ не был настолько доступен», «третьего не дано»
**Regex:** `(Надеюсь.{0,30}полезно|Надеюсь.{0,30}понравилось|Спасибо за внимание|Делитесь мнением)` → fail

### 1.7 Список из 3 в каждом абзаце
**Pattern:** AI-модели тяготеют к триплетам ("важно / полезно / просто", "быстро / эффективно / надёжно")
**FAIL:** >2 параграфа подряд с триплетом
**Fix:** разбить на отдельные мысли с rhythm 1/3/1, оставить максимум 1 триплет на пост

### 1.8 Generic intro structures
**EN tells:** "In this post, we'll explore...", "Today, I want to talk about..."
**RU tells:**
- «В этой статье мы рассмотрим…»
- «Сегодня я хочу рассказать вам о…»
- «Давайте разберём…»
- «В этом посте поговорим про…»
**FAIL:** intro начинается с meta-описания вместо сути
**Fix:** удалить intro полностью, начать с hook (per Maxwell Ross pt.1 «get in step with reader at once»)
**Regex:** `^(В этой статье|Сегодня я хочу|Давайте разберём|В этом посте)` → fail

## Категория 2: RU-specific AI tells (русский синтаксис + лексика)

### 2.1 Англицизмы AI-стиля
**Pattern:** AI пишет «осуществлять», «представлять собой», «являться», «иметь место» - formal calque с EN
**RU tells:**
- «В этой статье мы рассмотрим…» (см. 1.8)
- «Это позволяет вам…»
- «Стоит обратить внимание на тот факт, что…»
- «Не секрет, что…»
- «На сегодняшний день…»
**FAIL:** любое появление
**Fix:** разговорное упрощение. «Это позволяет вам» → «Это даёт». «Стоит обратить внимание» → «Заметь». «На сегодняшний день» → «Сейчас».

### 2.2 Канцеляризмы
**Pattern:** Бюрократический регистр документов
**RU tells:**
- «осуществляется»
- «представляет собой»
- «является ключевым»
- «играет важную роль»
- «в рамках»
- «в плане»
- «по факту»
- «в связи с тем, что»
**FAIL:** >0 канцеляризм per post
**Fix:** заменить на разговорные эквиваленты:
- «осуществляется» → «работает» / «происходит»
- «представляет собой» → «это»
- «играет важную роль» → «важно»
- «в рамках» → «в»
- «в связи с тем что» → «потому что»

### 2.3 Паразитные обороты
**RU tells:**
- «На текущий момент времени»
- «В плане X»
- «По факту»
- «На самом деле» (если ≥2 раза в посте)
- «По большому счёту»
- «Так сказать»
- «Что называется»
**FAIL:** любое появление кроме «на самом деле» 1 раз (автор это слово использует - gold-standard 2227)
**Fix:** удалить или заменить конкретикой
**Regex:** `(На текущий момент времени|По большому счёту|Что называется|Так сказать)` → fail

### 2.4 Прилагательные через «не» вместо позитивных альтернатив
**Pattern:** AI часто выбирает negation-style («не плохой» вместо «хороший»)
**RU tells:**
- «не плохой»
- «неплохой»
- «небезынтересный»
- «не лишний»
- «не помешает»
**FAIL:** >1 negation-adjective per post
**Fix:** заменить на прямые позитивные («хороший», «интересный», «полезный», «нужный»)

### 2.5 Списки из 3 как структурный паттерн
**RU-specific:** «важно / полезно / просто», «быстро / качественно / недорого»
**Same as 1.7, RU-version**

### 2.6 «Мы» в смысле «я» (royal we)
**Pattern:** AI часто пишет «мы рассмотрим», «мы поговорим» когда автор один
**FAIL:** >0 royal we в personal-постах
**автор-исключение:** «мы все в одной лодке», «у нас нет задачи», «вместе мы справимся» - это inclusive we (мы = автор + аудитория), это OK
**Fix:** royal we → «я» / «расскажу» / «покажу»
**Distinction:** «мы рассмотрим X» (royal, fail) vs «мы все в одной лодке» (inclusive, pass)

### 2.7 Безличные конструкции
**Pattern:** «Стоит понять», «Можно сказать», «Принято считать»
**FAIL:** >1 безличная per post (особенно в первых 200 chars)
**Fix:** добавить личное - «Я думаю», «По моему опыту», «Заметил, что»

### 2.8 Двойное отрицание шаблонное
**Pattern:** «Нельзя не отметить», «Невозможно не согласиться»
**FAIL:** любое появление
**Fix:** прямое утверждение - «Стоит отметить» → удалить, сразу к сути

### 2.9 Slug-фразы AI обзоров
**RU tells:**
- «Если коротко…»
- «Подводя итог…»
- «В двух словах…»
- «Резюмируя…»
**FAIL:** >0 (особенно как заголовок секции «TL;DR» - для длинных постов OK, для коротких fail)
**Fix:** убрать; вывод должен сам вытекать из текста

## Категория 3: Anti-patterns автора (memory rules)

### 3.1 Em-dash inside строк
См. 1.2. **Memory ref:** `feedback_no_em_dash.md`
**Regex:** `[А-Яа-я]\s*-\s*[А-Яа-я]` → fail
**Allowed:** em-dash «-» в начале bullet-списка

### 3.2 «Instagram» вместо «Нельзяграм»
**Memory ref (verbatim):** *«Нельзяграм=Instagram (ЖЁСТКО: никогда не "Instagram", всегда "Нельзяграм")»*
**FAIL:** любое появление «Instagram» (на латинице или кириллице)
**Auto-replace:** Instagram / Инстаграм / Insta → **Нельзяграм**

### 3.3 Em-dash и Instagram уже покрыты выше - продолжаем

### 3.4 Атаки на конкурентов по именам
**Memory ref (verbatim):** *«Враг = явление, не имя конкурента»*
**FAIL:** прямое упоминание конкретных конкурентов по имени **в негативном контексте**
**Allowed:** упоминание **в контексте событий рынка** (как автор делает в 2305 «Что с рынком после громких событий на рынке» - это новостная ссылка, не атака)
**Distinction:** "<конкурент> - мошенник" (fail) vs "после громких событий на рынке рынок изменился" (pass)

### 3.5 Негативные статистики о учениках в публичных постах
**Memory ref (verbatim):** *«НЕ использует негативные статистики про учеников («20% доходят…» внутри, но не в продающих постах)»*
**FAIL:** «20% доходят», «80% не делают», «большинство бросают» - в public posts
**Fix:** позитивный фрейм: «<число> выпускников с <метрики учеников>/мес», «<число учеников>»

### 3.6 Em-dash и Instagram (уже выше)

### 3.7 «Программирование как препятствие»
**Memory ref (verbatim):** *«НЕ упоминает «программирование как препятствие». Препятствие = «я не маркетолог», «я не технарь» - но фрейм решения «это не программирование, это вайбкодинг»»*
**FAIL:** «не нужно учиться программировать», «без знания кода» в смысле «легко обойти программирование»
**Fix:** «это не программирование, это вайбкодинг» / «не code-monkey, а оператор Claude»

### 3.8 Длинный intro перед сутью
**Memory ref (verbatim):** *«НЕ длинные intro перед сутью - punchline уже в 1-2 строке, дальше развёртывание»*
**FAIL:** >2 строк до первого ключевого факта / claim / question
**Auto-detect:** считать chars до первого explicit benefit / cifры / question; >180 chars → flag

### 3.9 Обещание результата без действия
**Memory ref (verbatim):** *«НЕ обещает результат без действия - везде conditional «если внедряешь», «если проходишь программу»»*
**FAIL:** «вы получите 100К» / «гарантировано» без conditional
**Fix:** «если применяешь - получишь» / «при внедрении» / «у тех, кто доходит до конца»

### 3.10 «Вы» в холодных-холодных постах
**Memory ref (verbatim):** *«НЕ использует «вы» в холодных-холодных постах - переходит на «ты» когда даёт action»*
**Distinction:**
- Action / call: «ты» («заполни анкету», «бери место»)
- Уважение / values: «вы» допустимо («[твоя подпись] ❤️», «Берегите себя на этом рынке»)
**FAIL:** «Вы» с большой буквы в action-call постах
**Note:** автор миксует ты/вы по контексту - это OK, но preference на «ты» в призывах

### 3.11 Markdown-bold формат
**Memory ref (verbatim):** *«НЕ форматирует через markdown-bold ** - использует физическое разделение через пустые строки, тире, emoji-bullets, brail-spacers (⠀⠀⠀⠀)»*
**FAIL:** массивное использование `**жирный**` через markdown
**Pattern автора:** разделение через:
- Пустые строки (главное)
- Emoji-маркеры начала абзаца
- Brail-spacers `⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀⠀`
- Тире-bullets «-» в начале строки
- CAPS внутри строки (УДВАИВАЮ, СВОЕГО) для emphasis

### 3.12 Подражание чужой лексике
Запрещены чужие category-маркеры:
- «Спринт / Реалити / Поток / забирай» (Палий) → fail
- «вахвахвах / девочки / красотка» (Афонина, Петкова, Арина) → fail
- «цыплёнок / хвостик / субботник» (Нагорнова) → fail
- «АРХИТЕКТОР / Перекладывай смыслы» (Миллер) → fail
- «Друзья! / Как Вы наверняка знаете» (Дамир, патернализм) → fail
- Мат-эвфемизмы «ё*аный / е*нулась» (Нагорнова, Афонина) → fail
- «связки/конвертеры/КЭВ/нейроагент» (Ширяев) → fail

**Fix:** фирменные термины автора (см. 3.13)

### 3.13 Фирменные термины автора (white-list, поощряем)

🔒 **Список живёт ВНЕ скилла** (подэтап 4i). Раньше здесь стояли фирменные слова
конкретного автора, и в раздаваемом скилле этот white-list работал ровно наоборот:
подталкивал текст ученика звучать чужим голосом.

Источник: ключ `canonical_terms` в файле по `config.voice_canon.owner_lexicon`
(по умолчанию `.business/processes/lint-owner-lexicon.json`, переопределяется
env `POST_OWNER_LEXICON`).

**Как применять:**

> файл читается → взять `canonical_terms` как white-list, поощрять эти слова
> файла нет / ключ пуст → правило НЕ применяется, флаг не ставится (у ученика свой
> голос описан в `config.voice_canon.voice_profile`, оттуда и берутся его маркеры)

Skill при отсутствии любого canonical-термина на пост >1000 chars → flag «возможно generic, добавь свой фирменный маркер». Гейт активен ТОЛЬКО когда список реально прочитан.

### 3.14 Образ ВМЕСТО сущности (метафора-подмена) - HARD

Класс дописан по решению автора: в каталоге AI-tells его не было вовсе, а по факту это самый частый дефект боевого корпуса - **34 единицы из 135** в пакетах августа 2026.

**Что ловим.** Предложение, которое не проходит буквальный тест: «это происходит ФИЗИЧЕСКИ БУКВАЛЬНО?». Двери никто не открывает, по ступеням никто не поднимается, карту никто не разворачивает - значит на месте факта стоит картинка.

**Улики из боевых текстов:**
- «Двери открыты всем, без регистрации» (`_pakety-0808/zakr20-link.md`)
- «Первую ступень вы прошли, второй у себя не собрали» (`_pakety-1008/inf22.md`)
- «Читать это стоит как карту складских полок» (`_pakety-1408/zakr26-2.md`)

**Fix:** заменить буквальным описанием того, что происходит, по таблице `references/metaphor-to-literal.md`. Не вычёркивать - **заменять**: вычеркнутый без замены образ возвращается на следующей итерации, потому что сказать то же самое иначе писателю нечем.

**Отличие от окрасочного эпитета** (законен, снимать запрещено): эпитет ОКРАШИВАЕТ названный рядом проверяемый факт («три недели по полдня, и завод контента заработал сам»), метафора СТОИТ ВМЕСТО факта. Соседнее буквальное слово образ не легализует.

**Машина:** `check_metaphor_roots` в `scripts/lint-post.py`, 13 корней, HARD, флаг `--allow-metaphor` только для постов старше правила п.49 (6.08.2026).

## Regex patterns для auto-detect

```yaml
# Категория 1
em_dash_inside_string: '[А-Яа-я]\s+-\s+[А-Яа-я]'  # fail
multiple_exclamations: '[^.!]!.*?[^.!]!.*?[^.!]!'  # fail (>2 «!» на пост)
hedge_phrases_ru: '(важно отметить|в конечном счёте|стоит отметить|по сути|безусловно|несомненно)'  # fail
generic_intro: '^(В этой статье|Сегодня я хочу|Давайте разберём|В этом посте)'  # fail
generic_close: '(Надеюсь.{0,30}полезно|Надеюсь.{0,30}понравилось|Спасибо за внимание|Делитесь мнением)'  # fail

# Категория 2
kanselyarizm: '(осуществляется|представляет собой|является ключевым|в рамках|в связи с тем что)'  # fail
parasit_ru: '(На текущий момент времени|По большому счёту|Что называется|Так сказать)'  # fail
double_negation: '(Нельзя не отметить|Невозможно не согласиться)'  # fail
slug_summary_short: '(Если коротко|Подводя итог|В двух словах|Резюмируя)'  # fail для short, ok для long

# Категория 3 (Ivan-specific)
instagram_ban: '(Instagram|Инстаграм|Insta(?!gram))'  # fail
negative_student_stats: '(20%.{0,10}доходят|80%.{0,10}не делают|большинство бросают)'  # fail в sales
markdown_bold_abuse: '\*\*[^*]{1,30}\*\*'  # warning если >3 на пост

# Quantitative gates
emoji_count: 'emojis_per_200_words > 5'  # warning
exclamation_count: 'exclamations_per_post > 1'  # warning
bullet_list_count: 'bullet_lists_per_post > 1' (short) / > 2 (long)  # warning
```

| markdown `**bold**` | пустые строки + emoji-маркеры |

## Применение в workflow

`workflow/04-review.md`:
1. Прогон всех regex patterns против драфта
2. Подсчёт quantitative gates (emoji / exclamations / bullets)
3. Match white-list canonical-терминов (есть ли minimum 1-2 на пост)
4. Список fails с auto-replace suggestions
5. На FAIL: skill применяет replacements, повторно прогоняет

Финальный отчёт:
- AI-tells detected: N (с указанием категорий)
- Auto-fixed: M
- Manual review: K (что не автоматизируется)

Mandatory pass: 0 fails в категории 3 (автор-memory), ≤2 warnings в категориях 1-2.
