# СЛОЙ 0 «ДЕНЬГИ» — боевая карточка поста запуска (v5.0, 2026-06-11)

> **Зачем.** Все слои скилла проверяют, что пост ХОРОШИЙ (канон/голос/мастера/конкретика). Этот слой гарантирует, что пост ПРОДАЁТ: у каждого поста окна запуска есть измеримая денежная цель и привязка к фазе воронки. Пост без цели в воронке = контент, не маркетинг.
>
> **Принцип разделения труда (зафиксировано с автором):** карта смыслов ДУМАЕТ (какой смысл, какое убеждение сдвигаем, чем), скилл ДОНОСИТ и ДОКАЗЫВАЕТ, что донёс. Слой 0 НЕ выбирает возражения/смыслы сам — он переносит решения из ячейки дня и канона запуска, и фиксирует цель. Выбор возражения скиллом из `objections.md` = ЗАПРЕЩЁН (второй центр решений, дрейф от карты).

## Когда применяется

- `brief.launch_window = true`: активный запуск идёт (окно = от анонса/открытия реги до закрытия продаж, даты из `Воронка.md` канона). **ЛЮБОЙ mode** (Plan / Spark / Transcript / Rewrite): в Plan карточка строится из ячейки дня; в Spark/Transcript — той же структурой, строки 3-4 = честный N/A, если ячейки дня под идею нет (строки 1, 2, 5 обязательны всегда). Карточка при launch_window ОБЯЗАТЕЛЬНА — её отсутствие = FAIL 4.S, не N/A.
- Вне окна запуска (evergreen / daily вне кампании) — слой пропускается молча, карточка не строится, Sales Gate 4.S = N/A. В state всегда пишется явный `launch_window: true|false` (хук в окне запуска требует этот ключ).
- Тип поста: тип из ячейки дня > дефолт «тип 8». Типы 9 (IG-caption) и 10 (closed-channel-intro) живут по своим CTA-правилам, 4.S.1 на них не распространяется.

## Источники (ВСЕ живые, по mtime — не кэш сессии)

| Что | Откуда | Правило |
|---|---|---|
| Решения запуска (канон, читать ПЕРВЫМ) | `<launch>/<решения-запуска>.md` | Любое противоречие между файлами решается этим файлом |
| Ячейка дня (смысл, петля, слом убеждения, демо) | живой `<карта-смыслов>.html` (явное имя, НЕ «свежий по mtime»: архивы v3 в корне переименованы в `_archive-v3-*.html`) | НЕ 5.4/архив/заготовки — |
| Фазы и даты воронки | `<launch>/Воронка.md` | Канонные даты не двигать |
| Цены/тарифы (только в sales window) | `<launch>/<твой состав тарифов>` | Другие файлы с ценами устарели |
| Цифра дефицита (места) | По умолчанию НЕ ставится в пост; если ячейка дня требует дедлайн как механику — ТОЛЬКО живой счётчик лендинга | Выдумывать/брать из памяти ЗАПРЕЩЕНО (<решения-запуска> п.6). 🔴 Ставить счётчик и даты в КАЖДЫЙ пост ЗАПРЕЩЕНО (автор): служебная фактура без смысла, выгорает от повтора |

## БОЕВАЯ КАРТОЧКА (5 строк, показывается автору ВМЕСТЕ с таблицей смыслов на ✋ «смысл»)

```
💰 КАРТОЧКА ПОСТА
1. День запуска + температура: <день N, фаза из шкалы ниже> (улика: Воронка.md:строка)
2. Цель поста в воронке: <что считаем успехом: реги с поста / явка на эфир / оплата>
3. Шаг денежной цепи из ячейки дня: <категория→кейс→демо→инструмент→рега: какой шаг несёт пост> (улика: <карта-смыслов> строка)
4. Слом убеждения ИЗ ЯЧЕЙКИ: <«верил X → после поста Y»> (улика: <карта-смыслов> строка) | «в ячейке не заложен» → N/A
5. Почему действовать СЕГОДНЯ: <реальный факт: счётчик мест с лендинга / дата эфира / событие дня> | нет факта → context-gap, спросить автора, НЕ выдумывать
```

- Карточка пишется уликой в state: `L1.money` (под-ключ слоя 1, хук-совместимо — отдельного чекпоинта НЕТ, апрув берётся тем же ✋ фазы «смысл»).
- Строка 4 — ПЕРЕНОС из ячейки, не выбор. Пустая ячейка по слому → честный N/A, скилл не лезет в objections.md.
- Строка 5 — двигатель «сейчас»: без реальной причины действовать сегодня пост откладывают «на потом» = ноль регистраций. Выдуманный дефицит = ложь = брак.

## ТЕМПЕРАТУРНАЯ ШКАЛА запуска «Вайбмаркетинг 2026» (даты = канон Воронки по решению автора + <решения-запуска>)

| Фаза | Даты | Что продаём | Баланс поста | Жёсткие запреты фазы |
|---|---|---|---|---|
| **Прогрев** | в даты запуска | ТОЛЬКО рега на воркшоп (бесплатный) | Желание + демо-пруф (60-70% примеры) → мягкий мост в регу. Не hard-sell | Программу НЕ продаём и НЕ якорим ценой; VIP НЕ пушим (<решения-запуска> п.1-2) |
| **Дни эфиров** | в даты запуска публичные (по решению автора = закрытый в день запуска, публично явку НЕ зовём) | Явка на эфир (для зарегистрированных) + дожим реги — но дожим реги ТОЛЬКО до этой редакции ~12:00 (счётчик = 0, автор объявляет «места разобрали») | Срочность на реальном счётчике + «сегодня в 19:00 МСК» (время — канон из Посты-по решению автора) | Цифра мест только с живого счётчика; «рега закрывается по решению автора» = устаревшая формулировка, НЕ использовать; после этой редакции 12:00 «почему сегодня» = эфир, не счётчик |
| **Sales window** | в даты запуска (окно закрывается по решению автора 23:59 МСК) | Программа (цены ТОЛЬКО из <твой состав тарифов>). Цена открывается В КОНЦЕ эфира в день запуска | Оффер + кейсы эфиров + ответы на возражения ИЗ карты | Tie-break перекрытия: в день эфира до его конца действует строка «Дни эфиров»; цена в постах — только ПОСЛЕ момента открытия на эфире по решению автора |
| **Закрытие** | по решению автора = последний день продаж (до 23:59 МСК) | Последний шанс программы | Дедлайн реальный | После закрытия продаж НЕТ: только пост-закрытие «места закрыты» + waitlist. Продавать без факта закрытия = выдуманный дедлайн = FAIL 4.S.3 |

> Переносимость: для другого запуска шкала пересобирается из его `Воронка.md` + `<решения-запуска>.md` — механика (фаза → что продаём → баланс → запреты) неизменна, даты/продукты подставляются.

## Жёсткие правила контента запуска (дублируют канон, проверяются Sales Gate 4.S)

1. **ЕДИНСТВЕННОЕ действие читателя = регистрация** (в sales window = оплата/рега по фазе). Никаких «открой Claude / попробуй / посчитай» —. Разрешён микро-да: commitment-шаг, ведущий В регистрацию (реакция/мини-опрос/ответ боту → следующее касание подводит к реге) — <решения-запуска> п.3.
2. **CTA = кнопка-ссылка + приписка P.S. ACTION** (курсивом, снимает трение и даёт запасную ссылку на случай, если первая не открылась). 🔴 Текст приписки НЕ сочиняется скиллом: он берётся ДОСЛОВНО из канона запуска `<папка активного запуска>/PS-ACTION-канон.md` вместе со свежим start-кодом запасной ссылки (см. `workflow/_phases-state.md`, блок «ПРИПИСКА ПОД CTA»). Своя формулировка вместо канонной = брак (прецедент по решению автора). Файла нет → context-gap, не выдумывать; на машине без запуска приписки просто нет.
3. **Без коммент-вопросов на основном лончевом посте** — вовлечение мимо реги запрещено.
4. **«Действие» в теле = МОИ (автора) действия и их результаты**, читатель вдохновляется сам.
5. **Соц-пруф**: «нас уже <число участников> / больше тысячи внутри», число обновлять по факту (<решения-запуска> п.4).
6. **Визуал-демо**: если в ячейке дня есть демо-артефакт (скрин автооплаты, рендер) — предложить его к посту (пруф = показанный результат, не слова).
7. **A/B-вариации CTA (05-publish) обязаны соответствовать 4.S.1** — вариация с вопросом/вторым действием = брак, варьируется мост к реге, не тип действия.
8. **Лонч-CTA-блок вне line/rotation-правил**: кнопка+практ-ремарка+реальный счётчик повторяются из поста в пост по дизайну — ротируются заголовок/контекст/драматургия/архетип, НЕ CTA-механика.
9. **Оффер отдаёт РОВНО показанное** (replication + реципрокность): инструмент/механизм, к которому пост строил желание в теле, оффер выдаёт буквально («1:1 как у меня», «даю доступ к скиллам»). Проверка: инструмент в оффере == инструмент, продемонстрированный в теле? Демонстрировал скиллы → оффер про скилллы, а не «методологию вообще» (иначе желание утекает). Приём F → `references/launch-warmup-devices.md`.
10. **Перевод результата в деньги читателя** (money-translation, поощряется в прогрев-демо): свой РЕАЛЬНЫЙ результат → рубли, которые читатель чувствует, + якорь-сравнение с дорогим привычным способом (реклама/агентство/команда). Математику показывать открыто (× и =). Эталон: «<твой результат>/мес = <твоя цифра> через рекламу». 🔴 Все числа и ставка сравнения — реальные (живой счётчик/лог/экономика ниши), не с потолка. Приём B → `references/launch-warmup-devices.md`.

## Anti-patterns Слоя 0

- Карточка построена из памяти/архива вместо живых файлов.
- Скилл сам выбрал возражение из objections.md (центр решений = карта, не скилл).
- «Почему сегодня» выдумано (дефицит без живого счётчика, несуществующий дедлайн).
- Hard-sell в фазе прогрева (продажа программы/цены <до раскрытия цены>).
- Слой применён вне окна запуска (evergreen-посту карточка не нужна).
