# Workflow 02e - Value Injection (Co-creation Lane)

**Назначение:** выдать 3-5 конкретных value-injection points (V1-V6 insights) с verbatim source из факт-базы. автор выбирает **по need** (сколько реально нужно для покрытия mandatory V + причинной цепи B3 своего класса - не квота ради квоты) которые попадут в финальный пост → fixed в outline.value_injections.
**Триггеры:** после `02d-components-options.md` в co-creation lane.
**Входы:** `outline.tuple` (mandatory value-vector из tuple) + `outline.research_summary`.
**Выходы:** `outline.value_injections = [insight1, insight2, insight3]` - fixed список.
**Следующая стадия:** `workflow/02f-polish.md`.

---

## Принцип

Hook + reveal + close определены в 02d, но они = **структурные слоты**. Без конкретных value-injections пост получит **форму без содержания** .

Value-injection = **конкретный insight с verbatim proof**, который inline вшивается в reveal или setup. Hard rule из `references/value-types-framework.md`: пост обязан доставить **≥2 из 6 value-types**. Этот шаг делает их явными ДО написания, а не надеется что они «появятся».

**Mandatory value-type** = `outline.tuple.V` (зафиксирован в 02c). Этот V обязан быть доставлен. Дополнительные V (1-2 ещё) подбираются для усиления.

## Шаг 1 - Read value-types-framework

Прочитать `references/value-types-framework.md` (Fix 3 output).

Извлечь для **mandatory V** из tuple:

- **Definition** (что считается доставленным value этого типа)
- **Сигналы что value доставлено** (3-5 checks)
- **автор-template** (verbatim пример из corpus)
- **Detection regex/heuristic** (как review 4.12 проверяет)

Запомнить также **complementary V** - какие value-vectors хорошо комбинируются с mandatory:

- V1 insight + V4 case (insight на базе case)
- V3 counter-intuitive + V4 case (опровержение mainstream + proof)
- V4 case + V6 frame (case через авторский фреймворк)
- V5 strategic + V1 insight (картина рынка с non-obvious углом)
- V2 actionable стоит особняком - добавлять только если topic операционный

## Шаг 2 - Surface 3-5 candidate insights под mandatory V

🔴 **Источник - ФАКТ-БАЗА, не пересказ (AC5).** `outline.research_summary` - компактная сводка, а `outline.factbase_path` (файл `.factbase-по решению автора.md`, записан в 02b) - полный реестр фактов с источниками `файл:строка`. Кандидаты surfacing'а берутся ИЗ ФАЙЛА факт-базы (Read `outline.factbase_path`), research_summary - только навигация по нему. Insight без строки в факт-базе = не кандидат, не придумывать.

🔴 **Сцена главнее факта (NEW по решению автора).** Первым читается корневой ключ `scene` (карточка из `02b1-scene-mining.md`), и **минимум один candidate обязан стоять НА ЭТОЙ сцене** - на её `did`/`broke`/`number`/`result`, а не на соседнем факте базы. Причина: факт-база наполняется тезисами карты смыслов и спецификациями механик, и surfacing по ней в чистом виде выдаёт «знание вообще» - формулировки вида «признак процесса простой», «возвращаться надо не с начала, а с участка, который встал». Такое знание верно и мертво: у него нет ни лица, ни времени, ни числа. Ключа `scene` в state нет → surfacing НЕ начинать, вернуться в `02b1`.

🔴 **Каркас называет боль читателя дословно (NEW по решению автора, второй корень фидбэка владельца).** Перед surfacing прочитать `scene.pain` (дословная боль из карты смыслов плюс улика `файл:строка`, кладётся в `02b1`) и `scene.novice_retell`. Каркас поста принимается только если он называет ЭТУ боль из карты, а не абстракцию («страх технологий», «нехватка времени», «хочется результата»). Нет привязки к боли из карты - **каркас не принят**, возврат в `02d` за компонентами под названную боль, а при пустом `scene.pain` - возврат в `02b1`.

Отсюда же порядок внутри поста: **заход идёт с боли или ситуации читателя**, сцена автора встаёт ВНУТРИ как доказательство под уже названную боль. Candidate, который годится только на роль первого абзаца-отчёта о работе автора («первого августа я считал, сколько у меня...»), в `integration_point: hook` не ставится - его место `reveal_anchor` или `close_echo`.

Из факт-базы (Karta sections + gold-standard + case studies + любые записанные там факты) **извлечь 3-5 candidate insights** под mandatory V.

**Правила surfacing:**

0. **Candidate I1 = insight, вынутый из сцены.** Формулируется как «что стало понятно ИЗ ТОГО, что <who> <did> и получил <number>/<result>». Остальные candidates могут стоять на других фактах базы, но I1 без сцены не принимается.

0б. **Каждый candidate читается через `novice_retell`.** Формулировка insight'а не имеет права требовать знания проекта: термины из чёрного списка `02b1` (дека, копи-блок, голая команда, расписка, гейт, линт, сегмент, реплей, автовыдача, контур, тех-имя скилла) в candidate не проходят. Такой candidate переписывается человеческими словами либо снимается.

1. Каждый insight = **verbatim quote** или **verbatim element** (число / имя / case / Karta phrase), взятый ИЗ ФАКТ-БАЗЫ. НЕ перифраз.
2. Каждый insight имеет **clear source `файл:строка`** (та же строка, что стоит в факт-базе рядом с фактом).
3. Если для mandatory V в факт-базе < 3 candidates → **ESCALATE** в Шаг 4 (нельзя выдумывать).
4. Приоритизация candidates:
   - Тier 1: real cases с цифрами (<имя ученика> $100K, F-3 факап <сумма>)
   - Тier 2: Karta verbatim quotes («5 уведомлений за выходные»)
   - Тier 3: Распаковка facts (<число учеников>, <N>K канала)
   - НЕ использовать: общие наблюдения без proof, чужие цитаты без атрибуции, выдуманные числа

**Пример (mandatory V = V4 case study, topic = первые продажи):**

```
Candidate I1 - <имя ученика> с 0 до $100K
- V-type: V4 case study
- Verbatim source: gold-standard пост 8
- Verbatim element: «$100K за <срок>», «база была <число>»
- How to integrate: основное тело reveal, anchor вокруг неё

Candidate I2 - «20К подписчиков и копейки в продажах»
- V-type: V1 insight (подмешать к V4)
- Verbatim source: corpus post ID из `config.voice_canon.voice_corpus_dir` (нет корпуса - поле остаётся пустым и элемент не считается verbatim, а не «взято из шаблона»)
- Verbatim element: «20К vs копейки»
- How to integrate: открывающий контр-пример перед case <имени ученика>

Candidate I3 - «5 уведомлений за выходные»
- V-type: V1 insight + V4 element
- Verbatim source: Карта 5.2 канон #5
- Verbatim element: «5 уведомлений за выходные»
- How to integrate: точечный sensory detail в close или reveal

Candidate I4 - <число учеников> → <число> млн подписчиков суммарно
- V-type: V4 aggregate proof
- Verbatim source: Passport §1 / Распаковка
- Verbatim element: «<число учеников>», «<число> млн подписчиков суммарно»
- How to integrate: authority anchor в setup, не в reveal

Candidate I5 - F-3 факап <сумма> (если topic смежен с провалом/откатом)
- V-type: V4 negative case
- Verbatim source: Passport §1
- Verbatim element: «<сумма> на платный трафик
- How to integrate: контраст «было vs стало», если уместно по тону
```

## Шаг 3 - Format каждый insight

Для каждого candidate output в формате:

```yaml
candidate:
  id: "I1"
  v_type: "V4"
  verbatim_source: "gold-standard пост 8"
  verbatim_element: "$100K, база <N>"
  integration_point: "reveal anchor"
  rationale: "1 sentence почему этот insight усиливает tuple"
```

`integration_point` варианты:
- `hook_anchor` - встроить в hook (numerical proof)
- `setup_authority` - встроить в setup до reveal (для credibility)
- `reveal_anchor` - основной материал reveal
- `reveal_contrast` - контр-точка внутри reveal
- `close_echo` - sensory detail в close

## Шаг 3.5 - B3: шесть фактов в ОДНОЙ причинной цепи (`razbor`, прикладной `sales`, `event`)

🔴 **ГЛАВНОЕ ОГРАНИЧЕНИЕ ЭТОГО ШАГА (канон правок пп.16, 40, эталон 6.08 п.3).** B3 - это **шесть обязательных ФАКТОВ, собранных в непрерывную причинную цепь**, а НЕ шесть блоков и НЕ шесть подзаголовков. Владелец 6.08 разнёс ровно эту сборку: «Никаких формульных блоков… Владелец просто перечисляет, что разберёт, и даёт внутрянку сетапа». Раньше здесь стоял список из шести ярлыков - писатель послушно выносил ярлыки в текст, и на выходе получалась слот-карточка, которую верификатор валит гейтом W15-цепь. Формулировка правила изменена так, чтобы ярлыку неоткуда было взяться.

**Шесть фактов (каждый = candidate из Шага 2 с адресом `файл:строка`):**

| F | Какой факт нужен | Чем доказан |
|---|---|---|
| F1 | стартовое состояние: с чем человек имеет дело до инструмента | цитата/цифра факт-базы |
| F2 | физическое действие системы: что она делает по шагам, дословно что ей говорят | внутрянка `SKILL.md`/воркфлоу (канон п.7, п.8) |
| F3 | предметный результат: что появилось - файл, страница, число, набор | артефакт из факт-базы |
| F4 | живой пример с цифрой: что вышло у автора или у ученика | 🔴 **это и есть `scene` из `02b1`**: `who` + `did` + `number` + `result` дословно, улика `файл:строка` из `scene.evidence`. Другого источника у F4 нет: «живой пример», собранный не из карточки сцены, - это пересказ, он и породил класс единиц без живого слоя |
| F5 | знание, меняющее решение читателя СЕГОДНЯ: признак рабочего против нерабочего, или дословная формулировка, которую он скажет системе | факт-база; ручная работа запрещена (канон п.22) |
| F6 | ограничение: когда инструмент бесполезен | факт-база либо честное ограничение автора, не выдумка |

**Сборка (это и есть суть шага).** Шесть фактов выписываются в **одну цепь минимум из 5 звеньев**, где каждое следующее звено объяснено предыдущим словом причины в самом тексте («потому что», «из-за этого», «и тогда», «поэтому у меня»). Порядок фактов свободный - он диктуется причинностью, а не таблицей выше. Тест звена: убери его из середины - следующее перестаёт следовать? Да → звено. Нет → это пункт описи, цепь не собрана, возврат в `02d-components-options.md`.

🚫 **Ни одной рубрикаторной формулировки в тексте поста.** Запрещены как видимые обороты, заголовки, буллеты и зачины абзацев (список закрытый, пополняется каждым пойманным случаем):

```
«на вход» · «на выходе» · «вход:» · «выход:» · «что забрать сегодня» ·
«честная граница» · «что делают вместо этого» · «раньше/теперь» ·
«было/стало» как подзаголовок · «шаг 1 / шаг 2» · «итого» · «резюме»
```

Смысл соответствующего факта обязан быть закрыт, слово-ярлык - нет. Проверка перед фиксацией: прочитать собранную цепь и найти хоть один из оборотов выше. Нашёл → переписать звено через действие («кладу запись, к утру лежит 30 нарезок»), а не через ярлык.

Факта нет в факт-базе → ESCALATE (Шаг 4), место общей фразой не заполнять.

**По классам** (пороги, не выключатели - канон п.17, гейт 4.DENS в `04-review.md`):

| `form_class` | Сколько фактов из шести обязательно | Минимум звеньев цепи |
|---|---|---|
| `razbor` | 6 | 5 |
| прикладной `sales` | 5 (F6 может быть снят, если факта ограничения нет) | 4 |
| `event` (событийный) | 3, из них обязательно F2 и F4 - конкретика именно этого события | 3 |
| `narrative` | 2 (F4 + любой) - ценность нарратива в близости, не в инструкции (R3) | 3 |
| `gate` | 2 (F3 + F4) | 3 |

Цепь требуется от ВСЕХ классов - меняется только её минимальная длина. Ветка «класс не прикладной → шаг пропускается целиком» отменена: именно она давала событийным и нарративным постам выходить набором лозунгов (канон п.42).

## Шаг 4 - ESCALATE если нет real insight

**Hard gates:**

1. **< 3 candidates для mandatory V** → ESCALATE
   - «Под V<X> в факт-базе (`outline.factbase_path`) нашлось N candidates. Нужно ≥3. Принеси real case / Karta quote / corpus extract или пополни факт-базу (02b) или меняем tuple.»

2. **Для V4 case study нет real имени** (только «один ученик» / «парень») → ESCALATE
   - «V4 требует real имя + цифра. У candidate I<X> только generic. Дай имя или меняем insight.»

2а. **Ни один candidate не стоит на `scene`** (правило 0 Шага 2 нарушено) → это НЕ эскалация автору, а возврат в `02b1-scene-mining.md` за второй карточкой либо в Шаг 2 за переформулировкой I1. Спрашивать автора можно только тем вопросом и только оттуда, где источники добычи уже отработаны и показаны пустыми

3. **Все candidates Tier 3 только** (Распаковка facts без свежих cases) → WARNING
   - «Все candidates = aggregate facts, нет fresh case. Будет статистически верно но эмоционально пресно. Принести свежий case?»

4. **Insight конфликтует с Passport** (memory `feedback_verify_author_past_in_posts`) → ESCALATE
   - «Candidate I<X> предполагает что автор делал рилсы руками - это противоречит Passport (нейроописания за 1-5 мин). Использовать другой.»

5. **Insight конфликтует с banned cases** (memory `feedback_no_student_failure_quotes`) → ESCALATE
   - «Candidate I<X> = "ученик прошёл курс и не получил результат" - banned для лендинга/публичных постов. Исключить.»

Если ESCALATE → **остановить** до получения ответа автора. Не переходить в Шаг 5.

## Шаг 5 - Show candidates + ask автору какие берём

Output компактно в чат:

```
## Value-injection candidates (mandatory V = V<X>)

**I1** (Tier 1, RECOMMENDED)
- Что: <имя ученика> с 0 до $100K
- Source: gold-standard пост 8
- Verbatim: «$100K за <срок>»
- Куда: reveal anchor

**I2** (Tier 2)
- Что: «20К подписчиков и копейки»
- Source: corpus
- Verbatim: «20К vs копейки»
- Куда: открывающий контр-пример

**I3** (Tier 2)
- Что: «5 уведомлений за выходные»
- Source: Карта 5.2 канон #5
- Verbatim: «5 уведомлений за выходные»
- Куда: sensory detail в close

**I4** (Tier 3)
- Что: <число учеников> → <число> млн подписчиков
- Source: Passport
- Verbatim: «<число учеников>»
- Куда: authority в setup

**I5** (опционально, если уместно)
- Что: F-3 факап <сумма>- Source: Passport §1
- Куда: контраст «было vs стало»

Recommendation: **I1 + I2 + I3** (reveal anchor + контр-пример + close echo) - даёт V4 (mandatory) + V1 + sensory.

Какие берём (по need - количество диктует таблица классов Шага 3.5)?
```

**Recommendation rule (квота «2-3 обязательны» снята - берём по need):**
- Mandatory V обязательно покрыт (хотя бы 1 insight под mandatory)
- Количество берётся из таблицы классов Шага 3.5 (`razbor` 6 фактов / прикладной `sales` 5 / `event` 3 / `narrative` 2 / `gate` 2), не из произвольной цифры
- Собранные insights обязаны складываться в причинную цепь своей минимальной длины (Шаг 3.5), иначе это набор карточек, а не раскрытие
- Insights дают complementary V (не дублируют один тип)
- Distribution по integration_point: под реальную структуру поста, не «для галочки»

## Шаг 6 - Зафиксировать выбор

После ответа автора:

```yaml
outline.value_injections:
  - id: "I1"
    v_type: "V4"
    verbatim_source: "gold-standard пост 8"
    verbatim_element: "$100K за <срок>"
    integration_point: "reveal_anchor"
  - id: "I2"
    v_type: "V1"
    verbatim_source: "corpus extended"
    verbatim_element: "20К vs копейки"
    integration_point: "reveal_contrast"
  - id: "I3"
    v_type: "V1"
    verbatim_source: "Карта 5.2 канон #5"
    verbatim_element: "5 уведомлений за выходные"
    integration_point: "close_echo"

  delivered_value_vectors: ["V4", "V1"]  # ≥2 required by framework
  mandatory_v_covered: true
```

**Validation:**
- ≥2 уникальных V-types в delivered_value_vectors → PASS
- < 2 → return в Шаг 5 «нужен ещё один insight другого V-type»
- **Боль названа:** в `outline` записан `pain_ref` = `{quote, file, line}` из `scene.pain`, и хотя бы один value_injection работает на эту боль. Нет `pain_ref` либо боль сформулирована не дословно по карте → каркас не принят, возврат (см. красный блок Шага 2)
- **Заход не с кухни:** ни один injection с `integration_point: hook` не требует знания проекта, чтобы его понять. Требует → перенести в `reveal_anchor`, на заход поставить боль читателя
