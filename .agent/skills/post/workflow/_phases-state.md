## Пакетный state `.post-packet-по решению автора.json` (NEW по решению автора, дефект Д11)

🔴 **Зачем.** Обязательное чтение (канон голоса, канон формы v2 и канон правок, эталон поста, ячейка дня, банк смыслов, справочники приёмов) - свойство ПАКЕТА, а не единицы. При `brief.route = packet` (`01-router.md` Шаг 0.7-Р) оно выполняется ОДИН РАЗ, кладётся сюда, и единицы на него ССЫЛАЮТСЯ. Повторный `Read` того же файла внутри пакета - брак: он сжигает контекст и ничего не добавляет. До этой редакции такого поля не было, поэтому единственной честной моделью было «каждая единица гоняет все фазы с нуля» - её никто не исполнял (18 единиц дня написаны за 20 минут), и система жила фикцией.

🔴 **Путь:** `~/.claude/skills/post/.post-packet-по решению автора.json` (запуск - доп. в его папке, рядом с `.post-state-*`).

Схема:
```
{packet_id, date, channel, route: "packet", units: [<file_slug>, ...],
 day_cell: {источник, файл:строка, носители},
 market_senses: [...],            // 02b Шаг 3.5, фильтры 1-4 прогнаны один раз
 voice_selection: {...},          // 02d Шаг 0, выборка эталонов класса
 reads: {form_canon_v2, voice_canon, etalon_post, donor_devices, etalons_json,
         ai_tells, corpus_pattern_index, author_character_passport,
         value_types_framework, genre_value_jtbd_mapping, maxwell_ross,
         hook_story_offer, tg_engagement_layer, formatting_skeleton,
         post_performance_log, launch_money_layer, phase_files},
 rotation: {...},                 // .used-anchors.jsonl прочитан один раз на пакет
 closed_at}
```

**Как ссылается единица.** В `.post-state-по решению автора-<file_slug>.json` появляется корневой ключ `packet_id`, а обязательные чтения помечаются строкой `"packet:<packet_id>"` вместо `true`. Значения читаются так:
> - `"packet:<id>"` - файл прочитан на уровне пакета и переиспользован (штатно при `route: packet`);
> - `true` - единица прочитала файл сама (штатно при `route: full`; при `route: packet` - сигнал, что чтение продублировано);
> - `false` - не прочитано, брак в обоих маршрутах.

🔴 **Что пакет НЕ покрывает и остаётся на каждой единице:** своя строка носителя из ячейки дня · своя факт-база `.factbase-по решению автора-<file_slug>.md` (общая на пакет ЗАПРЕЩЕНА - она и есть источник выдуманных чисел) · тело · осушение `03-dry.md` · линт и хук-гейт · гейты класса (`4.0.2` Gate Evidence Report - свой отчёт на каждую единицу, ключ `mandatory_reads.donor_devices` при пакете печатается как `packet:<packet_id>`, `4.DENS`, `W15-цепь`, `4.ET`, `4.SUB`, `4.R`, `4.M.2`, `Humaniser`) · свой `.post-state-*` с `final: true`. Пакетный state не заменяет ни одного ключа L1-L5 и хуком не читается - хуки по-прежнему работают по state ЕДИНИЦЫ.

## State-файл `.post-state-по решению автора.json`
🔴 **Путь:** `~/.claude/skills/post/.post-state-по решению автора-<file_slug>.json` (запуск - доп. в его папке). Хук сканирует `$HOME`+`.business/запуски`+`skills/post`.

Схема: `{post_id, date, channel, launch_window, layer(1-5), phase, budget, factbase_path, factbase_created_at, draft_at, anchor, hero, lint_allow(опц.), L1{смысл,якоря,заголовок,контекст,тело,ценность,cta,money}, L2_voice, L3_mastery, dry_report, draft{density}, L4_empirics{...,form_mode{goal,class,profile,source},benchmark}, post, L5_review{linter,blueprint,concreteness,verifier,humaniser,layer3,sales}, slug, file_slug, final}`.

🔴 **Ключи, которые читает КОД, а не человек.** Хук `~/.claude/hooks/post-phase-gate.sh` не ищет строки-улики в транскрипте (подделываемы), а САМ запускает `lint-post.py` и `bench-post.py` по тексту из сообщения, забирая параметры отсюда:
> - `factbase_created_at` (`02b`) и `draft_at` (`02f`) - ISO-время. Факт-база обязана быть СТАРШЕ черновика: обратный порядок = «база собрана из готового поста», и AC5 сверяет пост сам с собой. Отметок нет → BLOCK.
> - `anchor` / `hero` (пишет `02d` Шаг 6.1) - уходят в `lint-post.py --anchor/--hero`, гейт дубля якоря и героя за 7 дней (класс R2-8).
> - `lint_allow` (опц., список) - 🔴 **ровно ОДИН флаг:** `--allow-skeleton-repeat=<причина>`, только с непустой причиной (штатная - повторная проверка уже выданного поста). Всё остальное → BLOCK «этот закон снять нельзя»: `--allow-em-dash`/`-end-period`/`-colons`/`-marathon`/`-perelivN`/`-no-premium-hook` снимают ЗАКОН канона, а закон правится каноном, не строкой в state. Применение флага печатается в stderr даже при exit 0.
>
> Плюс `channel` и `budget` в корне (или в `brief`) - по ним хук зовёт линтер; нет - дефолт `osn`, бюджет не проверяется.
🔴 Ключи L1-L5 старого контракта НЕ переименованы (AC11), новые только ДОБАВЛЕНЫ.

🔴 **ДВА РАЗНЫХ СЛАГА (разведены по решению автора) - не путать:**
> - **`slug`** - фрагмент ~40 симв. из ТЕЛА финала (не заголовка), кириллица с пробелами. Держит D3-привязку state↔текст (хук ищет его в выданном посте), скелет-журнал и маркер верификатора. Нет `slug` → BLOCK, чужой → BLOCK.
> - **`file_slug`** (NEW) - суффикс ИМЕНИ state-файла: ОДНО слово без пробелов, латиница/цифры/дефисы. У файла `.post-state-2026-08-04-antiban-osn.json` это `antiban-osn`. Именно он идёт в строку-улику формы (`слаг=<file_slug>`, `05-publish` Шаг 5 и `01-router` Шаг 0.49): по нему хук выбирает НУЖНЫЙ state, а не свежайший по mtime. Хук ищет сначала по имени файла, потом по ключу `file_slug` внутри свежих state-json. Слаг читается только из строки, начинающейся с `форма: цель=`.

`L3_mastery` = СПИСОК 13 ИМЁН, не «13/13» - хук проверяет каждую фамилию поимённо: `ogilvy sugarman caples halbert schwartz hopkins collier bencivenga kennedy ries bird schwab ilyahov`.
Каждая закрытая фаза заполняет свой ключ. Финал - только при L1-L4 + `dry_report` + post + L5_review + final=true.

## 🔒 МЕХАНИЧЕСКАЯ СТРАХОВКА — хуки `post-phase-gate.sh` (Stop) и `post-layer-checkpoint-gate.sh` (PreToolUse)
Методология выше мягкая, гарантию даёт ХУК (детали - в самих хуках):
- **`post-phase-gate.sh` (Stop).** Детектирует выдачу ЦЕЛЬНОГО поста по структуре → проверяет ключи state (L1 семь под-ключей + L2_voice + L3_mastery + `dry_report` + L4_empirics + post + L5_review ≠ null и final=true, иначе `exit 2`) → сам гоняет `lint-post.py` и `bench-post.py` по извлечённому тексту → TRUTH-CHECK: `humaniser` реально вызван; ответ верификатора несёт маркер со слагом и строку `ВЕРДИКТ:`. 🔴 **по решению автора:** маркер ищется ТОЛЬКО в `tool_result`, не в промпте; `ВЕРДИКТ: FAIL` = BLOCK выдачи.
- **`post-layer-checkpoint-gate.sh` (PreToolUse на Write в `.post-state-*.json`).** Слои `{L1, L2_voice, L3_mastery, L4_empirics, L5_review, final}`: за один Write нельзя закрыть >1 нового слоя. 🔴 `dry_report` он НЕ знает - его проверяет только Stop-хук.
- **Вместе:** PreToolUse держит РИТМ сборки, Stop - ПОЛНОТУ перед выдачей.

## Anti-patterns
- Считать «черновик» фазой (это результат слоёв 1-4 + осушения).
- Назвать фазы Слоя 1 «всеми фазами» (это под-фазы одного слоя).
- Бандл слоёв/фаз в один ответ; прыжок к финалу мимо слоёв или мимо `03-dry.md`.
- Сборка без Слоя 4 (эмпирика) → пост не сверен с реально заходящим в нише.
- Применять критерии «на ревью» — критерии это МЕТОД СБОРКИ (Слои 1-4 + осушение), ревью только проверяет.
- Осушение как срезание вещества, не воды — `03-dry.md` сверяется с `factbase_path`, иначе сжатие = потеря фактов.
