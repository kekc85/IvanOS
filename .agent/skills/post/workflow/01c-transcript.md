# Workflow 01c - Mode C: Transcript (надиктовка)

**Назначение:** разобрать длинный неструктурированный текст автора в атомарные смыслы и выбрать top-1-3 для постов.
**Входы:** `brief.mode = "transcript"` + длинный текст (> 500 символов)
**Выходы:** `brief.topic`, `brief.angle`, `brief.source = "transcript"` + опционально queue остальных смыслов
**Следующая стадия:** `workflow/01-finalize.md`

**Когда применять:** автор надиктовал/написал поток мыслей, и оттуда надо вытащить готовые смыслы. Это **самый безопасный mode** - смысл уже от автора, нет риска AI-slop.

---

## Шаг 1 - Принять весь текст

Сохранить полный текст в `brief.raw_transcript`. Не обрезать, не редактировать.

Если текст пришёл частями - собрать все в один блок.

---

## Шаг 2 - Извлечь атомарные смыслы

Разбить транскрипт на **атомарные тезисы** - единичные мысли, каждая из которых может стать самостоятельным постом.

**Правила атомарности:**
- Один смысл = одно опровержимое утверждение или одно конкретное наблюдение.
- Не объединять связанные идеи в один смысл («ИИ меняет работу + ученики растут» = два смысла).
- Не разбивать одно утверждение на куски («рынок инфопродуктов» + «меняется» = один смысл).
- Минимум 3, максимум 10 смыслов на транскрипт. Если больше 10 - текст слишком сырой, попросить пользователя сузить.

**Что НЕ выделять как смысл:**
- Вводные фразы («так, я думаю что», «короче»).
- Повторы одной мысли разными словами - оставить одну формулировку.
- Метакомментарии («это надо записать в пост», «вот про это надо написать»).

### Формат извлечения

Для каждого смысла - два поля:
- `raw_quote` - точная цитата из транскрипта (1-3 предложения)
- `essence` - одна фраза, передающая суть (своими словами)

---

## Шаг 3 - Сгруппировать близкие смыслы

Если два смысла говорят почти об одном - объединить, оставив лучшую формулировку из автора.

---

## Шаг 4 - Оценить каждый смысл по 3 критериям

Для каждого смысла дать score 1-3 по:

1. **Дефицитность** - насколько редкая мысль в публичном поле (3 = почти никто так не говорит, 1 = общее место).
2. **Личная привязка** - насколько смысл укоренён в опыте автора (3 = только автор мог это сказать, 1 = универсальная мысль).
3. **JTBD-релевантность** - закрывает ли работу из `paths.jtbd` (3 = прямо закрывает, 1 = тангенциально).

**Total score:** сумма (3-9).

---

## Шаг 5 - Показать пользователю top-N

Отсортировать по total score (по убыванию). Показать top 3-5.

Формат:

```
Из надиктовки я вытащил <N> смыслов. Топ:

1. [score 8/9] <essence>
   Цитата: «<raw_quote>»
   Дефицитность: 3 / Личная привязка: 3 / JTBD: 2

2. [score 7/9] <essence>
   Цитата: «<raw_quote>»
   ...

3. [score 7/9] <essence>
   ...

Какой берём в пост? (номер)
Или: «все три» - поставлю в очередь по одному.
```

---

## Шаг 6 - Зафиксировать выбор

### Вариант A - пользователь выбрал один номер

Записать:
- `brief.topic = <essence выбранного>`
- `brief.angle = <essence> (детализация через raw_quote)`
- `brief.source = "transcript"`
- `brief.raw_quote = <цитата>`

→ Перейти в `workflow/01-finalize.md`.

### Вариант B - пользователь сказал «все три»

Создать **очередь постов**: первый смысл идёт в текущий run скилла, остальные - сохранить в `~/.claude/skills/post/queue.md` в формате:

```markdown
## Queue (created YYYY-MM-DD HH:MM, from transcript)

- [ ] Смысл 2: <essence> | quote: «...»
- [ ] Смысл 3: <essence> | quote: «...»
```

**Потребитель очереди именован (по решению автора, дефект Д11 - сирота закрыта):** `workflow/01a-plan.md` Шаг 5 пункт 2 читает этот файл условно (`[-f]`), предлагает непомеченные строки `- []` первым вариантом и отмечает взятый смысл `- [x]`. До этой редакции здесь стояло «Mode A может проверить», а в `01a-plan.md` слова `queue` не было вовсе - файл писался и не читался никем.

→ Текущий run продолжает с первым смыслом.

## Anti-patterns

- **Пересказ вместо цитаты.** `raw_quote` - точная фраза автора, не интерпретация (memory `feedback-verbatim-quote-transfer`).
- **Выкидывание «странных» смыслов.** Иногда самое сильное - то, что кажется неуместным. Score 9/9 редко даётся очевидным.
- **Слипание похожих в один - не доводить до абстракции.** Если две мысли близки, но обе сильные - лучше оставить две и сделать серию.
- **Score без обоснования.** Каждая оценка должна быть проверяема против `avatar.md`/`jtbd.md`.

---

## Принципы Mode C

1. **Транскрипт - это сырьё, не финал.** Извлечение → выбор → пост, а не «причеши и опубликуй».
2. **Голос автора уже встроен.** Цитата сильнее парафраза, потому что в ней лексика автора.
3. **3-9 атомов из одной надиктовки - норма.** Один транскрипт = серия постов, не один пост.
4. **Queue - это память между сессиями.** Не закрытые смыслы не теряются, они в `queue.md`.

## PII Safety Note (NEW v3.0)

авторская надиктовка может содержать PII (имена клиентов / суммы / контакты / private events). Перед использованием extract атомарных смыслов сделать regex-pass:

```python
pii_patterns = [
    r'\b\d{10,12}\b',                    # phone numbers
    r'[\w.-]+@[\w.-]+',                  # emails
    r'\$\s?\d{1,3}([,.]?\d{3})+',        # large $ amounts
    r'\b(имя|зовут|клиент|ученик)\s+[А-ЯA-Z][а-яa-z]+',  # named individuals
]
```

Если match найден → WARN в чат: «Найден потенциальный PII: <pattern>. Заменить на обезличенное (например "один из учеников" / "клиент" / "знакомый") или подтвердить разрешение публиковать verbatim».

Для post skill stylistic generation, по умолчанию anonymize. Если автор explicit подтверждает «оставить verbatim X» - оставить.
