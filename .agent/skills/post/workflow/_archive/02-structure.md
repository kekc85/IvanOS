## Шаг 2 - Detect mode (если brief.type = 'detect-in-02')

Если type уже определён в stage 01 - пропустить шаг 2.

Если type = unknown / detect-in-02 - применить decision tree:

**Decision tree:**

1. Есть ли news / crisis / incident в topic? («баг», «вышло», «случилось», «обвалилось», «новость», «закрылось»)
   → `short-situational` + hook modifier «crisis» (pattern interrupt, urgency)

2. Есть ли «как / framework / метод / система / распаковка / разбор / process / 7 шагов / urok» в angle?
   → `long-educational`

3. Это daily musing / observation / случайная мысль («сижу думаю», «заметил», «прикольный момент»)?
   → `short-situational`

4. Personal story / reflection / values («моя ошибка», «понял что», «жизненный момент», «отношения»)?
   → `personal-reflection`

5. Show progress / build / metrics / launch update («запустил», «cделал», «в работе», «MRR», «учеников»)?
   → `build-in-public` (v2 - если не доступен, fallback `short-situational`)

6. Анонс конкретного tool / app / mini-product?
   → `tool-drop` (v2 - если не доступен, fallback `short-situational`)

7. Sales-окно открыто? (user указал явно или sales context)
   → `sales-launch` (v2 - если не доступен, fallback `long-educational`)

8. Очень короткая мысль, one-liner?
   → `tweet` (v2 - если не доступен, fallback `short-situational`)

**Default fallback:** `short-situational`.

**Записать:** `brief.type = <detected>`.

## Шаг 5 - Структура поста ПО КАНОНУ (_voice-TEMPLATE.md)

> **ИСТОЧНИК ИСТИНЫ — `references/_voice-TEMPLATE.md` (КАНОН).** Структура поста = Заголовок (Шаг 6) → Контекст (5.1) → Примеры/истории (5.2) → Ценность (5.2) → CTA (5.3). НЕ Брансон-HSO, НЕ generic-scaffold. Прочитать канон разделы 1, 3, 4, 5, 6 перед планированием.

> 🔴 **КАРКАС — ОДИН ЧЕКПОИНТ СОГЛАСОВАНИЯ (см. `_phases-state.md` Слой 1, NEW по решению автора).** Заголовок (Шаг 6), Контекст (5.1), Ценность (5.2 Часть Б = «мясная»/полезная часть, ради чего читают) и CTA (5.3) НЕ зависят друг от друга → планируются здесь, но предъявляются автору ВМЕСТЕ, одним сообщением, под ОДИН ✋-апрув (не 4 итерации подряд). Контекст выносить на согласование явно (тип захода + готовый абзац). Тело (5.2 Часть А, примеры/истории) пишется в `03-write` ТОЛЬКО после апрува каркаса.

### 5.1 - Plan Контекст (первый абзац после заголовка, 1 из 7 типов захода)

Контекст продаёт желание читать дальше. Берётся ОДИН из 7 типов захода (КАНОН раздел 3):
1. ВРЕМЯ И МЕСТО · 2. ЗАХОД (прямой) · 3. ПОДЗАГОЛОВОК-ИНТЕРЕС · 4. ЦИТАТА · 5. АНЕКДОТ/ПРИМЕР · 6. ЛИЧНАЯ СИТУАЦИЯ · 7. ПРОВОКАЦИЯ

**Правила:**
- Тип контекста должен ОТЛИЧАТЬСЯ от последних 5 постов (line-правило, КАНОН раздел 7 + `01-finalize` line-check). Эффект новизны = дофамин.
- Опереться на примеры вербатим под выбранным типом в каноне (раздел 3) — как именно звучит заход.
- Якорь — реальная сцена/инфоповод из `config.story_bank` / `config.content_map`, не выдумка.

**Записать:** `outline.context_plan = {type: "<1 из 7>", text: "<готовый первый абзац>"}`.

### 5.2 - Plan Тело: Примеры/истории (60-70%) + Ценность (20-30%)

**Часть А — Примеры и истории (база, ~60-70% объёма, КАНОН раздел 4):**
- Инфоповоды из жизни автора ЛИБО истории о сотрудниках/клиентах/конкурентах (обезличенные)
- Триггерят сильные эмоции
- Динамика туда-сюда, нелинейно, с твистами. Запрещено «пришёл-увидел-победил»
- Драматургия — 1 тип из КАНОН раздела 12, отличный от последних 5
- **Receipts / Evidence (универсально, все платформы; поглощено из HubSpot v4.1):** хотя бы один **реальный** конкретный пруф — число / результат / скрин / имя / срок. Без него пост читается как ИИ-обобщение. Specificity = credibility: «26 986 подписчиков» / «за 3 недели» > «много» / «быстро». ⚠️ Пруф ТОЛЬКО настоящий: нет реального → context-gap gate, НЕ выдумывать и НЕ округлять (КАНОН раздел 0, Слой 1).

**Часть Б — Ценность (микро-польза, ~20-30%, финальная треть, КАНОН раздел 5):**
- Инсайт / пошаговый план / лист / система
- Внедряется немедленно, результат за 24 часа
- Настолько ценно, что читатель готов заплатить 500₽
- Даёт уверенность в успехе
- Боли/желания читателя — из распаковки (`config.paths.avatar` + `objections`)

Привязать к `brief.angle` — всё работает на одну главную идею.

**Пропорция по `brief.form_goal` (канон формы v2, канон-правка §8.2 «4.B.3 истории/ценность»).** Пропорция 60-70% истории + 20-30% ценности выше - **дефолт цели `reactions`** (оба её класса: нарратив и разбор). При объявленной иной цели: **`forwards`** - другая пропорция (выжимка 50-70% объёма) и другой критерий ценности - не «внедрение за 24ч», а **переносимость** (можно ли переслать этот кусок как самостоятельную пользу третьему лицу, канон §3.2 «замкнутый контур передачи»); **`gate`** - пропорция не применяется вовсе, пост-инструмент устроен по чек-листу §9 режим A, а не по историям и ценности. Пока `brief.form_goal` пуст - пропорция 60-70/20-30 остаётся дефолтом для всех постов, как сегодня.

**Записать:** `outline.story_plan = {examples: "<план историй с твистами>", value: "<микро-польза на 24ч>"}`.

### 5.3 - Plan CTA (КАНОН раздел 6 + TG-engagement слой, NEW v5.1)

> 📈 **HARD read для telegram-платформ:** `Read(references/tg-engagement-layer.md)` — CTA-лестница и механики по ЖИВЫМ данным (корпус 314 постов конкурентов + свой журнал). Выбор CTA обосновать по лестнице (разделы 1, 4): тизер-следующего 1.40x > реакция-голосование 1.17x (не чаще 1 раза на ~5 постов, сверить с последними постами канала) > вопрос-в-комменты 1.14x > без CTA 1.08x > ссылка 0.96x. «Рега/продажа» вне окна запуска НЕ ставится (0.87x, анти-топ корпуса).

**Ветвление CTA по `brief.form_goal` (канон формы v2, канон-правка §8.2 «CTA-лестница»).** Когда цель объявлена (Шаг 0.49 роутера), лестница выше применяется НЕ целиком ко всем целям, а по ветвям:
- **`reactions` (реакции)** — лестница как есть, без изменений (тизер > реакция-голосование > вопрос > без CTA > ссылка).
- **`forwards` (репосты)** — ссылка становится ВЕРХНЕЙ ступенью и ОБЯЗАТЕЛЬНА (канон §3.2: ссылка есть у 92% верха против 31% низа, ссылка в последних 250 знаках у 80% верха). Это прямо переворачивает место ссылки в лестнице цели `reactions`, и делается сознательно.
- **`sales` (продажа)** — по правилу 4.S.1 (`04-review.md`): финал не URL, CTA обосновывается Слоем 0 и Sales Gate.
- **`gate` (реакция-гейт)** — CTA = числовая просьба о реакции, см. анти-паттерны ниже.

Пока `brief.form_goal` пуст - лестница применяется целиком ко всем постам, как сегодня.

- Вопрос для вовлечения (не больше 1), с псих-триггером, на который реально хочется ответить
- ИЛИ тизер следующего поста («завтра расскажу… X»)
- ИЛИ реакция-голосование: выбор через 2 эмодзи («ставь 🔥 если…, 🐳 если…») — сильнейшая механика ER по данным (слой, раздел 4.1), беречь от выгорания

**Анти-паттерны:** «жми ❤️» / «подпишись если зашло» / «делитесь в комментариях» / «приходи на <твоё событие>» (если не sales) / реклама курса отдельной строкой. **Исключение (канон формы v2, §7 и §9 режим A):** при `brief.form_goal = "gate"` (буква улики A) числовая просьба о реакции («Накидайте 70 🔥», «150 🔥 и…») - не анти-паттерн, а ТЕЛО поста: число кратно 10 из набора {10,20,30,40,50,70,100,150}, приз - только контент, срок выдачи назван явно (полный чек-лист - канон §9 режим A). Вне цели `gate` запрет остаётся прежним.

> 💰 **При `brief.launch_window = true` (NEW v5.0)** правила CTA перебиваются Слоем 0 (`references/launch-money-layer.md` + `templates/sales-launch.md`): CTA = ЕДИНСТВЕННОЕ действие регистрация, кнопка-ссылка + практ-ремарка курсивом; вопрос-вовлечение/коммент-вопрос на лончевом ЗАПРЕЩЁН; в CTA-блок включить «почему сегодня» из боевой карточки (строка 5 — реальный факт: счётчик/дата эфира). Проверяется Sales Gate 4.S. **TG-слой при этом применяется к УПАКОВКЕ, не к действию (NEW v5.1):** носитель = личная история/сцена с регой внутри, не анонс с кнопкой — продающие со сценой 0.97x против 0.86x без, «живой голос» без сцены продающий пост НЕ спасает (0.58x). См. слой, раздел 2.

**Записать:** `outline.offer_plan = <готовый текст CTA>` + `outline.cta_ladder = {choice: "<ступень лестницы>", why: "<обоснование по слою>"}`.

3. **TG-адаптация:** на ТЫ, первая строка ≤ ~10 слов RU, без em-dash внутри строки, без «Instagram» (→ Нельзяграм). Заголовок = первая строка поста (TG не имеет title-поля), показывается превью в ленте.

## Шаг 5.LI - Platform-aware headline rule (NEW v3.0)

**Применяется когда `brief.combo.platform == "linkedin"`.**

LinkedIn headline = первые 1-3 строки (нет отдельного title field, hook = preview перед "see more"). Validated synthesis Section 5 (Donnelly rule).

**Hook spacing rule:**
- Line 1: ≤62 chars (автор target: 45-58)
- Line 2: ≤62 chars (автор target: 35-55)
- Line 3: ≤50 chars (автор target: 25-40)
- Fold перед 210-char "see more" cutoff
- Line 3 заканчивается на завершённое предложение (НЕ оборванное)

**Pattern (validated 24/29 авторов):** Numbered Framework Promise - `[Number] [adj] [units] [for/to] [outcome]:` (для tactical/how-to). Use odd numbers 3/5/7/9 (Donnelly explicit, avoid 10/100 = generic-AI).

**Альтернативы для headline (synthesis Section 2 top-10):**
- Contrarian / Pattern-Interrupt (22/29) - для category creation
- Result-First / Specific Number (20/29) - ТОЛЬКО с verifiable Ivan numbers
- Vulnerable / Story-Time Confession (15/29) - для pillar-credibility posts
- Story-Opener / Scene-Setter (13/29) - для case-study workflow demos
- Named Framework Reveal (8/29) - для category-creation moves (coin 1-2 max)

**Anti-patterns для автора LinkedIn headline:**
- ALL CAPS hooks (Bolis/Taha pattern) → fail
- "In today's fast-paced..." (Dunford explicit killed) → fail
- Generic numbers 10/100 → fail
- Faked $ amounts (US-validated numbers автора пока нет) → fail
- Celebrity name-drop (MrBeast/Hormozi/GaryVee) → fail в первые 6 месяцев EN
