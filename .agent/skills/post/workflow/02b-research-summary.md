Research summary = **input pool для tuple-choice / components / value-injection**. Все 3 следующих стадии (02c / 02d / 02e) опираются на этот summary. Если summary пустой или generic - вся co-creation lane вырождается в guessing.

## Шаг 3.5 - Банк смыслов рынка (Радар, NEW по решению автора, план v3 подэтап 4g)

**Зачем.** Контур «Радар конкурентов» (`konkurent-radar`) накапливает подтверждённые смыслы рынка отдельно от Карты 5.2 - это внешний срез (что говорят конкуренты), не внутренний (что знаем о себе). Без чтения здесь банк остаётся мёртвым капиталом: собран, но ни один writer-скилл его не открывает.

🔴 **ВЕТКА ДЕГРАДАЦИИ: банка нет.** `Read .business/growth/analytics/Радар/senses_index.md` УСЛОВНО (`[ -f ]` первым делом - это скилл раздаётся ученикам, у которых радар мог не запускаться никогда). Файла нет / путь не резолвится → пометить `market_senses: N/A (банка нет)` и идти в Шаг 4 как обычно. Это законная деградация, не блокер: банк - бонусный источник, не обязательный (в отличие от Карты 5.2 и Распаковки, у которых своя ветка деградации на интервью).

**Файл есть → отбор фильтром (все поля - штатные колонки банка, ничего не выдумывается):**

1. **Зрелость = «рыночный смысл»** - читается из колонки «сила» (тройная лестница банка: сигнал / гипотеза / рыночный смысл). Только этот уровень банк сам считает готовым к отстройке («Только от него полноценная отстройка и контент» - шапка файла); сигналы и гипотезы пропускаем, даже если у сигнала громкая реакция.
2. **Статус = «свежий» ИЛИ «в работе»** - читается из колонки «статус» (четыре штатных значения: свежий · в работе · выдыхается · мёртвый). «выдыхается»/«мёртвый» отсекаем.
3. **Наш ответ есть в каноне** - в колонке «ось + полюс рынка + наш полюс» после «мы → » стоит содержательный текст, а не «нет пары» (сама банка помечает так строки без отстройки). Пусто/«нет пары» → смысл не проходит, независимо от зрелости.
4. **Не использован за последние 7 дней** - `Read .business/growth/analytics/Радар/senses_usage.jsonl` УСЛОВНО (`[ -f ]`; файла ещё может не быть - это законно, значит использований пока нет). Для каждого смысла, прошедшего пункты 1-3, проверить: есть ли запись `{sense_id: <id>, date: ...}` с `date` в пределах последних 7 дней от сегодня. Есть → смысл временно выбывает из пула (не повторяем один и тот же угол неделю подряд), берём следующий по списку.

5. 🔴 **ПРОИСХОЖДЕНИЕ ЯКОРЯ (HARD, скептик Р3 находка 2, по решению автора)** - фильтры 1-4 читают колонки того же файла, поэтому сами по себе кругóвы: строку в банк мог вписать агент, и он же на неё сошлётся. Пятый фильтр выносит проверку ЗА пределы банка - в дампы радара (сырые посты каналов, их собирает `radar_pull.py`, агент их не пишет).

   Взять якорь смысла - `t.me`-ссылку из колонки «первое появление» - и проверить дословно:

   ```bash
   RADAR_DIR=.business/growth/analytics/Радар
   grep -rF '"<якорь>"' "$RADAR_DIR/dumps/" | head -2   # якорь В КАВЫЧКАХ: в дампах поле "url": "…"
   ```

   **Показать вывод grep в чат.** Правило приёмки:
   - ≥1 совпадение → смысл подтверждён дампом, идёт дальше (в факт-базу пишем `якорь подтверждён: <файл дампа>`)
   - **0 совпадений → смысл ОТБРАСЫВАЕТСЯ** с пометкой «якорь не подтверждён дампом», берём следующий по списку. Не «ослабить», не «взять с оговоркой» - выбросить: непроверяемый якорь и есть тот самый круг.

   Кавычки обязательны: без них `…/238` ловится в `…/23811`. Это ровно та проверка, которой не хватало: выдуманный `https://t.me/<канал>/9999` даёт 0 совпадений и не доезжает до поста.

   ⚠️ **Ветка деградации: дампов на машине нет** (`[ -d "$RADAR_DIR/dumps" ]` = false; каталог эфемерный, в git не попадает, у ученика его может не быть никогда). Тогда смысл идёт с пометкой **UNVERIFIED** и работает ТОЛЬКО как смысловая рамка: **его числа (сколько авторов, сколько недель, охват) запрещено переносить в факт-базу Шага 4.5 и, значит, употреблять в посте.** В факт-базу пишется строка `смысл рынка: <…> · спрос: UNVERIFIED (дампов нет) · наш угол: <…>` - без цифр. Молча деградировать до «числа как есть» нельзя.

**Выбор конкретного смысла под пост** - та же topic-эвристика, что в Шаге 1 (semantic match `brief.topic` ↔ поле «смысл» банка). Из прошедших фильтр смыслов взять тот, чья ось ближе всего к теме поста.

## Шаг 4.5 - Факт-база файлом (AC5, HARD GATE, корень №1 фидбэка владельца)

🔴 **Корень.** владелец (память `feedback_post_no_water_no_evaluative_labels_ilyahov.md`): «если не было контекста, то ты склонен выдумывать всякую хуйню, чтобы хоть что-то написать». R2 класс 3 (огрызок - объём/глубина не добраны) и класс 4 (выдуманные факты) закрываются одним и тем же файлом: пока контекст живёт только в саммари в голове модели, его нельзя измерить кодом и нельзя отличить от выдумки постфактум.

**Что писать.** Собрать ВСЕ факты/якоря/цифры/имена, найденные в Шагах 1-3 (`karta_sections`, `gold_standard`, `case_studies`) плюс любые дополнительные факты, встреченные при чтении source-файлов, построчным реестром в файл:

`~/.claude/skills/post/.factbase-<YYYY-MM-DD>.md` (несколько постов в день → суффикс `-<post_id>`, тот же принцип, что у `.post-state-по решению автора.json`)

```markdown
# Факт-база: <brief.topic>

## Боль читателя (обязательный раздел, NEW по решению автора)
- «<дословная формулировка боли из блока «Болит» карты смыслов>» - источник: <карта-смыслов>:98

## Карта смыслов
- «5 уведомлений за выходные» - источник: <карта-смыслов>.html:142

## Gold-standard / corpus
- <имя ученика> с 0 до $100K за <срок> - источник: examples/_TEMPLATE.md:88 (пост 8)

## Case studies / Распаковка
- <факт> - источник: .business/Распаковка бренда.md:210

## Прочее (story-bank, логи сессий, voice-corpus)
- <факт> - источник: <файл>:<строка>
```

Каждая строка = факт + `источник: файл:строка`. Факт без строки-источника в файл НЕ идёт - это и есть периметр «АБСОЛЮТНОГО ЗАПРЕТА ВЫДУМКИ» (`_phases-state.md` п.0), примененный на уровне сырья, а не готового текста.

🔴 **Раздел «Боль читателя» обязателен и стоит первым (NEW по решению автора, второй корень фидбэка владельца).** Минимум одна ДОСЛОВНАЯ формулировка боли из блока «Болит» карты смыслов (`config.paths.content_map`) с уликой `файл:строка`. Формулировка своими словами и абстракция («страх технологий», «нехватка времени») не принимаются: их нечем проверить и они не попадают в язык читателя. Раздел пуст - в `02b1` не переходить, факт-база не закрыта. Дальше эта же боль обязана стоять в поле `scene.pain` карточки сцены и в каркасе поста (`02e`, Шаг 2).

**Входной гейт (измеряется кодом).** Объём факт-базы в знаках (без служебных markdown-заголовков `#`/`##`) обязан быть **≥ `brief.budget`** (цель длины поста из канона §3, записана в `01-router.md` Шаг 0.49). Числу верить только измеренному: это меряет `scripts/lint-post.py --factbase-only <outline.factbase_path> --budget <brief.budget>` (Z1, AC5; режим без позиционного файла поста - на этой фазе поста ещё нет, сравнивать нечем; функция `factbase_body_len` выбрасывает строки, начинающиеся с `#`, - метод очистки ровно тот, что описан здесь), не на глаз.

🔴 **Уровни разные, не путать.** Линтер на дефицит печатает **WARN** «факт-база меньше бюджета - риск воды»: решение «добрать или понизить цель» принимает человек здесь, в 02b, а не скрипт. HARD в линтере остаётся один - объём факт-базы против длины ГОТОВОГО поста (AC5а). А вот запрет писать пост при непокрытом дефиците - **HARD на уровне фазы**, это прямой закон автора (ниже), и WARN линтера его не отменяет.

- **Объём ≥ budget** → PASS. Записать `outline.factbase_path = "<путь к файлу>"`, идти в Шаг 5
- **Дефицит** → ровно два легальных выхода:
  1. **Добор** из перечисленных источников: `config.paths.story_bank` (банк историй; у автора это `.business/story-bank/` - путь `.business/growth/story-bank/` до этой редакции стоял здесь ошибочно, такой папки на диске нет и `ls` по ней всегда падал), карта смыслов (доп. секции, не только уже выбранные), `config.voice_canon.voice_corpus_dir` (corpus фактов автора), логи прошлых сессий (`config.paths.retrospectives_dir`, память `feedback_*`/`project_*` по теме)
  2. **Снижение цели** - явно спросить автора одной строкой обоснования («под тему X контекста меньше среднего, предлагаю budget Y вместо Z») и понизить `brief.budget`, а не молчать
- 🔴 **Писать пост при дефиците ЗАПРЕЩЕНО.** Это прямой закон владельца, не эвристика оптимизации. Переход в 02c с непокрытым дефицитом = брак маршрута, по тяжести равный пропуску Шага 0.49 роутера

🔴 **ОТМЕТКА ВРЕМЕНИ `factbase_created_at` (ОБЯЗАТЕЛЬНО, NEW по решению автора).** В тот же момент, что и `factbase_path`, записать в state корневой ключ `factbase_created_at` = ISO-время окончания сборки базы (`date '+%Y-%m-%dT%H:%M:%S'`, брать РЕАЛЬНОЕ время командой, не писать от руки).

Зачем. Есть класс брака, который все проверки AC5 не видят по устройству: сначала пишется пост, а потом под него задним числом собирается «факт-база». После этого «каждое число поста есть в факт-базе» выполняется всегда - пост сверяется сам с собой, и гейт превращается в зеркало. Машинный признак обратного порядка один: факт-база МОЛОЖЕ черновика. Поэтому `02f-polish.md` симметрично пишет `draft_at`, а код-гейт `post-phase-gate.sh` при выдаче требует `factbase_created_at` < `draft_at` И mtime самого файла базы не позже `draft_at`. Отметок нет → выдача блокируется: доказать порядок нечем.

Файл базы после этого момента правится только на добор контекста (легальный выход «Добор» выше) - и тогда отметка перезаписывается ВМЕСТЕ с фактическим пересбором, до возврата в написание, а не после.

🔴 **Реальность - не понятность (NEW по решению автора).** Фаза `02b1` с этой даты меряет сцену дважды: реальна (улика резолвится) И понятна (пересказ для новичка + боль из карты болей + допуск по каналу). Порядок источников там перевёрнут - первыми люди и их результаты, рабочие журналы (`retrospectives/`, `plans/`, логи) последними и только с переводом. Факт-база не должна тянуть сюда внутреннюю кухню проекта как «контекст объёмом»: знаки она добирает, а гейт понятности потом валит всю единицу.

🔴 **Объём - не сцена (NEW по решению автора, корень дефекта «47 из 139 единиц без живого слоя»).** Этот гейт меряет знаки, и знаки прекрасно набираются тезисами карты, определениями механик и производственными решениями. Замер на боевом корпусе: у 10 единиц пакетов при PASS по объёму в теле 0-2 числа и 0-1 названный артефакт, у 4 эталонов автора - 11-21 число и до 14 артефактов. Поэтому сразу за этим шагом идёт отдельная фаза `02b1-scene-mining.md`: она добывает КОНКРЕТНЫЙ ЭПИЗОД (кто · когда · что делал · цифра · что сломалось · что получилось · улика `файл:строка`) и без него не пускает дальше. Объёмный гейт её не заменяет и не отменяет.

**Куда пробрасывается.** `outline.factbase_path` кладётся в state и передаётся БЕЗ ИЗМЕНЕНИЙ через **02b1** → 02c → 02d → 02e → 02f → **03-dry** → **04-review**. `03-dry` использует его для проверки, что каждое число/имя не потерялось и не подменилось при сжатии (осушение не имеет права дописывать факты). `04-review` (`lint-post.py --factbase <file>`) проверяет то же самое на финальном тексте - каждое число/имя из поста присутствует в факт-базе, иначе HARD FAIL «выдуманный факт» (AC5 (б)(в)).

## Шаг 5 - Flag missing data (HARD GATE)

**ESCALATE условия (стоп → спросить автора):**

1. **V4 case study required** (по genre G1/G5) И **нет real имени + verifiable цифры** в Распаковке/gold-standard/corpus
   → «Нужен real case под тему <X>. Какой кейс ученика берём? Имя + цифра + механика.»

2. **Genre = G2 vulnerability+reveal** И **нет real факапа автора** в Passport / Распаковке под тему
   → «Под жанр vulnerability нужен real факап. Используем F-3 (<сумма> ₽) или есть свежее?»

3. **Topic про конкретный продукт / запуск / sales-window** И **нет данных о цене/сроках/механике** в brief
   → «Sales-launch требует цена + срок + механика. Где они?»

4. **Topic про конкретный tool / app / mini-product** И **нет ссылки / скрина / описания** что именно
   → «Tool-drop требует имя tool + что делает + где взять. Что показываем?»

5. **Karta sections + gold-standard + case studies все пустые** (3 source pool = 0)
   → «По теме <X> в Карте / gold-standard / Распаковке ничего нет. Уточни угол или принеси material.»

Если ESCALATE - **остановить конвейер**. Не переходить дальше. Ждать ответ автора → дополнить summary/факт-базу → продолжить.

Если все checks PASS → переход в **`02b1-scene-mining.md`** (добыча сцены, HARD GATE), и только оттуда в `02c-tuple-choice.md`. Прыгать из 02b сразу в 02c запрещено: без карточки сцены единица уходит в производство пустой, это корень №1 брака пакетов.
