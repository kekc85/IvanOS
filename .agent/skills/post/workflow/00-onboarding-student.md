# Workflow 00 - Onboarding (для ученика, первый запуск)

**Назначение:** провести нового пользователя (ученика) от «клонировал скилл» до «config.md заполнен, можно запускать /post».
**Триггер:** Router (`01-router.md`, Шаг 0) обнаружил отсутствие `config.md` ИЛИ обнаружил `config.md` с placeholder-значениями (`<active-launch>`, `<your-handle>`, etc.).
**Выход:** заполненный `config.md` + переход в `01-router.md`.

**Когда применять:** только при первом запуске скилла под новый проект. После заполнения config - этот файл не вызывается.

---

## Шаг 0 - Объяснить что это

Перед чем-либо - короткое сообщение пользователю:

```
Привет. Это первый запуск скилла post под твой проект.

Скилл универсальный - он будет работать с тобой так же, как с автором,
но ему нужен контекст ИМЕННО твоей аудитории и продукта. Сейчас мы это настроим.

Если у тебя есть готовый запуск по методологии автора (фазы 0-3), большая часть
файлов уже у тебя есть - я их найду и подцеплю. Если ты ещё не делал запуск -
часть полей будет пустой, и скилл будет работать в режиме «без карты смыслов»
(только Mode B и Mode C). Это нормально для старта.

Поехали.
```

---

## Шаг 1 - Проверить дерево проекта

Прочитать структуру корня (текущий working directory):

```
ls -la
ls -la .business/ 2>/dev/null
```

Определить:
- Это репо с готовой структурой `.business/`? (как у автора)
- Это пустой проект?
- Это что-то третье (другая структура папок)?

---

## Шаг 2 - Собрать обязательный минимум

Запросить у пользователя **5 обязательных полей**. Идти **последовательно, по одному вопросу за раз**, не списком.

### 2.1 Имя автора и канал

```
Q1: Как тебя зовут (как ты подписываешься в публичных постах)?
Q2: Какой у тебя TG-канал (handle или URL)? Если ещё нет - ответь «нет».
```

→ Записать `subject.name`, `subject.channel_handle`, `subject.channel_url`.
→ Если канала нет - `recent_posts_source: none`.

### 2.2 Аватар читателя

```
Q3: Опиши свою аудиторию в 2-3 предложениях.
Кто это, что они делают сейчас, чего они хотят?
```

→ Записать ответ во временный файл `intake/avatar.md`. Предложить позже довести его до полноценного `avatar.md` по фазе 0.2 запуска.

Альтернатива: если у пользователя уже есть `avatar.md` в его проекте - спросить путь к нему вместо текстового ответа.

### 2.3 JTBD (что покупают)

```
Q4: За какой результат тебе платят / собираются платить?
Не «контент-курс», а конкретная работа: «первые 100К на онлайн-продукте»,
«поставленный канал в TG за 30 дней», «выход на 500К/мес без выгорания».
```

→ Записать в `intake/jtbd.md`.

### 2.4 Продукт

```
Q5: Что у тебя сейчас продаётся (или будет продаваться)?
- Название
- Цена
- Формат (курс / клуб / консультации / SaaS / etc.)
```

→ Записать в `intake/product.md`.

### 2.5 Голос автора (короткий замер)

```
Q6: Приложи 3-5 своих лучших постов (любая платформа - TG, X, Threads, LinkedIn).
Или 3-5 цитат из интервью / разговоров с клиентами.
Это нужно чтобы скилл слышал твой голос, а не писал generic.
```

→ Записать в `intake/voice-samples.md`.

Если пользователь не может - fallback: попросить 5 минут надиктовать аудио на любую тему «как ты обычно общаешься с клиентами», расшифровать через `hyperframes-media` (transcribe) → положить в `voice-samples.md`.

---

## Шаг 3 - Опциональные поля

```
Q7 (опц.): У тебя есть Карта смыслов на ближайший месяц? Если да - путь к файлу.
Если нет - Mode A (по плану) пока работать не будет, это ок.

Q8 (опц.): Какие 3 архетипа подходят твоему голосу
(Magician, Sage, Outlaw, Hero, Ruler, Creator, Explorer, Everyman, Jester)?
Если не знаешь - скилл подберёт по voice-samples.
```

→ Записать `paths.content_map` (если есть), `voice.archetypes_allowed`.

---

## Шаг 4 - Запретные термины (нишевые)

```
Q9: Какие термины тебе НЕЛЬЗЯ использовать в публичном контенте?
(Например, у автора: «программист», «artifact», «КЭВ», «связки», em-dash «-»)
Список можно сделать коротким - потом дополнишь.
```

→ Добавить к `lexicon_banned_hard` поверх дефолтного списка.

---

## Шаг 5 - Создать заполненный config.md

Сгенерировать `config.md` под пользователя:
- Подставить все ответы в соответствующие поля
- Сохранить с пометкой `last_reviewed: YYYY-MM-DD`
- Если каких-то путей ещё нет (`avatar.md` не существует) - поставить путь на `intake/<file>.md`

**Не перетирать существующий config.md** - если файл уже есть, спросить пользователя: «Это перезапись существующего конфига или новый проект?»

---

## Шаг 6 - Краткое summary

После сохранения - резюме:

```
Готово. Что я сделал:

✓ Создал config.md по пути <path>
✓ Создал intake/{avatar, jtbd, product, voice-samples}.md из твоих ответов
✓ Подключил Mode B (ситуативный) и Mode C (надиктовка)
○ Mode A (по карте смыслов) - заработает когда сделаешь карту в запуске

Следующий шаг - запусти /post, и скилл начнёт работу.

Долгосрочно: пройди фазы 0-3 методологии запуска (см. .business/processes/),
тогда у тебя будет полноценный avatar.md, jtbd.md, brand-dna.md, и Mode B2
(генерация идей) будет работать на уровне автора, а не на «общих представлениях».
```

---

## Принципы onboarding

1. **Один вопрос за раз, не анкета.** Анкета пугает, диалог - нет.
2. **Минимум - 5 полей.** Без них скилл выдаёт generic.
3. **Опциональные поля = опциональные.** Не блокировать запуск.
4. **Intake - временное хранилище.** Это не replacement методологии автора, это bootstrap.
5. **Все ответы - на диск.** Файлы в `intake/` остаются у пользователя после onboarding, не теряются.
