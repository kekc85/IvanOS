# Workflow 06 - Periodic Refresh banned AI-tells

**Назначение:** еженедельный pass обновления списка banned AI-tells (semantic classes).
**Когда запускается:** auto-warning в 01-router если `config.banned_list_last_review_date` > 7 дней назад, либо вручную `/post --refresh-banned`.
**Выход:** новые классы дописаны в анти-словарь голоса + дата в config. Адрес записи: файл по `config.voice_canon.voice_profile`, если он подключён; иначе раздел `## 3. Запретные AI-обороты` шаблона `references/_voice-TEMPLATE.md` (это единственный легальный случай ЗАПИСИ в шаблон - он же остаётся не-источником закона, пока не подключён через config).

## Шаги

### Шаг 1 - Собрать корпус для сканирования
- Последние 30 постов канала автора (через recent_posts_source webfetch)
- Последние 10 черновиков скилла (если сохраняются)
- Опционально: 5 актуальных постов из competitors-refresh-*.md (последний refresh)

### Шаг 2 - Сканирование на новые классы
LLM-сканирование корпуса по 4 фокусам:
- Конструкции с inflated certainty / pseudo-paradox / vague abstractions / hedge / tricolon (паттерны не уже представленные в A-Z catalog)
- Лексика которая «звучит как ИИ» - отметить candidate
- Cross-check с feedback memory `feedback_no_metaphors_in_posts`, `feedback_living_language_not_robotic`
- 🔴 **Фокус 4: НОВЫЕ КОРНИ МЕТАФОР (по решению автора).** Список корней в `check_metaphor_roots` (`scripts/lint-post.py`) статичен - 13 корней, все добавлены разово. Движок при этом рождает новые образы быстрее, чем список растёт: в пакетах августа рядом с ловимыми «дверь/ступень/лестница» жили неловимые «главное блюдо», «упираешься в стену», «меняю дверь», «карта складских полок», «инструмент = чит-код». Каждый прогон обязан искать именно новые.
  **Как искать (механически, не «на глаз»):** взять корпус Шага 1, выписать каждое СУЩЕСТВИТЕЛЬНОЕ из физического мира (предмет, здание, часть здания, мебель, еда, дорога, транспорт, стройка) и проверить его буквальным тестом - **в этом предложении оно происходит ФИЗИЧЕСКИ БУКВАЛЬНО?** Нет → это корень-кандидат. Слово, уже стоящее в `METAPHOR_ROOTS`, - skip.
  **Куда класть.** `scripts/lint-post.py` из этой фазы НЕ правится (код меняется отдельной задачей, с калибровкой по зелёному корпусу). Кандидаты пишутся списком в `references/metaphor-to-literal.md`, раздел «Кандидаты в корни линтера», каждый - строкой `корень | цитата-улика | файл-источник | буквальная замена`, и печатаются в отчёт Шага 6 отдельной строкой для владельца.

### Шаг 3 - Триаж candidates
Для каждого candidate:
- Если уже есть в A-Z - skip
- Если новый класс - добавить как AA, BB, CC, ... (продолжение алфавита)
- Привести 2-3 example посланий + reason почему AI-tell

### Шаг 4 - Обновить анти-словарь голоса
- Дописать новые классы в конец раздела анти-словаря (адрес - см. «Выход» выше)
- 🔴 Дописать пары «образ → буквальная замена» в `references/metaphor-to-literal.md`: каждый корень-кандидат из Шага 2 фокус 4 приходит с ГОТОВОЙ буквальной заменой, иначе он не кандидат, а жалоба. Запрет без замены не работает: писателю нужно сказать то же самое, и он скажет это другим образом
- Обновить дату «Last refresh: <date>»

### Шаг 5 - Обновить config.md
- `validation.banned_list_last_review_date: <today>`

### Шаг 6 - Отчёт в чат
«Periodic Refresh banned list: добавлено N классов / 0 классов (нет новых). Корпус скана: 30 постов + 10 черновиков. Дата: <today>»
🔴 Второй строкой - метафоры: «корней-кандидатов в линтер: N (<перечислить>) · пар в metaphor-to-literal дописано: M». Ноль кандидатов печатается тоже - это факт замера, а не повод строку опустить.

## Anti-patterns
- НЕ удалять старые классы из A-Z без явного «эти не работают» от автора
- НЕ дублировать классы под другим именем (semantic dedup перед добавлением)
- НЕ выдумывать классы без 2-3 verbatim примеров
- 🔴 НЕ добавлять корень метафоры без буквальной замены рядом (Шаг 4)
- 🔴 НЕ править `scripts/lint-post.py` из этой фазы: корни там калибруются по зелёному корпусу (доля срабатываний <20%), иначе HARD-гейт начинает валить здоровые посты
