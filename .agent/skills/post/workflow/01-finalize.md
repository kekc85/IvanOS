## Шаг 6 - Determine type & length_target

**Если `brief.type` задан (Mode A с карты, или пользователь сказал «short personal про X»)** → использовать.

**Иначе:** detect по логике 8 типов (описана в `workflow/_archive/02-structure.md` как справочный канон, применяется в глубоком конвейере 02c-02e).

**Приоритет источника длины (канон формы v2, §3, канон-правка §8.2 «floor по типам»).** `length_min`/`length_max` берутся из `brief.form_profile` (записан в `01-router.md` Шаг 0.49), когда `brief.form_goal` объявлена. Таблица «Defaults по типам» ниже становится **fallback-веткой**, которая применяется ТОЛЬКО когда `brief.form_goal` пуст, и НЕ поднимает пол выше значения из профиля (то есть профиль не может быть перебит более строгим типовым floor).

**КРИТИЧНО (без изменений при пустой цели):** length - это **target_range (min, max)**, не одно число. Пока `brief.form_goal` пуст, действует старое правило: пост короче min для своего type **автоматически failит** на review (4.1.6) - это закрывает прецедент по решению автора когда скилл выдал пост 250 chars для build-in-public темы (gold-standard range 1250-2400).

**Блокировка при объявленной цели (перекрывает «автоматически failит» выше).** Когда `brief.form_goal` объявлена, выход за коридор `brief.form_profile.len_min`..`len_max` **не блокирует** выдачу: печатается `WARN: длина <N> вне профиля <len_min>-<len_max> цели <R/F/S>` плюс одна строка обоснования (улика прокидывается в `04-review.md` 4.1.6). Причина: канон измерил гейты качества (ценность, конкретика, «не огрызок») как держащие «огрызок» без порога знаков сами по себе, а разброс верхнего квартиля по каждому профилю огромен (например R-нарратив 362-1242 при цели 671, R-разбор 402-990 при цели 542) - жёсткая вилка резала бы собственные эталоны канона. Режим A (реакция-гейт) длину не проверяет вовсе - у него свой чек-лист §9.

Defaults по типам (target_range = min - max, основано на gold-standard автора; **fallback**, см. приоритет выше):

Записать в brief:
```yaml
brief:
  length_min: <min из таблицы>
  length_max: <max из таблицы>
  length_target: <middle of range - для guidance, не блокер>
```

**Анти-паттерн (закрыт системно):**
- Раньше length_target был ОДНИМ числом и интерпретировался как «не превышать». В результате скилл писал 250-460 chars для build-in-public (где gold-standard 1300+) и считал PASS. Это исправлено: теперь min - hard floor, max - hard ceiling, длина вне диапазона = fail в 4.1.6.

> **⚠️ Оговорка (дубль Шага 6 выше, волна 7 - чтобы правило не читалось в отрыве).** Всё, что сказано в этом анти-паттерне про «hard floor / hard ceiling / fail в 4.1.6», относится к **fallback-ветке - то есть ТОЛЬКО к случаю, когда `brief.form_goal` пуст**. **Оси формы при объявленной цели (канон формы v2, канон-правка §8.2 «Variation Rotation Gate»).** Когда `brief.form_goal` объявлена, две оси из пяти - **тип хука** и **формула финала** - выводятся из ротации: они диктуются `brief.form_profile` (профилем цели), а не требованием новизны. Ротировать «ради непохожести» тип хука или финал, которые канон закрепил за профилем (например R-нарратив: хук-кадр, финал-вывод с закрытой петлёй), означает написать следующий правильный пост хуже предыдущего. Ротируются по-прежнему смысловые оси: тема, риторический движок, эмоциональная арка, рамка-злодей, архетип. Пока `brief.form_goal` пуст - ротация работает по всем 5 осям без изменений, как сегодня.

Это улика, что rotation-gate реально прогнан (а не пропущен по поверхностному чтению). Прецедент по решению автора: два поста подряд на одном скелете. Память `feedback_rotate_post_axes_every_time`.
