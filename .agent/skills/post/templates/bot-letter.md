# Template: Бот-письмо-рассылка запуска (структура Фёдора Сидорова) — v1.0, 2026-07-18

> **Назначение:** ПОЛНОЕ письмо-рассылка запуска (сбор реги / прогрев / продажа), которое бот регистрации шлёт сегментом. Это НЕ ОСН-пост-история и НЕ bot-message-огрызок (100-300 знаков push): это письмо на 130-260 слов с баннером, буллетами «что внутри», жирной кнопкой-инструкцией и P.S.
> **Когда:** `brief.carrier = "bot"` И `brief.launch_window = true`. Грань бота извлекает `01a-plan.md` Шаг 3.0 Ветка B (смысл-код бота / тип 8b-8c / `bot_segment` / `bot_link` из бот-фрагмента строки НОСИТЕЛИ ячейки дня).
> **Грунд:** структура «письма Фёдора Сидорова» (память `feedback_bot_warming_message_is_full_letter_not_push_stub`): бот-прогрев/дожим = полноценное письмо, а не пуш-заглушка. Голос владельца — `.business/voice-corpus/_voice-profile.md`.
> **Обязательная пара:** строится ТОЛЬКО поверх боевой карточки Слоя 0 (`references/launch-money-layer.md`), как и `sales-launch.md`. Без карточки не собирается.

## Когда применять (под-типы по фазе температурной шкалы)

| Под-тип | Фаза | Цель (единственное действие читателя) |
|---|---|---|
| **8b Прогрев-письмо** | прогрев (окно реги) | мягкий CTA на регистрацию/явку — кнопка `bot_link` |
| **8c Продажа-письмо** | sales window (после открытия цены в день запуска) | заявка/оплата — кнопка `bot_link`, дедлайн зашит ВНУТРИ истории, не отдельным пушем |

Под-тип берётся из бот-фрагмента ячейки (тип `8b`/`8c`), НЕ детектится заново.

## Каноническая структура (6 частей)

1. **Баннер-обложка** — первой строкой ОПИСАНИЕ визуала обложки письма (что на картинке + короткая надпись поверх). Формат: `🖼 [обложка: <что на скрине/сцене> · надпись «<крупный текст>»]`. Технарь ставит картинку кнопкой в редакторе, картинку сам post не генерит (media-upload). Эмодзи-строка допустима вместо/вместе с описанием, если визуала нет.
2. **Контекст / приветствие** — 1-2 предложения, тёплый вход на «ты» («Привет. Это снова я…» / короткий заход в тему). НЕ дублирует крючок.
3. **Крючок** — история / цифра / вопрос / эмпатия из смысл-кода бот-грани (`brief.topic`). Живая личная сцена или конкретный факт, не абстракция. Это то, ради чего письмо читают дальше.
4. **Блок «что внутри»** — буллетами (`📌` или `-`, 3-5 пунктов), развёрнутое тело смысла: что человек соберёт / получит / разберёт. Мясо письма, не срезать при ужатии.
5. **Жирная инструкция-кнопка** — отдельной строкой: **`**жми кнопку под этим сообщением «<подпись из bot_link>»**`**. Подпись кнопки = ровно то, что задано в `brief.bot_link` (ячейка), не выдумывать. Это ЕДИНСТВЕННЫЙ CTA письма.
6. **P.S.** — эмпатия или доп-аргумент: «почему сегодня» (реальный факт из карточки — мало мест / запись не у всех / дата эфира) ИЛИ снятие последнего возражения. Один абзац.

Длина всего письма — **130-260 слов**. Формат-тройка (как humaniser): без нейроклише, без длинных тире (только дефис `-`), без точки в конце абзаца.

## Consumer полей брифа (ОБЯЗАТЕЛЬНО, иначе сегмент/ссылка теряются)

- **`brief.bot_link` = КНОПКА (обязана быть).** Часть 5 поднимает её как жирную инструкцию с подписью из ячейки. Нет кнопки в письме → брак (правило `feedback_every_broadcast_message_must_have_link`).
- **`brief.bot_segment` = КОМУ.** В само письмо НЕ вставляется. Уходит в ТЗ РАССЫЛКИ технарю (`05-publish.md` финальный output): `СЕГМЕНТ: <bot_segment> · ССЫЛКА: <bot_link> · КАНАЛ: бот регистрации <бот из config.platforms>`. Каскад доходимости/прогрев к эфиру = ВСЕГДА только зарегистрированные через бота реги, НЕ вся база (кроме явного «база минус зарегистрированные» на сбор реги).
- **Доставка:** сегментный broadcast делает БОТ регистрации по сегменту. `post` даёт письмо + ТЗ; превью письма владельцу - если у тебя настроен свой канал доставки, обычным текстовым каналом (только по явному «да», страж no-bot-send). Канала доставки нет - показывай превью прямо в чате, руками. Превью ≠ рассылка. 🔴 Rich-отправщик `send-rich-post.py` снят по решению автора вместе со всем rich-слоем (архив `scripts/_archive/`) - письмо тоже идёт донорским текстом, без таблиц/чек-боксов/rich-блоков.

## Жёсткие правила (проверяет Sales Gate 4.S, пункт 4.S.8-bot)

- Единственное действие читателя = регистрация/явка/заявка через кнопку `bot_link`. Reader-homework («открой Claude», «попробуй сам», «посчитай») — брак.
- Кнопка `bot_link` физически присутствует в теле жирной инструкцией с подписью из ячейки.
- ТЗ рассылки (сегмент + ссылка + канал) идёт в выдачу ПЕРЕД/ПОСЛЕ письма.
- Все факты программы/механизма/цены — из канона (`workshop.html`, <решения-запуска>, <твой состав тарифов> для 8c). Цены — только в 8c и только из канона.
- Негативных статистик и «цена в личке» нет. Дедлайн (8c) — только реальный из карточки, не выдуманный.
- ЦА = новички без ниши/продукта: не писать «твоя экспертиза» как данность, снимать возражение «у меня нет ниши».

## Чем НЕ является (отличие от ОСН sales-launch.md)

- `sales-launch.md` (8a/8b/8c) = пост-ИСТОРИЯ в ОСН-канал (Telegram/LinkedIn), проходит блюпринт заголовков/контекста, тело 60-70% истории + ценность, HSO-shape.
- `bot-letter.md` (8b/8c) = ПИСЬМО в бот-рассылку: баннер-обложка + буллеты «что внутри» + жирная кнопка + P.S., адресное «Привет, это снова я». Это письмо человеку в личку от бота, не пост в ленте.
- carrier=bot роутится СЮДА, carrier=osn (дефолт) — в `sales-launch.md` как раньше. Не смешивать shape.

Вот что мы разберём на бесплатном воркшопе:

Никакой теории на подумать. Ты выйдешь с воркшопа с первым собранным куском своей системы
