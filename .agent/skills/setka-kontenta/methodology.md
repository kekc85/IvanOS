# Скилл №12 «Сетка контента» — методология

> **Статус:** методология финализирована, реализована в `prompt.md` v1.0.0.
> Дата фиксации: 2026-05-19.

## Принцип: быстрая сборка, не двухчасовой анализ

Главное правило скилла — **не превращаться в тяжёлое действие**. Эксперт
не должен залипать на сетке. Любое тяжёлое действие → откладывается на
завтра → сетки нет → контент-цикл рвётся. Скилл должен **за 5–15 минут**
выдать рабочую сетку, не идеальную, на которую можно опереться сразу.

Реализуется через два режима глубины диалога (как у писателей №13-16):
- **Быстрый** — скилл решает сам, минимум вопросов, дефолтная сетка из контекста. 1–5 минут
- **Осмысленный** — на ключевых развилках уточняем у эксперта. 15–30 минут

Быстрый — основной режим. Осмысленный — для важных периодов (запуск, новый продукт, смена позиционирования).

## Три режима работы

| Режим | Когда | Длительность |
|---|---|---|
| **A. Обычная сетка** | Рутинный контент-цикл. В сетку можно частично включать слоты с CTA-воронкой на лидмагнит — это не отдельный режим | неделя / 2 нед / месяц |
| **B. Прогрев к запуску** | В Календаре запусков есть запуск в окне 0–8 нед | 3–7 дн / 2–4 нед / 1–2 мес |
| **D. Банк тем** (опц.) | Эксперт хочет наполнить запас идей для будущих сеток (боль ЦА «не знаю о чём») | без привязки к датам |

**Лидмагнит — не отдельный режим.** Раньше делали сетку 7-14 дней под один ЛМ. Сейчас не работает: ЛМ упоминается несколько дней и всё. Решение: в режиме A эксперт указывает «хочу разбавить ЛМ» → скилл назначает на часть слотов CTA-воронку с буллетами лидмагнита. Без отдельного режима.

## Скилл работает только в нашей ЦА (валидация)

контент-завод рассчитан на **615 экспертов** (4 архетипа из Профиля ЦА).
Все экспертные блоги, разные ниши. Скилл №12 учитывает:
- **Только экспертный блог** — без выбора «личный/развлекательный»
- **Только IG + TG** — без YouTube/TikTok (нет соответствующих писателей)
- **Быстрая выдача** — критично для боли «нет времени» (35% тратят 6-15+ часов/нед на контент)
- **Hard-stop при пустом `.business`** — для архетипа B (начинающие из офлайна): если нет хотя бы 1 из 3 источников (свои разборы / наполненный Темник / Сетка продуктов с продуктом) → не делаем «пустую» сетку из общих фраз
- **Простая выдача без шкал и баллов** — никаких «оценка 4.2/5», просто список слотов

## Что делает скилл

На входе: эксперт говорит «сделай сетку на неделю/месяц».
На выходе: файл `.business/growth/production/Сетка/<период>.md` с темами под каждый
формат × канал × день по решётке из `Ритм публикаций.md`.

## Источники тем (порядок поиска эксперта, его собственная методология)

1. **Профиль ЦА** (`.business/Профиль ЦА.md`) — приоритетные сегменты,
   их боли и язык. Это база: о чём вообще говорим.
2. **Гипотезы по своему успешному контенту** — из аналитики своего архива
   (свои разборы, `.business/growth/analytics/Разборы/*_свой_разбор.md`).
3. **Гипотезы по успешному контенту конкурентов** — из разборов конкурентов
   (`.business/growth/analytics/Разборы/<имя_конкурента>/`) и из свёртки аналитик
   конкурентов (`.business/growth/analytics/Свёртка аналитик конкурентов.md`).
4. **Ресёрчи ниши** (если есть и релевантно) —
   `.business/growth/materials/Ресёрчи/*.md`.
5. **Свой темник** — `.business/growth/production/Темник.md` (сырые идеи эксперта).
6. **Что уже постил недавно** — `.business/growth/production/Готовый контент/_index.md`
   за последние N недель (избегать повторов, держать баланс тем и форматов).

Из всего этого скилл рождает гипотезы тем под каждый канал.

## Решётка частоты

Из `.business/growth/production/Ритм публикаций.md`:
- IG: N рилзов/неделю, M каруселей/неделю, K сторис/неделю
- TG: P длинных/неделю, Q коротких/неделю

Скилл строит сетку под указанные частоты. Если поле пустое — формат пропускаем.

## Учёт особенностей форматов

Это причина, почему сетку пишем ПОСЛЕ писателей: каждый писатель
(№13-16) задаёт, какие темы вообще подходят под формат:

- **Карусели** (№13): структурированные темы со списками, шагами, чек-листами,
  ошибками — то, что хорошо разбивается на слайды.
- **Рилз-разговор** (№14): личные истории, мнения, провокационные тезисы —
  то, что эксперт может сказать на камеру за 30-60 секунд.
- **Рилз-overlay** (№15): короткие хуки + визуальная демонстрация — темы,
  где есть визуал (скриншот, цифра, цитата на фоне).
- **TG-пост** (№16): длинные тексты с рассуждением; короткие — анонсы,
  цитаты, кейсы.

Когда писатели готовы — каждый из них экспортирует «требования к темам»
для своего формата (в `<репо>/<писатель>/prompt.md` будет блок «какие темы
подходят»). Сетка читает эти блоки и распределяет темы корректно.

## Артефакт сетки (структура файла `2026-W21.md`)

```markdown
---
тип: сетка
период: 2026-W21
даты: 2026-05-18 — 2026-05-24
статус: черновик | утверждена | в работе | закрыта
ритм: { рилзы: 3, карусели: 1, TG_длинные: 2, TG_короткие: 3 }
---

# Сетка W21 (18-24 мая)

## IG · Рилзы (3)

1. **Понедельник** — Тема: «Антихрупкость в малом бизнесе»
   - Формат: рилз-разговор
   - Источник идеи: [[Антихрупкость_Талеб/свёртка]] + [[2026-05-15_свой_разбор|свой удачный пост]]
   - Хук: «Все боятся кризиса. А что если он — твой ресурс?»

2. ...

## IG · Карусели (1)

...

## TG · Длинные (2)

...
```

## Стратегический слой (без отдельного артефакта «Контент-стратегия»)

Отдельного файла «Контент-стратегия.md» нет — это лишний шаг онбординга
(via negativa). Стратегические оси распределены по двум существующим артефактам:

1. **Целевой баланс функций** живёт в `.business/growth/production/Ритм публикаций.md`,
   секция «Целевой баланс функций (на квартал)». Эксперт указывает целевое
   распределение в процентах:
   - Информационный: N%
   - Прогрев / продажа: N%
   - Отношения: N%
   - Рефлексия: N%

   Скилл №12 при создании сетки **считает фактический баланс** из
   `.business/growth/production/Готовый контент/_index.md` за последние 4–8 недель
   (по YAML-полю `функция:` каждого поста) и **сравнивает с целевым**.
   Если перекос — подсвечивает эксперту: «У тебя в последние 4 недели
   информационного 75%, при целевом 50%. Продаж 0% при целевом 20%.
   Выравниваем эту неделю?» В режиме «осмысленный» эксперт принимает решение,
   в «быстром» — скилл выравнивает сам.

   Если поле в Ритме публикаций пустое — скилл №12 работает без целевого
   и без подсветки перекосов. Это допустимо для начинающих.

2. **Календарь запусков** живёт в `.business/Сетка продуктов и оффера.md`,
   раздел «Календарь запусков». Эксперт указывает планируемые запуски
   с датами и длительностью прогрева. Скилл №12 на старте проверяет:
   есть ли запуск в горизонте `сегодня + 0..8 недель`. Если есть и
   текущая неделя попадает в окно прогрева — **автоматически предлагает
   режим прогрева** для всех или части постов недели (см. ниже).

   Эксперту не нужно говорить «начинаем прогрев» — скилл сам видит
   календарь и предлагает.

   Если календарь пустой / эксперт «продаёт в моменте» — скилл работает
   без триггеров прогрева.

## Развилка режимов: прогрев vs обычный постинг

Скилл №12 на старте спрашивает (или определяет автоматически по календарю
запусков в `.business/Сетка продуктов и оффера.md`):

**Режим A — обычный постинг.** Сетка под рутинный контент-цикл: микс функций
(информационный / отношения / рефлексия / иногда продажа). Темы из всех
источников, баланс по последним N неделям из Готового контента.

**Режим B — прогрев к запуску.** Сетка под конкретный запуск продукта
(дата старта продаж, дата открытия дверей). Серия идёт по канве:
открытие истории → проблема → агитация → социальное доказательство →
решение / продукт → продажа. Каждому посту присваивается:
- `позиция_в_серии: 3/7`
- `прогрев_к: <имя продукта>`
- `канва_шаг: проблема` (или: открытие, агитация, решение, продажа)

Писатель в фазе создания видит контекст серии («ты пост 3 из 7 в прогреве
к курсу X, твоя задача — раскрыть проблему через личную историю») и
выбирает структуру из арсенала под этот шаг.

В рамках одной недели можно мешать оба режима (часть постов прогревочных,
часть рутинных) — это нормально и должно поддерживаться.

**Почему не делаем отдельный скилл «Контент-стратегия».** Думали — лишняя
точка: стратегия эксперта уже распределена по артефактам Контекста
(Профиль ЦА, Распаковка, Сетка продуктов). Сетка контента читает их
напрямую и не нуждается в промежуточном «стратегическом» документе.
Via negativa — экономим одну сущность.

## Связи

- **На входе**: Профиль ЦА, Распаковка, Сетка продуктов, Разборы своего,
  Разборы конкурентов, Свёртка аналитик конкурентов, Карта знаний,
  Свёртки, Ресёрчи, Темник, Ритм публикаций, Готовый контент (что уже было).
- **На выходе**: файл в `.business/growth/production/Сетка/` + обновление
  `Сетка/_index.md`. Дальше каждая тема уходит в соответствующего писателя.

## Open questions (для финализации перед написанием промпта)

1. **Период по умолчанию** — неделя или месяц? Возможно: спрашиваем у эксперта.
2. **Интерактивный vs автоматический режим** — по аналогии со скиллом №4.
3. **Сколько недель «назад» смотреть в Готовом контенте** — 4? 8? Зависит
   от длины контентного цикла.
4. **Как балансировать темы** — формальные правила (не повторять тему 2 недели
   подряд) или эвристика (отдать на интуицию модели + показать прошлое)?
5. **Сторис** — попадают в сетку или мимо? Сейчас в Ритме они есть, но
   писателя сторис в списке нет.
6. **Кто обновляет статус сетки** (черновик → утверждена → закрыта) —
   эксперт руками или скилл по сигналу?
