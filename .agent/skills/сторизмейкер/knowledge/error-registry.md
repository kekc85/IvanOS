# Реестр анти-ошибок сторизмейкера

Каждый пункт = реальный разнос автора в сессии в даты запуска.2026 (дека «мой путь», ~30 итераций до приёмки). Перед отдачей ЛЮБОЙ версии деки прогнать выход по этому списку. Нарушение любого пункта = брак, автору не показывать.

## A. Текст кадров

1. **Телеграфные обрубки = «набор звуков».** «контент идёт, просмотры капают, оплат ноль» - разнос. Писать связными человеческими предложениями с логической сцепкой. Тест: прочитай вслух - так говорят?
2. **Жаргон без расшифровки.** «бот ловит», «AI-измы», «парсер виралок» голыми - новичок не понимает. Термин допустим только с раскрытием: «скилл «парсер виралок»: сам находит залетевшие ролики в твоей нише»
3. **Мета-ярлыки запрещены:** «ключевая история», «результат», «доказательство», «одно действие», «Было → станет». Кикер должен нести смысл («а вот твоя ситуация», «хорошая новость»), не тип кадра
4. **Ложь в нарративе.** «мне не пришлось быть маркетологом, экспертиза осталась моя» - бред: автор И ЕСТЬ маркетолог. Нарратив сверять с реальной фигурой автора
5. **Работа маркетолога = у Claude Code, не у человека.** Цена, аудитория, оффер, продающий текст - «обычный человек сам не поймёт, сколько ставить цену». Человеку в нарративе остаётся: рассказать, чем занимается и что умеет
6. **Не отрезать сегменты аудитории.** «Продавать то, в чём ты силён» отрезало тех, кто не считает себя экспертом. Смыслы проверять на покрытие: «не знаю, что продавать» и «я не эксперт» - обязательные сегменты
7. **«Система» без конкретики запрещена.** Всегда: «продающая система», «система монетизации: продукт, трафик, продажи»
8. **990 и любая цена - всегда со знаком ₽**
9. **«Claude Code» полным именем всегда.** Не «код», не «нейросеть», не «ИИ». «Кодовое слово» - термин, не трогать
10. **Слово «стикер» запрещено.** Только «жми ссылку наверху». Запрещены также: нумерация кадров, подпись-вотермарк, «link-стикер → t.me/...» на кадрах
11. **Единственное действие читателя = регистрация.** Никаких вторых CTA, домашек, «напиши в директ». Ссылка = кадр оффера + финальный CTA
12. **Формат-тройка текстов:** без нейроклише (humaniser), без длинных тире (только дефис), без точки в конце последнего абзаца кадра

## B. Продающая механика

13. **Пруфы ДО боли.** Холодный зритель сначала видит скрины (профиль, комменты, лента оплат), потом ему продают
14. **Смежные кадры не дублируют смысл.** Заголовок кадра 2 не пересказывает кадр 1; «что я сделал» не повторяет пруф-кадр. Каждый кадр даёт НОВОЕ
15. **Срочность у ПЕРВОГО CTA, не только в хвосте.** До хвоста доходит треть. Механика очереди (VIP-разбор по времени регистрации) - строкой на кадре сразу после оффера + мостик «ссылка на следующем экране» на предпоследнем кадре
16. **Дефицит только честный.** «Мест хватит всем, а VIP-разбор достаётся ранним» - ок. Фейк-таймеры и «осталось 5 мест» - запрещены
17. **Якорь цены на CTA:** сравнение с реальной альтернативой («сайт на фрилансе от 50 000 - тут сам за 0 ₽»)
18. **Мостик механизм→оффер:** после схемы воронки строка «эту машину ты соберёшь на воркшопе». Между схемой и оффером ничего не вставлять
19. **Факты не выдумывать.** Нет цифры/факта (записи вечеров, сроки) - пометить «требует подтверждения автора», в кадр не ставить

## C. Визуал и моушн

20. **Статика ТОЛЬКО на кадрах с фото автора.** Всё остальное - полноценное видео (Playwright recordVideo → ffmpeg)
21. **Первый кадр и CTA = static-first.** Всё стоит с первого кадра, никаких входных анимаций - зритель не ждёт. Допустим только мягкий пульс акцента
22. **Бегающие блики (shine sweep) запрещены.** «Дёрганный» = разнос; стоп-кадр ловит блик как артефакт-прямоугольник. Пульсы мягкие: ease-in-out, цикл ≥3s, spread ≤16px
23. **«Всё появляется сверху вниз» = 1/10 монтажа.** Чередовать стороны входа, wipe, pop, стаггер - динамика, не парад
24. **Скрины-пруфы целиком, без обрезки.** Рамка-выделение внутри zoom-контейнера (не дрейфует), позиционируется на конкретную цифру
25. **Фото не дублируются между кадрами; лицо видно (не затылок); AI-фото запрещены.** 3+ однотипных фото подряд (машины) бьют доверие - чередовать сцены
26. **Контраст:** кикер на тёмной пилюле (читается на любом фоне), gold на светлом гаснет - скрим плотный до зоны текста, text-shadow на заголовках фото-кадров
27. **Сейф-зоны IG:** первый текст не выше y≈170, последний не ниже y≈1720 (шапка сторис и поле ответа закрывают)
28. **Висячие слова.** Серверный типограф: одно-двухбуквенные предлоги/союзы клеятся NBSP к следующему слову + последнее слово абзаца к предпоследнему. НО: длинные NBSP-цепочки дают overflow за край (прецедент «на воркшопе») - связывать точечно, большие заголовки при нужде переносить жёстким `<br>`, каждый кадр проверять стоп-кадром
29. **Зачёркивание барьера:** тонкое (4px), cream с прозрачностью, ниже x-height - слова остаются читаемыми

## D. Процесс и доставка

30. **«Проверил» = открыл стоп-кадр с диска.** Каждый изменённый кадр: ffmpeg-стоп-кадр (видео в содержательной фазе) или PNG → Read → глазами. Без этого не заявлять «готово»
31. **Кэш-барьер обязателен.** Браузер автора кэширует: НОВЫЕ имена файлов на каждую ревизию (b28-, b29-), маркер в заголовке деки «если видишь этот заголовок, кэш сброшен», curl 200 на КАЖДУЮ ссылку перед отдачей
32. **Реестр правок автора вести и сверять.** Каждый разнос = пункт реестра; перед отдачей прогон по всем пунктам, не только последним
33. **Многослойное ревью до отдачи** (для новой деки / крупной ревизии): 3 параллельных критика по стоп-кадрам с диска - маркетолог (с mastery-линзой), дизайнер, холодный зритель-новичок. Фиксы классами, потом отдача
34. **Правки строк с NBSP/юникодом:** replace может тихо не сработать (U+00A0 невидим). Всегда assert после замены; при провале - смотреть repr() и менять по индексу
35. **Рабочая папка вне iCloud** (`~/highlight-work/`) - iCloud-синк сносит файлы посреди работы
36. **Доставка: localhost-дека + инлайн стоп-кадры в чат.** НЕ отправлять в <твой-бот> (бот - для каруселей) и никуда без явной просьбы. Если localhost-сервер умер - перезапустить и curl-проверить
37. **Не задавать автору вопросов по ходу** - только идеал на выходе. Исключение: реальный факт, который нельзя взять из контекста (п.19)
38. **В Telegram вертикальные кадры (9:16) слать ТОЛЬКО документами (sendMediaGroup type=document).** Photo/video-альбомы Telegram пережимает (фото до 1280px, текст мылится) и растягивает превью - «растянуто, стрёмно» = разнос по решению автора. Файлом уходит оригинал 1080×1920 без изменения сторон
