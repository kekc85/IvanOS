## 🔴 BLUEPRINT ПОСЕГМЕНТНОГО РЕВЬЮ (Фаза 6) — ПОЧЕМУ так и 8 СЛОЁВ (автор)

**ПОЧЕМУ блупринт-подход (а не «собрал ролик → отревьюил один раз»):**
Сильная модель психологически срезает на большом ролике — лень + соблазн сэкономить токены: собирает 30с разом, ревьюит поверхностно, докладывает «готово». Fable так делал и не прописывал что делает; я тоже. Лечение: **ролик собирается КУСКАМИ по 3-5с, и КАЖДЫЙ кусок проходит ВЕСЬ ревью-стек ниже, как будто это ВЕСЬ ролик и больше ничего не предстоит.** Маленький кусок легко довести до идеала; полный ревью на каждом = негде срезать. **Каждый кусок докладывается автору целиком** (отчёт убивает склонность врать — нельзя тихо пропустить слой). **Машина блокирует переход к куску N+1 и слово «готово», пока кусок N не прошёл ВСЕ 8 слоёв + отчёт** (`.chunk-ledger.json`, страхуется `chunk-review-gate.py` + Stop-хук).

> Разворот по решению автора: прежний «ОДИН критик по склейке ради экономии токенов» ОТМЕНЁН. Приоритет — макс качество, не токены. Per-chunk дороже — это сознательный размен.

> 🔴 Гейт НЕ верит флагу `PASS` (его можно напечатать, не сделав слой — прецедент скилла «пост»). `chunk-review-gate.py` ПЕРЕПРОВЕРЯЕТ первичные улики и заставляет ДЕЙСТВИЕ: рендер декодируется (нет рендера = работа не сделана) · audit/critic привязаны к md5 ЭТОГО рендера (старый/чужой = stale=MISS) · бенчмарк-контакт-PNG реально на диске · каждая из ≥9 осей панели с содержательной заметкой (≥30 симв) + ссылкой на реальный кадр (пустые `{axis}` = фабрикация, не считаются) · отчёт ссылается на реальный артефакт. Остаточный предел честно: само vision-СУЖДЕНИЕ машинно не докажешь — но всё ВОКРУГ него нефабрикуемо.

### L5 — ПАНЕЛЬ КРИТИКОВ (самый «жирный» класс ревью): КАТЕГОРИИ АРТЕФАКТОВ × ОСИ

Не один критик «посмотрел кадр» — **матрица адверсар-критиков на КАЖДЫЙ кусок**. Каждый критик берёт ОДНУ категорию артефакта, презумпция «МЫ ХУЖЕ, найди всё», и сверяет её по ВСЕМ осям против 3 опор + плана. ≥9 критиков на кусок = НОРМА (не перерасход).

🔴 **БАЗА СУЖДЕНИЯ — `knowledge/montage-lexicon.md` (НЕ вкусовщина).** Суждение «хорошо/плохо» НЕ выносится на глаз. Критик ДЕКОДИРУЕТ кадр в терминах лексикона (расшифровка эталонов автора: rpn/Cintas/Steve Tan/DUqeScpDAHW в конкретные планки числом/техникой) и сверяет с эталонным уровнем. **Заметка каждой оси ОБЯЗАНА назвать якорь-эталон + конкретную планку** (не «красиво», а «темп 0.7 смен/с < Cintas ≈1/с = FAIL» / «overlap: глаза внутри карточки, макушка за гранью = Steve Tan = PASS»). Вердикт по категории = max(планка источника, планка эталона); ниже любой = FAIL.

**Категории артефактов (объекты сравнения — по одному критику на категорию):**
1. **Субтитры/титры** — шрифт-роль, позиция, тайминг word-pop, акцент-слово
2. **Аватар/спикер** — кадрирование (full/half), headroom, lip-sync, рамка K3
3. **UI/сайт/контент-зона** — реализм, заполненность, анимация, верность источнику
4. **Переходы/стыки** — тип, длительность, чистота шва, аудио-шов
5. **Типографика** — премиум-шрифт @font-face, обводка, иерархия ролей
6. **Цвет/палитра/контраст** — бренд-золото vs лайм, WCAG-контраст, cream-on-cream
7. **Раскладка/композиция** — чередование (split/full/ui), воздух, наезд блоков
8. **B-roll/футаж** — real-product, camera-work, ноль рисованных моков
9. **SFX/звук** — событие→звук на переходах, без перебора, громкость под голос
10. **Динамика/монтаж-темп** — плотность смен ≥ эталона, без fast-scroll-блюра

**Оси сравнения (каждая категория проходит по каждой):**
- (A) vs **конкурент-источник** — ролик, который реплицируем
- (B) vs **эталон формата** — `_canon.md` (Steve Tan/Cintas/rpn/DUqeScpDAHW)
- (C) vs **канон best-practice** — оси A-F 36 виралок
- (П) vs **план-деконструкция** — построил ли ровно то, что в `deconstruction.md`
- (H) **дефекты H1-H8** — окклюзия/дубли/рамка-в-пустоте/невидимый/наезд/воздух/safe-zone/реализм

Каждый критик → строка в `.critic-verdict.json` `axes[]` `{axis:"<категория>", verdict, note, vs:[A/B/C/П/H]}`. ЛЮБОЙ FAIL = чинить кусок, не показывать. Свод панели = вход L6 (отчёт автору).

## 🔴 УРОК по решению автора (motion накрутил блюр, аудит пропустил говно)
Прецедент: гнался за motion-числом → разогнал скролл github → лента превратилась в **ghosted/смазанное нечитаемое месиво**, НО motion-метрика выросла (frame-diff растёт от смаза!) → аудит дал PASS на мусоре. автор при полноразмерном просмотре сразу увидел.
- **motion-метрику НАКРУЧИВАЕТ блюр/хаос** — высокий frame-diff ≠ хорошая динамика. Числа НЕОБХОДИМЫ, но НЕ ДОСТАТОЧНЫ.
- **Резкость (Laplacian) НЕ ловит ghosting** мелкого текста (смаз тоже даёт края). Числом читаемость не докажешь.
- **СЛЕДСТВИЕ — обязательный слой:** после машинного PASS критик ОБЯЗАН смотреть `ui_legibility.png` (full-res верх на 3 таймкодах) и выносить: текст UI ЧИТАЕМ? не смазан/ghosted/хаотичен? Нечитаемо = FAIL, даже если motion зелёный.
- **Build-правило:** динамику брать из ЧИСТЫХ кат-ов между читаемыми состояниями + word-stream, НЕ из fast-scroll-блюра; скролл держать читаемым (медленно). UI всегда чёткий.
- **L-проверка добавлена** в `scene-audit.py`: жёсткая вертикальная грань в нижней зоне = рамка-коробка аватара (вклеенная фотка) = FAIL → растворять край/full-bleed.

## Принцип
Машина мерит измеримое (геометрия, строки, motion, рамка-бокс) и блокирует **снизу** (необходимое); но motion/резкость можно накрутить → **обязателен full-res vision на читаемость** (ghosting/хаос только глазами); агент судит вкус ПОСЛЕ машины; автор — финал. Каждый раз, когда дефект прошёл — дописать проверку в `scene-audit.py` И/ИЛИ усилить обязательный vision-слой.

## 🔴 PRE-SHOW DEFECT CHECKLIST (классы H) — критик ОБЯЗАН прогнать КАЖДЫЙ кадр КАЖДОГО UI-состояния ДО показа автору
Добавлено по решению автора после G0DM0D3-v2: автор ловил эти баги сам круг за кругом (корень — показывал рендер без покадрового прогона по чек-листу, само-критик штамповал PASS). Любой хит = FAIL, чинить и перерендерить, НЕ показывать. Не выборка midpoint — КАЖДОЕ состояние.

- **H1 Окклюзия:** аватар/голова/элемент перекрывает значимый UI ИЛИ текст лежит на лице. Перекрытое-важное = FAIL. (Прецеденты: голова перекрывала подписи баров Claude/Gemini; по решению автора CTA-текст на лице двойника - позиция скопирована у автора, у которого лицо в другом углу.) 🔴 МАШИННО, не глазами (класс трижды пропущен глазами): `scripts/overlay-face-occlusion-check.py --render <final> --cues <cues.json>` - пересечение alpha-bbox текста × face-bbox >2% = FAIL; позицию текста источника ВСЕГДА сверять с лицом НАШЕГО кадра (ERROR-REGISTER #16).
- **H2 Дубли:** один текст/CTA показан дважды (субтитр на груди + пилл в карточке). FAIL. (Прецедент: CTA-пилл «напиши ФАЙЛ» за головой дублировал субтитр.)
- **H3 Подсветка/рамка в пустоте:** glow/рамка/highlight не привязана к элементу или осталась после смены состояния (нет fade-out). FAIL. (Прецедент: winglow-рамка победителя висела в пустоте на CTA.)
- **H4 Невидимый элемент:** `fill`/`color` элемента == цвет его фона → лого/иконка/текст пропадает. FAIL. Грепабельно: искать `background:#X`+вложенный `fill="#X"`/`color:#X` с тем же hex. (Прецедент: Claude-лого CC785C на фоне CC785C = невидим.)
- **H5 Наезд блоков:** карточки/секции перекрывают друг друга, текст лезет на блок. Чистый грид без overlap. FAIL. (Прецедент: блоки лендинга кофейни наезжали + текст поверх.)
