## 🔴 УТОЧНЕНИЯ по решению автора (вечер, после 5 раундов правок на RuFlo — автор «очень хорошо, мне нравится»; ЗАКРЕПИТЬ, не повторять)

Эти три машинных фикса добили валидированный результат. Прецеденты — мои ошибки этой сессии:

1. **🔴 АВТОР НЕ ПОЯВЛЯЕТСЯ В ВЕРХУ НИКОГДА (даже на полкадра).** При сборке split-реплики (верх = инструмент автора 1:1, низ = двойник) автор протекал в верхнюю панель на стыках сегментов и на отдельных кадрах (≈13с, 30с — «на пару миллисекунд сверху вместо терминала»). Фикс: верхняя панель строится ПОКАДРОВО — если в top-кропе оригинала есть автор (детект по КОЖЕ в HSV, не по фронтальному лицу: Haar пропускает лоб/частичное лицо), кадр подменяется на удержанный кадр инструмента (gh-hold), с ЗАПАСОМ ±0.5с (дилатация маски на ±15 кадров) — автор прямо предложил «продли последнюю картинку на полсекунды». Тул-сегменты (терминал/скролл репо) при этом СОХРАНЯЮТСЯ живыми (у них нет кожи → не триггерят). Порог кожи ≈0.045 доли top-зоны.
2. **🔴 ДВОЙНИК В КАДРЕ ВИДЕН (лицо, не «только лоб»).** Если лук двойника = ШИРОКИЙ план (атриум/локация, спикер мелко и низко), при кропе нижней панели остаётся только лоб — «меня вообще не видно». Фикс: для широких луков нижняя панель = ЗУМ-кроп вокруг лица (face-detect median-box → crop ~810×729 вокруг центра лица → scale до панели). Близкие подкаст-луки кропятся как есть (offset ~340). Кроп per-сегмент, не один на ролик.
3. **🔴 ПЛАШКА СУБТИТРОВ ШИРОКАЯ — НАКРЫВАЕТ АВТОРСКИЙ СУБТИТР ЦЕЛИКОМ.** Узкая плашка по ширине нашего текста оставляла хвосты чужого субтитра по краям («субтитры автора видны»). Фикс: ширина плашки = max(наш_текст+130, ~1000px), почти на всю ширину, высота ~124px. Гарантирует, что английский субтитр автора не торчит ни с какой стороны.

## 🔴🔴 СЕССИЯ по решению автора — ПЕРЕСБОРКА reel-DXUH5dcDwKN (Open Generative AI / СТУДИЯ; «говняно вышел, переделать один в один просто аватаром» → валидировано автором). НОВЕЙШАЯ ОС, ПЕРЕКРЫВАЕТ конфликты.

> Корень брака прошлой версии: (а) раскладка собиралась ГРУБЫМИ битами и разъехалась по таймлайну; (б) кинематографичные AI-выводы автора (бролл) подменялись НАШИМИ перерисованными lib-клипами/гридами; (в) аватар стоял full-frame на хуке, где у автора другой layout. Ниже — рабочая методология, которая дала результат «один в один».

**МЕТОД 1 — АВАТАР-ЯКОРЬ + ВСТАВКИ АВТОРА 1:1 ПО ТАЙМКОДАМ (дефолтный способ сборки talking-head реплики).** Это конкретная реализация ЗАКОНОВ 1+2, защищённая от протечки автора:
- **Аватар = НЕПРЕРЫВНАЯ БАЗА** на всём таймлайне (talking-head якорь, синхрон к нашему RU-аудио). По умолчанию в кадре аватар.
- **Вставки = ОРИГИНАЛЬНЫЙ футаж автора 1:1**, вырезанный из ИСХОДНИКА по таймкодам (UI-скринкаст / кинематографичный бролл / код / B-roll). 🔴 НИКОГДА не рисовать свои мокапы/гриды/lib-клипы вместо выводов автора — это и был «говняный» брак. Реюз нашей `lib/` поверх места выводов автора = FAIL.
- **Окна вставок = КОМПЛЕМЕНТ к зонам головы автора.** Детектор голов автора по исходнику (фронт-лицо + СТУДИЙНЫЙ фон + кожа в HSV + центр кадра) даёт диапазоны, где автор-ведущий; вставки берём из ОСТАЛЬНЫХ окон, с ОТСТУПОМ ±0.3-0.5с от границ голов. Так автор-ведущий физически не может протечь (в worst case — лишний аватар, это якорь, не дефект).
- **Тайминг:** наш ролик = длина RU-аудио; исходный таймлайн масштабируется (k = audio/orig), биты идут в том же ПОРЯДКЕ и пропорции. Аватар-бит берёт `full_avatar[our_t]`, вставка-бит берёт `orig[orig_t]`.
- Перед выдачей: прогнать `foreign-face-gate` (см. МЕТОД 3) + покадрово свериться оригинал↔реплика на одних таймкодах (сетка пар).

**МЕТОД 2 — ПЛАШКА СУБТИТРОВ КОМПАКТНАЯ (🔴 ПЕРЕКРЫВАЕТ правило по решению автора «~1000px почти на всю ширину»).** автор: «плашка в три раза больше, должна аккуратно закрывать только субтитры автора». Правило:
- СНАЧАЛА ИЗМЕРИТЬ реальную полосу субтитров автора (одна строка ≈ y1355-1415, высота ~60px у этого источника; мерить по ярким текст-строкам в нижней зоне), плашка кроет ИМЕННО её с небольшим запасом (высота ~90-100px, не 230+).
- ШИРИНА = по нашему тексту (`max(текст+~90, небольшой floor)`), НЕ форсить ~1000px / «на всю ширину». Широкая плашка нужна ТОЛЬКО если субтитр автора реально широкий (длинная строка) — тогда крыть по его ширине. Короткий центрированный субтитр автора → узкая плашка по нашему тексту.
- ПЛАШКА НЕПРОЗРАЧНАЯ alpha=255 (при 0.9 чужой текст ПРОСВЕЧИВАЕТ снизу — было). БЕЗ drop-shadow за белым текстом (тень двоит контур = «размытие», прецедент жалоба «11с размыто»). Белый текст + чистая тёмная плашка, без тени.

**МЕТОД 3 — foreign-face-gate ЛОЖНО ФЕЙЛИТ на AI-лицах бролла.** Гейт детектит ЛЮБОЕ лицо; кинематографичные выводы автора (самурай, AI-люди) = генеративные лица → FAIL на легальном футаже 1:1, который по «один в один» обязан остаться. Разрешение до правки гейта: (1) визуально сверить флагнутые таймкоды = это броллы, не competitor-ведущий; (2) прогнать СТРОГИЙ детектор именно автора-ведущего (фронт-лицо + СТУДИЙНЫЙ teal-фон + кожа>0.12 + центр) по окнам вставок исходника — 0 кадров автора = чисто, FAIL гейта = ложный, задокументировать в DELIVERY-REVIEW. 🔴 TODO-хук: добавить в `foreign-face-gate.py` либо `generative_broll:true` per-bit exempt в спеке, либо вторичную автор-специфичную проверку, чтобы не фейлить бролл.

**МЕТОД 4 — СУБТИТРЫ КЛАСТЬ БЫСТРЫМ PIL-OVERLAY, НЕ EAST-detect по кадрам.** `subtitle-cover.py --detect` (EAST покадрово) на этой сборке ЗАВИС ~1.5 часа. Дефолт: рендерить PNG (плашка+белый текст) по каждому cue через PIL → один проход `ffmpeg overlay ... enable='between(t,start,end)'` (быстро, секунды). EAST-detect — только если реально нужна авто-детекция полосы, и ОБЯЗАТЕЛЬНО под `timeout`. 🔴 TODO: вынести быстрый путь в `scripts/subtitle-fast-overlay.py` как дефолт + таймаут на EAST в subtitle-cover.

## 🔴🔴 СВОДКА ПОВТОРЯЮЩИХСЯ ОШИБОК 

> Эти 11 пунктов — механика принципа «вырезки автора 1:1, себя генерируем» по конкретным граблям. Часть дублирует законы ниже намеренно (поднята в начало, чтобы агент не пропустил). Любой пункт = брак, не выдавать.

**СУБТИТРЫ**
1. **Наши субтитры = КАРАОКЕ ≤3 слова**, быстро появляются и пропадают. НИКОГДА не статичная плашка-абзац и не «широкая маска с длинным текстом». 🔴 МАШИНА: `subtitle-cover.py` блокирует рендер любого cue с >3 слов (exit 1 «СУБТИТР-АБЗАЦ»; порог `--max-karaoke-words`). Selftest: `subtitle-cover-selftest.py` CHECK 1 (позитив 3 слова / негатив 4 слова).
2. **Наши субтитры покадрово ПЕРЕКРЫВАЮТ субтитры автора** (та же позиция, та же высота плашки = по высоте оригинальных субтитров). Плашка под субтитрами НЕПРОЗРАЧНАЯ и ТЕМНЕЕ оригинала — оригинал не должен просвечивать ни на одном кадре, ни с одной стороны (`subtitle-cover.py --detect`, ширина max(текст+130, ~1000px)). 🔴 МАШИНА: `subtitle-cover-selftest.py` CHECK 3 проверяет residual чужого текста по ЦЕНТРУ И по ЛЕВОМУ/ПРАВОМУ краю плашки + что плашка по высоте полосы (короткая плашка → их текст просвечивает = негатив-кейс).
   - **🔴 2a. ПЛАШКА = РАЗМЕР ПЛАШКИ АВТОРА + пара мм. НЕ «жирный бар» и НЕ «впритык к тексту» (автор, дважды поправил).** Прецедент <твой-прошлый-проект>: (1) сначала сделал высокий бар 180-227px до двойника — «жрёт пространство»; (2) перекрутил в другую сторону, плашка впритык к тексту (text+22 высота, text+70 ширина) — «тоненькие, кривые, тоньше оригинала по ширине». Эталон = САМА авторская Submagic-пилюля (замерить её): для текста ~58px высотой плашка ≈ +56px (≈115px пилюля), ширина = `текст + ~150px` (мин ~540px), радиус ~26. То есть плашка = размер плашки автора + пара мм, НЕ хуже (не уже/не ниже) и НЕ толще. В сплите (субтитр на шве) низ плашки прижать к верхней грани двойника, расти вверх до этой щедрой высоты.
   - **🔴 2b. ПОЗИЦИЯ ПЛАШКИ = ДЕТЕКТ субтитра автора ПОКАДРОВО, не фикс (автор).** Прецедент <твой-прошлый-проект>: фиксировал нашу плашку на y≈1165, а у автора субтитр ГУЛЯЕТ по сценам (сплит — на шве y≈830; демо ранний — y≈1160; демо после 30с — y≈1290-1330, под контентом). Фикс-позиция → «с 30-й секунды не попадает, субтитры реально ниже». Правило: детектить полосу субтитра автора в КАЖДОМ кадре (по всей высоте, не только нижние 45%) и ставить нашу плашку РОВНО туда. Детектор робастный: жирный белый текст + эрозия 3×3 убивает тонкий UI-текст + ТЕМПОРАЛЬНЫЙ признак (караоке меняется покадрово, статичный UI — нет → предпочесть меняющуюся полосу) + удержание последней позиции при сбое (скачок >260px = глитч). Боевой образец — `~/<твоя рабочая папка ролика>/build2/subs2.py` (`capdetect`). 🔴 **2b-EAST — ДЛЯ ПЁСТРЫХ/РАДУЖНЫХ ИСТОЧНИКОВ ДЕТЕКТ ПО ЦВЕТУ ПРОВАЛИВАЕТСЯ → БРАТЬ EAST text-детектор (автор, <твой-прошлый-проект>).** Прецедент: на мульт-источнике (жёлтое караоке на радужном фоне + слои UI-текста) `capdetect` по белому/жёлтому ловил СЦЕНЕРИЮ клипа, не субтитр — ~13 итераций промахов. Bbox EAST-маски покадрово → позиция+ширина+высота нашей плашки (плашка = bbox + поля, гарантированно накрывает). Сглаживать медианой (окно ~9 кадров) = без джиттера. Боевой образец — `~/<твоя рабочая папка ролика>/build/finalize2.py` (читает EAST-маски `subtitle-remover/detect.py` → плашка по bbox). EAST дал попадание на КАЖДОМ бите там, где цветовой детект мазал. **Где у автора субтитр стоит ВНЕ EAST-полосы (напр. большой текст ВВЕРХУ слайда y<900) — точечный manual-override позиции на этот бит.** Если плашка-кавер всё равно «ужасно» по виду (автор) и нужен Инста-чистый результат — единственный путь убрать авторский субтитр СОВСЕМ = `subtitle-remover` ProPainter (нужно ≥8ГБ свободной RAM, гнать с закрытыми приложениями/ночью). 🔴 **Плашка ВЫШЕ детектнутой полосы в ОБЕ стороны (автор, итерация по пикселям).** Детектор ловит яркое ЯДРО текста, а реальный субтитр автора (glow/обводка/descender) выходит за него и сверху, и снизу. Если центрировать плашку впритык по ядру — вылезает снизу; сдвинуть вниз — вылезает сверху. Решение: НЕ шифт, а высота с запасом В ОБЕ СТОРОНЫ — `ph = max(текст, детект) + ~100px` (≈±50 за ядро), центр по детекту (можно +10-14px вниз, т.к. детект смещён вверх). Проверять кропом ОБЕ кромки (верх и низ), не одну.
3. **Шрифт субтитров ОДНОЦВЕТНЫЙ, НЕ жёлтый.** Один чистый цвет (белый) + обводка/тень. ⚠️ Это уточняет старый «white+yellow key» — жёлтый ключ УБИРАЕМ. Субтитры НИКОГДА не на лице спикера (`subtitle-face-check.py`). 🔴 МАШИНА: `subtitle-cover-selftest.py` CHECK 2 — пиксельный чек доминирования жёлтого в зоне нашего текста (>35% ярких пикселей жёлтые = FAIL; позитив белый / негатив синтет. жёлтый).
   - **🔴 3a. АВТО-ФИТ ШРИФТА — СУБТИТР НИКОГДА НЕ ВЫЕЗЖАЕТ ЗА КРАЯ (автор, reel-DZMhFWotKBn, дважды «выезжают за края везде»).** Фикс-кегль НЕ годится: длинный cue торчит за кадр.
