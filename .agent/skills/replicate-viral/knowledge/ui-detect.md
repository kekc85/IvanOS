# ui-detect.md — как читать отчёт «UI-РЕПЛИКАЦИЯ ВЕРХА»

`scripts/ui-detect.py <video.mp4> [--out report.md] [--fps 1] [--debug]`

## Зачем
Агент на Opus, разбирая виралку, не понимал ЧТО у конкурента на верхнем экране (выше
лица / сплит-линии) — скринкаст реального инструмента? отрисованный анимированный UI-мок?
hero-вставка фотореала? — и потому не мог отрисовать так же. Этот скрипт ВИДИТ верхнюю зону
эвристиками (без платных API) и выдаёт машиночитаемую инструкцию репликации по сегментам.

## Как работает
1. Семплит кадры (по умолчанию fps≈1).
2. На каждом кадре детектит лицо (haar-cascade, как в `scene-audit.py`) → определяет сплит-линию.
   Лицо внизу → верх = UI-зона (режем чуть выше лица). Лицо занимает верх → `full-author`.
   Лица нет → берём верх до 0.78 высоты (низ = аватар-зона).
3. Считает числовые признаки верхней зоны и классифицирует балльной системой.
4. Склеивает подряд идущие кадры одного класса в шоты (t0–t1), пишет markdown-таблицу.

## Классы и маппинг класс → действие

| класс | что это | действие репликации (колонка отчёта) |
|---|---|---|
| `real-screencast` | запись реального UI (тулбары, панели, ряды мелкого текста, dark-mode хром) | **footage-fetch.sh** — записать/добыть скринкаст ТОГО ЖЕ сервиса, что у автора (открой кадр, опознай инструмент) |
| `animated-ui-mock` | отрисованный мок: плоская ЯРКАЯ/насыщенная заливка + крупная типографика | **G-ui-mocks блок** (`motion-blocks/_INDEX.md`) + выданные доминирующие цвета (#hex) + флаг крупный/мелкий текст |
| `hero-footage` | фотореал-вставка (рендер продукта, интерьеры, сцена), высокая текстурная энтропия | **footage-fetch.sh** галерея ИЛИ **Higgsfield-generate** (сгенерить фотореал-вставку) |
| `full-author` | лицо занимает верх — говорящая голова, не UI | — (ничего реплицировать в верхней зоне не надо) |

## Как читать таблицу
- **сегмент (t0-t1)** — временной интервал шота. Раскладывай верх по этим интервалам.
- **conf** — честная уверенность 0..1. `(не уверен)` при conf<0.45 — ОБЯЗАТЕЛЬНО открой кадр глазами и перепроверь, не полагайся на класс.
- **почему** — какие числовые сигналы сработали (неон-заливка, UI-сетка, энтропия…).
- **действие репликации** — что именно делать; для моков тут УЖЕ лежат hex-цвета (брать как есть в G-ui-mocks).
- **Доминирующий тип верха** (внизу) — главный режим верха ролика: с него и начинай сборку.

## Что несут признаки (для отладки `--debug`)
- `neon_frac` — доля кислотно-насыщенных ярких пикселей. Высокий ⇒ мок (неон-фон).
- `fill_frac` — dom_frac, засчитанный в мок ТОЛЬКО если доминант — яркая/насыщенная заливка
  (а не near-black). Это ключевая правка: dark-mode скринкаст имеет высокий dom_frac на чёрном
  фоне, но это НЕ мок — `dom_is_dark` гасит ложный мок.
- `text_rows_frac` — доля строк с рядами мелкого текста. Высокий ⇒ screencast.
- `ui_grid` — число длинных вертикальных/горизонтальных рёбер (панели/тулбары). ≥6 ⇒ жёсткая UI.
- `entropy` — текстурная энтропия яркости. >4.2 без UI-структуры ⇒ hero-footage.
- `dom_is_dark / dom_is_fill` — тёмный near-black доминант vs яркая designed-заливка.

## Ограничения эвристик (ЧЕСТНО)
- **Точность не 100%.** Это эвристики по пикселям, не семантика. conf<0.45 и `(не уверен)` — всегда сверять кадром.
- **OCR опционален.** Без `tesseract` слова в моках НЕ распознаются — крупность текста оценивается по
  форме (мало строк + есть края + плоская заливка), без чтения слов. С установленным tesseract можно
  расширить (сейчас честно пропускается).
- **3-зонные кадры** (hero + screencast + автор разом): скрипт читает ДОМИНАНТУ верхней зоны над лицом.
  Если сверху крупный фотореал-рендер, а ниже node-граф — вернёт hero (по доминанте верха). Это честный
  «что крупнее видно», но для тонкой раскладки 3 зон — открывай кадр.
- **Какой ИМЕННО инструмент** в скринкасте скрипт не называет (нет распознавания бренда UI) — выдаёт
  «тот же сервис, что у автора (см. кадр)»; опознание инструмента — за агентом по кадру.
- **Граница mock↔screencast** на тёмном моке с мелким текстом размывается (см. DZF t≈11.7, conf 0.48) —
  низкая conf честно это показывает.
- Детект лица — frontal haar: профиль/сильный поворот/перекрытие может не словиться → сплит уедет к 0.78.

## Где это в конвейере replicate-viral
Фаза 3a добытчика: `footage-fetch.sh` тянет официальный футаж. ui-detect выдаёт «что добывать» для
real-screencast/hero шотов и «какой G-ui-mocks блок + цвета» для mock-шотов. Интеграцию в SKILL.md
делает оркестратор (этот скрипт SKILL.md не трогает).
