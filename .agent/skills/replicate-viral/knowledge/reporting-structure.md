> Корень: машинерия фаз и посегментного ревью есть (`phase-gate.py`, `chunk-review-gate.py`,
> L0–L7, панель критиков), НО автор видел «ничего не даёшь» — отчёт по фазам не предъявлялся,

> (улика для машинного гейта). Текст в чат = читает автор; файл = проверяет `report-gate.py`.

## A. ОТЧЁТ ФАЗЫ — после КАЖДОЙ фазы Ф1…Ф7 (обязателен)

Файл: `<project>/reports/f<slug>-report.md` (slug = id без «Ф» и точек: Ф1→`f1`, Ф2→`f2`,
Ф2c→`f2c`, Ф3→`f3`, Ф4→`f4`, Ф4.6→`f46`, Ф5→`f5`, Ф6→`f6`, Ф7→`f7`). Плюс этот же текст — в чат.

Фиксированный формат (НЕ менять порядок полей — гейт ждёт улику-путь и вердикт):

```
📋 ФАЗА <id> — <название> — <✅ done | 🟡 done-with-concerns | ❌ blocked>

ЧТО СДЕЛАЛ: <2-4 строки конкретики, без воды; что именно произведено>
УЛИКА: <реальные пути к артефактам фазы — файлы/JSON/кадры; гейт проверит, что путь существует>
ГЕЙТ ФАЗЫ: <какой машинный чек прогнан + результат: «phase-gate Ф4 PASS» / «scene-audit exit0» /
            «voice-qa md5=abc123…» / «layout-contract rc=0»>
ЧИСЛА: <метрики фазы если есть: motion-ratio vs эталон, headroom px, cps, LUFS, кредиты, длит-ть; иначе —>
РИСК / ЧТО НЕ ВИЖУ: <blind-spot 1 строкой; если чисто — «—»>
ДАЛЬШЕ: <следующая фаза + что в ней произойдёт>
```

Правила:
- Вердикт `❌ blocked` = фаза не закрыта, дальше НЕ идём (внешний блокер фиксируем одной строкой,
  идём до максимума без него — Правило №1 CLAUDE.md).
- `🟡 done-with-concerns` = сделано, но есть флаг — назвать его явно в РИСК, не прятать.
- УЛИКА обязана содержать ≥1 реально существующий путь (пустой отчёт = фабрикация, гейт ловит).
- Без воды и самопохвалы: факты + числа + улики. Это рабочий отчёт, не маркетинг.

Соответствие фаз и их главных улик (из `phase-gate.py`):

## Почему файл + чат, а не «мысленно»
автор: «каждый раз давай, что ты мне ничего не даёшь». Мысленный/устный проход = пропуск под
нагрузкой (тот же корень, что у per-chunk ревью). Файл = нефабрикуемая улика для машины; чат =
видит автор. Структура одна, вызывается ВСЕГДА: после каждой фазы (A) и на выдаче (B).
