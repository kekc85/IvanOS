# source-deconstruction — покадровый деконструктор источника (вход Фазы 2c)

**Назначение:** убить корневой брак `Build-on-guess` (RC-A, ANTI-METHODOLOGY) — реплицировать
механику эталона ИЗ ВЕРИФИЦИРОВАННЫХ КАДРОВ, а не из догадки/памяти. Это «вход» в тропинку
Opus: deconstruction (что РЕАЛЬНО в источнике) → `scene.spec.json` (что строим) →
`scene-assemble.py` (детерминированная сборка). Без покрытой деконструкции сборка НЕ стартует.

**Философия (как в EDL индустрии):** мерило детальности = ПРИВЯЗКА КАЖДОЙ СТРОКИ К ТАЙМКОДУ +
МЕХАНИЗМ, а НЕ объём прозы. Подробно — да; но каждая строка ссылается на реальный извлечённый
кадр (`ffmpeg -ss`), не на фантазию. «Механизм, не "мелькает"» (автор).

---

## Поток

```
ref.mp4  →  deconstruct.sh / ffmpeg -ss  →  кадры  →  заполнить deconstruction.md
         →  deconstruction-check.py  →  .deconstruction-verdict.json (PASS/FAIL)
                                      →  pairs.json (авто, для benchmark-pairs.py)
```

Заполняется НА КАЖДЫЙ ролик в `<project>/deconstruction.md`. Объявляется в `project-meta.json`
ключом `deconstruction`. Проверяется машинно перед Фазой 6.

## Формат (markdown-таблица — автор читает+апрувит на концепт-экране, скрипт парсит)

Заголовок таблицы ОБЯЗАН быть дословно таким (парсер ищет эти колонки):

```
| t_start | t_end | frame | layout | shows | motion | text | sfx | block | bench |
```

| Колонка | Что | Правило валидатора |
|---|---|---|
| `t_start` `t_end` | границы бита, сек (float) | покрытие сплошное от 0 до длительности источника; НЕТ дыр; на первых 3.0с шаг `t_end-t_start` ≤ 0.5с; **на ДИНАМИЧНОЙ зоне бит ≤1.0с** (правило ниже) |
| `frame` | путь к РЕАЛЬНО извлечённому кадру (`frames/d_NNN.jpg`) | файл ДОЛЖЕН существовать (привязка к источнику; нет кадра = догадка) |
| `layout` | раскладка в этот бит, СТРОГО из enum: `full-head` / `split` / `full-ui` / `full-broll` / `anchor-rotate` | ОБЯЗАН быть И ∈ enum (валидатор FAIL на чужое значение). `full-demo` принимается как АЛИАС `full-broll` (обратная совместимость со scene-spec). Единый источник enum — `scripts/layout_enum.py` |
| `shows` | что РЕАЛЬНО показано в источнике (настройка→модель→результат) | непустой |
| `motion` | МЕХАНИЗМ: `static` / `video` / `push-in` / `ken-burns` / `cut` / `cursor-trace` / `highlight-sweep` / `word-pop` / `scroll`(только если в источнике реально скролл) | непустой; динамику реплицируем динамикой |
| `text` | титр/саб в этот бит: `title:<…>` / `caption:<…>` / `none` | обязан быть (none допустимо) |
| `sfx` | звук-событие, если есть: `whoosh`/`click`/`ding`/`riser`/… или `-` | опционально |
| `block` | резолв в enum-блок `scene.spec.json` (см. ниже) ИЛИ `-` если бит не строится блоком | если непусто — ДОЛЖЕН быть реальным блоком И строка ДОЛЖНА иметь `frame` (запрет выдуманного эффекта без кадра-улики) |
| `bench` | `★label` если этот бит = якорь бенчмарка (hook/showcase/ui-demo/payoff/cta), иначе `-` | из этих строк авто-генерится `pairs.json` (5-7 якорей) |

### enum-блоки scene-spec (резолв колонки `block`)
Валидатор грузит допустимый список из `~/.business/growth/assets/motion-blocks/_index.json`
(или fallback — меню `knowledge/scene-spec.md`). Базовое меню:
`E5-perspective-grid-floor` · `K3-overlap-card-avatar` · `O6-avatar-feathered-fill` ·
`A18-title-strap-caps` · `F5-ai-model-icon-row` · `G24-repo-file-list` · `G25-readme-card` ·
`G26-glow-frame-highlight` · `G27-command-input-typeon` · `J5-word-stream-whisper-sync`.
Неизвестный block = FAIL (выдуманный эффект). `-` = бит без блока (чистый кадр/спикер).

## Правила заполнения

1. **Кадры сначала.** `deconstruct.sh <ingest-dir>` или `ffmpeg -ss <t> -i ref.mp4 -frames:v 1 frames/d_NNN.jpg`. Строка без существующего `frame` = FAIL.
2. **Хук плотнее.** Первые 3с — шаг ≤0.5с (хук решает всё). Дальше — по битам (новая мысль/раскладка = новый бит), как ложатся 8/13/9с по смыслу.
2a. **🔴 Посекундно на динамике (AC1, автор).** Если зона ДИНАМИЧНА — бит ≤1.0с, иначе валидатор FAIL «разбей мельче». Зона динамична, когда `layout` бита ∈ {`full-head`, `split`} ИЛИ соседний бит имеет ДРУГОЙ `layout` (смена раскладки = монтаж). Залипший длинный бит на динамике нельзя реплицировать кадр-в-кадр. Статичный длинный b-roll (`full-broll` встык с тем же layout) — можно держать длинным.
3. **Механизм, не "мелькает".** В `motion` — КАК именно (push-in на контент, не «эффект»). `scroll` ставить ТОЛЬКО если в источнике реально скролл (анти-RC-A).
4. **Верность источнику.** `shows` = что РЕАЛЬНО в кадре (тот сайт, та анимация), не «удобная замена» (анти-RC-B). Динамику (`video`) не упрощать до `static`.
5. **Запрет выдуманного.** `block` без `frame` = FAIL: нельзя заявить эффект для бита, который не извлечён из источника (анти-BENCH-2).
6. **Якоря бенчмарка.** Пометить 5-7 ключевых битов `★label` в `bench` — из них генерится `pairs.json` (не «из головы агента», анти-BENCH-1).
7. **Проверка скептиком.** После заполнения — второй агент-скептик сверяет таблицу с кадрами (презумпция «врёшь»); расхождение = переписать, сборку не начинать.

## Пример (фрагмент, реальный источник)

> ref.mp4 = талкинг-хед разбор тула, dur 28с. Кадры в `frames/`.

```
| t_start | t_end | frame | layout | shows | motion | text | sfx | block | bench |
|---|---|---|---|---|---|---|---|---|---|
| 0.0 | 0.5 | frames/d_001.jpg | full-head | спикер крупно, текст-хук влетает | push-in | title:ОН СЛИЛ ВСЁ | whoosh | A18-title-strap-caps | ★hook |
| 0.5 | 1.0 | frames/d_002.jpg | full-head | спикер, титр держится | static | title:ОН СЛИЛ ВСЁ | - | A18-title-strap-caps | - |
| 1.0 | 1.5 | frames/d_003.jpg | split | верх = демо тула (видео), низ спикер | video | caption:вот что он сделал | click | K3-overlap-card-avatar | - |
| 1.5 | 3.0 | frames/d_004.jpg | split | демо крутится, спикер говорит | video | none | - | K3-overlap-card-avatar | ★showcase |
| 3.0 | 9.0 | frames/d_006.jpg | full-ui | экран тула, ряд моделей, глоу на выбранной | push-in | caption:выбираешь модель | - | F5-ai-model-icon-row | ★ui-demo |
| 9.0 | 16.0 | frames/d_014.jpg | full-ui | репозиторий, файлы появляются | video | none | ding | G24-repo-file-list | - |
| 16.0 | 24.0 | frames/d_024.jpg | split | результат-сайт + спикер реагирует | video | caption:за 8 секунд | - | K3-overlap-card-avatar | ★payoff |
| 24.0 | 28.0 | frames/d_028.jpg | full-head | спикер, призыв | static | title:напиши СЛОВО | riser | A18-title-strap-caps | ★cta |
```

Покрытие 0.0→28.0 сплошное; первые 3с шаг ≤0.5с; каждый блок имеет кадр; 5 якорей бенчмарка.

> ⚠️ **Пример упрощён до читаемости.** Под правило 2a (посекундно на динамике) длинные
> `split`-биты `1.5→3.0` и `16.0→24.0` ОБЯЗАНЫ быть раздроблены на под-биты ≤1.0с
> (`split` ∈ динамичных), иначе валидатор FAIL. В боевой таблице эти строки разбиваются
> мельче с привязкой кадра на каждый под-бит — здесь склеены, чтобы не раздувать пример.
