# 01-router.md - Mode + Platform + Language detection

Первый этап workflow. Detects mode (Plan / Spark / Transcript), platform target (X / Threads / both), language (RU / EN), и subject (автор / ученик).

## Step 1 - Load config

Read `~/.claude/skills/tweet/config.md` → extract:
- `subject.language_default`
- `subject.x_handle` / `subject.threads_handle`
- `platform.default_target`
- `voice.primary_register`
- `paths.*`

Если config неполный или отсутствует - invoke `00-onboarding-student.md`.

## Step 2 - Detect mode by input signal

| User input | Mode | Next |
|---|---|---|
| `/tweet` без аргументов | **Plan** | `01a-plan.md` |
| `/tweet --plan` или «по плану» / «смысл дня» / дата | **Plan** | `01a-plan.md` |
| `/tweet про X` / «напиши твит про X» / «тред про X» | **Spark-B1** | `01b-spark.md` (B1) |
| `/tweet --spark` или «дай идеи твитов» / «что писать на X» | **Spark-B2** | `01b-spark.md` (B2) |
| Длинный input >500 знаков ИЛИ «надиктовал для твита» / `/tweet --transcript` | **Transcript** | `01c-transcript.md` |

## Step 3 - Detect platform target

| Сигнал | Platform target |
|---|---|
| Флаг `--x` или «только X» / «только Twitter» | x-only |
| Флаг `--threads` или «только Threads» | threads-only |
| Флаг `--both` или nothing | both (default из `config.platform.default_target`) |
| `subject.x_handle == null` AND `subject.threads_handle != null` | threads-only |
| `subject.threads_handle == null` AND `subject.x_handle != null` | x-only |

## Step 4 - Detect language

| Сигнал | Language |
|---|---|
| Флаг `--ru` | ru |
| Флаг `--en` | en |
| Input language detect | match input language |
| Nothing | `config.subject.language_default` |

## Step 5 - Detect subject

- Если `config.subject.name == "автор"` → subject = ivan
- Иначе → subject = student
- Subject влияет на доступные source paths (автора `.business/` vs ученика `intake/`)

## Step 5.5 - FORM-GOAL ROUTER (HARD, канон формы v2)

> Место рождения цели формы для X / Threads. Выполняется ПОСЛЕ определения mode (Step 2), platform target (Step 3), language (Step 4) и subject (Step 5), ДО handoff в mode-handler. Тип твита (single / mini-thread / mega-thread) на решение не влияет: решает ЗАМЫСЕЛ.

**Зачем шаг существует.** Пока `brief.form_goal` пуст, профильные ветки `04-review.md` (Hook Char Zone Gate по составу хука, нумерация, `form_mode`) не имеют цели для сравнения, а `form_mode` в `04-review.md` даёт HARD FAIL: без этого шага дальше пайплайна двигаться нельзя.

### 5.5.1 Read канона (HARD)

Прочитать `~/.business/voice-corpus/_format-canon-v2.md`, разделы **§0-§4** (что канон отменяет, метод, ГЛАВНОЕ ПРАВИЛО «цель до написания», три профиля формы, кластеры приёмов) и **§9** (статусы HARD / WARN / SOFT). Пометить `mandatory_reads.form_canon_v2 = true`. Путь абсолютный и только этот: `~/.business` - симлинк на шаблон IvanOS, боевой канон живёт в твоём `~/IvanOS` (канон §8.2).

### 5.5.2 Флаг launch_window

Источник - `~/.business/запуски/<активный запуск>/карточка-дня.md`, поле `launch_window` (канон §2.1). Файла нет или поле пусто → **false**. Угадывать флаг запрещено.

### 5.5.3 Дерево решений §2.1 (адаптация под X / Threads)

По признакам ЗАМЫСЛА, не текста. Спрашивать «есть ли ссылка / список / сколько знаков» на этом шаге запрещено.

```
1. launch_window == true ?                                     -> S (продажа)
2. Есть внешний артефакт, который читатель может УНЕСТИ
   (видео, подкаст, статья, урок, практикум, гайд, чек-лист,
    промт, приложение, разбор), и я готов дать на него адрес ?  -> F (репосты)
3. [режим A на X / Threads НЕ ДОСТУПЕН - см. 5.5.5]            -> перейти к следующему пункту
4. Предмет = личный эпизод автора (место, время,
   физическое действие) ?                                      -> R-нарратив
5. Предмет = причинная механика без артефакта
   (почему это работает) ?                                     -> R-разбор
6. Ничего из перечисленного ?                                  -> правило выхода §2.1:
   (а) переупаковать в личный эпизод → R-нарратив
   (б) добавить артефакт и адрес → F
   (в) не публиковать
```

### 5.5.4 Куда применяется профиль: твит-единица и тред целиком

Цель формы **одна на всю публикацию** - две текстовые цели в одном треде запрещены (§2). Профиль применяется на двух уровнях сразу:

- **твит-единица.** Конструкция хука §4.1 применяется к первому твиту (для треда - к твиту 1, он же хук), правила разметки и перечислений §3 - к каждому твиту в отдельности: списочный блок внутри одного твита считается блоком, нумерация `^\d+\.` внутри твита проверяется профильно (§9 S-13 HARD, F-8 разрешён алгоритм 3-5 шагов)
- **тред целиком.** Длина, число выделений, число списочных блоков, число адресов и позиция адреса считаются **по треду как по одному тексту**: `links_rule` (§9 S-4 «якорей 0 или 1 адрес», F-3 «адрес в последних 250 знаках») применяется к треду, а не к каждому твиту, иначе правило одного адреса теряет смысл. Финал §9 (R вывод, F адрес, S живая реплика) - это последний твит треда

### 5.5.5 Режим A недоступен на X / Threads

Реакция-гейт §7 - TG-механика (числовая просьба о реакции эмодзи, приз-контент, срок выдачи, закрытие гейта выдачей). На X / Threads этой механики нет. `form_goal = gate` этот скилл не выставляет никогда, чек-лист §9 «Режим A» помечается `N/A`.

### 5.5.6 Лимиты платформы бьют длины канона (жёстко зафиксировано)

**Лимит символов X / Threads выше по приоритету, чем любой коридор длины из канона §3.** Это физическое ограничение платформы, а не правило письма: канон измерен на TG-постах, где потолка в 280 знаков не существует. Порядок разрешения конфликта:

1. `platform_limit` (X 280 / X Premium 25 000 / Threads 500 - из `config.md`, старое правило без изменений) - **HARD, не снимается ничем**, включая строку override §8.1: канон не может разрешить опубликовать 700 знаков в твит
2. коридор длины канона §3 - **справочный ориентир по треду**, статус WARN (канон §3: «длина не блокирует выдачу ни в одном режиме»)

Конфликт печатается вслух строкой-уликой по §8.1: `конфликт: коридор §3 <min-max> знаков vs лимит платформы <N> -> взял лимит платформы (физическое ограничение носителя, уровень 1 «реальность и факты»)`.

### 5.5.7 Записать в brief

```yaml
brief:
  form_goal: "reactions | forwards | sales"   # значения-слова: их сравнивают гейты 04-review
  form_goal_letter: "R | F | S"               # та же цель буквой, для улики form_mode
  form_class: "narrative | razbor | sales"
  form_topic: "<тема одной фразой>"
  form_scope: "unit+thread"                   # профиль -> и к твит-единице, и к треду целиком
  form_profile:
    length_unit_max: <platform_limit: X 280 | X Premium 25000 | Threads 500>   # HARD, физическое
    length_thread_ref_chars: "<R-нарратив 362-1242 цель 671 | R-разбор 402-990 цель 542 | F 838-1695 цель 1159 | S 759-2248 цель 1489>"
                                # §3.1-3.3, ориентир по треду целиком, статус WARN, лимиту не перечит
    length_status: "WARN (канон) / HARD (лимит платформы)"
    bold_target: <R-нарратив 1 | R-разбор 1-2 | F 3 (ориентир 4) | S 4-5>   # §3, все WARN;
                                # на X разметки жирным нет - пункт печатается как N/A, не как FAIL
    list_blocks_max: <R-нарратив 0 HARD | R-разбор 1 до 3 предикативных пунктов | F 1-2 опись | S 1>
    numbered_list_allowed: <S нет (HARD, 88% верха) | R-нарратив WARN | R-разбор да (25% против 17%) | F да, алгоритм 3-5 шагов>
    links_rule: <R-нарратив 0 HARD | R-разбор WARN-0 | F адрес обязателен HARD, в последних 250 знаках треда | S 0 или 1 адрес HARD>
    hook_digit_required: <R нет числа ≥1000 и круглой метрики канала (HARD), бытовая сумма <1000 ок | F цифра или валюта желательна, 63% против 20% | S без связки «ты+сумма» (HARD, 0/34)>
    hook_len_ref: <R ориентир 60 (≤60 у 70% верха) | F цель 64, ориентир 50 | S цель 36, ориентир 50 (62% верха)>   # всё WARN, §9
    sentence_median_min: <5 только в R-разборе (цель 5.5, 11/12 верха) | null>
    final_rule: <R вывод или жест | F адрес в последних 250 знаках треда | S живая реплика, не URL>
```

### 5.5.8 Улика одной строкой (обязательна)

Формат ровно тот, что ждёт `form_mode` в `04-review.md`. Цель печатается словом (значение для гейтов), буква - в скобках только для быстрого чтения человеком; тот же порядок, что в `01-finalize.md` Шаг 4.5:

```
форма: цель=<reactions|forwards|sales> (<R/F/S>) класс=<narrative/razbor/sales> тема=<...> -> длина <min-max>, жирный <N>, перечислений <N>, ссылок <N>, цифра в хуке <да/нет>
```

В поле «длина» печатать обе величины: `<лимит платформы N знаков на твит> / <ориентир §3 min-max по треду>`.

### 5.5.9 Что перекрыто и что остаётся fallback

Ни одно старое правило не удалено:

| старое правило tweet | чем перекрыто при объявленной цели | справочно: как было ДО канона (недостижимо - Гейт 0 блокирует раньше) |
|---|---|---|
| Hook Char Zone Gate (dead zone 100-200 = FAIL) | понижен до WARN, добавлен состав хука по профилю (§8.2: зоны заимствованы из чужого исследования) | было WARNING (см. `04-review.md`) |
| «1. ОК в beats, не в final tweet» | профильно: S FAIL, R-нарратив WARNING, R-разбор разрешено, F алгоритм 3-5 шагов | было без изменений |
| `templates/numbered-list.md` | шаблон условный: только цель `forwards` и только когда цифра работает обещанием в хуке (§8.2) | было доступен всегда |
| «рубленый» как требование в `03-write.md` | `sentence_median_min` только в R-разборе; в R-нарративе признак не различает (6 против 6) | было без изменений |
| лимит символов платформы | **не перекрыт ничем** - см. 5.5.6 | действует всегда (физический лимит, цели не касается) |

**Если шаг пропущен (процедурная ошибка, не легальный режим).** `brief.form_goal` пуст → `form_mode` в `04-review.md` даёт HARD FAIL (Гейт 0, канон §9), выдача текста запрещена целиком, а не переходит на старые пороги. Единственный маршрут починки: вернуться в `01-router.md` **Step 5.5 FORM-GOAL ROUTER** и прогнать дерево канона §2.1 до появления одного из `reactions | forwards | sales`. Столбец «статус при пустой цели» в таблице выше показывает, какие пороги действовали ДО подключения канона - это справка для починки, а не рабочее состояние, в которое можно уйти вместо выбора цели.

```yaml
mode: plan | spark-b1 | spark-b2 | transcript

input_signal: <original user input>
config_loaded: true
form_goal: reactions | forwards | sales | null      # Step 5.5; null = HARD FAIL ниже, не рабочее значение

form_class: narrative | razbor | sales | null
form_topic: "<тема одной фразой>"
form_scope: unit+thread
form_profile: {<см. Step 5.5.7>} | null             # null допустим ТОЛЬКО вместе с form_goal = null
form_evidence_line: "форма: цель=... класс=... тема=... -> длина ..., жирный ..., перечислений ..., ссылок ..., цифра в хуке ..."
mandatory_reads:
  form_canon_v2: true | false
```

→ Hand off to one of `01a-plan.md` / `01b-spark.md` / `01c-transcript.md`.

## Anti-patterns router

- НЕ guess'ить mode если ambiguous - спросить пользователя
- НЕ override `config.subject.language_default` без явного флага
- НЕ trigger Plan mode если `paths.launch_sense_map` отсутствует - fallback на Spark-B2
- НЕ загружать full per-author research файлы - they used только в `04-review.md` для voice match
- НЕ пропускать Step 5.5: цель формы рождается только здесь. Пропуск = `brief.form_goal` пуст = `form_mode: FAIL` в `04-review.md` и весь профильный слой канона в fallback
- НЕ решать цель формы по признакам текста (есть ли ссылка, список, сколько знаков) - только по замыслу, дерево §2.1
