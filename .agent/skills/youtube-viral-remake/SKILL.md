# youtube-viral-remake - виральный YouTube long-form в готовый ролик-заготовку

> Скилл - оркестратор-надстройка. Он НЕ изобретает скриптинг (это делает `[[video]]` mode
> Replication) и НЕ рендерит вертикаль (это `[[reel-to-script]]`/`[[replicate-viral]]`). Он
> закрывает пробел, которого нет ни у одного скилла: сквозная репликация ДЛИННОГО YouTube -
> поиск доказанной виралки → деконструкция структуры удержания → визуальный production-пакет →
> сборка под запись говорящей головы. Модель автора: «быстро запишу голову, система отрисует
> визуал». Скилл производит СЫРЬЁ и черновую сборку под финальный глаз автора - НЕ гарантию
> просмотров и НЕ идеал без ревью (качество видео машина не оценивает, только человек).

## Когда применять

Триггеры:
- `/youtube-viral-remake <тема>` или `/youtube-viral-remake <YouTube-URL>`
- «реплицируй длинный YouTube про X» / «сделай длинный ролик из этой виралки»
- «найди виральный ютуб-ролик для переделки» (в длинный формат, не Shorts)
- «повтори этот YouTube-разбор под меня» / «собери YouTube-ролик под мою запись»
- На выходе нужен production-пакет длинного ролика (скрипт + визуал + сборка), а не заметка

## Когда НЕ применять (разграничение - иначе ломается триггеринг)

- **`[[video]]`** - нужен ТОЛЬКО скрипт видео в голосе автора (любой длины), без визуального ряда
  и сборки. Этот скилл ВЫЗЫВАЕТ `video` для скрипта, но добавляет поиск + деконструкцию + визуал +
  монтаж. Голый скрипт → `video`.
- **`[[reel-to-script]]` / `[[replicate-viral]]`** - вертикаль до 60с (Reels/TikTok/Shorts). Другой
  формат (9:16), другой пайплайн (Seedance до 15с). Этот скилл - только 16:9 long-form.
- **`[[cut-from-long-form]]`** - нарезка СВОЕГО готового long-form в Shorts (обратное направление).
- **`[[найди-виралку]]`** - нужен ТОЛЬКО список виралок без переделки. Этот скилл использует его
  метод поиска как первый шаг, но идёт до готового ролика.
- **`[[ingest-reel]]`** - быстрая analysis-карточка вертикали для контент-завода.

## Что делает (8 фаз, детали в prompts/ - читать по порядку)

| Фаза | Файл | Вход → Выход |
|---|---|---|
| 0 | `prompts/00-onboarding-config.md` | Загрузка/создание config; развилка входа (тема / URL / ничего); выбор `role` (acquisition / launch-lead-magnet) |
| 1 | `prompts/01-find-viral.md` | Тема → массовая YouTube long-form виралка (yt-dlp ytsearch, `duration≥600`, ранж по views) ИЛИ принятый URL |
| 2 | `prompts/02-deconstruct-longform-card.md` | URL → забор (yt-dlp) + транскрипт + деконструкция структуры удержания → `card.md` в ingest-совместимой папке |
| 3 | `prompts/03-delegate-script.md` | `Skill('video')` replicate `<VIDEO_ID>` (tier long-10-60min) → скрипт в голосе автора + chapter map; outcome-language-гейт |
| 4 | `prompts/04-visual-storyboard.md` | Скрипт + chapter map → storyboard 16:9 (per-сегмент UI source path); real-footage-роутер + motion-floor + аватар-букенд |
| 5 | `prompts/05-production-package.md` | Storyboard → готовые промпты отрисовки каждой вставки (скринкаст / hyperframes / Higgsfield); clean-screencast keep-out |
| 6 | `prompts/06-assemble-from-recording.md` | Запись головы автора → whisper word-level → синк по таймкодам → `scripts/assemble.sh` (ffmpeg) → черновик; аутро последним; доставка по role |
| 7 | `prompts/07-verify.md` | `scripts/verify.sh` (exit 0) + бенчмарк против источника и эталона до заявления «готово» |

Два прохода: фазы 0-5 = первый заход (до записи автора), фаза 6-7 = второй (после записи). Состояние
между проходами живёт в `$PROJECT_DIR` (`~/Desktop/yt-remake/<date>-<slug>/` + `project.json`);
второй проход входит веткой `resume` (фаза 00 находит проект по `ls`), не начинает заново.

## Ключевые законы (страхуют исторические грабли - детали в knowledge/)

1. **Только массовые виралки.** Донор = сотни тысяч / миллионы просмотров. Слабый по метрикам
   ролик = механика не доказана, репликация бесполезна. Ранжировать пул, резать низ.
  
2. **Бенчмарк источника 1:1 + по качеству.** Реплицируем структуру удержания и качество эстетики
   конкретного источника, не выдумываем формат. Готово = выглядит так же дорого/цельно, не только
   «механика повторена».,
  
3. **Real-footage-роутер (`knowledge/engine-boundary.md`).** Сегмент показывает реальный
   инструмент/сайт → ТОЛЬКО живой скринкаст (screen-record / CDP) или официальный футаж тула,
   с провенансом URL. hyperframes/Higgsfield → ТОЛЬКО абстракции, диаграммы, титры, метафоры.
   Рисованный HTML-мок реального UI = брак.,
  
4. **Clean-screencast keep-out.** Поверх скринкаста реального UI - ноль оверлеев (чипы/титры/
   бейджи). Подписи идут в другой зоне (шов/поле).
5. **Motion-floor.** Динамика визуала НЕ ниже эталона-источника: новое событие ~каждую секунду,
   не статичный слайд с медленным зумом. `scripts/motion-floor-check.sh --donor <донор>` (scene-
   детекция, порог = донор × 0.8, FAIL блокирует если наш статичнее эталона).
  ,
  
6. **Аватар-букенд под long-form.** Лицо автора видно на хуке + CTA + опорных точках глав;
   середина = визуал-носитель с VO поверх. Не говорящая голова 20 минут подряд.
  
7. **Аутро последним.** Вставки монтируются ПЕРЕД концовкой; финальный кадр = CTA/аутро.
  
8. **Две роли (config).** `acquisition` → CTA лид-магнит + код-слово, доставка публичный YouTube
   по команде. `launch-lead-magnet` → единственное действие РЕГИСТРАЦИЯ, доставка ТОЛЬКО
   localhost+бот, никогда публичный домен. Скилл не смешивает.
  ,
  
9. **Пруф с первой секунды.** Наглядный визуальный пруф на экране с 1-й секунды хука, не пустая
   текст-карточка.

## Гейты по типу артефакта (mixed)

**Text (фазы 02-03, скрипт):** context-gap (нет темы/цифр → спросить, не выдумывать) · mastery-линза
(`virality-attention`: MrBeast/Thompson/Peretti · `storytelling`: McKee/Snyder · `public-speaking`:
Chris Anderson - по `mastery/PROTOCOL.md`) · **outcome-language-гейт** (в outcome для ЦА запрещено
«программирование / MVP / SaaS / приложение / разработчик»; только «мини-продукт / цифровой продукт
эксперта») · **humaniser** (формат-тройка: без клише, без длинных тире, без точки в конце абзаца).
Скрипт делегируется `video` (он несёт свой humaniser+voice-стек), эти гейты - финальная сверка.

**Visual (фазы 04-06):** visual-anchors (реальные кадры эталонов, `visual-anchors/manifest.md`) ·
real-footage-роутер · clean-screencast keep-out · motion-floor · качество финала = глаз автора,
не машина.

## Доставка результата

- Показать в чат: ссылка на оригинал + путь к production-пакету + собранный черновик (открываемо).
- **acquisition:** черновик в открываемом виде; публикация на YouTube ТОЛЬКО по команде автора.
- **launch-lead-magnet:** черновик ТОЛЬКО через localhost + бот, НИКОГДА публичный домен.
- Ничего не деплоить/не публиковать без явной команды. Higgsfield-промпты - под гардом, не жечь
  кредиты сам.

## Portability

Один код у автора и учеников. Различие - `config.md` (кто автор, язык, тема, пути к voice-profile
/ audience / банку смыслов, role по умолчанию). Нет config или неполон → фаза 00 создаёт его
вопросами. Бизнес-специфика (оффер, код-слова) заходит через config как ВХОД, не вшита в логику.
