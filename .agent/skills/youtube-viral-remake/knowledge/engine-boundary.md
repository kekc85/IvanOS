# engine-boundary - водораздел движков (ядро защиты от брака)

Этот файл - жёсткая граница «чем визуализировать что». Он закрывает самый частый класс браков
автора (рисованные HTML-моки реального UI вместо живого футажа, циклы правок ×8). Читается фазами
04 (storyboard), 05 (production-пакет), 06 (сборка). Согласован с законами 3-5 SKILL.md дословно

## 1. Real-footage-роутер (закон 3)

Развилка на КАЖДЫЙ сегмент storyboard: показывает ли он реальный инструмент / сайт / UI

- **Реальный инструмент/сайт/UI в кадре** (Claude Code, VS Code, ChatGPT, браузер, дашборд тула,
  экран приложения) → **ТОЛЬКО живой захват**: screen-record (`screen-record-face-cam` как метод) /
  CDP-скринкаст живого браузера / официальный демо-футаж тула с его лендинга или пресс-кита.
  У каждого захвата - **провенанс**: URL источника (какой сайт/тул) + как снят (screen-record /
  CDP / official). Без провенанса сегмент не принимается
- **НИКОГДА рисованный HTML/CSS-мок реального UI**. hyperframes-композиция, которая изображает
  «как бы Claude Code» / «как бы окно VS Code» / «как бы дашборд» = БРАК. Это класс браков автора,
  циклы ×8: мок выглядит мёртвым, палится за секунду, роняет доверие ролика
 ,
- **hyperframes / Higgsfield / motion-графика → ТОЛЬКО НЕ-реальный UI**: абстракции, диаграммы,
  схемы, титры/лоуэр-тёрды, метафоры, данные-в-движении (числа, графики, стрелки потока),
  переходы-заставки глав. Всё, что НЕ претендует быть конкретным экраном реального тула. Higgsfield
  под гардом - только промпты, не жечь кредиты сам

Тест на границе: «если зритель поверит, что это настоящий экран тула - обязан быть настоящим».
Сомнение «мок или захват» → всегда захват. Нельзя снять вживую (тула нет под рукой, доступ закрыт) →
берём официальный футаж тула, а НЕ рисуем; нет и его → сегмент помечается блокером, не подделывается

## 2. Clean-screencast keep-out (закон 4)

Поверх скринкаста реального UI - **ноль оверлеев**: ни чипов, ни титров, ни бейджей, ни подписей,
ни прогресс-баров, ни «водяных знаков». Скринкаст показывается чистым, как есть


Подписи/пояснения к тому, что на экране, идут в **другой зоне**:
- в **шве** композиции (полоса над/под скринкастом, отдельный слой)
- в **поле экрана** (боковая колонка, нижняя треть ВНЕ области скринкаста)
- в **отдельном кадре** до/после захвата (титр-глава, кадр-подводка)

Причина: оверлей поверх живого UI перекрывает то самое, ради чего показан захват, и делает кадр
грязным. Голова автора (`graphic-overlays`/`embedded-captions`) одевается графикой ТОЛЬКО в зонах
головы, НИКОГДА поверх скринкаста - отдельным проходом после сборки

## 3. Motion-floor (закон 5)

Динамика визуала **не ниже эталона-источника**. Пол:
- новое визуальное событие **~каждую секунду** (смена кадра/плана, движение курсора, появление
  элемента, зум-акцент на конкретную деталь, реальный клик-действие)
- **запрещён** статичный слайд с медленным зумом Ken-Burns как несущий носитель середины -
  это провал удержания
- бенчмарк против источника: если у донора событие ~0.5с, наш пол = не реже - НЕ усредняем вниз
 

Инструмент проверки: `scripts/motion-floor-check.sh` (pixel-diff по кадрам - считает частоту
изменений, сравнивает с эталоном-источником). Сегмент ниже пола → возврат на переработку, не в финал

## 4. Сборка по главам (движок финальной склейки)

Длинный ролик (10-30-60 мин) НЕЛЬЗЯ рендерить одной hyperframes-композицией: headless-браузер
падает по памяти/таймауту на длинной таймлайн-композиции. Поэтому:

- hyperframes рендерит motion/абстракт-клипы **ПО ГЛАВАМ**: ≤N сек на композицию (одна глава =
  один-несколько коротких клипов), чтобы каждая композиция укладывалась в лимит рендера
- скринкасты реального UI пишутся **отдельными файлами** по сегментам (свой захват на сегмент)
- **финальная склейка глав** = ffmpeg concat через `scripts/assemble.sh` (детерминированный):
  голова автора base + вставки по таймкодам через `-loop 1` + concat глав + мукс аудио, аутро
  последним кадром (закон 7)

**НЕ движки сборки** (за границей контракта, не вызывать как сборщик):
- `general-video` - NLE/footage-editing out of scope по его контракту, не собирает запись+вставки
- `faceless-explainer` - ≤3 мин + своя TTS, не синкается под запись головы автора
- готового long-form-сборщика в системе нет → используем ТОЛЬКО СВОЙ ffmpeg-узел `assemble.sh`
  (штатный скрипт скилла = штатный, не самопал в чате)

## 5. Таблица «тип сегмента → чем визуализировать → чем НЕЛЬЗЯ»

| Тип сегмента | Чем визуализировать (можно) | Чем НЕЛЬЗЯ |
|---|---|---|
| Демо реального тула (Claude Code, VS Code, ChatGPT, браузер, дашборд) | Живой screen-record / CDP-скринкаст / официальный демо-футаж тула + провенанс URL | Рисованный HTML/CSS-мок «как бы этот UI»; hyperframes-имитация окна; Higgsfield-«скриншот» |
| Реальный результат/выход (собранное приложение, лендинг, сгенерённый артефакт в браузере) | Живой захват самого артефакта на экране | Мок результата; статичный скриншот с зумом вместо живого взаимодействия |
| Абстрактное объяснение (как работает вайбкодинг, цикл промпт→код, архитектура) | hyperframes: диаграмма, схема потока, анимация-метафора, данные-в-движении | Кадр, притворяющийся реальным экраном тула |
| Данные / метрики / сравнение (числа, «было/стало», рост) | hyperframes / motion: числа-в-движении, графики, счётчики, стрелки | Статичный слайд-таблица без движения (ниже motion-floor) |
| Титр главы / подводка / переход между главами | hyperframes: титр-карточка, лоуэр-тёрд, шот-заставка | Оверлей-титр ПОВЕРХ идущего скринкаста (нарушает keep-out) |
| Метафора / визуальный образ тезиса | hyperframes / Higgsfield (под гардом): абстрактная сцена, метафора | Метафора, замаскированная под реальный UI тула |
| Говорящая голова автора (хук / CTA / опорные точки глав) | Запись камеры/аватара; графика `graphic-overlays`/`embedded-captions` в зоне головы | Графика головы поверх скринкаста; голова 20 мин подряд без визуала-носителя |
| Подпись к тому, что на скринкасте | Отдельная зона: шов / поле экрана / отдельный кадр до-после | Любой оверлей в области самого скринкаста (keep-out) |

Правило разрешения спора по строке: если сегмент показывает нечто, что зритель примет за настоящий
экран реального инструмента - строка «Демо реального тула», путь только через живой захват
