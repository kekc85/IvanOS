# Фаза 00: онбординг + config + развилка входа + выбор роли

Цель: до любого поиска и забора зафиксировать три вещи - (1) рабочий `config.md` автора, (2) какая из трёх веток входа сработала (тема / URL / ничего), (3) роль ролика `acquisition | launch-lead-magnet`. Без этих трёх фаза 01 не стартует - иначе скилл поедет вслепую и соберёт не тот CTA и не ту доставку

## Вход

Сырой ввод пользователя после `/youtube-viral-remake`. Может быть: тема словами, YouTube-URL, пусто, либо флаг роли `--role acquisition|launch`

## Шаги

1. **Загрузить config.md автора:**
   ```bash
   cat ~/.claude/skills/youtube-viral-remake/config.md
   ```
   Это точка адаптации под автора (структура как у `carousel/config.md`: `subject` / `paths` / `voice` + блоки «Для ученика:»). Скилл один у автора и учеников, различие только тут

2. **Если config.md нет или неполон - создать/дополнить вопросами.** Спросить одним нумерованным списком (не по одному), НЕ выдумывать значения:
   - кто автор (`subject.name`)
   - язык вывода RU / EN / both (`subject.language`)
   - ниша/тема-домен (`subject.niche`, у автора - вайбкодинг + нейросети для соло-экспертов)
   - путь к voice-profile (у автора `.business/voice-corpus/_voice-profile.md`)
   - путь к audience/аватару (`.business/audience/`)
   - путь к банку смыслов эталонов (для опоры структуры удержания, см. `knowledge/longform-structure.md`)
   - `role` по умолчанию (`acquisition` | `launch-lead-magnet`)
   Пустой config - не блокер: собрать его тут и записать, дальше идти самому

3. **Развилка входа - определить ветку явно (четыре):**
   - **(а) дал ТЕМУ без URL** (`«реплицируй длинный YouTube про вайбкодинг»`) → ветка `theme` → фаза 01 (поиск донора)
   - **(б) дал YouTube-URL** (`youtube.com/watch?v=...` или `youtu.be/...`) → ветка `url` → фаза 01 ПРОПУСКАЕТСЯ, сразу фаза 02 (донор уже выбран автором, метрики примем при заборе)
   - **(в) не дал НИЧЕГО** (голый `/youtube-viral-remake`) → ветка `empty` → context-gap: спросить одной строкой «тема или ссылка на длинный YouTube-ролик?», НЕ выдумывать тему и НЕ брать случайную. Опора -
   - **(г) ВТОРОЙ ПРОХОД - «собери из записи / продолжи проект / вот запись»** (автор вернулся с записью говорящей головы через дни) → ветка `resume`: НЕ новый проект. Найти папку проекта первого прохода и показать ТЕМУ каждого (из project.json), не только имя папки (важно: у русских тем имя папки = дата+таймстамп, тема читается только из json):
     ```bash
     for d in $(ls -dt ~/Desktop/yt-remake/*/ 2>/dev/null); do
       theme=$(jq -r '.theme_human // "без темы"' "$d/project.json" 2>/dev/null)
       echo "$d - ${theme}"   # jq берёт тему целиком, запятая в теме легальна (не режем по ней)
     done
     ```
     Показать список (папка + тема + дата), автор выбирает (или взять свежий, если один). Прыжок сразу в фазу 06 с найденным `PROJECT_DIR`. Фазы 01-05 не повторяются

4. **Создать/восстановить рабочую папку проекта `PROJECT_DIR` (единый якорь состояния - переживает между проходами):**
   ```bash
   # ветки theme/url - новый проект. Slug латиницей (кириллица в путях хрупка): транслит либо
   # безопасный fallback на VIDEO_ID/таймстамп, чтобы имя папки всегда было ASCII-safe
   RAW="<тема или заголовок донора>"
   # python-slug: транслитерирует кириллицу в латиницу (читаемо + ASCII-safe путь), пробелы/спец→дефис.
   # sed/iconv на macOS кириллицу теряют - python надёжнее
   SLUG=$(python3 -c "
import sys,re
t=sys.argv[1].lower()
m={'а':'a','б':'b','в':'v','г':'g','д':'d','е':'e','ё':'e','ж':'zh','з':'z','и':'i','й':'y','к':'k','л':'l','м':'m','н':'n','о':'o','п':'p','р':'r','с':'s','т':'t','у':'u','ф':'f','х':'h','ц':'c','ч':'ch','ш':'sh','щ':'sch','ъ':'','ы':'y','ь':'','э':'e','ю':'yu','я':'ya'}
t=''.join(m.get(c,c) for c in t)
t=re.sub(r'[^a-z0-9]+','-',t).strip('-')[:40]
print(t)
" "$RAW")
   [ -z "$SLUG" ] && SLUG="yt-$(date +%H%M%S)"   # fallback только если тема пустая
   PROJECT_DIR=~/Desktop/yt-remake/$(date +%F)-${SLUG}
   # коллизия: два прогона в день с одной темой не должны затирать друг друга - суффикс -2/-3
   if [ -e "$PROJECT_DIR" ]; then n=2; while [ -e "${PROJECT_DIR}-${n}" ]; do n=$((n+1)); done; PROJECT_DIR="${PROJECT_DIR}-${n}"; fi
   mkdir -p "$PROJECT_DIR/segments"
   # записать project.json через jq -n --arg (НЕ heredoc: тема с кавычкой/бэкслешем рушит heredoc-JSON;
   # jq экранирует любой спецсимвол → валидный json всегда):
   jq -n --arg slug "$SLUG" --arg theme "$RAW" --arg role "<acquisition|launch-lead-magnet>" \
         --arg branch "<theme|url>" --arg created "$(date +%F)" --arg seg "$PROJECT_DIR/segments" \
     '{slug:$slug, theme_human:$theme, role:$role, branch:$branch, created:$created,
       ingest_dir:"", script_path:"", segments_dir:$seg, recording:"", out:""}' \
     > "$PROJECT_DIR/project.json"
   ```
   Ветка `resume` - НЕ создаёт, а читает `$PROJECT_DIR/project.json` выбранного проекта. ВСЕ последующие фазы пишут артефакты в `$PROJECT_DIR` (storyboard.md, production-package/, script.md, out.mp4) и дописывают пути в project.json. Это чинит разрыв состояния между фазами и проходами

5. **Выбрать роль ролика и провести её как флаг через все фазы** (закон №8 SKILL.md, скилл роли НЕ смешивает):
   - **`acquisition`** (top-of-funnel YouTube): CTA = лид-магнит + код-слово в комменты. Доставка - публичный YouTube ТОЛЬКО по явной команде автора
   - **`launch-lead-magnet`** (закрытый разбор за регистрацию): единственное действие зрителя = РЕГИСТРАЦИЯ, никакого код-слова и домашки. Доставка - ТОЛЬКО localhost + бот, НИКОГДА публичный домен
   Роль берётся из `--role`, иначе из `config.role.default`, иначе спросить одной строкой. Записать в `project.json`

6. **Зафиксировать резюме входа в чат** (одним блоком): автор · язык · ветка входа (`theme`/`url`/`empty`/`resume`) · тема или URL · роль · `PROJECT_DIR`. Это контракт для следующих фаз

## Выход

- рабочий `config.md` (существует, ключевые пути заполнены)
- `PROJECT_DIR` создан (или восстановлен при `resume`) с `project.json` - единый якорь состояния
- ветка входа: `theme` | `url` | `empty` | `resume`
- при `theme` - строка темы для фазы 01; при `url` - URL для фазы 02; при `resume` - прыжок в фазу 06
- роль: `acquisition` | `launch-lead-magnet`

## Гейт

Не переходить дальше, пока роль И ветка входа НЕ определены явно И `PROJECT_DIR`/`project.json` не создан (или восстановлен при `resume`). Ветка `empty` = стоп и вопрос, не гадать. Роль не выбрана = стоп, не идти с дефолтом «acquisition» молча (доставка и CTA разные - ошибка роли = брак по всему ролику)
