# Фаза 06: сборка черновика под запись автора

Второй проход скилла. Первый (фазы 00-05) шёл ДО записи. Здесь автор прислал запись говорящей головы,
вставки отрисованы по инструкциям фазы 05 - собираю черновик ffmpeg-узлом: голова = base-track,
motion/скринкаст-вставки бурнутся по таймкодам речи, аутро остаётся последним кадром

## Цель

Из записи автора + отрисованных вставок (`segments-dir`) собрать открываемый черновик ролика 16:9,
выровненный по реальной речи, с аутро последним кадром, доставленный по `role`. Машина собирает
черновик - качество видео (motion, синхрон, эстетику) оценивает глаз автора, не скилл


## Вход

- `$PROJECT_DIR` из `project.json` (ветка `resume` фазы 00 нашла его по `ls ~/Desktop/yt-remake/`)
- `<recording.mp4>` - запись говорящей головы автора (base-track с исходным аудио), путь в project.json
- `$PROJECT_DIR/production-package/shotlist.md` + отрисованные клипы в `$PROJECT_DIR/segments/`
  (`seg-NN.mp4`/`seg-NN.png`, имена строго по № сегмента из shotlist)
- `$PROJECT_DIR/storyboard.md` (фаза 04) - целевой порядок и таймкод-окна вставок по главам
- `config.md` / `project.json`: `role` (acquisition / launch-lead-magnet)

## Шаги

0. **Загрузить состояние проекта.** Прочитать `$PROJECT_DIR/project.json` (ветка `resume` фазы 00
   уже нашла папку). Взять `RECORDING` (путь к записи автора - спросить/принять, если ещё не в json),
   `role`, `segments_dir`. Проверить: `storyboard.md`, `production-package/shotlist.md`, клипы в
   `segments/` на месте. Нет записи → context-gap: спросить путь к файлу записи, не выдумывать

1. **Whisper word-level транскрипт записи.** Реальная речь автора редко ложится ровно в плановые
   таймкоды - выравниваю storyboard по фактической речи:
   ```bash
   whisper "$RECORDING" --model medium --word_timestamps True --output_format json --output_dir "$PROJECT_DIR/asr"
   ```
   Даёт `recording.json` со словами и их таймкодами. medium - баланс точность/скорость для RU/EN

2. **Выровнять сегменты по речи И записать `manifest.tsv`** (это вход assemble.sh - БЕЗ него черновик
   соберётся как голова без единой вставки). По транскрипту найти где в реальной записи начинается
   смысл каждой главы/вставки (якорь = первые слова главы из `$PROJECT_DIR/script.md`). Получить
   фактические окна `t0..t1` - реальные из речи, не плановые. Затем из `shotlist.md` собрать
   `$PROJECT_DIR/manifest.tsv` в формате `type<TAB>start<TAB>end<TAB>file` (одна строка на вставку):
   - `type` определяется по РАСШИРЕНИЮ файла клипа (детерминированно, без догадок):
     `.mp4`-клип (скринкаст / hyperframes-mp4 / higgsfield) → **overlay-video** (кладётся ПОВЕРХ головы
     в своём окне); `.png` (статичный титр / пилюля / оверлей) → **overlay-png**. Если сегмент в
     storyboard помечен `fullscreen` (UI-демо на весь экран, голова уходит в VO) → **replace** вместо
     overlay-video. Сегменты `face` (голова) в manifest НЕ пишем - это база, поверх неё оверлеи
   - `start`/`end` = выровненные `t0`/`t1` в секундах
   - `file` = имя клипа `seg-<NN>.mp4` / `seg-<NN>.png` в `$PROJECT_DIR/segments/` (по № из shotlist)
   ```bash
   # пример строки: printf 'overlay-video\t45.0\t83.5\tseg-03.mp4\n' >> "$PROJECT_DIR/manifest.tsv"
   ```
   Проверить: каждый файл из manifest реально лежит в `$PROJECT_DIR/segments/` (иначе assemble пропустит)

3. **🔴 Аутро ПОСЛЕДНИМ кадром - вставки монтируются ПЕРЕД концовкой.** Финальный кадр = CTA/аутро
   (лицо автора + призыв). Все motion/скринкаст-вставки ложатся внутри тела, ни одна не заходит на
   аутро-окно. Определить `OUTRO_START` = таймкод начала аутро-сегмента по выровненной карте (первое
   слово CTA/аутро из речи). Проверить: max(t1 вставок) < OUTRO_START. Эта же метка передаётся в
   assemble.sh (шаг 4) - скрипт САМ предупредит, если вставка заходит за аутро (машинная страховка
   поверх ручной проверки,)

4. **Собрать черновик ffmpeg-узлом** (абсолютный путь, manifest.tsv 4-м арг, OUTRO_START 5-м):
   ```bash
   bash ~/.claude/skills/youtube-viral-remake/scripts/assemble.sh \
     "$RECORDING" "$PROJECT_DIR/segments" "$PROJECT_DIR/out.mp4" "$PROJECT_DIR/manifest.tsv" "$OUTRO_START"
   ```
   Если assemble выдал `⚠️ ВНИМАНИЕ: вставка ... заходит на аутро` - вернуться к шагу 2, сдвинуть
   окно вставки перед `OUTRO_START` (закон «аутро последним» нарушать нельзя)
   `assemble.sh` работает по проверенному паттерну автора:
   - **Голова = base video track** (запись автора), исходное АУДИО записи муксится в финал
   - **Вставки-клипы** из segments-dir ложатся по выровненным таймкодам (concat по главам /
     overlay поверх окон, где визуал-носитель перекрывает голову с VO)
   - **🔴 image-оверлеи (титры/пилюли/PNG) ОБЯЗАТЕЛЬНО через `-loop 1 -t <дольше ролика> -i png`**
     плюс финальный `-t <длина> -shortest`. БЕЗ `-loop 1` у PNG PTS=0 → `enable='between(t,t0,t1)'`
     покажет его ТОЛЬКО если t0≤0 → все оверлеи с t0>0 молча НЕ бурнутся. Это исторический дефект,
     assemble.sh несёт паттерн в комментариях
   - **16:9** на всех дорожках (assemble.sh приводит базу И вставки к 1920×1080 канвасу)
   - **🔊 Финальный loudnorm + skew-фикс** (assemble.sh делает автоматически последним шагом,
     +):
     голос из записи выходит тихим (~-38 LUFS), без нормализации «звук тихий, спикера не слышно».
     Прогоняет `loudnorm=I=-13:TP=-1.0:LRA=7` + жёсткое выравнивание по видео-длине (skew <50мс)

5. **Субтитры отдельным проходом (НЕ поверх скринкаста).** После сборки тела - бёрн субтитров
   вторым ffmpeg-проходом, ТОЛЬКО в зонах головы/абстракций. Поверх скринкаста реального UI субтитры
   НЕ кладём (clean-screencast keep-out) - там подпись идёт в шве/поле. Word-level ASR из шага 1
   даёт тайминг субтитров

6. **Доставка по `role`** (,
  ):
   - **acquisition**: черновик в ОТКРЫВАЕМОМ виде (живой `https://`-URL / TG-бот / инлайн). Публикация
     на публичный YouTube - ТОЛЬКО по прямой команде автора, сам не публикую
   - **launch-lead-magnet**: черновик ТОЛЬКО через localhost + бот, НИКОГДА публичный домен. Единственное
     действие зрителя = регистрация, никакого код-слова/домашки. В бот - `sendDocument` (не sendVideo,
     чтобы не пережало качество), с описанием
   - Ни в каком режиме не деплою/не публикую без явной команды. Higgsfield-вставки уже отрисованы
     автором (гард фазы 05), кредиты сам не жёг

7. **Показать результат в чат.** Ссылка на оригинал источника + путь к собранному черновику
   (открываемый) + что внутри (главы, вставки, длительность). автор смотрит качество глазами -
   машина motion/lip-sync не оценивает

## Выход

- `$PROJECT_DIR/out.mp4` - собранный черновик 16:9 (голова + вставки по таймкодам + субтитры, аутро последним)
- `$PROJECT_DIR/manifest.tsv` + `asr/recording.json` в папке проекта как улика синка
- `out`/`recording` записаны в `project.json` через `jq` (не `cat >`, чтобы не стереть ключи):
  `jq --arg o "$PROJECT_DIR/out.mp4" --arg r "$RECORDING" '.out=$o | .recording=$r' project.json > .pj && mv .pj project.json`
- Доставка по role: открываемый черновик (acquisition) / localhost+бот sendDocument (launch)
