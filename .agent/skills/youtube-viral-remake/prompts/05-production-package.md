# Фаза 05: production-пакет отрисовки

Из `storyboard.md` (фаза 04) собираю production-пакет: для КАЖДОГО сегмента готовую исполнимую
инструкцию отрисовки по его типу. Эта фаза НЕ рисует и НЕ жжёт кредиты - она производит текст
промптов и инструкции, по которым автор (или следующий проход) отрисует каждую вставку

## Цель

Превратить абстрактный storyboard в папку `production-package/` где на каждый сегмент лежит готовый
к исполнению файл: что записать / какой HTML отрендерить / какой промпт вставить в Higgsfield / где
в кадре лицо автора. Плюс сводный `shotlist.md` - карта всех вставок по главам и таймкодам

## Вход

- `$PROJECT_DIR/storyboard.md` (фаза 04): сегменты 16:9 с № (`seg-NN`), типом, главой, таймкод-окном
- `$PROJECT_DIR/card.md` (фаза 02): структура удержания, провенанс URL источника, инструменты автора
- `config.md`: `role` (acquisition / launch-lead-magnet), язык, voice-profile путь
- `$PROJECT_DIR/script.md` (фаза 03): текст глав - смысл вставки и её длительность

## Шаги

1. **Read `storyboard.md` + `knowledge/engine-boundary.md`.** engine-boundary несёт real-footage-роутер
   и clean-screencast keep-out - без него сегмент можно ошибочно отдать в генеративку. Прогнать
   КАЖДЫЙ сегмент через роутер ещё раз: показывает реальный инструмент/сайт → ТОЛЬКО скринкаст,
   абстракция/метафора/данные-в-движении → hyperframes или Higgsfield

2. **Создать `$PROJECT_DIR/production-package/`.** Внутри - по файлу на сегмент, имя
   `seg-<NN>-<тип>.md` (напр. `seg-03-real-screencast.md`), плюс `shotlist.md` сводкой.
   **🔑 Соглашение имён клипов (ключ для сборки):** каждый сегмент, когда будет отрисован, кладётся в
   `$PROJECT_DIR/segments/` под именем `seg-<NN>.<ext>` (клип-вставка → `seg-03.mp4`, PNG-титр/пилюля
   → `seg-03.png`). Это имя = колонка `file` в manifest.tsv фазы 06. № сегмента из storyboard = ключ

3. **Для сегмента `real-screencast` → инструкция записи, НЕ рисованный мок.** Файл содержит:
   - **Что записать**: точный инструмент/сайт (напр. Claude Code, конкретный дашборд, сайт X)
   - **Сценарий**: пошаговый сценарий скролла/клика/ввода - что появляется на экране по секундам,
     какой результат должен быть виден (печать промпта → ответ → success-карточка и т.п.)
   - **Инструмент захвата**: `screen-record-face-cam` (метод) или CDP-скринкаст или официальный
     футаж тула с сайта - выбрать по природе сегмента, назвать конкретно
   - **Провенанс URL**: откуда реальный интерфейс (URL инструмента / репо / дашборда) - чтобы
     запись была настоящим UI, а провенанс проверяем
   - **🔴 clean-screencast keep-out**: НОЛЬ оверлеев поверх этой записи (ни чипов, ни титров, ни
     бейджей, ни субтитров). Подписи к этому сегменту идут в ДРУГОЙ зоне (шов кадра / поле), их
     помечаю отдельной строкой «подпись в шве», не поверх UI. Рисованный HTML-мок реального UI = брак

4. **Для сегмента `hyperframes-abstract` → HTML-композиция + команда рендера.** Файл содержит:
   - **Что показать**: диаграмма / титр / данные-в-движении / стат-ревил / переход-стингер - только
     АБСТРАКЦИЯ или точная дата-виз с цифрами (hyperframes держит числа/логотипы детерминированно,
     генеративка их исказит)
   - **HTML-скелет композиции 16:9**: структура секций (фон, hero-текст, дата-элементы, линии),
     тайминг по методологии `motion-design-prompter` (ease in/out, стаггер, breathing zoom) но
     под 16:9 канвас
   - **Команда сборки**: `npx hyperframes init <seg-slug> --non-interactive` → авторинг HTML →
     `npx hyperframes lint` → `npx hyperframes inspect` → `npx hyperframes render --output <seg>.mp4`
     Одна композиция = одна глава/вставка (не весь ролик одним HTML) - сборка ПО ГЛАВАМ
   - Node ≥22 + FFmpeg (проверены в среде). Клип рендерится в `$PROJECT_DIR/segments/seg-<NN>.mp4`
     (имя строго по № сегмента - фаза 06 найдёт его по manifest)

5. **Для сегмента `higgsfield-abstract` → ТОЛЬКО текст промпта, ПОД ГАРДОМ.** Файл содержит:
   - **🔴 Гард**: этот скилл НЕ вызывает Higgsfield и НЕ жжёт кредиты сам. Он кладёт готовый текст
     промпта, автор запускает генерацию по явному «да»
   - **Только абстракции**: концепт-метафора (деньги/рост/масштаб), атмосферный фон, стат-заставка
     без точных данных-носителей. Реальный UI сюда НИКОГДА (роутер), точные числа-носители - в
     hyperframes-оверлей, не в генеративку (буквы поплывут)
   - **Промпт**: собран через `Skill('motion-design-prompter')` из дизайн-описания сегмента, НО
     выход-строка на конце = `OUTPUT: 16:9 horizontal, 60fps, cinematic quality` (motion-design-prompter
     по умолчанию пишет 9:16 - переопределить на 16:9 под long-form)
   - **Формат текста автора** (если в композиции RU-текст): без длинных тире, без точки в конце абзаца,
     без нейроклише

6. **Для сегмента `face` → метка присутствия лица автора.** Файл содержит:
   - **Где лицо**: хук (первые секунды) / CTA (аутро) / опорная точка главы - по закону аватар-букенда
     (лицо на хук+CTA+точках глав, середина = визуал-носитель с VO, не говорящая голова 20 минут)
   - **Что в кадре**: сценарий что автор говорит/делает в этом окне (из скрипта фазы 03), таймкод-окно
   - На эти окна graphic-overlays/embedded-captions можно класть графику ОТДЕЛЬНЫМ проходом (фаза 06),
     но ТОЛЬКО в зоне головы, НЕ поверх скринкаста

7. **Собрать `shotlist.md`** - сводная таблица: № сегмента (`seg-NN`) · глава · таймкод-окно (t0-t1) ·
   тип · движок · **имя-клипа** (`seg-NN.mp4`/`seg-NN.png`) · файл-инструкция · статус отрисовки
   (TODO/готов). Плюс шапка: role, провенанс источника, порядок вставок по главам. Это карта для
   фазы 06 (assemble) - из неё фаза 06 напрямую строит `manifest.tsv` (тип→overlay-video/overlay-png,
   таймкод→t0/t1, имя-клипа→file)

8. **Прогнать motion-floor напоминание**: у КАЖДОГО визуального сегмента в инструкции есть строка
   «динамика: новое событие ~каждую секунду» - статичный слайд с медленным зумом = брак ниже эталона
  . Для скринкаста это живой скролл/клик,
   для hyperframes - стаггер/печать/каскад, для higgsfield - движение по motion-design-prompter

## Выход

`$PROJECT_DIR/production-package/`:
- `seg-NN-<тип>.md` на каждый сегмент storyboard с исполнимой инструкцией по его типу
- `shotlist.md` - сводная карта вставок: № · глава · t0-t1 · тип · имя-клипа · статус · role · провенанс
- `$PROJECT_DIR/segments/` - пустая папка, куда автор/рендер кладут отрисованные клипы `seg-NN.mp4/.png`

## Гейт (ПЕРЕД переходом к фазе 06)

- [ ] Каждый сегмент storyboard имеет файл-инструкцию, ни один не пропущен
- [ ] Каждая инструкция ИСПОЛНИМА: скринкаст = что записать + сценарий + инструмент + URL-провенанс,
      hyperframes = HTML-скелет + команда рендера, higgsfield = готовый текст промпта, face = метка+окно
- [ ] Реальный UI = скринкаст (не рисованный HTML-мок) - прогнан real-footage-роутер

- [ ] higgsfield-сегменты = ТОЛЬКО текст промпта под гардом, скилл не жёг кредиты, выход 16:9
- [ ] У каждого визуального сегмента строка про motion-floor (динамика ~каждую секунду)
- [ ] `shotlist.md` собран, role проведена, провенанс источника на месте
