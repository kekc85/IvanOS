# Контракт dzen-engine ↔ SEO-движок 2.0

Договор между движком Дзена и SEO-машиной `lead-magnit`. Он отвечает на один вопрос: как
сделать так, чтобы обновление одной стороны не оставляло вторую работать по вчерашнему канону

Машинная часть контракта - `.engine-contract.json`, проверяет её `tools/sync-check.py`

## 1. Разделение зон (кто чем владеет)

| Зона | Владелец | Кто читает |
|---|---|---|
| Законы автора для SEO-текстов | `lead-magnit/seo-engine/ZAKONY-SEO.md` | dzen-engine читает, НЕ копирует |
| Методология 16 этапов | `lead-magnit/seo-engine/methodology/` | dzen-engine читает при входе «тема с нуля» |
| Машинные чекеры текста | `lead-magnit/tools/*.py` | dzen-engine вызывает по пути |
| Финальная антиклише-зачистка | скилл `humaniser` | dzen-engine вызывает `Skill('humaniser')` |
| Картиночный тракт | `post-image/scripts/gen-chatgpt-image-cdp.py` | dzen-engine вызывает по пути |
| Правила и лимиты Дзена | **dzen-engine/knowledge/platform-rules.md** | lead-magnit и statya-na-ploshadku читают отсюда |
| Эталоны и заходы Дзена | **dzen-engine/knowledge/etalony-dzen.md** | то же |
| Чекер лимитов Дзена | **dzen-engine/tools/dzen-limits-check.py** | то же |

Правило зоны: у каждого факта один владелец. Дзен-специфика не живёт в SEO-движке, общие
законы не живут в движке Дзена. Копия факта в двух местах = рассинхрон через месяц

## 2. Направление «донор обновился» (SEO 2.0 → Дзен)

Работает автоматически двумя механизмами:

**а) Read-through.** Движок Дзена не хранит копий донорских правил. `ZAKONY-SEO.md` читается
на этапе 0 каждого прогона, чекеры вызываются по путям. Поменялся закон в SEO-движке - следующий
же прогон Дзена работает по новому закону, переносить руками нечего

**б) Хеш-сверка.** `sync-check.py` держит снимок sha256 донорских файлов из `.engine-contract.json`.
Изменился любой - код возврата 1 и печать списка изменившихся файлов. Гейт на этапе 0 требует
прочитать изменённое в этом же прогоне, потом зафиксировать новый снимок:

```bash
python3 ~/.claude/skills/dzen-engine/tools/sync-check.py            # проверка
python3 ~/.claude/skills/dzen-engine/tools/sync-check.py --accept   # после ревизии изменений
```

Отдельно сверяется поле `version` во frontmatter `lead-magnit/SKILL.md`: смена MAJOR у донора =
контракт пересматривается целиком, не только хеши

## 3. Направление «движок Дзена обновился» (Дзен → SEO 2.0)

**а) Вызов по имени.** Консьюмеры не хранят дзен-логику и зовут `Skill('dzen-engine')`. Имя
стабильно, содержимое подтягивается свежее. Это и есть автоматическая новая версия: обновлять
на стороне консьюмера нечего

**б) Проверка версии на стороне консьюмера.** В своём этапе 0 консьюмер запускает:

```bash
python3 ~/.claude/skills/dzen-engine/tools/sync-check.py --role consumer
```

Скрипт печатает текущую версию движка Дзена и говорит, менялись ли его файлы с момента
последнего зафиксированного снимка. Код 1 = движок обновился, дзен-ветку консьюмера надо
перечитать (а не работать по тому, что помнится)

**в) Депрекейт дублей.** `statya-na-ploshadku/platforms/dzen.md` больше не канон: файл оставлен
указателем сюда. Дзен-правила правятся только в `dzen-engine`

## 5. Правила версионирования

SemVer движка Дзена:

- **MAJOR** - изменился контракт: состав файлов под контрактом, коды возврата `sync-check.py`,
  разделение зон. Консьюмеры обязаны перечитать этот файл
- **MINOR** - новый этап конвейера, новый knowledge-файл, новый режим
- **PATCH** - уточнение правил площадки, обновление эталонов, фикс чекера

`contract_version` в `.engine-contract.json` меняется только на MAJOR движка или донора

## 6. Что делать при конфликте правил

Если закон донора и правило площадки расходятся - прав закон донора (`ZAKONY-SEO.md`
перекрывает generic по своей же первой строке), КРОМЕ технических лимитов и механики Дзена:
лимиты, размеры, санкции и конструкцию заголовка задаёт площадка, спорить с ней бесполезно

Пример разрешённого конфликта: донор требует humaniser-хардгейт и формат-тройку - применяется
к дзен-тексту как есть. Дзен требует заголовок 45-90 знаков - применяется, даже если на своём
сайте заголовок той же статьи длиннее
