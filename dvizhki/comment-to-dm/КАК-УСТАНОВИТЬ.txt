КАК УСТАНОВИТЬ commentdm
========================

НАЧНИ ОТСЮДА. Это единственный файл «с чего начать»

commentdm следит за комментариями под твоими постами и рилзами в Инстаграме
и отправляет человеку сообщение в директ, когда он написал заданное тобой
слово. Работает на твоём собственном сервере, месячной платы нет

Сколько это займёт: примерно час. Из них сама установка на сервере минут
20 (на самом слабом тарифе дольше, там медленнее идёт сборка), остальное -
кабинет разработчика Meta, единственная часть, которая делается руками в
браузере

Терминала бояться не нужно: печатать ничего не придётся, все команды ниже
копируются целиком и вставляются

Внутри папки лежит README.md - README теперь тоже ведёт по установке из
архива, тем же путём, что и этот файл. Ставить всё равно удобнее отсюда:
здесь подробнее и с нуля. Остальное в README и в docs верно и пригодится


=====================================================
ПЕРЕД НАЧАЛОМ - 4 ВЕЩИ
=====================================================
1. СЕРВЕР (VPS). Ubuntu 22.04 или 24.04 (20.04 тоже подойдёт), память от
   2 ГБ. Хостер любой, тариф самый дешёвый. После оплаты хостер пришлёт
   письмом IP-адрес сервера и пароль пользователя root - они понадобятся
   в шаге 1

2. ДОМЕН. Нужна A-запись домена, которая указывает на IP твоего сервера.
   A-запись делается в панели у регистратора домена, не на сервере. Без
   домена не выпустится HTTPS, и установка остановится на предпроверке.
   Своего домена нет - подойдёт бесплатный поддомен у сервиса динамического
   DNS (DuckDNS и похожие), требование к нему то же самое: A-запись смотрит
   на IP сервера. Создал запись - подожди 10-15 минут, DNS обновляется не
   мгновенно

3. АККАУНТ ИНСТАГРАМА типа Business или Creator. Личный не подойдёт: Meta
   не даёт личным аккаунтам доступ к сообщениям и комментариям. Тип
   переключается в самом приложении: Настройки -> Аккаунт -> Тип аккаунта

4. ЮРИСДИКЦИЯ ДЛЯ ШАГА С КАБИНЕТОМ META. Кабинет разработчика Meta и сам
   Инстаграм в части стран открываются не сразу. Открывается штатно -
   идёшь дальше; не открывается там, где ты сейчас, пройди шаг 4 из
   юрисдикции, где доступ к Meta обычный. Дело не в гайде


=====================================================
ШАГ 1 - ЗАКИНУТЬ АРХИВ НА СЕРВЕР
=====================================================
Открой терминал на своём компьютере (на Mac он называется «Терминал», на
Windows - PowerShell) и вставь одну команду, подставив в неё IP своего
сервера вместо IP-СЕРВЕРА:

   scp ~/Downloads/CommentDM.zip root@IP-СЕРВЕРА:/root/

Если архив лежит не в загрузках - подставь его путь. На Windows тот же путь
пишется так: $HOME\Downloads\CommentDM.zip

Команда спросит пароль root - тот самый, что прислал хостер. При вводе
пароля терминал не показывает ничего: ни точек, ни звёздочек. Это не
зависание, печатай вслепую и жми Enter

ЧТО ДОЛЖНО ПОЛУЧИТЬСЯ: в терминале прошла строка CommentDM.zip, в конце
неё стоит 100%


=====================================================
ШАГ 2 - ЗАЙТИ НА СЕРВЕР И РАСПАКОВАТЬ
=====================================================
Той же командой, с тем же IP:

   ssh root@IP-СЕРВЕРА

Первый раз спросит «Are you sure you want to continue connecting» - ответь
yes и снова введи пароль. Дальше три команды, вставляй по одной:

   apt update && apt install -y unzip
   unzip /root/CommentDM.zip -d /root
   sudo mv /root/commentdm /opt/commentdm

Распаковывать во временную папку /tmp нельзя: установщик специально
откажется ставить оттуда, потому что фоновые службы Ubuntu файлы из /tmp
не видят. Поэтому папка и переезжает в /opt/commentdm - это её постоянное
место, туда же ты будешь заходить потом

ЧТО ДОЛЖНО ПОЛУЧИТЬСЯ: команда ls /opt/commentdm печатает список файлов,
среди них install.sh


=====================================================
ШАГ 3 - УСТАНОВКА ОДНОЙ КОМАНДОЙ
=====================================================
Подставь свой домен вместо твой-домен.ru:

   cd /opt/commentdm
   sudo bash install.sh твой-домен.ru

Ты вошёл на сервер как root, поэтому слово sudo можно и не писать, команда
сработает одинаково

Дальше 20 минут делать нечего. Установщик сам поставит Node.js,
PostgreSQL, Redis и Caddy, соберёт приложение, накатит базу, поднимет
фоновые службы, закроет файрволом всё лишнее и выпустит HTTPS-сертификат
на твой домен. Весь ход пишется в файл /var/log/commentdm-install.log

Установка остановилась на предпроверке - значит она ещё ничего в системе
не поменяла. Прочитай, что она написала: чаще всего это A-запись домена,
которая пока не разошлась по DNS. Поправь и запусти команду снова,
повторный запуск полностью безопасен

ЧТО ДОЛЖНО ПОЛУЧИТЬСЯ: в конце установщик нарисовал рамку, внутри неё
адрес https://твой-домен.ru, логин owner@localhost и пароль


=====================================================
ЧЕМ ВСЁ ЗАКОНЧИТСЯ
=====================================================
В самом конце появится рамка примерно такая:

   ##############################################################
   #
   #   commentdm установлен
   #
   #   Адрес:  https://твой-домен.ru
   #   Логин:  owner@localhost
   #   Пароль (сгенерирован сейчас, больше нигде не показывается):
   #
   #       длинный-пароль-вот-здесь
   #
   ##############################################################

СОХРАНИ ПАРОЛЬ ПРЯМО СЕЙЧАС, в заметки или менеджер паролей. Он больше
нигде не покажется: в базе лежит только его зашифрованный отпечаток

Бывает второй финал: «commentdm установлен, НО npm run doctor нашёл
проблемы». Установка при этом прошла, просто самопроверка что-то нашла.
Почти всегда это два ключа Meta, которых ещё нет - их ставит следующий шаг

Ниже рамки установщик напечатает список полезных команд. Из них пригодится
одна: cd /opt/commentdm && npm run doctor - самопроверка, её можно
запускать в любой момент


=====================================================
ШАГ 4 - КАБИНЕТ META (самая долгая часть)
=====================================================
Сервер готов, но Инстаграм к нему ещё не подключён. Подключение идёт через
кабинет разработчика Meta: там создаётся «приложение» - не программа для
скачивания, а запись в системе Meta с двумя ключами, по которым commentdm
работает с твоим аккаунтом

Весь маршрут пройден вживую и расписан по экранам в файле docs/META.md.
Читать его удобнее на своём компьютере, а не на сервере: распакуй
CommentDM.zip у себя двойным кликом и открой внутри папку commentdm, файл
docs/META.md - он текстовый, откроется любым редактором

Что будет в конце того гайда: два значения, Instagram app ID и Instagram
app secret, которые нужно вписать на сервере в файл .env - там сейчас
заглушки. Команды для этого есть в самом гайде, в разделе «Дальше»

ЧТО ДОЛЖНО ПОЛУЧИТЬСЯ: в файле .env на сервере вместо заглушек стоят два
значения из кабинета Meta: Instagram app ID и Instagram app secret


=====================================================
ШАГ 5 - ПЕРВЫЙ ВХОД
=====================================================
1. Открой https://твой-домен.ru в браузере.
2. Введи пароль владельца из рамки установщика.
3. В Настройках нажми «Подключить Instagram» - откроется экран согласия
   Meta (он заработает только после шага 4).
4. Создай кампанию: выбери пост, задай ключевое слово, напиши сообщение.
5. Проверь на себе: попроси кого-то другого написать это слово под постом.
   Свои собственные комментарии программа игнорирует намеренно. Подожди
   один цикл опроса, по умолчанию до 5 минут - сообщение приходит не
   мгновенно, так устроено

ЧТО ДОЛЖНО ПОЛУЧИТЬСЯ: человеку, который написал слово под постом, пришло
в директ твоё сообщение из кампании


=====================================================
ЕСЛИ ЧТО-ТО СЛОМАЛОСЬ
=====================================================
Порядок один и тот же, сверху вниз:

1. Самодиагностика. На сервере:

      cd /opt/commentdm
      npm run doctor

   Она сама проверит базу, очередь, фоновый процесс, токены и напечатает
   человеческим языком, что не так, с кодом ошибки вида E-08

2. Файл ЛЕЧЕНИЕ.md в папке commentdm. Там разобран каждый код E-01..E-16 и
   отдельно частые жалобы: «сообщения не приходят», «приходят с задержкой»,
   «приходят не всем», «сайт не открывается», «забыл пароль владельца».
   В конце файла словарь терминов, если слова вроде A-записи или systemd
   видишь впервые

3. Claude Code, он у тебя уже стоит. Открой его прямо в папке
   /opt/commentdm и попроси разобраться своими словами: «сообщения не
   приходят, разберись и почини». Внутри папки лежит файл CLAUDE.md - это
   карта всего кода и типичных поломок, написанная специально для него.
   Он прочитает её сам, ты ничего дополнительно объяснять не должен


=====================================================
ПРО ОБНОВЛЕНИЯ - ЧЕСТНО
=====================================================
Внутри есть команда npm run update, и в документации она описана. У тебя
она НЕ сработает: эта команда тянет новую версию из закрытого репозитория,
к которому доступа нет

Как обновления приходят на самом деле: новым файлом от автора системы. Установка
обновления делается по инструкции, которая придёт вместе с этим файлом.
Заранее ничего делать не нужно, просто пользуйся


=====================================================
МЕЛОЧИ, КОТОРЫЕ ПУГАЮТ НА СТАРТЕ
=====================================================
- Пароль в терминале не отображается вообще. Это защита, а не поломка,
  печатай вслепую.
- Жёлтые и белые строки во время apt и установки пакетов - обычный шум
  Ubuntu. Смотреть надо на итоговую рамку в конце.
- Сайт открылся не сразу после установки: сертификат HTTPS выпускается
  минуту-другую. Подожди и обнови страницу.
- Порт 3000 снаружи закрыт специально, и так и должно быть. Наружу отвечает
  только Caddy на 80 и 443.
- Запустил install.sh второй раз - ничего страшного, каждый шаг проверяет,
  не сделан ли он уже. Ключ шифрования при повторе никогда не
  перезаписывается, подключённые аккаунты не отвалятся.
- Сообщения приходят с задержкой до 5 минут, а не мгновенно. Это
  конструкция, а не поломка: commentdm сам ходит к Meta и спрашивает, что
  нового, вместо того чтобы держать открытый порт наружу.
- Закрыл терминал - на сервере ничего не остановилось. Службы держит
  systemd, они переживают и закрытое окно, и перезагрузку сервера
