# Task Manager — правила игры

**Создано:** 2026-05-12
**Спека:** `specs/2026-05-12-task-manager.md`
**План:** `plans/2026-05-12-task-manager.md`

## Суть

Один Task Manager для **личных и рабочих задач** в формате markdown + git. Соединяет годовую цель ($1M к 31.12.2026) → 12-нед цели → задачи недели → задачи дня.

## Три методологии, три уровня

| Уровень | Методология | Где живёт | Что задаёт |
|---|---|---|---|
| Стратегия | **12 Week Year** (Brian Moran) | `12wy/current.md` | Vision + 3 цели на цикл + lead measures + scorecard |
| Процесс | **GTD** (David Allen) | `inbox/today/week/someday/waiting/projects/` | Куда положить любую новую мысль и как через неё пройти |
| Приоритет | **Eisenhower** (Covey) | внутри `week.md` и `today.md` | Что делать первым: срочно+важно > важно > срочно > удалить |

Они не конфликтуют — работают на разных уровнях абстракции.

> **Методология-мозг (зачем и по какому методу) — [mastery/planning/СИСТЕМА.md](../mastery/planning/СИСТЕМА.md).** 12WY/GTD/Eisenhower — три слоя *этого* Task Manager (руки); СИСТЕМА синтезирует их с OKR (Доерр), ONE Thing (Келлер), MBO (Друкер) и др. в один процесс. Здесь — где что лежит; там — как двигаться.

### Принцип секвенирования: ключевое — первым и в первую половину

Фрактал на всех горизонтах (из `СИСТЕМА.md §0`):
- **Цикл:** цель №1 форсируется в недели 1–6, вторичные консолидируются в недели 7–12 (живой пример: RU-запуск — июнь, EN — июль).
- **Неделя:** ⭐ северная задача — пн-ср, поддержка — чт-сб.
- **День:** ключевая задача — в первый ресурсный блок, операционка и мессенджеры — после.

Не параллелить ключевое — толкать домино по очереди (Келлер). WIP в форсаже ≤ 1-2 проектов.

### 12 Week Year — 2 минуты на главное

- Год = 4 цикла по 12 недель. Каждый цикл = "год".
- **3 цели на цикл, не больше.** Хочешь 4 — переформулируй или объедини.
- Lead measures — это **действия** ("снять 5 видео"), а не результаты ("получить 1000 подписчиков"). На действия ты влияешь, на результаты — нет.
- Scorecard: считаем % выполненных тактик за неделю. **≥85% = успех.**

### GTD — поток задачи

```
capture → clarify → organize → reflect → engage
inbox → разнести по местам → today/week → weekly review → выполнить
```

Правило 2 минут: если задача меньше 2 мин — делай сразу, не записывай.

### Eisenhower — что делать первым

- **Q1** срочно + важно — кризисы, дедлайны. Минимизировать.
- **Q2** важно, не срочно — **главный квадрант.** Стратегия, запуски, обучение.
- **Q3** срочно, не важно — делегировать.
- **Q4** не срочно, не важно — удалить.

## Формат задачи

Одна строка markdown-чекбокса:

```markdown
- [ ] (Q2) Закрыть Фазу 1.1 — Аудитория курса | #запуск-ru | 12wy:цель-1 | due:2026-05-15 | →plans/2026-05-12-launch-vaybmarketing-course.md
```

Разбор полей (порядок свободный после описания):

| Поле | Зачем | Пример |
|---|---|---|
| `- [ ]` / `- [x]` / `- [~]` | Чек: не сделано / сделано / отменено | `- [x]` |
| `(QN)` | Eisenhower квадрант | `(Q2)` |
| `[!]` | Маркер пожара (любой Q) | `[!]` перед `(Q1)` |
| Описание | Что сделать (глагол + объект) | `Закрыть Фазу 1.1...` |
| `#тег` | Контекст / проект | `#запуск-ru`, `#личное`, `#финансы` |
| `12wy:цель-N` | Линк к 12WY-цели | `12wy:цель-1` |
| `due:YYYY-MM-DD` | Дедлайн | `due:2026-05-15` |
| `→путь` | Ссылка на план / документ | `→plans/2026-05-12-launch-vaybmarketing-course.md` |
| `@кто` | Делегировано (→ `waiting.md`) | `@маша` |

**Минимум:** `- [ ] описание`. Остальное — по необходимости.

## Где какая задача живёт

| Что хочу зафиксировать | Куда положить |
|---|---|
| Новая мысль/идея/задача, не знаю куда | `inbox.md` |
| Точно сделаю на этой неделе | `week.md` под нужный Q |
| Делаю сегодня (3-5 шт) | `today.md` |
| Когда-нибудь, может быть, не сейчас | `someday.md` |
| Передал кому-то / жду ответа | `waiting.md` |
| Часть конкретного запуска | `projects/<name>.md` |

Задача может быть **дублирована между `projects/`** (источник правды) и **`today.md`/`week.md`** (срез для выполнения). Закрыли `[x]` в `today.md` — закрыли и в `projects/`.

Задача в двух проектах — храним в основном, ссылаемся `→projects/...md` из второго.

## Правила игры

1. **Inbox разгребается до нуля раз в неделю** (weekly review).
2. **В `today.md` максимум 5 задач.** Хочешь добавить 6-ю — что-то вынеси.
3. **3 цели в 12WY — жёстко.** Хочешь 4-ю → пересобери.
4. **Lead measures = действия, не результаты.** "Снять 5 видео", не "получить 1000 подписчиков".
5. **Закрытие фазы плана `[x]` → задача в `projects/` тоже `[x]`** (синк руками через Claude).
6. **Личное и рабочее в одной системе.** Одна голова, один день.
7. **`[~]` для отменённых задач** — не удаляем, помечаем (важно для ретро).

## Ритуалы — кратко

Полные шаги в `routines.md`.

| Когда | Что | Сколько |
|---|---|---|
| Утром | Daily plan: смотрю `12wy/current.md` → выбираю 3-5 в `today.md` | 5 мин |
| Вечером | Daily close: закрываю `[x]` сделанное, переношу несделанное | 2 мин |
| Воскресенье | Weekly review (WAM): score, разгрести inbox, обновить week | 30 мин |
| Раз в 12 нед | 12WY ретро: ретроспектива цикла, новые 3 цели | 1 час |

## Как работать с Claude

При начале сессии я (Claude):
1. Читаю `tasks/today.md` первым делом
2. При апдейте плана `plans/*.md` — синкаю соответствующий `tasks/projects/*.md`
3. При закрытии фазы плана — закрываю задачу в `projects/`
4. По запросу пользователя — провожу любой из ритуалов

Прямые команды примеры:
- "Покажи today" → читаю `today.md`
- "Добавь в inbox: [текст]" → дописываю в `inbox.md`
- "Сделай weekly review" → провожу процедуру из `routines.md`
- "Закрой задачу [N] в today" → ставлю `[x]` в `today.md` и в исходном `projects/`
- "Обнови score за W20" → апдейчу `12wy/current.md` scorecard
