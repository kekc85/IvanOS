# Как устроен mastery/ — методология

mastery — это **личный совет директоров** автора. За столом сидят лучшие умы мира по нужным областям. Когда автору нужно решить задачу или усилить навык — он открывает файл автора и берёт его метод.

## Один принцип

> **Один автор = один файл. Только методы, не пересказ.**

## Что кладём в файл автора

1. **Кто это и за что он в совете** — одна строка. Почему именно этот человек даёт метод по этой области.
2. **1-2-3 гениальных метода** — ядро, ради которого его помнят. У каждого метода:
   - **Суть** — в чём приём, одним абзацем.
   - **Как применять** — конкретный шаг/вопрос/чек-лист, который автор делает руками.
   - **Когда брать** — в какой ситуации этот метод включается.

## Чего НЕ кладём

- ❌ Пересказ книги, конспект глав, «основные идеи».
- ❌ Биографию, контекст эпохи, историю успеха автора.
- ❌ Метод, который нельзя применить действием (красивая теория без шага).
- ❌ «10 лучших цитат», «20 принципов» — это размывание. Берём 1-2-3, самые острые.

## Почему 1-2-3, а не всё

У каждого великого ума есть ядро — приём, который реально меняет, как ты думаешь и действуешь. Остальное вокруг — обвязка. Совет директоров ценен концентратом: за минуту открыл, взял рычаг, применил. Книга целиком — это не совет директоров, это библиотека.

## Как добавлять автора

1. Определи **область** → если папки нет, создай (`<область>/`) и добавь строку в `INDEX.md`.
2. Создай файл `<область>/<фамилия>.md`.
3. Заполни по структуре выше: кто → 1-2-3 метода (суть / как применять / когда брать).
4. Прогони тест: «автор может взять это и сделать действие прямо сейчас?» Нет → дорабатывай или выкидывай метод.

## Связь с проектом

mastery даёт **методы для решений** (головы за столом). skills/ даёт **инструменты для производства** (руки). Не путать: в mastery нет кода и автоматизации — только концентрат мышления, который применяет сам автор.
