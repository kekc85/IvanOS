# mastery/ — личный совет директоров

Концентрат методов лучших умов мира по областям, важным для автора. Не библиотека книг, не пересказы — **только рабочие методы**, которые можно применить сегодня.

## Что такое mastery

Это «личный совет директоров»: когда нужно принять решение или прокачать область — открываешь файл нужного автора и берёшь его 1-2-3 гениальных метода. Каждый автор сидит «за столом» и даёт не теорию, а инструмент.

## Чем отличается от skills/

| | `mastery/` | `skills/` |
|---|---|---|
| Что это | методы мышления лучших умов | исполняемые инструменты Claude |
| Кто применяет | **автор** (человек, решением/действием) | **Claude** (автоматически, по триггеру) |
| Формат | концентрат метода автора, проза | SKILL.md + код + промпты |
| Когда берётся | когда автору нужен взгляд эксперта | когда нужно произвести артефакт |

Короче: skills — это **руки** (производят контент/код), mastery — это **головы** за столом совета директоров (дают метод и угол зрения).

## Регламент применения

**Как обращаться к mastery, чтобы это реально работало — в [PROTOCOL.md](PROTOCOL.md).** Коротко: Inventory ВСЕХ авторов области → Select с обоснованием → Apply → Evidence Report (метод → цитата) → независимый верификатор. Защита от частичного/фиктивного применения. Обязателен для меня в чате, для writer-скиллов и для skill-craft.

## Главное правило наполнения

**1-2-3 гениальных метода у каждого автора, не книги целиком.**

Берём у автора то, ради чего его помнят — ядро, которое меняет действие. Не конспект, не «10 идей из книги», не биография. Если метод нельзя применить — он не попадает в файл.

## Структура

- **Одна папка = одна область** (например: переговоры, мышление, продукт, деньги).
- **Один файл = один автор** (`фамилия.md`), внутри — его 1-2-3 метода.

```
mastery/
├── INDEX.md            ← этот файл, карта
├── README.md           ← методология наполнения
└── <область>/
    └── <автор>.md      ← 1-2-3 метода одного автора
```

## Кейсы применения

mastery не лежит мёртвым грузом — Claude автоматически проваливается в нужную папку под задачу:

- **Контент-завод.** «Напиши пост про X» → Claude входит в `copywriting/` + (если уместно) `storytelling/`/`persuasion-psychology/`, берёт конкретные методы + голос автора → пост через линзу мастеров, а не generic.
- **Запуск.** Каждая фаза запуска (`.business/processes/prompts.md`), родив артефакт (оффер/VSL/прогрев/вебинар), прогоняет его через релевантную область mastery (оффер→`offer-design`, вебинар→`public-speaking`, прогрев→`storytelling`+`persuasion`) и только тогда артефакт готов.
- **Решение.** «Стоит ли делать X?» → `decision-making/` (инверсия Мангера, premortem Канемана, ставки Дьюк) к реальным данным `.business/`.
- **Планирование.** «Что делать сегодня / как разложить цикл / спринт проекта» → `planning/СИСТЕМА.md` — применённая методология (12WY + OKR + ONE Thing + GTD + Eisenhower синтезированы), вшита в `tasks/`.

Один Claude — десятки экспертных линз под рукой, по `mastery/PROTOCOL.md`.
