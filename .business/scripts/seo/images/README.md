# Каталог съёмки кадров SEO-статьи

Кадр для статьи снимается с РЕАЛЬНОГО интерфейса. В каталоге ровно то, что для этого нужно:

| файл | зачем |
|---|---|
| `shot.py` | съёмка кадра: URL-режим, сценарный режим (путь клика), регистрация чужого кадра, манифест |
| `convert.py` | пост-обработка кадра: webp + jpeg-фолбэк, готовый `<figure>` для вставки |
| `uniq.py` | гейт уникальности обложек (одна картинка не уходит в две статьи) |
| `_brand.py` + `fonts.css` + `fonts/` | общий слой бренда (палитра, шрифты аннотаций) |

Стек: python3 + playwright (headless Chromium) + Pillow. Сеть при рендере не нужна, шрифты лежат
рядом в `fonts/`. Палитра: бумага `#FAF6EF`, текст `#1C1815`, акцент `#BE4A24`.

Установка браузера для съёмки, если playwright ставится впервые:

```bash
python3 -m pip install playwright pillow
python3 -m playwright install chromium
```

## 🔴 Статус каналов: картинка в SEO-статье только ультра-реалистичная и только ценная

Кадр легален в одном из четырёх классов:

- **result** - кейс-превью: результат функции в реальном интерфейсе (вход, интерфейс, готовый выход)
- **step** - путь клика: реальный интерфейс с рамкой-аннотацией «жми сюда»
- **own-run** - свой прогон: окно-чат (панель ИИ-ассистента в редакторе) или веб-панель результата;
  окно оболочки/терминала в класс НЕ входит
- **inherited** - кадр перенесён с уже существующей страницы при её ревизии; съёмку инструмент
  не подтверждал, класс переходный

`shot.py` - ОСНОВНОЙ и единственный канал новых кадров. Генеративные каналы (фото-обложки,
код-рендер сцены, мемы, типографские плашки) для SEO-статей ЗАКРЫТЫ целиком, их файлов в пакете
нет по этой же причине. Запрещено: сцена-декорация, надпись-картинка, текст-плашка, «скрин
главной» вместо функции, картинка ради пола. Нет доказательного кадра - кадр не ставится, ось
закрывает `.vizblock` в тексте статьи.

Канон классов и следствий - `~/.claude/skills/lead-magnit/seo-engine/ZAKONY-SEO.md`, приёмка
кадра глазами - `~/.claude/skills/lead-magnit/checklists/visual.md`, что именно должно быть
ВНУТРИ кадра - `~/.claude/skills/lead-magnit/knowledge/visual-engine.md`.

Это срезанная версия README - только то, что нужно для работы с этим каталогом. Полная версия
(со всей внутренней кухней производства) живёт у автора движка; при разночтении с обновлением
закона ориентируйся на файлы канона выше - они переустанавливаются вместе со скиллом.

## shot.py - съёмка кадра

Актуальный перечень флагов держит сам скрипт: `python3 shot.py --help`.

🔴 **Кадр без манифеста = брак, и брак ТИХИЙ.** Любой прогон, снимающий кадр статьи, идёт с
`--manifest` и `--class`. Без них записи о съёмке не возникает: гейт `frame-provenance` печатает
«записи в shots-manifest.json нет», но по умолчанию это WARN, стадия остаётся зелёной, а кадр
непокрытым.

### URL-режим

```bash
python3 shot.py --url <адрес функции> \
    --out $WORK/<slug>/shots-src/<slug>-result-1.png \
    --class result --manifest $WORK/<slug>/shots-manifest.json \
    --note "что за функция и какой результат в кадре" \
    --annotate '[
      {"type":"box","selector":"h1","n":1,"label":"Заголовок"},
      {"type":"box","x":100,"y":200,"w":300,"h":60},
      {"type":"arrow","from":[500,400],"to":[420,240]},
      {"type":"num","x":120,"y":180,"n":2},
      {"type":"label","x":520,"y":410,"text":"Жми сюда"}]'
```

- свой чистый headless-профиль, viewport 1440x900, retina 2x
- координаты - CSS-пиксели (как в DevTools). У `box` с `selector` рамка садится на живой элемент;
  опции `n` (номер в углу рамки) и `label` (плашка под рамкой) привязываются сами
- `--selector CSS` - скрин только элемента, `--fullpage` - вся страница (обязателен, если
  аннотируешь элемент ниже первого экрана, скрипт предупредит)
- в манифест уходит webp-версия кадра записью `mode: url`, `steps: 1`
- адрес - страница ФУНКЦИИ с готовым результатом, не корень сервиса: `class=result` с адресом
  корня гейт помечает замечанием «функция, не главная»

### Сценарный режим - съёмка пути клика

Браузер идёт по шагам и снимает кадр ПОСЛЕ реальных действий, а не «скрин главной».

```bash
python3 shot.py --scenario steps.json --out <каталог кадров> \
    --class result --manifest $WORK/<slug>/shots-manifest.json
```

- `--out` в сценарном режиме - КАТАЛОГ, а не файл: имя кадру даёт поле `name` шага `shot`
- `steps.json` - список шагов или `{"steps": [...], "viewport": {...}, "state": "..."}`.
  Шаги: `goto` / `wait_for <селектор>` / `click <селектор>` / `fill <селектор> <значение>` /
  `shot <имя>`; понимается и короткая форма шага строкой. У шага `shot` свои поля `class`,
  `note`, `annotate`, `selector`, `fullpage`, `mobile_crop`
- консент-баннеры закрываются сами (отключить - `--no-consent`), на каждом шаге ретраи
  `--retries` (3) и таймаут `--timeout` (45000 мс). Ждём по селектору (`wait_for`), а не
  `networkidle`: на живых одностраничных приложениях он не наступает
- `--state <storage_state.json>` - готовая авторизованная сессия playwright. Снимаем публичный
  интерфейс или СВОЙ аккаунт: в кадре не должно быть чужих персональных данных, лиц и приватных
  писем. Сервис называем в подписи под картинкой
- `--mobile-crop X,Y,W,H` (CSS-пиксели) плюс `--mobile-width` (по умолчанию 720) режет плотную
  зону тем же кадром, файл кладётся рядом с суффиксом `-mobile`. Это ОПЦИЯ (кроп под og, узкая
  колонка), а не обязательный шаг: мобильную отдачу hero собирает сам сборщик страницы
- 🔴 манифест пишется ТОЛЬКО при `--manifest`, класс обязателен: `--class` на весь прогон либо
  поле `class` в шаге `shot`, иначе прогон падает с требованием класса
- при `--mobile-crop` мобильный кроп получает СВОЮ строку манифеста тем же классом: гейт ключует
  записи по имени файла, общей строкой два разных файла не закрываются

### Регистрация кадра, снятого не через shot.py

```bash
python3 shot.py --register-external assets/<имя>.webp --class step \
    --manifest $WORK/<slug>/shots-manifest.json --url https://<сервис> \
    --note "что на кадре"
```

- это ОТДЕЛЬНЫЙ режим: отрабатывает первым и выходит, сценарий в том же прогоне не запустится
- `--mode external|relay` - способ получения кадра. `external` по умолчанию; `relay` = кадр
  перенесён с уже существующей страницы при её ревизии, съёмку скрипт не подтверждал
- `--shot-at YYYY-MM-DD` - дата съёмки (по умолчанию сегодня). У кадра, снятого раньше, ставится
  обязательно: без неё в запись уйдёт сегодняшняя дата и ось приёмки «свежесть» соврёт
- `--class inherited` легален ТОЛЬКО здесь; сценарная съёмка ставит `result`, `step` или `own-run`.
  Канонический вид команды переноса:

  ```bash
  python3 shot.py --register-external <файл> --manifest $WORK/<slug>/shots-manifest.json \
      --class inherited --mode relay --shot-at <дата старой съёмки>
  ```

- это СЛАБЫЙ класс происхождения: съёмку скрипт не подтверждал, hero одной такой записью не
  закрывается
- 🔴 наследуется только реальный скрин интерфейса. Кадр генеративного происхождения (сцена,
  предмет, руки, плашка, мем) не наследуется никогда: ему пересъёмка либо снятие со страницы

### `--terminal` - легаси-режим и словари стоп-токенов

```bash
{ echo '$ node --version'; node --version; } > out.txt
python3 shot.py --terminal out.txt --title "~/moy-proekt" --out term.png
```

Вывод берётся ТОЛЬКО из файла с реально прогнанными командами, скрипт ничего не выдумывает.
Строки `$ ...` подсвечиваются как команды, высота окна - по контенту.

🔴 В НОВЫХ статьях режим не используется: own-run допускает окно-чат или веб-панель результата,
окно оболочки в класс не входит. Манифест этот режим не пишет вовсе, легаси-кадр закрывается
только `--register-external`.

Что реально ловит машина (`tools/novice-check.py` скилла `lead-magnit`), без иллюзий - ДВЕ разные
проверки с РАЗНЫМИ словарями:

- по ИМЕНИ файла бьёт `SHOT_SRC_TOKENS`, и не подстрокой, а целым СЕГМЕНТОМ имени (имя режется по
  не-буквенно-цифровым): `guide-terminal-1.png` ловится, `guide-myterminal.png` уже нет
- по `alt` и классу картинки бьёт другой шаблон, `SHOT_ALT_HINT`: русские «терминал», «консоль»,
  «командная строка», «оболочка», «трассировка», «приглашение командной строки» и латинские
  `terminal`, `console`, `shell`, `bash`, `powershell`, `iterm`, `traceback`, `stdout`. В нём НЕТ
  `cli`, `cmd`, `tty` и голого `term`, поэтому alt вида «скрин cli-панели» не ловит ни одна из двух
- в черновике той же парой проверяются `alt` и `caption` блока `:::figure` и hero из шапки; на
  собранной странице - только `alt` и `class` картинки

Актуальные словари держат те же две константы в `novice-check.py`, по памяти их не переписываем.
Кадр оболочки, названный нейтрально и с нейтральным alt, машина не поймает вовсе: барьер держат
определение класса own-run и приёмка глазами.

## Манифест происхождения кадров

Один файл на статью, рядом со страницей, НЕ в `assets/` (заливка тарит `assets/` целиком на прод,
манифесту там делать нечего): `$WORK/<slug>/shots-manifest.json`.

```json
{"frames":[{"file":"<справочно: фактический путь съёмки, shots-src/… или assets/…>",
  "class":"result|step|own-run|inherited",
  "url":"<адрес или ->","mode":"url|scenario|external|relay","steps":<N>,
  "shot_at":"YYYY-MM-DD","note":"<1 строка>"}]}
```

- поле `file` СПРАВОЧНОЕ: опираться на путь в нём нельзя (один кадр живёт и в `shots-src/`, и в
  `assets/`, а на страницу попадает третьим путём). Ключ записи - базовое имя файла БЕЗ расширения,
  каталог отбрасывается
- ключи латиницей; значения полей форм (что вводили в поле ввода) в манифест не пишутся никогда,
  только селектор поля и метка «заполнено»
- гейт `frame-provenance` (`article_gates.py`, стадия page) сверяет каждый `<figure>`-кадр, hero и
  og с этой записью: WARN по умолчанию, FAIL по `--provenance-hard`
- один кадр в двух файлах (основной и `-mobile`, hero и его og-кроп) требует ДВУХ строк
- ступени `srcset` - исключение и отдельной регистрации не требуют: хвост из 3-4 цифр после дефиса
  (`-720`, `-1440`) схлопывается в базовый ключ кадра
- границы схлопывания: нумерация съёмок не ступень (`-result-1` остаётся отдельным кадром); ступень
  схлопывается только при живой базе (базовый файл встретился на странице или уже есть в манифесте);
  запись, оформленная на файл ступени, тоже засчитывается
- 🔴 манифест не удаляют. Отсутствие манифеста - это «съёмка не подтверждена», а не «кадров нет»

### Как og-кроп попадает в манифест

Отдельного флага «сделай og» у `shot.py` нет: `--mobile-crop` даёт файл с суффиксом `-mobile`, а не
og. Маршрут - вырезать кроп 1200x630 и зарегистрировать его как внешний кадр:

```bash
python3 - <<'PY'
from PIL import Image, ImageOps
im = Image.open("<полный путь>/shots-src/<slug>-result-1.png").convert("RGB")
im = im.crop((X0, Y0, X1, Y1))          # зона результата, пиксели файла
ImageOps.fit(im, (1200, 630), Image.LANCZOS).save(
    "<полный путь>/assets/<slug>-og.jpg", "JPEG",
    quality=88, optimize=True, progressive=True)
PY

python3 shot.py --register-external $WORK/<slug>/assets/<slug>-og.jpg \
    --class result --mode external --url <адрес функции> \
    --manifest $WORK/<slug>/shots-manifest.json --note "кроп hero под og 1200x630"
```

Класс у og тот же, что у исходного кадра (`result` или `own-run`; `inherited`, если исходник
перенесён со старой страницы). Запись слабая по построению, но закрывает она только сам og: hero
остаётся кадром, снятым прогоном `shot.py`.

🔴 Абсолютный адрес в `og:image` обязан нести сегмент `/<имя каталога статьи>/assets/<файл>`: гейт
берёт слаг из имени каталога и адрес без этого сегмента считает чужой обложкой, молча. Каталог
статьи и путь публикации держим одинаковыми.

Текста на кадр не кладём: заголовок несёт H1 страницы, og идёт без вшитой надписи.

## Конвенция имён кадров

- кадры тела: `<slug>-result-N` / `<slug>-step-N`
- hero и og: `<slug>-hero` и `<slug>-og` (og - плотный кроп 1200x630 с зоны результата hero-кадра;
  у og своя запись манифеста, строкой hero он не закрывается)
- кадр `own-run` называется по РОЛИ содержимого тем же паттерном `result`/`step` (отдельный токен
  `own-run` в имени тоже допустим), кадр `inherited` сохраняет исходное имя со старой страницы
- стоп-токены ИМЕНИ файла: `term`, `terminal`, `cli`, `cmd`, `shell`, `console`, `bash`, `tty`.
  Машина матчит их как целые сегменты имени; в `alt` она проверяет другим, более узким шаблоном
  (разбор выше, подраздел `--terminal`). Правило канона шире машины: терминальных слов не должно
  быть ни в имени, ни в alt

## convert.py - пост-обработка и готовый сниппет

```bash
python3 convert.py --in raw.png --slug <slug> \
    --alt "что на кадре, 50-125 знаков" \
    --caption "Подпись" --outdir assets/ [--eager]
```

- на выходе `<slug>.webp` (q82) + `<slug>.jpg` фолбэк; слаг валидируется (слова через дефис)
- `alt` проверяется на 50-125 знаков
- печатает готовый `<figure><picture>` с width/height и `loading="lazy"`; `--eager` для hero
  (`loading="eager" fetchpriority="high"`)
- 🔴 в `assets/` статьи файлы кладёт только `convert.py`. Сырьё съёмки живёт в
  `$WORK/<slug>/shots-src/`

## uniq.py - гейт уникальности обложек

Один индекс на машину: `cover-index/index.json` плюс миниатюры 600x315 в `cover-index/thumbs/`.
Любая обложка встаёт туда в момент готовности и с этой секунды видна всем параллельным прогонам:
так одна картинка не уходит в две статьи.

```bash
python3 uniq.py --seed                                   # пересобрать индекс по корпусу
python3 uniq.py --check FILE --slug SLUG                 # проверить (код 4 = клон)
python3 uniq.py --register FILE --slug SLUG --role og    # проверить и встать в очередь
python3 uniq.py --publish SLUG                           # queued -> published после деплоя
python3 uniq.py --matrix A B C                           # попарная таблица по трём метрикам
python3 uniq.py --list
```

Три метрики, клон - если сработала любая:

| метрика | что ловит | порог клона |
|---|---|---|
| `mean\|Δ\|` 0-255 | буквально та же картинка | `< 6` |
| доля различающихся пикселей | перекрашенная копия | `mean < 15` И `различается < 30%` |
| структура: медиана корреляции карт границ по 16 тайлам | та же сцена в другой палитре | `>= 0.40` |

Картинки одной статьи (hero и og) друг с другом не сравниваются: слаг общий, это один кадр в двух
раскладках. Перекодировки одного визуала (`png`/`webp`/`jpg`) схлопываются при `--seed` в одну
запись.

🔴 **Пустой индекс на новой машине.** Пока в корпусе нет обложек, `--seed` соберёт 0 записей, а
`--check` / `--register` выйдут с кодом 5 и напечатают «индекс уникальности подозрительно мал:
0 записей < 20». Это самооборона гейта от битого индекса, а не отказ по твоей картинке: сравнивать
пока не с чем. На первых статьях шаг закрывается строкой-обоснованием «индекс пуст, сравнивать не с
чем», гейт заводится сам, когда обложек в корпусе станет больше двадцати.
