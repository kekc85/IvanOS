# Универсальный каркас ChatPlace-воронки (IG-директ) под код-слово

> Структура флоу в конструкторе app.chatplace.io под ЛЮБУЮ нишу. ChatPlace не умеет импорт
> файлов - узлы рисуются в canvas руками по этому листу. Тексты каждого узла пишутся ПОД ТВОЮ
> нишу и оффер (см. функции ниже), каркас и тайминги остаются. Всё, что в `{{...}}` - подставь
> своё на этапе мостика (ниша, оффер, ссылки).

## Что это и зачем

Человек видит твою карусель/рилз, пишет код-слово в комментарий или директ IG. ChatPlace
ловит слово, отдаёт лид-магнит и параллельно догревает до твоего оффера. Это IG-сторона
воронки. TG-сторона (бот выдачи лид-магнита + прогрев C1-D7) собирается скиллом `tg-voronka`
ПЕРВЫМ - оттуда берётся ссылка-вход, которую вставляешь в узел ВЫДАЧА.

## Твои входы (собираются на мостике, ШАГ 0 скилла)

| Поле | Что это |
|---|---|
| `{{КОДСЛОВО}}` | слово-триггер этой воронки (кириллица, любой регистр) |
| `{{ССЫЛКА_ВХОД_В_TG_ВОРОНКУ}}` | ссылка из твоей TG-воронки под это слово (её даёт `tg-voronka`); человек по ней подписывается на канал и бот выдаёт лид-магнит |
| `{{ССЫЛКА_НА_ТВОЙ_ОФФЕР}}` | куда догреваем: твой бот/лендинг оффера (в дожиме M1/M2/M3) |
| `{{ССЫЛКА_НА_ТВОЙ_КАНАЛ}}` | твой канал/сообщество для мягких касаний M2/M3 |
| суть лид-магнита | из твоей живой статьи/гайда (H1, лид, подзаголовки) - на этом строятся GATE и ВЫДАЧА |

## Карта узлов (порядок сборки в canvas)

```
Entry point (Set start trigger)
 └─ GATE (Message, Card-шаблон: кнопка «Забрать инструкцию»)
     ├─ [кнопка] ─────────────────────────────→ ВЫДАЧА
     └─ [тело] → Action: Save message (→ переменная)
                  → Condition: Variable value contains {{КОДСЛОВО}} → ВЫДАЧА
ВЫДАЧА (Message: «что внутри» + {{ССЫЛКА_ВХОД_В_TG_ВОРОНКУ}})
 → Delay 10 Minutes  → M1    (мостик слово→оффер + {{ССЫЛКА_НА_ТВОЙ_ОФФЕР}})
 → Delay 2 Hours     → M2    (польза/подарок + {{ССЫЛКА_НА_ТВОЙ_КАНАЛ}})
 → Delay 20 Hours    → M3    (последнее касание + {{ССЫЛКА_НА_ТВОЙ_КАНАЛ}})
```

Сумма задержек после выдачи ≈ 22ч 10м < 24ч - НЕ увеличивать: последнее сообщение обязано
влезть в 24-часовое окно IG (после 24ч без входящего IG закрывает отправку в директ).

## Настройки флоу (панель Set start trigger)

- События: Direct Message + Post Comment (Multiple triggers = ON)
- Trigger on: Message contains → `{{КОДСЛОВО}}` (задать в верхнем и нижнем регистре)
- Prohibit restart = ON (человек не запускает воронку повторно)

## Функции узлов - ЧТО писать под свою нишу

Пиши целиком под свою тему и голос, каркасных фраз-заготовок не бери (звучит шаблонно).
Опирайся на реальную статью лид-магнита, ничего не выдумывай.

- **GATE** (≤460 симв): назови боль твоей ЦА по теме гайда + скажи, что за кнопкой «Забрать
  инструкцию» лежит гайд + мотивация нажать сейчас. Словесный фолбэк: «или напиши `{{КОДСЛОВО}}`
  в ответ» (на случай, если человек не жмёт кнопку).
- **ВЫДАЧА** (≤460): конкретно «что внутри» ЭТОГО гайда (из живой статьи) + `{{ССЫЛКА_ВХОД_В_TG_ВОРОНКУ}}`
  с призывом перейти и забрать. Открытие своё, не повторяй GATE.
- **M1-мостик** (≤190): персональная связка «запрос человека по этому слову → как твой оффер даёт
  эту трансформацию». 1-3 предложения, релевантно и уникально под слово + `{{ССЫЛКА_НА_ТВОЙ_ОФФЕР}}`.
- **M2** (≤460): дай пользу/бонус по теме + мягко позови в `{{ССЫЛКА_НА_ТВОЙ_КАНАЛ}}`.
- **M3** (≤460): последнее тёплое касание + `{{ССЫЛКА_НА_ТВОЙ_КАНАЛ}}`.

## Инварианты (проверь перед сборкой)

- Каждый `{{...}}` заменён на твоё (нет ни одного плейсхолдера в финальных текстах).
- Ссылка ВЫДАЧИ = именно вход в TG-воронку ЭТОГО слова (не случайная, не голый сайт): иначе
  человек получит канал без бота и прогрев не запустится.
- В текстах нет длинных тире (только дефис), абзацы без точки в конце.
- Финальная зачистка каждого текста через humaniser (без нейроклише, живой голос).

## UTM / трекинг источника (проверено в движке <твой-бот-воронки> по решению автора)

Цель: понимать, какое слово и какой канал (IG-ChatPlace vs TG) приводят регистрации на воркшоп. Ниже что реально трекается сегодня и где предел.

### Что трекается без правок

1. **Внутри ChatPlace** - аналитика флоу пословно (один флоу = одно слово). Видно всю воронку: написал слово → нажал кнопку GATE → дошёл до ВЫДАЧИ → кликнул воркшоп-ссылку в M1/M2/M3. Это родная пословная атрибуция IG-стороны, добавлять ничего не нужно
2. **Инвайт закрытого канала** - у каждого слова СВОЯ ссылка `t.me/+hash` (СТУДИЯ ≠ ШТАТ). В TG «Управление пригласительными ссылками» канала счётчик join по каждой ссылке = сколько человек с какого слова реально зашли. Назови инвайт в TG как `cp-<слово>`, чтобы читалось в списке
3. **Воркшоп-бот** - поле `source_funnel` в БД (`db.py`). Пишется как ключ воронки, по которой человек вошёл В БОТА, и держится через COALESCE (первый источник не перетирается последующим `?start=<твоё-слово-воронки>`)

### Жёсткое ограничение (иначе ломается вход)

- Ссылку `{{ССЫЛКА_НА_ТВОЙ_ОФФЕР}}` НЕ трогать. `on_start` (`bot.py:262`) резолвит ВЕСЬ payload как ключ воронки, `resolve()` (`runtime.py:33`) делает только точное / keyword / alias совпадение и разделитель не разбирает. `?start=<твоё-слово-воронки>_zapas` → не резолвится → человек падает в заглушку, в воронку ВОРКШОП не попадает. UTM-суффикс на бот-ссылке = сломанная регистрация
- Инвайт `t.me/+hash` не несёт query-параметров: UTM прямо в ссылке канала не работает
- Клик-трекер `/r/<uuid>` (`redirect.py`) - динамические ссылки под конкретного юзера, генерит бот внутри TG-воронки, статически в ChatPlace их не вставить

### Сквозная склейка «ChatPlace-клик ↔ воркшоп-рег до слова» - СДЕЛАНО (по решению автора)

Движок <твой-бот-воронки>/<бот-твоего-события> теперь разбирает source-тег в deep-link. `on_start`
(`bot.py`) через `parse_start_payload` (`runtime.py`) делит payload по первому дефису:
funnel-часть резолвится как раньше, хвост пишется тегом `src:<тег>` на контакт +
в событие `start` как `ВОРКШОП#<тег>`. Голый `?start=<твоё-слово-воронки>` (без дефиса) ведёт
себя байт-в-байт как прежде. Выкачено на оба инстанса, проверено на живом
<бот-твоего-события>: `<твоё-слово-воронки>-cpzapas` входит в ту же воронку ВОРКШОП. Тесты `test_runtime` зелёные.

**Схема тегов воркшоп-ссылки** `{{ССЫЛКА_НА_ТВОЙ_ОФФЕР}}-<тег>`:

| Источник | Формат тега | Пример |
|---|---|---|
| ChatPlace (IG-директ) под слово | `cp<слово>` | `<твоё-слово-воронки>-cpzapas` |
| TG-воронка (SaleBot) под слово | `tg<слово>` | `<твоё-слово-воронки>-tgzapas` |
| Прямой пост/канал | `ch<метка>` | `<твоё-слово-воронки>-chpost` |

Тег - латиница нижним регистром. Аналитика: контакты с меткой источника =
`SELECT ... FROM tags WHERE tag LIKE 'src:cp%'` (или по конкретному `src:cpzapas`).
При сборке новой воронки (tg-voronka + chatplace) в дожим M1/M2/M3 и C-узлы
ставить воркшоп-ссылку С тегом слова, а не голую - тогда рег атрибутируется до слова.
Пословная IG-аналитика ChatPlace (п.1-2) работает независимо, как страховка.
