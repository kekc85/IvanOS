# Мобильная разработка через Claude Code — reference

Мобайл для автора — не новая планета, а **прямое расширение веб-стека**. Тот же React, тот же Claude, тот же бэкенд. Один JavaScript, один Claude, одна голова.

## Стек: React Native + Expo + Expo Go

**Берём всегда: React Native + Expo.** НЕ Flutter, НЕ Xcode, НЕ нативный Swift/Kotlin.

| Слой | Что это |
|---|---|
| **React Native** | фреймворк мобильных приложений на JavaScript/TypeScript. Один код → два приложения (iOS + Android), отдельную версию под каждую ОС писать не нужно. |
| **Expo** | надстройка над RN. Три функции: (1) готовые нативные модули (камера, гео, push, вибрация — подключаются одной строкой `expo-camera`, `expo-location`); (2) hot reload (правка → экран за 1-2 с); (3) облачная сборка финальных билдов через EAS (без Xcode на твоём компе). «GitHub для мобилок». |
| **Expo Go** | бесплатное приложение из стора (~30 МБ), куда загружаешь свой код по QR. Без сборки APK/IPA, без сертификатов — навёл камеру, через 10-30 с приложение работает на телефоне. Самый быстрый способ показать прототип. |

### Почему именно этот стек (а не другой)
- **Тот же React, что в вебе.** Собрал веб-MVP — ты на 80% готов писать мобильное приложение.
- **Claude знает RN лучше всех.** Самый распространённый фреймворк (Instagram, ВКонтакте, кусок Facebook) → максимум обучающих данных.
- **Один стек = три формата:** сайт (React) + телефон (React Native) + Telegram mini-app (React внутри ТГ). Один JS/TS + один Claude + одна голова.
- **Бэкенд переиспользуется.** Тот же сервер/API, что под веб, обслуживает и мобайл.

### Альтернативы и почему НЕ берём
- **Flutter** — другой язык (Dart), Claude знает хуже, придётся учить новый синтаксис. Чуть быстрее на экране, но для первого приложения незаметно.
- **Ionic / Cordova / WebView** — «сайт в обёртке приложения». Apple банит на модерации без объяснений. Не вариант.
- **Нативный Swift / Kotlin** — отдельный язык под каждую ОС, две команды, тяжёлые среды (Xcode, Android Studio). Путь только если упёрся в функцию, которую RN физически не умеет (см. ниже «Когда RN не хватает»).

## Цикл разработки: Expo Go + hot reload

Сохранил файл → через 1-2 секунды видишь изменение на экране телефона. Это hot reload — техническая причина, почему RN+Expo выиграли у нативки. В нативке (Swift/Kotlin) каждое изменение = пересборка 1-3 минуты.

**Живое демо по QR:** `npx expo start` выдаёт QR-код в терминале → камера телефона (или сканер в Expo Go) → приложение открывается. Можно дать любому человеку с Expo Go, он откроет твоё приложение на своём телефоне — бесплатно, без сертификатов, без билда.

## Команды

```bash
# создать проект (АКТУАЛЬНАЯ команда, Expo SDK 51+)
npx create-expo-app@latest hello-mobile

# запустить dev-сервер (выдаёт QR + опции: i = iOS-симулятор / a = Android-эмулятор / w = веб)
npx expo start

# туннельный режим — когда QR не сканируется / телефон и комп в разных сетях
# (медленнее, но работает через любую сеть, даже мобильный интернет)
npx expo start --tunnel

# собрать APK для друзей через облако EAS (без Xcode), начинать отсюда
eas build --platform android --profile preview

# поставить Claude Code, если не стоит
npm install -g @anthropic-ai/claude-code
```

Цикл «правки»: внутри окна `npx expo start` нажать `i` (iOS-симулятор на Mac) или `a` (Android-эмулятор). Если эмулятор тормозит/не стартует — пропустить, работать через Expo Go на физическом телефоне (даже удобнее).

## Анти-паттерны (Claude сам предложит — ловить и возвращать)

Claude трижды пытается уйти не туда:

1. **`expo init` / Expo CLI v6** — устаревшая команда. Только `npx create-expo-app@latest`.
2. **«Завернём твой сайт в WebView, приложение за 5 минут»** — гибрид. Apple банит на модерации без объяснений. Ответ: «нет, делаем настоящее RN».
3. **«Раз у тебя Mac — поставлю Xcode и через него запустим»** — стоп. Xcode не открывается ни разу. iOS-симулятор стартует без Xcode (нужны только Xcode Command Line Tools, одна команда). Финальная сборка — через облако EAS, не через Xcode.

Доп. правило при затыке: если упёрся в нативное (Xcode, gradle, `eject` от Expo) — НЕ трогать нативный код, сказать «упёрся в нативку», решать (оставить функцию или менять подход).

## Публикация в сторы

Старт — **с Android** (дешевле, быстрее модерация). Сборка финальных билдов — через облако EAS, **Xcode не нужен**.

| | Google Play | App Store |
|---|---|---|
| Стоимость аккаунта | **$25 разово** | **$99/год** (Apple Developer) |
| Формат билда | AAB (через `eas build`) | IPA (только через Apple Developer + TestFlight) |
| Модерация | до 24 ч (по «Что дальше» — до 7 дней закладывать) | 2-7 дней |
| Бета-тест | Internal Test | TestFlight (билд живёт 90 дней vs 7 дней при установке через Xcode) |

Лестница «после первого приложения» (каждый блок 1-3 ч, в таком порядке, спроектированы под этот стек — встают без переписывания):
1. **APK для друзей через EAS** (~30 мин, начать отсюда) — `eas build --platform android --profile preview`, APK кидаешь в Telegram, ставят без стора. Первый реальный кейс за минимум денег.
2. **Иконка + сплеш** (~30 мин) — генерация (nano-banana) + правка `app.json`. Без иконки конверсия в установку проседает.
3. **Регистрация аккаунтов** — Apple Developer $99/год + Google Play Console $25 разово (1-2 ч + 24-48 ч верификация).
4. **TestFlight (iOS) / Internal Test (Google Play)** (~1-2 ч) — `eas submit`, ссылка для 5-10 друзей, 90 дней без перезалития.
5. **Push через Expo Notifications** (~1-2 ч) — цикл «рассылка → заход в приложение». Без push retention в мобайле слабый.
6. **In-App Purchase через RevenueCat** (~2-3 ч) — обходит ручной StoreKit/Billing, аналитика подписок out-of-box. Для подписочной монетизации.

## Когда RN не хватает (нативка)

React Native физически не умеет низкоуровневое — тогда (и только тогда) нативный Swift/Kotlin:
- чтение SMS
- программные звонки
- доступ к контактам
- NFC
- низкоуровневый Bluetooth

На первом приложении этого не нужно. Если Claude упёрся в такое — сказать «упёрся в нативку», решить осознанно.

## Связь с веб-стеком автора

- **Те же frontend-принципы.** Веб-скиллы (`frontend-design`, `ui-ux-pro-max`, `motion`) и принцип «сначала смысл, потом форма» (CLAUDE.md) переносятся в мобайл — это тот же React.
- **Бэкенд один.** API/сервер под сайт обслуживает и мобильное приложение, и Telegram mini-app. Не дублировать.
- **Не дефолтить тёмную «иишную» тему** и в мобайле (правило из памяти про веб действует).

## Главный риск (не технический)

Переоценить свой темп после первого приложения. Мобайл в среднем **в 5 раз медленнее** веба по циклу «правка → проверка»:
- hot reload — быстро, как веб;
- первый запуск эмулятора — 1-3 мин;
- сборка APK — 10-15 мин;
- публикация в стор — 2-7 дней (Apple) / до 24 ч (Google).

Для первого приложения намеренно остаёмся на самом быстром цикле: код + Expo Go на физическом телефоне. Не лезть сразу в публикацию/иконки/платежи/push — отдельные темы по 1-3 ч каждая, встают на фундамент потом.
