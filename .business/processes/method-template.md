# Шаблон метод-файла

Технологическая карта повторяющегося артефакта (лендинг, презентация, рассылка-разовая, питч, КП, оффер-док). Раз → пишу промпт руками. Два → выношу метод в файл. Три → AI собирает артефакт по этому файлу, не переизобретая каждый раз. Лог применений калибрует метод за 3-5 итераций.

## Когда заводить метод-файл, а когда нужен writer-скилл

- **Метод-файл (этот шаблон)** — редкий или новый артефакт, у которого ещё НЕТ скилла. Лёгкий формат: один .md, правлю руками, не требует движка/валидаторов/рендера. Примеры: питч инвестору, КП партнёру, разовый лендинг-промо, структура презентации.
- **Writer-скилл (через skill-craft)** — частый ПУБЛИКУЕМЫЙ контент, который пойдёт в массовое производство (посты, карусели, письма, longform, рилз). Это уже есть: post / carousel / email / longform. Туда метод-файл НЕ лезет — там голос + humaniser + валидаторы зашиты в скилл.
- **Тест:** «буду делать это >5 раз в месяц И это публичный контент аудитории?» да → skill-craft, не метод-файл. Нет (редко / внутренний / разовый) → метод-файл.
- **Эскалация:** если метод-файл за 3-5 применений показал, что артефакт пошёл в поток — поднять его до скилла через skill-craft (лог применений уже = готовое ТЗ на скилл).

## Когда применять

Триггер-фразы и ситуации, на которых берётся этот метод. Один артефакт = один метод. Если триггер пересекается с writer-скиллом — уточнить границу (что делает метод, что скилл).

## Что прочитать перед сборкой

Викилинки на источники истины в `.business/` — AI читает ДО сборки, не из головы. Минимум:
- [[INDEX]] — стратегия/позиционирование
- `audience/` — боль/желание/язык сегмента
- `products/` — оффер/цена/тариф
- [[_voice-profile]] — голос автора
- профильные свёртки конкурентов / reference, если артефакт продающий

## Структура артефакта

Блоки по порядку, что в каждом и зачем (функция блока, не просто заголовок). Сначала смысл, потом форма — структура и содержание до любого визуала.

## Правила стиля и голоса

Канон — [[_voice-profile]] (`.business/voice-corpus/_voice-profile.md`). Сухо, конкретно, факты/цифры/действия без воды и мотивационных метафор. Специфика регистра под тип артефакта (питч ≠ лендинг ≠ КП). Публикуемый аудитории текст внутри артефакта — через humaniser.

## Чего НЕ делать

Анти-паттерны конкретно этого артефакта. Что ломало результат в прошлых применениях (тянуть из лога). Общие табу: выдумывать цифры/кейсы/цитаты (нет контекста → спросить, не изобретать) · AI-slop тёмная тема · вода и синонимичные пары · staccato-рубка предложений.

## Финальный чек-лист

- [ ] Прочитаны источники из раздела «Что прочитать»
- [ ] Структура соответствует разделу выше (все блоки, в порядке)
- [ ] Голос сверён с [[_voice-profile]], воды нет
- [ ] Цифры/факты/кейсы — из источника, не выдуманы
- [ ] Публикуемый текст прошёл humaniser
- [ ] Результат показан текстом в чат + объяснён (что/зачем/инсайт)
- [ ] Запись добавлена в «Лог применений» ниже

## Лог применений

Запись после КАЖДОЙ сборки. Через 3-5 применений метод стабилизируется — повторяющееся «что переделали» поднимается в «Структуру» или «Чего НЕ делать».

```
Применение 1: ГГГГ-ММ-ДД — что собрали: ___ / что сработало: ___ / что переделали: ___ → тюнинг метода: ___
Применение 2: ...
```
